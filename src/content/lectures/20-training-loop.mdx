前面五讲把训练的零件一个个造好了：模型（第 12–15 讲），损失函数（第 16 讲），梯度和梯度下降（第 17 讲），反向传播（第 18 讲），优化器（第 19 讲）。这一讲把它们组装起来，从一个随机初始化的网络开始，真正训练出第 15 讲那样能拟合曲线的网络。

组装时会碰到几个前面没有细说的实际问题：数据是一次全喂进去，还是分批？分多大的批？整份数据要过几遍？学习率要一直不变吗？这一讲回答这些问题，并且在浏览器里实时地训练一个小网络，你可以亲手调这些设置，看损失曲线怎么变。

## 训练循环的五步

训练的骨架是两层循环。外层循环一遍遍地过整份数据，每过一遍之前先把数据顺序打乱；内层循环每次取出一小批数据，做五件事：

1. **取一批**：从打乱后的数据里按顺序取出 B 个样本。
2. **前向**：把这一批输入送进网络，算出预测（第 15 讲）。
3. **算损失**：把预测和答案比较，得到这一批的平均损失（第 16 讲）。
4. **反向**：从损失出发做反向传播，得到每个参数的梯度（第 18 讲）。
5. **更新**：优化器用梯度更新参数（第 19 讲）。

用 PyTorch 写出来，内层循环就是这么几行。注意第一行的清零：第 18 讲说过，PyTorch 的梯度是累加的，不清零的话，这一步的梯度会和上一步的加在一起。

```python
for x, y in loader:              # ① 取一批
    optimizer.zero_grad()        #    把上一步的梯度清零
    pred = model(x)              # ② 前向
    loss = loss_fn(pred, y)      # ③ 损失
    loss.backward()              # ④ 反向：算出所有参数的梯度
    optimizer.step()             # ⑤ 更新
```

这一讲的例子是第 15 讲的同一个网络结构：1 → 8 → 8 → 1，ReLU，97 个参数。数据是 −3 到 3 之间均匀取的 64 个点，答案是 sin(1.5x) 再加上一点随机噪声（标准差 0.1）。加噪声是为了更像真实的数据：真实的数据总有测不准、标错了的地方。也因为有噪声，即使网络完美地学会了 sin(1.5x)，损失也降不到 0，而是停在噪声本身的大小，约 0.0101。

权重用一种叫 He 初始化的方法随机生成：每层的权重从均值为 0 的正态分布里抽，方差是 2 / 输入个数。这样各层输出的大小在一开始比较合适，不会太大也不会太小。偏置初始化为 0。随机初始化的网络，损失是 4.8043，比直接输出 0（损失约 0.5）还差得多。

## batch、step、epoch

几个术语先说清楚：

- **batch**（批）：一次前向、反向用到的那一小批样本。它包含的样本个数叫 **batch size**，记作 B。
- **step**（步），也叫 iteration：处理一个 batch 并更新一次参数。
- **epoch**（轮）：把整份数据完整地过一遍。

数据有 64 个样本，batch size 是 8，那么每个 epoch 有 64 / 8 = 8 个 step。训练 400 个 epoch，一共更新 3200 次参数。

为什么每个 epoch 都要重新打乱顺序？如果每次都按同样的顺序分批，同一个 batch 里总是那几个样本，梯度的噪声会带上固定的偏向；打乱以后，每个 epoch 的分组都不一样，平均下来更接近全体数据的梯度。

## batch 选多大

batch size 有两个极端。

一个极端是 **B 等于全部数据**（这里是 64）。每一步的梯度都是精确的，没有噪声，但每个 epoch 只能更新一次参数。下面的代码用 Adam、学习率 0.01 训练 400 个 epoch：一共只有 400 步，损失在第 100 个 epoch 还是 0.0799，到第 200 个 epoch 才降到 0.0105。

另一个极端是 **B = 1**，每一步只用一个样本。每个 epoch 能更新 64 次，前期下降最快：第 10 个 epoch 损失就到了 0.1597，第 100 个 epoch 是 0.0092。但每一步的梯度只来自一个点，噪声很大，参数一直被推来推去，停不下来：第 200 个 epoch 是 0.0117，第 400 个 epoch 反而回到了 0.0288。

中间的 **B = 8** 兼顾了两边：每个 epoch 更新 8 次，梯度的噪声比 B = 1 小得多。第 50 个 epoch 就降到 0.0332，最后是 0.0067。

<Note kind="warn">0.0067 比噪声本身的 0.0101 还低。这说明网络不只学到了 sin(1.5x)，还开始“记住”这 64 个点各自的噪声。这叫过拟合（overfitting）：在训练数据上越来越好，换一批新数据却未必。判断有没有过拟合，要留一部分数据不参与训练，专门用来检验，这叫验证集。</Note>

在 GPU 上，batch size 还和速度直接相关。一个 batch 里的样本是同时计算的，batch 越大，矩阵乘法越“胖”，第 3 讲说的算术强度越高，GPU 的计算单元越能被喂饱。所以实际训练中，batch size 往往在显存允许的范围内尽量大，再相应地调学习率。

## 学习率：先热身，再慢慢降

第 17 讲说过，学习率是最重要的超参数。学习率太大会怎样，下面的代码也试了：B = 8、学习率 0.1，损失前期降得飞快（第 10 个 epoch 就到 0.0307），之后却在 0.01 到 0.07 之间来回跳，第 50 个 epoch 是 0.0671，第 200 个 epoch 是 0.0520，始终稳定不下来。步子太大，到了谷底附近就会一直在两边来回跨。

于是有了一个很自然的想法：**开始时步子大一点，快速接近谷底；后期步子小一点，稳稳地落进去**。这就是学习率调度（learning rate schedule）。大模型训练最常用的组合是**预热 + 余弦衰减**：

- **预热**（warmup）：前若干步，学习率从很小线性增大到设定值。刚开始时参数是随机的，梯度很大、方向也乱；Adam 的 **v** 还没积累起来，对梯度大小的估计不准。这时步子太大，容易一下子把网络推到很糟糕的地方。
- **余弦衰减**（cosine decay）：之后学习率按余弦曲线的一半，从设定值平滑地降到 0（或一个很小的值）。降得前慢、中间快、最后又慢。

这一讲的设定是：设定值 0.01，前 20 个 epoch 预热，之后在 400 个 epoch 内余弦衰减到 0。几个时刻的学习率是：第 1 个 epoch 0.0005，第 10 个 0.00499，第 20 个 0.00994，第 101 个 0.00854，第 201 个 0.005（正好一半），第 301 个 0.00146，最后一个 epoch 已经几乎是 0。

效果是：前期因为预热，下降比不调度时慢一点（第 1 个 epoch 损失还是 4.4762）；但后期学习率越来越小，损失稳稳地停在 0.0084，曲线比不调度时平滑得多。

## 用代码复现

下面的代码完整实现了这一讲的训练循环：反向传播按第 18 讲的公式手写，优化器是第 19 讲的 Adam。它比较了几种 batch size 和学习率的组合，打印第 1、10、50、100、200、400 个 epoch 结束时在全部数据上的损失，最后算了 Llama-3-8B 的训练账（下一节用）。

```python
import numpy as np

rng = np.random.default_rng(2026)
X = np.linspace(-3, 3, 64)[:, None]                       # 64 个样本
Y = np.sin(1.5 * X) + 0.1 * rng.standard_normal((64, 1))  # 带一点噪声的目标

def init(seed):
    r = np.random.default_rng(seed)
    he = lambda n_in, n_out: r.standard_normal((n_in, n_out)) * np.sqrt(2 / n_in)
    return [he(1, 8), np.zeros(8), he(8, 8), np.zeros(8), he(8, 1), np.zeros(1)]

def forward(P, x):
    W1, b1, W2, b2, W3, b3 = P
    z1 = x @ W1 + b1; h1 = np.maximum(0, z1)
    z2 = h1 @ W2 + b2; h2 = np.maximum(0, z2)
    return (z1, h1, z2, h2), h2 @ W3 + b3

def backward(P, x, y):                                    # 第 18 讲：线性层的反向是两次矩阵乘法
    W1, b1, W2, b2, W3, b3 = P
    (z1, h1, z2, h2), yh = forward(P, x)
    dy = 2 * (yh - y) / len(x)
    dz2 = (dy @ W3.T) * (z2 > 0)
    dz1 = (dz2 @ W2.T) * (z1 > 0)
    return [x.T @ dz1, dz1.sum(0), h1.T @ dz2, dz2.sum(0), h2.T @ dy, dy.sum(0)]

def lr_at(epoch, base, warmup=20, total=400):             # 预热 + 余弦衰减
    return base * min(1, (epoch + 1) / warmup) * 0.5 * (1 + np.cos(np.pi * epoch / total))

def train(batch, base_lr, epochs=400, schedule=False):
    P = init(15)
    m = [np.zeros_like(p) for p in P]; v = [np.zeros_like(p) for p in P]
    order_rng, t, log = np.random.default_rng(7), 0, {}
    for epoch in range(epochs):
        lr = lr_at(epoch, base_lr) if schedule else base_lr
        order = order_rng.permutation(64)                  # 每个 epoch 重新洗牌
        for s in range(0, 64, batch):
            idx = order[s:s + batch]                       # ① 取一批
            G = backward(P, X[idx], Y[idx])                # ② 前向 ③ 损失 ④ 反向
            t += 1
            for k in range(6):                             # ⑤ Adam 更新
                m[k] = 0.9 * m[k] + 0.1 * G[k]
                v[k] = 0.999 * v[k] + 0.001 * G[k] ** 2
                P[k] -= lr * (m[k] / (1 - 0.9 ** t)) / (np.sqrt(v[k] / (1 - 0.999 ** t)) + 1e-8)
        if epoch + 1 in (1, 10, 50, 100, 200, 400):
            log[epoch + 1] = float(np.mean((forward(P, X)[1] - Y) ** 2))
    return t, log

print("噪声本身的均方误差：", round(float(np.mean((np.sin(1.5 * X) - Y) ** 2)), 4))
print("随机初始化时的损失：", round(float(np.mean((forward(init(15), X)[1] - Y) ** 2)), 4))
for batch, lr, sch in [(64, 0.01, False), (8, 0.01, False), (1, 0.01, False), (8, 0.1, False), (8, 0.01, True)]:
    steps, log = train(batch, lr, schedule=sch)
    print(f"batch {batch:2d}，η = {lr}{'，预热+余弦' if sch else ''}：{steps:5d} 步　" + "  ".join(f"{e}:{l:.4f}" for e, l in log.items()))
print("学习率调度：", [round(float(lr_at(e, 0.01)), 5) for e in (0, 9, 19, 100, 200, 300, 399)])

N, D = 8.03e9, 15e12
print(f"Llama-3-8B 训练约 15T token：6 × N × D = {6 * N * D:.2e} FLOPs")
print(f"H100 BF16 峰值约 989 TFLOPS，按 40% 利用率：{6 * N * D / (989e12 * 0.4) / 3600:.3g} GPU 小时")
```

## 到了大模型里

大模型的训练循环和这一讲的一模一样：取一批、前向、损失、反向、更新。区别在规模。

**数据和 batch 以 token 计。**语言模型的“样本”是一段段文本，每个位置都要预测下一个词（第 16 讲），所以 batch 的大小通常用 token 数来说，一步要处理几百万个 token。训练数据往往大到只过一遍，甚至不到一遍，所以大模型预训练很少说“训练了几个 epoch”，而是说“训练了多少 token”。Meta 公布的 Llama 3 预训练数据是 15 万亿（15T）个 token 以上。

**一张卡放不下一个 batch。**几百万个 token 的激活值，单卡根本存不下。常用的办法是**梯度累积**（gradient accumulation）：把一个大 batch 拆成几个小份，依次前向、反向，梯度先不清零、一直累加（正好利用了 PyTorch 梯度累加的特性），全部做完再更新一次参数，效果和一次处理整个大 batch 相同。再加上多卡的数据并行，每张卡处理一部分，最后把梯度加起来（第 103 讲）。

**训练的总成本可以估算。**第 18 讲说过，训练一个 token 约需 6N 次浮点运算。Llama-3-8B 的 N 约 80.3 亿，D 按 15T 个 token 算，总共约 6 × N × D = 7.23 × 10<sup>23</sup> 次。H100 的 BF16 峰值算力约 989 TFLOPS，实际训练能用上 40% 就算不错，这样算下来约 50.7 万 GPU 小时，相当于一千张 H100 连续跑三个星期左右。实际花费还要加上调试、失败重来、评估等开销，Meta 在模型卡里公布的数字要比这个估算更高。

**学习率调度按 step 走。**大模型训练的预热通常是前几千步，之后余弦衰减（或类似的曲线）一直到训练结束。训练过程中，工程师盯得最紧的就是右边那种损失曲线：它突然往上跳（loss spike），往往意味着学习率太大或者数据有问题，需要回到之前的检查点重新开始。

## 容易混淆的地方

1. **训练损失降低，不等于模型变好。**这一讲 B = 8 的损失降到了 0.0067，比噪声还低，说明网络在记忆噪声。真正要看的是没参与训练的验证数据上的损失。大模型预训练因为数据量极大、几乎每段数据只看一次，过拟合反而不是主要问题。
2. **batch size 和学习率要一起调。**batch 变大，梯度噪声变小，一般可以（也需要）用更大的学习率；只改一个不改另一个，结论可能完全相反。
3. **“step”“epoch”的横轴要看清楚。**比较两次训练的损失曲线时，横轴用的是 step、epoch 还是 token 数，会得出很不一样的结论。大模型的论文和训练日志里，横轴通常是训练过的 token 数。

## 回顾

训练循环是两层循环：外层每个 epoch 把数据打乱，内层每个 step 取一个 batch，做“前向 → 损失 → 反向 → 更新”五件事（PyTorch 里还要先把梯度清零）。batch 太大，每个 epoch 更新次数少；太小，梯度噪声大、停不下来，B = 8 这样的中间值往往最好。学习率太大会在谷底附近来回跳，所以常用“预热 + 余弦衰减”：先小、再大、再慢慢降到 0，让训练前期稳、后期准。大模型的训练循环完全一样，只是规模大得多：一步几百万个 token，靠梯度累积和多卡并行完成，总计算量约 6 × 参数量 × token 数。
