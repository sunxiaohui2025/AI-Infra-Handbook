上一讲结尾留了一个问题：注意力机制里，一次要算成千上万个点积，而且是“一批向量”和“另一批向量”两两之间都要算。一个一个地写、一个一个地算，显然不是办法。

这一讲要介绍的矩阵乘法，就是为这件事准备的写法。它能把“一批向量对一批向量”的所有点积，用一个式子写出来，再一次交给硬件算完。你在大学里肯定学过矩阵乘法，但当时可能只记住了“行乘列”的口诀。这一讲换一个角度：先从具体的点积出发，看矩阵乘法是怎么“长”出来的，再看它在大模型里扮演什么角色。

## 16 个点积，排成一张表

还是用全站的玩具模型 TinyLM。第 1 讲说过，“我 爱 学 AI”这句话里的 4 个词，各自对应一个 4 维向量：

| 词 | 向量 |
| --- | --- |
| 我 | (0.7, −0.6, −0.9, 0.3) |
| 爱 | (−0.3, −0.1, −0.8, −0.2) |
| 学 | (0.3, −0.3, 0.6, 0.6) |
| AI | (0.4, 0.8, 0.4, −0.6) |

现在假设模型的某一层要对每个词做这样一件事：准备好 4 个固定的“探测方向”，每个方向也是一个 4 维向量，然后让每个词分别和这 4 个方向做点积。上一讲说过，点积量的是“两个向量有多一致”，所以每个点积都可以理解成“这个词在这个方向上得几分”。

4 个词，每个词对 4 个方向，一共要算 4 × 4 = 16 个点积。16 个数，最自然的摆法是一张表：**每个词占一行，每个方向占一列**，第 i 行第 j 列就填“第 i 个词和第 j 个方向的点积”。

为了让这张表好算，我们把参与计算的向量也摆成表。4 个词的向量一行一个，叠成一张 4×4 的表，叫它 X；4 个方向一列一个，并排成另一张 4×4 的表，叫它 W。下图把三张表画在一起：

<MatrixFigure row={1} col={0} />

图里高亮的是一个例子：“爱”这一行（X 的第 2 行）和 W 的第 1 列做点积，结果填在右边那张表的“爱”这一行、第 1 列。四对数字分别相乘再相加：

$$
(-0.3)\times(-0.4) + (-0.1)\times(-0.7) + (-0.8)\times 0.3 + (-0.2)\times(-0.7) = 0.12 + 0.07 - 0.24 + 0.14 = 0.09
$$

其余 15 格也一样，每一格都是“左边一行”和“右边一列”的点积。

## 这张表就是矩阵乘法

上面这三张数字表，在数学里就叫**矩阵**：m 行 n 列的数排成一个长方形，就是一个 m×n 的矩阵。X 是 4×4，W 也是 4×4。

而“用 X 的每一行去和 W 的每一列做点积，把结果填成一张新表”这个操作，就是**矩阵乘法**，写作 C = XW（或 X · W，代码里写 `X @ W`）。所谓“行乘列”的口诀，说的就是这件事：

<Note kind="point">矩阵乘法 C = XW 的每一格，都是 X 的一行和 W 的一列的点积。整个 C 就是一张点积表。</Note>

写成一般的公式：设 A 是 m×k 的矩阵，B 是 k×n 的矩阵，它们的乘积 C = AB 是 m×n 的矩阵，第 i 行第 j 列为

$$
C_{ij} = \sum_{t=1}^{k} A_{it}\cdot B_{tj} = A_{i1}B_{1j} + A_{i2}B_{2j} + \dots + A_{ik}B_{kj}
$$

式子里各个符号的意思：

<dl class="ai-defs"><dt>m</dt><dd>A 的行数：有几个输入向量。这里是 4 个词</dd><dt>k</dt><dd>每个输入向量的维度，也就是 A 的列数；它必须等于 B 的行数</dd><dt>n</dt><dd>B 的列数：有几个探测方向，也就是结果的列数</dd><dt>i, j</dt><dd>C 的第 i 行、第 j 列</dd><dt>t</dt><dd>求和下标，从 1 走到 k，对应点积里“第 t 个分量相乘”</dd></dl>

对照上一讲的点积定义 *a*<sub>1</sub>*b*<sub>1</sub> + *a*<sub>2</sub>*b*<sub>2</sub> + … + *a*<sub>k</sub>*b*<sub>k</sub>，就能看出这个式子并没有新东西：A 的第 i 行是一个 k 维向量，B 的第 j 列也是一个 k 维向量，C<sub>ij</sub> 就是它们的点积。

## 一格一格算出来

在看演示之前，先用手算第一格：“我”这一行和 W 的第 1 列。

$$
0.7\times(-0.4) + (-0.6)\times(-0.7) + (-0.9)\times 0.3 + 0.3\times(-0.7) = -0.28 + 0.42 - 0.27 - 0.21 = -0.34
$$

再用下面的演示核对，并把剩下的 15 格也算出来。点“下一格”一格一格往前走，点“▶ 播放”让它自动走，也可以直接点结果 C 里的任意一格，跳到那一格。每走一步，参与计算的那一行、那一列会被高亮，下方的提示条写出这一格的完整算式。

<MatrixStepper />

走完 16 格，可以停下来数一数一共做了多少次运算：每一格是一次 4 维点积，要做 4 次乘法、把结果累加起来；16 格就是 16 × 4 = **64 次乘加**。这个数字在后面算计算量时会用到。

X 和 W 里的数字都可以直接改。试着把 X 第一行的 0.7 改成 0，你会发现只有“我”这一行的结果变了，其他三行纹丝不动。这是一个很重要的性质，后面马上会用到。

<Note kind="column" title="专栏　这些数字从哪来">
X 和 W 都来自课程目录下的 `tinylm/tinylm.py`（随机种子 2026，权重取一位小数）。X 是 4 个词的词向量，第 22 讲会讲它们是怎么来的；W 是 TinyLM 第 1 层里的一个权重矩阵，到第 26 讲，它会以“W<sub>Q</sub>”的名字出现，这里算出的 C 就是注意力里的 Q。
</Note>

## 形状要对得上

矩阵乘法有一个硬性要求：**左边矩阵的列数，必须等于右边矩阵的行数。**

这个要求不是凭空规定的。回想一下，C 的每一格是“左边一行”和“右边一列”的点积，而上一讲说过，点积要求两个向量维度相同。左边一行有几个数，由左边矩阵的列数决定；右边一列有几个数，由右边矩阵的行数决定。两者不相等，就凑不成点积。

结果的形状也可以这样推出来：左边有几行，就有几个输入向量，结果就有几行；右边有几列，就有几个方向，结果就有几列。把这些写成一条规则：

$$
[m,\,k] \,\text{@}\, [k,\,n] \to [m,\,n]
$$

**中间的 k 相消，两边的 m 和 n 留下**。比如只要 W 的前两列，也就是只保留 2 个探测方向，那么 [4, 4] @ [4, 2] → [4, 2]，每个词只得到两个分数，正好是原来 C 的前两列：(−0.34, 0.18)、(0.09, 0.07)、(−0.15, −0.21)、(−0.18, 0.32)。

这条规则在大模型里每天都在用。模型里的一批 token 通常写成形状 [s, d] 的矩阵：s 个 token，每个 d 维。经过一个 d × d<sub>out</sub> 的权重矩阵，就变成

$$
[s,\,d] \,\text{@}\, [d,\,d_{\mathrm{out}}] \to [s,\,d_{\mathrm{out}}]
$$

每个 token 从 d 维变成了 d<sub>out</sub> 维。看到一个矩阵乘法，先把两边的形状写出来，检查中间的维度对不对得上，是读大模型代码时最有用的习惯之一。第 5 讲会专门讲形状。

## 换个角度：一次对一批向量做同一种变换

到目前为止，我们是一格一格地看 C 的。现在换一个角度，**一行一行地看**。

C 的第 1 行，是“我”这个词分别和 W 的 4 列做点积得到的 4 个数：(−0.34, 0.18, −0.16, 0.11)。也就是说，“我”原来是一个 4 维向量 (0.7, −0.6, −0.9, 0.3)，乘以 W 之后，变成了另一个 4 维向量 (−0.34, 0.18, −0.16, 0.11)。同样，“爱”变成了 (0.09, 0.07, 0.13, 0.13)，依此类推。

所以，矩阵乘法 XW 还可以这样理解：**W 是一台“变换机器”，X 的每一行都被送进这台机器，变成 C 里对应的一行。**所有的行用的是同一台机器 W，而且各行之间互不干扰——这就是刚才在演示里看到的现象：改了“我”那一行的数字，其他行的结果都不变。

这正是大纲给这一讲提出的问题——怎么一次对一批向量做同一种变换——的答案：**把这批向量一行一行叠成矩阵 X，乘以同一个 W。**一句话有 4 个词，就是 4 行；有 1000 个词，就是 1000 行，W 不需要任何改变。大模型里几乎每一层都在做这件事：注意力里的 Q、K、V 投影，前馈网络里的升维和降维，最后的输出层，都是“一批 token 乘以同一个权重矩阵”。

至于这台“变换机器”到底对向量做了什么——是拉长、旋转，还是别的什么——这是下一讲的内容。

## 用代码试一试

先在 `tinylm/` 目录运行一次 `python tinylm.py` 生成 `tinylm.json`，再在同一目录运行下面的代码。它用两种写法计算同一个 C：一种是照着定义写三重循环，另一种是一次矩阵乘法。

```python
import json
import numpy as np

ex = json.load(open("tinylm.json", encoding="utf-8"))["examples"]["03"]
X = np.array(ex["X"])   # 我 爱 学 AI，每个 token 一个 4 维向量
W = np.array(ex["W"])   # 一个 4×4 权重矩阵

# 写法一：三重循环，逐格做点积
m, k = X.shape
_, n = W.shape
C = np.zeros((m, n))
for i in range(m):
    for j in range(n):
        for t in range(k):
            C[i, j] += X[i, t] * W[t, j]

# 写法二：一次矩阵乘法
print(np.round(X @ W, 2))
print(np.allclose(C, X @ W))       # 两种写法一致
print(np.allclose(X @ W, ex["C"])) # 与手算一致
print(np.round(W @ X, 2)[0])       # 顺序反过来，结果就不一样了
```

输出：

```text
[[-0.34  0.18 -0.16  0.11]
 [ 0.09  0.07  0.13  0.13]
 [-0.15 -0.21 -0.51 -0.51]
 [-0.18  0.32  0.7   0.86]]
True
True
[-0.11  0.55  0.44 -0.36]
```

第一行第一格是 −0.34，第二行第一格是 0.09，都和前面的手算一致。三重循环和 `X @ W` 的结果相同（这里用 `allclose` 而不是 `==` 比较，原因和上一讲见到的 0.9099999999999999 一样：浮点数的加法顺序不同，最后几位可能有极小的差别）。

两种写法的差别在速度。三重循环在 Python 里一格一格地算；`X @ W` 则把整个运算一次交给底层的数值库，在 GPU 上还会交给专门做矩阵乘法的硬件单元。矩阵一大，两者的速度能差几个数量级。

最后一行是 `W @ X` 的第一行：(−0.11, 0.55, 0.44, −0.36)，和 `X @ W` 的第一行完全不同。下一节会解释为什么。

## 放大到真实模型：要算多少、要搬多少

前面数过，4×4 乘 4×4 要做 64 次乘加。推广到一般情况：C 有 m × n 格，每格是一个 k 维点积，要做 k 次乘法和 k 次加法，所以一次矩阵乘法大约要做

<div class="ai-formula">2 · <i>m</i> · <i>n</i> · <i>k</i> 次浮点运算（FLOPs）</div>

手算那一例是 2 × 4 × 4 × 4 = 128 FLOPs。这个公式是第 11 讲估算计算量的基本单位，后面会反复用到。

现在把 TinyLM 的 4 换成真实模型的 4096（大纲里用作例子的 Llama-3-8B 的隐藏维度，写正文时请对照官方配置核实），看一个 4096 × 4096 的权重矩阵。用下面的计算器试两组预设：“逐词生成”时一次只处理 1 个 token（s = 1），“读完长提示”时一次处理 1000 个 token（s = 1000）。

<MatmulCalc />

两组预设里，权重矩阵是同一个：4096 × 4096 个数，用 BF16 存（每个数 2 字节）要 **32 MiB**。不管一次处理多少个 token，这 32 MiB 都要从显存里读一遍。

区别在于读一遍之后能做多少计算。s = 1 时，只做 3.4 × 10<sup>7</sup> 次运算，平均每读 1 字节只算 **1 次**；s = 1000 时，做 3.4 × 10<sup>10</sup> 次运算，每读 1 字节算 **1000 次**。推一下就知道，这个比值正好约等于 s：FLOPs 是 2·s·k·n，读的字节数是 k·n·2，相除就剩下 s。

这个比值叫**算术强度**，是 AI Infra 里最重要的概念之一。GPU 算得很快，但从显存里搬数据相对慢。每读 1 字节只算 1 次，GPU 的大部分时间都在等数据；每读 1 字节算 1000 次，GPU 才能真正忙起来。大模型逐字生成文字时，恰恰是 s = 1 的情况——为什么生成文字比读提示慢得多，第 62 讲的 Roofline 模型和第 68 讲的 Prefill 与 Decode 会从这里展开。把精度换成 FP8，权重少搬一半，这是第 63、93 讲低精度能提速的原因之一。

## 容易混淆的地方

1. **XW 和 WX 一般不相等**。上面的代码已经看到了，即使两个矩阵都是 4×4，交换顺序后结果也完全不同。原因很直接：XW 是“X 的行”和“W 的列”做点积，WX 是“W 的行”和“X 的列”做点积，参与计算的根本不是同一批向量。形状不是方阵时，交换顺序连形状都可能对不上：[2, 3] @ [3, 2] 得到 2×2，[3, 2] @ [2, 3] 得到 3×3。
2. **`A * B` 不是矩阵乘法**。在 NumPy 和 PyTorch 里，`*` 是对应位置的元素相乘，两个 4×4 矩阵 `*` 出来还是 4×4，但每一格只是一次乘法，不是点积。矩阵乘法要用 `@`（或 `np.matmul`、`torch.matmul`）。
3. **“行乘列”，不是“列乘行”**。C<sub>ij</sub> 用的是左边矩阵的第 i 行和右边矩阵的第 j 列。如果你发现自己需要“左边的列”，通常说明应该先把矩阵转置（行列互换），或者两个矩阵的顺序写反了。

## 回顾

这一讲从上一讲的点积出发：4 个词各自对 4 个方向做点积，得到 16 个数，排成一张表，这张表就是矩阵乘法的结果。矩阵乘法 C = XW 的每一格，都是 X 的一行和 W 的一列的点积；要乘得起来，左边的列数必须等于右边的行数，结果的形状是 [m, k] @ [k, n] → [m, n]。换个角度一行一行地看，矩阵乘法就是用同一个 W 一次变换一批向量，这正是大模型每一层都在做的事。从工程上看，一次矩阵乘法约 2mnk 次运算，而一次处理的 token 越多，读一遍权重能做的计算就越多。

还有一个问题没有回答：这台“变换机器”W，究竟把向量变成了什么样？如果把向量画成平面上的箭头，乘以一个矩阵之后，整个平面会被拉伸、旋转，还是扭曲？这就是下一讲的内容：**线性变换的几何意义**。
