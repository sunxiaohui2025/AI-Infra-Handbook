第 88 讲算过，训练一个模型，每个参数要存约 16 字节：BF16 的权重 2 字节、梯度 2 字节，FP32 的主权重 4 字节，Adam 的两个状态（第 19 讲）各 4 字节。Llama-3-8B 就是 128 GB，一张 80 GB 的卡放不下。

训练最常用的并行方式是**数据并行**，可它恰恰要求每张卡放一份完整的状态。这一讲先讲数据并行怎么工作，再讲 **ZeRO** 怎么在不改变计算结果的前提下，把这些状态切到多张卡上，以及它要付出多少通信。PyTorch 的 **FSDP** 就是 ZeRO 最彻底的那一级。

## 数据并行：每人一份模型，各算一批数据

数据并行的想法很简单：N 张卡上各放一份完整的模型，把一个大批次的数据平均分成 N 份，每张卡用自己那份数据做前向、反向，算出梯度。

可是各卡算出的梯度不一样（数据不同），直接各自更新，模型就分叉了。所以在更新之前，要用 **All-Reduce**（第 89 讲）把所有卡的梯度加起来、取平均。因为损失是对所有样本求平均的，各份数据的梯度取平均，**正好等于用整个大批次算出的梯度**。代码用一个线性回归验证了这一点：4 张卡各用 16 条数据算梯度再平均，和用 64 条数据一次算出的完全相同。

之后每张卡用同样的梯度做同样的更新，模型始终保持一致。

数据并行的计算是完美切分的：N 张卡，每张只算 1/N 的数据。可显存一点没省：**每张卡都存着完整的 16 字节/参数**。8B 模型每张卡要 128.5 GB，放不下。

## ZeRO：把冗余的状态切开

2019 年微软的 **ZeRO**（Zero Redundancy Optimizer）注意到：数据并行里，N 张卡存的状态**完全一样**，这是 N 倍的冗余。能不能每张卡只存 1/N，需要的时候再去拿？

它分三级，一级比一级切得多：

**ZeRO-1：切优化器状态。**优化器状态（FP32 主权重和 Adam 的两个状态，12 字节/参数）是大头。让每张卡只负责 1/N 的参数的更新：卡 r 只存第 r 段参数的优化器状态。更新时，梯度还是要 All-Reduce，但每张卡只更新自己那一段，然后用 **All-Gather** 把更新后的各段参数拼回完整的模型。8 张卡时，每张卡从 128.5 GB 降到 **44.2 GB**。

**ZeRO-2：再切梯度。**既然卡 r 只更新第 r 段，它也只需要第 r 段的梯度。把梯度的 All-Reduce 换成 **Reduce-Scatter**（第 89 讲）：求和之后，每张卡只拿自己那一段。梯度也只需存 1/N。每张卡降到 **30.1 GB**。

**ZeRO-3：连参数也切。**每张卡平时只存 1/N 的 BF16 权重。前向算到某一层时，用 All-Gather 临时拼出这一层的完整权重，算完就扔掉；反向时再拼一次。每张卡降到 **16.1 GB**，正好是 16Ψ/N。PyTorch 的 **FSDP**（Fully Sharded Data Parallel）就是 ZeRO-3 的实现。

代码验证了 ZeRO 的切分更新不改变结果：每张卡只更新自己那一段参数，再拼起来，和不切分时一步更新的结果完全相同。

## 要多付多少通信

切开状态，代价是通信。设参数量为 Ψ，BF16 下一份梯度或参数是 2Ψ 字节。用第 89 讲的结论，All-Reduce 每张卡收发约 2 × 2Ψ，Reduce-Scatter 和 All-Gather 各约 2Ψ：

- **数据并行**：梯度 All-Reduce，约 2 × 2Ψ。
- **ZeRO-1、ZeRO-2**：梯度 Reduce-Scatter（2Ψ）+ 更新后的参数 All-Gather（2Ψ），一共还是约 2 × 2Ψ，**和数据并行一样多**。All-Reduce 本来就等于 Reduce-Scatter 加 All-Gather，ZeRO 只是把这两半拆开，中间插进“只更新自己那段”。
- **ZeRO-3**：前向 All-Gather 参数（2Ψ），反向再 All-Gather 一次（2Ψ），梯度 Reduce-Scatter（2Ψ），一共约 3 × 2Ψ，是数据并行的 **1.5 倍**。

对 8B 模型，每步每张卡的通信从 32 GB 增加到 48 GB。用第 91 讲的估算，跨机网络上这是零点几秒到一秒的量级。实际的实现会把通信和计算**重叠**起来：算第 k 层时，提前 All-Gather 第 k + 1 层的参数；反向算完一层的梯度，就开始 Reduce-Scatter 它，同时算下一层。只要计算时间足够长，通信大部分可以被藏起来。

<Note kind="point">数据并行每张卡放一份完整的模型、算 1/N 的数据，梯度用 All-Reduce 求平均，结果和单卡大批次相同，但每卡要存完整的 16 字节/参数。ZeRO 去掉这种冗余：ZeRO-1 切优化器状态，ZeRO-2 再切梯度（All-Reduce 拆成 Reduce-Scatter + All-Gather，通信不变），ZeRO-3/FSDP 连参数也切（用到时 All-Gather，通信变成 1.5 倍）。</Note>

## 显存里还有激活

ZeRO 切的是和参数有关的状态。训练时还有一大块是**激活**：前向每一层的中间结果要留到反向时用（第 18 讲）。它和批大小、序列长度成正比，长序列训练时往往比参数状态还大。ZeRO 管不了激活，要用别的办法：

- **激活重算**（activation checkpointing）：前向时只保留少数几层的输出，反向时再把中间的重新算一遍，用计算换显存。
- **张量并行、序列并行**（第 93、95 讲）：把激活本身也切到多张卡上。

所以大规模训练通常把 ZeRO/FSDP 和其他并行方式组合起来用。

## 到了大模型里

**训练框架的标配。**DeepSpeed 实现了 ZeRO 的三级；PyTorch 的 FSDP（以及新版的 FSDP2）实现了 ZeRO-3；Megatron-LM 里有“分布式优化器”，相当于 ZeRO-1。中小规模的模型（几十亿参数），只用 FSDP 往往就够了。

**推理一般不用 ZeRO-3。**推理没有梯度和优化器状态，只有权重。如果像 ZeRO-3 那样把权重切开、每次用到再 All-Gather，decode 的每一步都要把整个模型的权重在卡之间传一遍：8B 模型每步每卡要收约 14 GB，即使走 NVLink 也要 30 ms 左右，比读一遍权重（4.8 ms）还慢得多。所以推理用的是张量并行、专家并行这些“不搬权重、只搬激活”的切法（第 93、96 讲）。

**强化学习里训练和推理挨在一起。**第 49 讲的 RL 训练，一边用推理引擎生成回答，一边用训练框架更新参数，权重要在两种切分方式之间来回转换。这也是现在训练框架和推理引擎结合得越来越紧的原因之一。

## 用代码复现

下面的代码先验证数据并行的梯度平均等于全量梯度、ZeRO 的切分更新等于不切分；再算出 8B 模型在 8 张卡上各级 ZeRO 每张卡的显存和每步的通信量。

```python
import numpy as np

# 1. 数据并行：4 张卡各拿一份数据算梯度，All-Reduce 取平均 = 用全部数据算一次梯度
rng = np.random.default_rng(0)
X, y = rng.standard_normal((64, 8)), rng.standard_normal(64)
w = np.zeros(8)
grad = lambda w, X, y: 2 * X.T @ (X @ w - y) / len(y)          # 线性回归的均方误差梯度
g_full = grad(w, X, y)
g_dp = sum(grad(w, X[i::4], y[i::4]) for i in range(4)) / 4     # 每张卡 16 条数据，All-Reduce 后求平均
print("4 卡梯度求平均 = 全部数据的梯度：", np.allclose(g_full, g_dp))

# 2. ZeRO：每张卡只负责 1/4 的参数的优化器状态。Reduce-Scatter 拿到自己那段梯度，只更新自己那段，再 All-Gather 拼回完整参数
p, lr = 4, 0.1
w_ref = w - lr * g_full                                     # 对照：普通的 SGD 一步（这里没用动量，只演示切分）
shards = np.split(np.arange(8), p)
w_parts = [w[s] - lr * (sum(grad(w, X[i::4], y[i::4]) for i in range(4)) / 4)[s] for s in shards]   # 卡 r 只更新第 r 段
print("ZeRO 切分更新再 All-Gather = 不切分：", np.allclose(np.concatenate(w_parts), w_ref))

# 3. 训练 Llama-3-8B，每张卡的显存（只算和参数有关的状态）：BF16 权重 2Ψ + BF16 梯度 2Ψ + FP32 主权重和 Adam 两个状态 12Ψ
Psi, N = 8.03e9, 8
stages = {
    "数据并行（每卡一份完整的）": 2 * Psi + 2 * Psi + 12 * Psi,
    "ZeRO-1（切优化器状态）":     2 * Psi + 2 * Psi + 12 * Psi / N,
    "ZeRO-2（再切梯度）":         2 * Psi + (2 * Psi + 12 * Psi) / N,
    "ZeRO-3 / FSDP（再切参数）":  16 * Psi / N,
}
comm = {"数据并行（每卡一份完整的）": 2, "ZeRO-1（切优化器状态）": 2, "ZeRO-2（再切梯度）": 2, "ZeRO-3 / FSDP（再切参数）": 3}
for k, v in stages.items():
    print(f"{k}：每卡 {v / 1e9:6.1f} GB；每步每卡通信约 {comm[k]} × 2Ψ = {comm[k] * 2 * Psi / 1e9:.0f} GB")
```

输出：

```text
4 卡梯度求平均 = 全部数据的梯度： True
ZeRO 切分更新再 All-Gather = 不切分： True
数据并行（每卡一份完整的）：每卡  128.5 GB；每步每卡通信约 2 × 2Ψ = 32 GB
ZeRO-1（切优化器状态）：每卡   44.2 GB；每步每卡通信约 2 × 2Ψ = 32 GB
ZeRO-2（再切梯度）：每卡   30.1 GB；每步每卡通信约 2 × 2Ψ = 32 GB
ZeRO-3 / FSDP（再切参数）：每卡   16.1 GB；每步每卡通信约 3 × 2Ψ = 48 GB
```

前两行是两个验证。后四行是显存和通信：从数据并行的 128.5 GB 降到 ZeRO-3 的 16.1 GB；通信前三者都是 32 GB，ZeRO-3 是 48 GB。

## 容易混淆的地方

1. **ZeRO 不改变计算结果。**它只是改变了状态存在哪里、什么时候通信，每一步的更新和普通的数据并行完全相同。
2. **ZeRO-3 和张量并行都在“切参数”，方式不同。**ZeRO-3 存的时候切开、算的时候拼回完整的矩阵，每张卡仍然做完整的计算（只是数据不同）；张量并行连计算也切开，每张卡只算矩阵乘法的一部分（下一讲）。
3. **卡数增加，没切的部分不会变小。**ZeRO-1 时，权重和梯度每卡始终是 4Ψ；只有切开的部分随卡数减少。要压到最小，就得用 ZeRO-3。

## 回顾

数据并行让每张卡用一份完整的模型算 1/N 的数据，梯度用 All-Reduce 求平均，结果等于单卡大批次，但每张卡要存约 16 字节/参数的完整状态，8B 模型 128.5 GB。ZeRO 去掉这种冗余：ZeRO-1 切优化器状态（44.2 GB），ZeRO-2 再切梯度（30.1 GB），ZeRO-3/FSDP 连参数也切（16.1 GB）。ZeRO-1、2 的通信和数据并行一样，ZeRO-3 是 1.5 倍，靠和计算重叠来掩盖。激活要靠重算或其他并行方式。推理不用 ZeRO-3，因为每步搬一遍权重太慢。

ZeRO-3 存的时候切开，算的时候还要拼回完整的权重。有没有办法让每张卡**只用自己那一块权重**就能完成计算，只交换小得多的激活？下一讲：**张量并行**。
