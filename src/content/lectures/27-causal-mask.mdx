上一讲的复读模型有一个细节：它的注意力矩阵右上角全是空的，每个词只看自己和前面的词，从不看后面的词。上一讲的 TinyLM 演示则没有这个限制，每个词都看了整句话。

这一讲解释这个限制是什么、为什么语言模型必须有它。它叫**因果掩码**（causal mask）：在注意力里把“后面的词”遮住。它的实现只有一行代码，却直接决定了两件大事：一是训练时能不能一次前向就把一整段话的所有位置都训练了；二是推理时能不能用 KV Cache。后者是整个推理优化的基石，所以这一讲标了重点。

## 生成的时候，后面还不存在

先想想生成。第 24 讲说过，模型一个词一个词地往外吐：写第 5 个词时，第 6 个词还不存在，模型只能根据第 1 到第 5 个词来决定。

模型在生成时面对的条件，训练时就得一样。否则就像考试时开卷、平时练习却从不允许翻书，或者反过来，练的和考的根本不是一回事。

## 训练时，答案就在旁边

问题出在训练。第 23 讲说过，训练时整段文本是已知的，Transformer 一次前向，就给每个位置都预测下一个词：第 i 个位置的输出，用来预测第 i + 1 个词。

可是自注意力会让第 i 个位置去看句子里**所有**的词，包括第 i + 1 个，那正是它要预测的答案。不加限制的话，模型很快就会发现一条捷径：根本不用理解前文，直接“看一眼下一个词，照抄”就行了，训练损失能降得非常低。等到生成时，下一个词还不存在，这条捷径用不上，模型就什么也不会了。

我们可以直接验证“后面的词会影响前面”。用 TinyLM，把第 4 个词“AI”换成另一个向量，看前 3 个词的注意力输出变不变：不加掩码，前 3 个词的输出最多变了 0.3804，说明它们确实“看到”了第 4 个词。加上掩码，变化是 0：前面的词对后面发生了什么一无所知。

## 掩码怎么加

做法很简单：在 softmax **之前**，把分数矩阵里“j > i”的那些位置（第 i 个词看排在它后面的第 j 个词），全部换成 −∞：

<div class="ai-formula"><i>A</i> = softmax(<i>QK</i><sup>T</sup> / √<i>d</i><sub>k</sub> + <i>M</i>)，　<i>M</i><sub>ij</sub> = 0（j ≤ i），−∞（j &gt; i）</div>

e<sup>−∞</sup> = 0，所以 softmax 之后，这些位置的权重恰好是 0，其余位置的权重重新归一，加起来仍然是 1。被保留的是矩阵的**下三角**（含对角线），所以也叫下三角掩码。

拿 TinyLM 的注意力看看加掩码前后的变化：

| 提问的词 | 不加掩码 | 加因果掩码 |
| --- | --- | --- |
| 我（第 1 个） | 0.262, 0.268, 0.242, 0.227 | 1, 0, 0, 0 |
| 爱（第 2 个） | 0.243, 0.251, 0.252, 0.253 | 0.491, 0.509, 0, 0 |
| 学（第 3 个） | 0.289, 0.241, 0.228, 0.242 | 0.381, 0.318, 0.301, 0 |
| AI（第 4 个） | 0.196, 0.274, 0.295, 0.235 | 0.196, 0.274, 0.295, 0.235 |

第 1 个词只能看自己，权重只能是 1；第 2 个词在“我”和“爱”之间分配；最后一个词本来就没有“后面”，加不加掩码都一样。

注意掩码必须加在 softmax 之前。如果先 softmax、再把后面的权重改成 0，剩下的权重加起来就不到 1 了，而且分数里已经混进了后面的词的信息（softmax 的分母用到了它们）。

## 一次前向，做完所有的题

有了因果掩码，训练就可以放心地“一次前向，所有位置一起算”了。第 i 个位置的输出只依赖前 i 个词，它预测第 i + 1 个词时看不到答案，和生成时的条件完全一样。一段 8192 个 token 的文本，一次前向就是 8192 道合法的“猜下一个词”的题。

这一点非常重要。早期的循环神经网络（RNN）必须一个词一个词地顺序处理，训练时没法并行；Transformer 靠“注意力 + 因果掩码”，让训练在序列长度这个维度上也能并行，这是它能在海量数据上训练的关键原因之一。

## KV Cache 为什么能成立

现在回到推理。这一节是这一讲最重要的部分。

因果掩码保证了：**第 i 个词的输出，只依赖第 1 到 i 个词**。往后面接新的词，前面的词的输出一个数都不会变。这对每一层都成立：第 1 层前 i 个词的输出不变，作为第 2 层的输入也就不变，第 2 层前 i 个词的输出也不变……一直到最后一层。所以，**每一层里，前面每个词的 k 和 v 一旦算出来，就永远不会再变**。

既然不变，就不必每一步都重算。把它们存起来，叫 **KV Cache**。生成第 i + 1 个词时：

1. 只把新来的这一个词送进模型，在每一层只算它自己的 q、k、v。
2. 把它的 k、v 追加到缓存里。
3. 用它的 q，去和缓存里所有词的 k 打分，用权重把缓存里所有的 v 加起来。

第 3 步里，新词本来就是最后一个，它能看的正是“自己和前面所有的词”，所以**这一步不需要掩码**。分数也不再是 s × s 的矩阵，而是 1 × s 的一行。

下面的代码验证了这件事：把“我 爱 学”的 k、v 当成缓存，只为“AI”算 q、k、v，用这一行算出的注意力权重 (0.196, 0.274, 0.295, 0.235) 和输出，和整句加掩码一起算出的最后一行完全相同。

如果没有因果掩码，前面每个词的输出都会随着后面的词变化，每生成一个词，就得把整段从头算一遍，第 24 讲算过，生成 1000 个词要多处理上百万个 token 位置。

## 用代码复现

下面的代码算了加掩码前后的注意力权重；验证改最后一个词会不会影响前面；模拟了一步用 KV Cache 的解码；最后算出 Llama-3-8B 的 KV Cache 有多大。

```python
import json
import numpy as np

t = json.load(open("tinylm.json", encoding="utf-8"))
X = np.array(t["examples"]["03"]["X"])                      # “我 爱 学 AI”
L0 = t["weights"]["layers"][0]
Wq, Wk, Wv = (np.array(L0[k]) for k in ["W_q", "W_k", "W_v"])

def softmax(S):
    e = np.exp(S - S.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def attention(X, causal):
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    S = Q @ K.T / np.sqrt(Q.shape[1])
    if causal:
        S = S + np.triu(np.full(S.shape, -np.inf), k=1)     # 右上角（j > i）加上 −∞
    A = softmax(S)
    return A, A @ V

# 1. 加掩码前后的注意力权重
for causal in [False, True]:
    print("因果掩码" + ("开" if causal else "关") + "：")
    print(attention(X, causal)[0].round(3))

# 2. 改最后一个词，前面的输出会不会跟着变
X2 = X.copy(); X2[3] = X[2]                                 # 把“AI”换成“学”的向量
for causal in [False, True]:
    changed = np.abs(attention(X, causal)[1][:3] - attention(X2, causal)[1][:3]).max()
    print("掩码" + ("开" if causal else "关") + f"：改了第 4 个词，前 3 个词的输出最多变了 {changed:.4f}")

# 3. 生成时的一步：新词的 q 去看缓存好的 K、V，结果和整句一起算的最后一行完全一样
Q, K, V = X @ Wq, X @ Wk, X @ Wv
K_cache, V_cache = K[:3], V[:3]                              # 前 3 个词早就算好、存起来了
q_new, k_new, v_new = Q[3], K[3], V[3]                      # 新来的第 4 个词只算自己的 q、k、v
K_all, V_all = np.vstack([K_cache, k_new]), np.vstack([V_cache, v_new])
a = softmax(q_new @ K_all.T / 2)                             # 1×4：新词对 4 个词的权重，不需要掩码
print("一步解码：", a.round(3), (a @ V_all).round(3))
print("和整句算的最后一行一致：", np.allclose(a @ V_all, attention(X, True)[1][3]))

# 4. Llama-3-8B 的 KV Cache：每个 token 每层存 8 个 KV 头的 k 和 v（每头 128 维，BF16）
per_token = 2 * 32 * 8 * 128 * 2
print(f"每个 token {per_token // 1024} KiB；8192 个 token {per_token * 8192 / 2**30:.0f} GiB")
```

## 到了大模型里

**KV Cache 有多大？**Llama-3-8B 有 32 层，每层有 8 个 KV 头（第 39 讲的 GQA，比 32 个查询头少），每个头 128 维，k 和 v 各一份，用 BF16 存：每个 token 要 2 × 32 × 8 × 128 × 2 字节 = 128 KiB。一个请求有 8192 个 token，就是 1 GiB；同时服务 50 个这样的请求，光 KV Cache 就要 50 GiB，比模型权重本身（16 GB）还大得多。第三章里大量的工作，都是在想办法管好这块显存：第 61 讲讲 KV Cache 本身，第 63 讲算显存账，第 67 讲的 PagedAttention 解决它的碎片问题。

**prefill 和 decode 的注意力长得不一样。**处理提示时（prefill），整段提示一起算，用的是 s × s 的打分矩阵加因果掩码，和训练时一样；之后每生成一个词（decode），用的是 1 × s 的一行，不需要掩码，但要把整个缓存读一遍。两者的计算特点截然不同，推理引擎常常为它们准备不同的注意力算子（第 60 讲）。

## 容易混淆的地方

1. **“因果”和因果关系无关。**这里的“因果”只是说“前面可以影响后面，后面不能影响前面”，像时间的方向一样。有的资料也叫它“自回归掩码”或“未来掩码”（look-ahead mask）。
2. **不是所有 Transformer 都用因果掩码。**BERT 这类用来理解文本（而不是生成文本）的模型，每个词可以看整句话，没有因果掩码，叫双向注意力。它们也就不能像 GPT 那样一个词一个词地生成。
3. **因果掩码和填充掩码是两回事。**把长短不同的句子凑成一批时，短的句子后面会补上无意义的填充 token，要用另一个掩码（padding mask）把它们遮住，防止真实的词去看它们。推理引擎里两种掩码常常同时存在。

## 回顾

生成时后面的词还不存在，所以训练时也不能让模型看到后面的词，否则它会学会“偷看答案”。因果掩码在 softmax 之前把每个词对后面的词的分数设成 −∞，权重就成了 0，注意力矩阵只剩下三角。有了它，训练可以一次前向就做完一段文本里所有位置的预测；而且第 i 个词的输出只依赖前 i 个词，后面接再多词也不会变，于是每一层每个词的 k、v 都可以缓存起来，这就是 KV Cache。Llama-3-8B 每个 token 的 KV Cache 是 128 KiB，长序列、多请求时，它往往比模型权重还占显存。

复读模型有两个头，第 1 个头“回头看 3 格”，那第 2 个头在干什么？为什么要把注意力拆成好几个头，而不是用一个大的头？下一讲：**多头注意力**。
