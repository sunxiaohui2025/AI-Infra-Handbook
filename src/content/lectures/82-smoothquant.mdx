上一讲的 GPTQ、AWQ 只量化权重，矩阵乘法仍然用 BF16 来算。它们让 decode 读权重更快，却没有让**计算**更快。prefill、大批量的 decode 是计算受限的（第 60、62 讲），要加速它们，得让矩阵乘法本身用更低的精度来算：INT8 的 Tensor Core 算力是 BF16 的两倍。这就要求**权重和激活都量化**，叫 W8A8。

权重是固定的，可以离线慢慢量化；激活是每次推理时才算出来的，而且大模型的激活里有一类非常棘手的东西：**离群通道**。这一讲讲为什么它让激活量化变得困难，以及 SmoothQuant 怎么用一个简单的等价变换绕过它。

## 激活里的离群通道

2022 年的 LLM.int8() 论文发现：模型规模超过六七十亿参数以后，Transformer 每一层的输入激活里，会出现少数几个**固定的通道**，数值比其他通道大几十倍甚至上百倍。而且它们几乎在每个 token 上都出现，就是那几个通道。权重里则没有这么极端的情况。

我们造一个类似的例子：一层的输入 X 有 256 个 token、64 个通道，其中 3 个通道是离群通道。普通通道的最大值约 3.0，离群通道的最大值约 178。

## 为什么不能逐通道量化激活

第 80 讲说过，对付离群值的办法是缩小共用 scale 的范围。对激活来说，最自然的是每个**通道**一个 scale，把离群通道单独处理。可惜，这在矩阵乘法里行不通。

看 Y = X · W 的一个元素：Y_ik = Σⱼ X_ij · W_jk。量化后，X_ij ≈ a · qx_ij，W_jk ≈ b · qw_jk，我们希望用整数做乘加，最后再乘一次 scale：

<div class="ai-formula">Y_ik ≈ a · b · Σⱼ qx_ij · qw_jk</div>

这要求 a、b 在求和的过程中**不随 j 变化**，才能提到求和号外面。所以：

- 激活的 scale 可以随 **i**（token）变：**每个 token 一个 scale**；
- 权重的 scale 可以随 **k**（输出通道）变：**每个输出通道一个 scale**。

而“激活每个通道一个 scale”，scale 随 j 变，提不出去，整数矩阵乘法就没法用了。

于是只能每个 token 一个 scale。可每个 token 里都有那几个离群通道，scale 由它们决定（一个 token 里离群通道的值常有几十上百，scale 就是它除以 127），普通通道的值只在 ±3 以内，只能落在少数几个格点上。代码里，直接 W8A8 的激活整体误差只有 1.52%（被离群通道的大数撑着），**普通通道的激活误差却高达 17.40%**，输出误差 1.70%。在真实模型里，这会让效果明显下降。

LLM.int8() 的做法是把离群通道拆出来，用 FP16 单独算，其余的用 INT8 算。效果很好，但一个矩阵乘法拆成两个、精度又不同，速度反而可能变慢。

## SmoothQuant：把难度迁移给权重

**SmoothQuant**（2022 年）注意到：激活难量化，是因为它的通道之间差别太大；权重好量化，因为它的通道之间差别不大。能不能把激活的“难”匀一部分给权重？

用的还是上一讲 AWQ 那个等价变换：

<div class="ai-formula">X · W = (X / s) · (s · W)，　第 j 个通道：激活除以 sⱼ，权重的第 j 行乘以 sⱼ</div>

离群通道的 sⱼ 取得大，激活这一列就被压小了；对应的权重行被放大。SmoothQuant 给出的取法是

<div class="ai-formula">sⱼ = max|Xⱼ|^α ÷ max|Wⱼ|^(1−α)</div>

α 叫**迁移强度**。α = 0 时几乎不动激活；α = 1 时激活每个通道的最大值都被压成 1，所有的不均匀都转移到了权重上；α = 0.5 时，平滑后激活和权重第 j 个通道的最大值相等，都是 √(max|Xⱼ| · max|Wⱼ|)，两边一样“难”。

代码扫了几个 α，看平滑后激活和权重的“最大值 ÷ 中位数”（越接近 1，通道之间越均匀，越好量化）和 W8A8 的输出误差：

- **α = 0**：激活 59.8、权重 1.0，输出误差 1.75%。激活太难。
- **α = 0.5**：激活 7.7、权重 7.7，输出误差 **0.50%**。两边一样难，误差最小。
- **α = 1**：激活 1.0、权重 59.8，输出误差 1.88%。权重太难。

SmoothQuant 的论文里，大部分模型取 α = 0.5 左右效果最好。

下面的演示画出了平滑前后每个通道的最大值（对数坐标）。从 α = 0 拖到 1，看离群通道的高度怎么从激活那边“搬”到权重那边。

<SmoothView caption="图 82-1　SmoothQuant 的平滑缩放。α = 0 时激活的两个离群通道（琥珀色）比别的高几十倍；α 增大，它们被压低，权重对应的两行被抬高；α 在 0.5 附近时两边都不极端，INT8 的输出误差最小。" />

和 AWQ 一样，激活除以 s 不用真的在推理时做：s 在离线时用校准数据算好，合并进前一层（比如前面 RMSNorm 的权重），权重乘以 s 也离线做完。推理时没有任何额外开销，矩阵乘法照常用 INT8。

<Note kind="point">激活里有少数固定的离群通道，而整数矩阵乘法只允许激活每个 token 一个 scale，离群通道就把普通通道的精度挤没了。SmoothQuant 用 X·W = (X/s)·(s·W) 的等价变换，sⱼ = max|Xⱼ|^α ÷ max|Wⱼ|^(1−α)，把激活的不均匀按比例迁移给权重，α 取 0.5 左右时两边都好量化。s 合并进前一层，推理时没有开销。</Note>

## 静态还是动态

激活的 scale 什么时候算？有两种做法：

- **静态**：用校准数据提前算好每层激活的 scale，推理时直接用。最快，但遇到和校准数据差别大的输入，可能截断。
- **动态**：推理时对每个 token 现算 scale（求这一行的最大绝对值）。多一点计算，但更稳。现在的实现多用每个 token 动态的 scale，开销可以融合进前一个 kernel（第 74 讲）。

## 到了大模型里

**FP8 替代了大部分 INT8 的场景。**在 H100 这一代 GPU 上，FP8 的 Tensor Core 算力和 INT8 一样，而浮点格式天生更能容忍数值范围大的分布（下一讲）。所以今天的 W8A8 部署，大多用的是 FP8，而不是 INT8。但离群通道的问题并没有消失，FP8 只是更耐得住一些；到了 4 比特，它又成了大问题。

**更激进的办法：旋转。**要把激活也量化到 4 比特（W4A4），平滑往往不够。一类方法（比如 QuaRot、SpinQuant）在激活和权重之间插入一个**正交矩阵**（比如 Hadamard 矩阵）：X · W = (X · R) · (Rᵀ · W)。正交矩阵把每个离群通道的“能量”均匀地摊到所有通道上，离群值就消失了。它和平滑一样是等价变换，大部分旋转也可以合并进相邻的权重里。

**KV Cache 也是激活。**注意力里的 K、V 也是推理时算出来的激活，也有离群通道的问题，第 84 讲会专门讲。

## 用代码复现

下面的代码构造了一个有 3 个离群通道的激活，先看直接 W8A8 的误差（激活每个 token 一个 scale，权重每个输出通道一个 scale），再扫描 SmoothQuant 的 α，最后对照“激活逐通道量化”这种硬件做不了的方式。

```python
import numpy as np
rng = np.random.default_rng(0)

# 一层的输入 X（256 个 token × 64 个通道），其中 3 个通道是离群通道，数值大 50 倍；权重 W 没有离群值
d = 64
X = rng.standard_normal((256, d)); X[:, [5, 30, 47]] *= 50
W = rng.standard_normal((d, d)) * 0.05

def q8(A, axis):
    """INT8 对称量化，沿 axis 求最大值：axis=1 → 每行（每个 token）一个 scale；axis=0 → 每列一个 scale"""
    s = np.abs(A).max(axis, keepdims=True) / 127
    return np.round(A / s) * s

def rel(a, b): return np.linalg.norm(a - b) / np.linalg.norm(a)
Y = X @ W
print(f"每个通道的最大 |x|：普通通道约 {np.abs(np.delete(X, [5, 30, 47], 1)).max(0).mean():.1f}，离群通道约 {np.abs(X[:, [5, 30, 47]]).max(0).mean():.1f}")

# W8A8：激活每个 token 一个 scale，权重每个输出通道一个 scale——两者都能在矩阵乘法之后再乘回去
Xq, Wq = q8(X, 1), q8(W, 0)
print(f"直接 W8A8：激活误差 {rel(X, Xq):.2%}，普通通道的激活误差 {rel(np.delete(X, [5, 30, 47], 1), np.delete(Xq, [5, 30, 47], 1)):.2%}，输出误差 {rel(Y, Xq @ Wq):.2%}")

# SmoothQuant：s_j = max|X_j|^α / max|W_j|^(1−α)，X' = X / s，W' = s · W，X'W' = XW
for a in [0.0, 0.25, 0.5, 0.75, 1.0]:
    s = np.abs(X).max(0) ** a / np.abs(W).max(1) ** (1 - a)
    Xs, Ws = X / s, W * s[:, None]
    print(f"α = {a:.2f}：激活最大值 / 中位数 = {np.abs(Xs).max() / np.median(np.abs(Xs).max(0)):5.1f}，"
          f"权重最大值 / 中位数 = {np.abs(Ws).max() / np.median(np.abs(Ws).max(1)):5.1f}，输出误差 {rel(Y, q8(Xs, 1) @ q8(Ws, 0)):.2%}")

# 对照：激活每个“通道”一个 scale。这个 scale 落在求和的维度上，没法在矩阵乘法之后再乘回去
print(f"对照：激活逐通道量化（硬件做不了）输出误差 {rel(Y, q8(X, 0) @ Wq):.2%}")
```

输出：

```text
每个通道的最大 |x|：普通通道约 3.0，离群通道约 178.1
直接 W8A8：激活误差 1.52%，普通通道的激活误差 17.40%，输出误差 1.70%
α = 0.00：激活最大值 / 中位数 =  59.8，权重最大值 / 中位数 =   1.0，输出误差 1.75%
α = 0.25：激活最大值 / 中位数 =  21.5，权重最大值 / 中位数 =   2.8，输出误差 0.71%
α = 0.50：激活最大值 / 中位数 =   7.7，权重最大值 / 中位数 =   7.7，输出误差 0.50%
α = 0.75：激活最大值 / 中位数 =   2.8，权重最大值 / 中位数 =  21.5，输出误差 0.76%
α = 1.00：激活最大值 / 中位数 =   1.0，权重最大值 / 中位数 =  59.8，输出误差 1.88%
对照：激活逐通道量化（硬件做不了）输出误差 0.99%
```

第一行是离群的程度：普通通道最大约 3.0，离群通道约 178.1。第二行是直接 W8A8：普通通道的激活误差 17.40%。中间五行是不同 α 的结果，α = 0.5 时激活和权重的“最大值 ÷ 中位数”都是 7.7，输出误差最小（0.50%）。最后一行是逐通道量化激活的对照：误差 0.99%，还不如平滑后的 W8A8，而且硬件做不了。

## 容易混淆的地方

1. **SmoothQuant 不改变模型的数学。**平滑前后 X·W 完全相等，变的只是“哪一边更难量化”。
2. **它和 AWQ 用的是同一个变换，目的不同。**AWQ 只量化权重，放大重要的行是为了让这些行的相对误差变小；SmoothQuant 两边都量化，是为了在激活和权重之间平衡难度。
3. **激活的离群通道不是噪声。**它们对模型的输出很重要（去掉它们，模型效果会大幅下降），所以不能简单地截断，只能想办法“安置”它们。

## 回顾

要让矩阵乘法本身用低精度计算，激活也必须量化。大模型的激活里有少数固定的离群通道，比普通通道大几十上百倍；而整数矩阵乘法只允许激活每个 token 一个 scale、权重每个输出通道一个 scale，离群通道就让普通通道只剩几个格点，例子里普通通道的激活误差达到 17.40%。SmoothQuant 用 X·W = (X/s)·(s·W)，取 sⱼ = max|Xⱼ|^α ÷ max|Wⱼ|^(1−α)，把激活的不均匀迁移一部分给权重；α = 0.5 时两边一样均匀，W8A8 的输出误差从 1.70% 降到 0.50%。s 合并进前一层，推理没有额外开销。

INT8 是整数，格点均匀分布。还有一类低精度格式是浮点数：同样 8 比特，格点在 0 附近密、远处疏，更适合神经网络里大小悬殊的数值。H100 支持 FP8，新一代的 GPU 还支持 FP4。它们是怎么表示数的，用起来要注意什么？下一讲：**FP8 与 FP4**。
