上一讲算出，一台 8 卡的 H100 服务器里，卡与卡之间每卡有约 450 GB/s 的 NVLink；出了这台机器，每卡只剩 50 GB/s 的网络。差了 9 倍。

这个落差把集群分成了两层，业界分别叫作 **scale-up** 和 **scale-out**。这一讲讲清楚这两个概念，以及为什么近几年各家都在努力把 scale-up 的范围做大，做成所谓的**超节点**。

## 两种扩展

**scale-up（纵向扩展）**：在一个紧密耦合的范围里加更多的卡，卡与卡之间用 NVLink 这类专用的高速互联直接相连。特点是：

- 带宽高：H100 每卡单向约 450 GB/s，B200 约 900 GB/s。
- 延迟低，而且支持**内存语义**：一张卡可以像访问自己的显存一样，直接读写另一张卡的显存（load/store），不需要打包成消息再发送。
- 规模有限：传统上一台服务器里 8 张卡。

**scale-out（横向扩展）**：把很多台机器用网络连起来（InfiniBand、RoCE，第 56 讲）。特点是：

- 规模几乎不限：几千、几万张卡都可以。
- 带宽低一个数量级（每卡约 50 GB/s），延迟也更高。
- 通信是**消息语义**：数据打包成消息，经网卡、交换机发出去（RDMA 让这个过程很高效，但仍然是另一种方式）。

一个大模型集群两者都有：每台机器内部是一个 scale-up 域，机器之间是 scale-out 网络。

## 为什么 scale-up 的范围有限

既然 NVLink 这么好，为什么不把所有卡都用它连起来？主要有几个限制：

- **距离。**高速的铜缆信号只能传一两米。8 张卡放在一个机箱里没问题，放满一整个机柜就需要专门设计的背板和线缆，再远就得用光纤，成本和功耗都上去了。
- **交换芯片的端口数。**每张卡要连到交换芯片上，交换芯片的端口数（以及每个端口的带宽）限制了一个域里能放多少张卡。
- **功耗和散热。**几十张高功耗的 GPU 挤在一个机柜里，要几十到上百千瓦的供电，需要液冷。

## 超节点：把 scale-up 域做大

**超节点**就是把 scale-up 域从 8 张卡扩大到几十、几百张。公开的例子：

- **NVIDIA GB200 NVL72**：一个机柜里 72 张 Blackwell GPU，通过机柜内的 NVLink 交换托盘和铜缆背板全部互连，每张卡双向 1.8 TB/s（单向约 900 GB/s），任意两张卡之间都是满带宽。
- **华为 CloudMatrix 384**：384 张昇腾 910C 通过统一的高速互联网络（用了大量光模块）组成一个超节点。

它们的思路一样：让一大批卡都处在高带宽、低延迟、可直接读写对方内存的范围里。

## 同一次通信，两种组织方式

用第 91 讲的 α-β 模型比较一下。同样 64 张卡：

- **A：8 台 8 卡服务器**。机内 NVLink 每卡 450 GB/s，机间每卡 50 GB/s。
- **B：64 张卡在一个 NVLink 域里**，每卡 900 GB/s。

**All-Reduce 1 GB**：A 可以分层做（第 90 讲）：先在机内 Reduce-Scatter，把数据缩成 1/8；机间网络只对这 1/8 做 All-Reduce；最后机内 All-Gather。约 **8.39 ms**（机内 3.93 + 机间 4.46）。B 在一个域里直接做，约 **2.26 ms**。快了 3.7 倍。

**All-to-All 每卡 1 GB**：每张卡要给其余 63 张卡各发一份不同的数据。在 A 里，其中 56 张卡在别的机器上，56/63 的数据都要挤过 50 GB/s 的网卡，约 **17.79 ms**；B 约 **1.12 ms**，快了 16 倍。

差别来自通信的模式：All-Reduce 可以先在机内“缩小”数据，机间只传一部分；All-to-All 的每份数据都不一样，没法缩小，只能全部走慢路。

还可以看**对分带宽**：把 64 张卡切成两半，两半之间最多能传多快。A 是 32 张网卡 × 50 GB/s = **1.6 TB/s**；B 是 32 张卡 × 900 GB/s = **28.8 TB/s**，差了 18 倍。

## 对推理意味着什么

第四章会反复用到这一讲的结论：

- 张量并行每层都要同步，必须放在 scale-up 域内（第 93、97 讲）。域大了，TP 可以超过 8，更大的稠密模型也能只用 TP（第 103 讲）。
- MoE 的专家并行靠 All-to-All，是 scale-out 网络最怕的负载；超节点让一整组专家并行都走高速链路（第 99、103 讲）。
- PD 分离的 KV 传输、KV Cache 的池化，在一个大的高带宽域里都更容易（第 100、101 讲）。

超节点也有代价：成本、功耗、故障的影响范围、软件的适配。第 103 讲会从推理负载的角度具体比较。

## 到了大模型里

**两张网并存。**即使在超节点里，scale-out 网络也不会消失：超节点之间、超节点和存储之间，仍然要靠以太网或 InfiniBand。设计集群时要同时规划两层：scale-up 域多大、scale-out 网络多宽。

**scale-up 的技术在多元化。**除了 NVLink，业界也在推动开放的 scale-up 互联标准（比如 UALink），以及用以太网做 scale-up 的方案。它们的目标一样：让更多加速器在一个高带宽、低延迟的域里协作。

**本站只用公开资料。**各家超节点的具体参数（拓扑、带宽、延迟）以官方发布的资料为准，本站的数字只用于说明量级和比较思路。

## 用代码复现

下面的代码按 α-β 模型，比较 64 张卡在“8 台 × 8 卡”和“一个 64 卡域”两种组织方式下，All-Reduce（16 MB、1 GB）和 All-to-All（每卡 16 MB、1 GB）的耗时，以及两者的对分带宽。

```python
# 同样 64 张卡，两种组织方式（带宽取公开规格的量级，α 是示意值）：
#   A：8 台 8 卡服务器。机内 NVLink 每卡单向 450 GB/s；机间每卡一张网卡 50 GB/s（按轨道连接，8 条轨道并行）
#   B：64 张卡都在一个 NVLink 域里（超节点），每卡单向 900 GB/s
A_NV, A_NET = 3e-6, 6e-6

def allreduce_A(m):                                      # 分层：机内 Reduce-Scatter → 机间对 1/8 做 Ring All-Reduce → 机内 All-Gather
    intra = 2 * (7 * A_NV + 7 / 8 * m / 450e9)
    inter = 2 * 7 * (A_NET + (m / 8) / 8 / 50e9)
    return intra + inter, intra, inter

def allreduce_B(m):                                      # 域内：Ring 和 Tree（第 90 讲）取快的
    return min(2 * 63 * (A_NV + m / 64 / 900e9), 2 * 6 * A_NV + 2 * m / 900e9)

def alltoall_A(m):                                       # 每张卡给其余 63 张各发 m/63；其中 56 张在别的机器上，走网卡
    return max(7 / 63 * m / 450e9, 56 / 63 * m / 50e9) + 2 * A_NET

def alltoall_B(m):
    return 63 / 63 * m / 900e9 + 2 * A_NV

for m in [16e6, 1e9]:
    t, intra, inter = allreduce_A(m)
    print(f"All-Reduce {m / 1e6:5.0f} MB：A（8 台 × 8 卡）{t * 1e3:6.2f} ms（机内 {intra * 1e3:.2f} + 机间 {inter * 1e3:.2f}）；B（64 卡一个域）{allreduce_B(m) * 1e3:6.2f} ms")
for m in [16e6, 1e9]:
    print(f"All-to-All 每卡发 {m / 1e6:5.0f} MB：A {alltoall_A(m) * 1e3:6.2f} ms；B {alltoall_B(m) * 1e3:6.2f} ms，快 {alltoall_A(m) / alltoall_B(m):.0f} 倍")

# 整体带宽：把 64 张卡切成两半，两半之间最多能传多快（对分带宽）
print(f"对分带宽：A 是两半之间 32 张网卡 × 50 GB/s = {32 * 50 / 1000:.1f} TB/s；B 是 32 张卡 × 900 GB/s = {32 * 900 / 1000:.1f} TB/s")
```

输出：

```text
All-Reduce    16 MB：A（8 台 × 8 卡）  0.26 ms（机内 0.10 + 机间 0.15）；B（64 卡一个域）  0.07 ms
All-Reduce  1000 MB：A（8 台 × 8 卡）  8.39 ms（机内 3.93 + 机间 4.46）；B（64 卡一个域）  2.26 ms
All-to-All 每卡发    16 MB：A   0.30 ms；B   0.02 ms，快 12 倍
All-to-All 每卡发  1000 MB：A  17.79 ms；B   1.12 ms，快 16 倍
对分带宽：A 是两半之间 32 张网卡 × 50 GB/s = 1.6 TB/s；B 是 32 张卡 × 900 GB/s = 28.8 TB/s
```

前两行是 All-Reduce：A 的机内、机间两部分加起来，大消息时比 B 慢 3.7 倍。中间两行是 All-to-All：B 快 12 到 16 倍。最后一行是对分带宽：1.6 对 28.8 TB/s。

## 容易混淆的地方

1. **超节点不是更快的单卡。**它改变的是卡与卡之间的连接；单卡就能做完的工作，不会因为超节点变快。
2. **“一个机柜”不等于“一个 scale-up 域”。**普通的机柜里可以放好几台 8 卡服务器，它们之间仍然走网络；只有用 NVLink 一类的互联连在一起，才是一个 scale-up 域。
3. **scale-up 和 scale-out 的界线在移动。**以前 scale-up 就是一台服务器；现在可以是一个机柜，未来可能是多个机柜。判断时看的是连接方式和带宽，而不是物理边界。

## 回顾

集群里有两层连接：scale-up 用 NVLink 一类的专用互联，带宽高（H100 每卡单向 450 GB/s）、延迟低、能直接读写对方显存，但传统上只有 8 张卡；scale-out 用网络，规模不限，每卡约 50 GB/s。超节点把 scale-up 域扩大到几十上百张卡，比如 GB200 NVL72（72 张卡、每卡单向约 900 GB/s）和 CloudMatrix 384。同样 64 张卡，All-Reduce 1 GB 从 8.39 ms 降到 2.26 ms，All-to-All 每卡 1 GB 从 17.79 ms 降到 1.12 ms，对分带宽从 1.6 TB/s 到 28.8 TB/s。能分层的通信受益有限，All-to-All 受益最大。
