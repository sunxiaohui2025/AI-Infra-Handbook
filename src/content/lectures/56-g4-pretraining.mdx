这一讲让它学。要做的事第 2 篇都讲过：定义一个衡量“猜得多准”的数，叫 loss（第 16 讲）；用反向传播算出每个参数该往哪个方向改（第 18 讲）；用优化器沿着这个方向走一小步（第 19 讲）；一个 batch 接一个 batch 地重复（第 20 讲）。区别只在规模：这次是 530 万个参数、30 万个 token，在 GPU 上跑 3000 步。

## loss：正确答案拿到了多少概率

模型在每个位置输出 4096 个打分，softmax 之后是一个概率分布。这个位置的正确答案是 y[t]，模型给它的概率是 p。交叉熵 loss 就是 −ln p（第 16 讲）：

- 模型把握十足，p = 0.9，loss = 0.105；
- 模型完全没把握，在 4096 个 token 里平均地猜，p = 1/4096，loss = ln 4096 = 8.318；
- 模型猜错了方向，p = 0.0001，loss = 9.21。

一个 batch 是 16 × 256 = 4096 个位置，每个位置一个 loss，取平均，就是这一步的 loss。它的指数 e^loss 叫困惑度（perplexity）：loss = 8.318 时困惑度是 4096，意思是“模型的犹豫程度相当于在 4096 个选项里瞎猜”；loss 降到 3，困惑度是 20，相当于在 20 个选项里挑。

所以，**没训练过的模型，loss 应该在 8.3 附近**。如果一开始就远大于它，说明初始化有问题，某些 token 的打分被放得特别大；如果远小于它，多半是数据泄漏了答案（比如掩码写反，模型看得到下一个 token）。这是训练开始时第一个要看的数。

## 两条线为什么分开

第 900 步之前，两条线一起往下走：模型学到的东西（常用词、句式、哪些词常连在一起）在验证集上一样有用。第 900 步之后，训练 loss 继续下降，从 3.06 一路降到 1.0；验证 loss 却从 4.84 回升到 5.86。

这叫**过拟合**：模型开始背训练集了。训练 loss 1.0 意味着困惑度不到 3，模型几乎能逐字复述训练集里的句子；可验证集是它没见过的讲义，背下来的东西用不上，反而让它对没见过的句子更自信地猜错。验证集是语料的最后 10%，从第 126 讲的中间开始，到第 133 讲为止，正好是读 nano-vllm、vLLM、SGLang 源码的那几讲，话题和训练集也不完全一样，这让两条线的差距又大了一些。

为什么会这样？算一笔账。Chinchilla 论文给出的经验比例是：计算最优的训练，每个参数大约配 20 个 token（Scaling Laws 见第 46 讲）：

```python
N = 5_319_168          # 参数量
D = 302_475            # 训练集 token 数
print(f"计算最优需要约 {20 * N / 1e6:.0f} M 个 token，我们只有 {D / 1e6:.2f} M，差 {20 * N / D:.0f} 倍")
seen = 3000 * 16 * 256
print(f"3000 步一共看了 {seen / 1e6:.1f} M 个 token，相当于把训练集过了 {seen / D:.0f} 遍")
print(f"验证 loss 最低的第 900 步：看了 {900 * 16 * 256 / 1e6:.2f} M 个 token，约 {900 * 16 * 256 / D:.0f} 遍")
```

```text
计算最优需要约 106 M 个 token，我们只有 0.30 M，差 352 倍
3000 步一共看了 12.3 M 个 token，相当于把训练集过了 41 遍
验证 loss 最低的第 900 步：看了 3.69 M 个 token，约 12 遍
```

数据少了三百多倍。大模型预训练通常每个 token 只看一两遍，同一段话看第十几遍时，模型能学到的“规律”早就学完了，剩下的只有“这一段具体写了什么”。

让结论翻转的条件也就清楚了：**要么数据多，要么模型小。**语料扩大几百倍（比如把整个中文维基百科加进来），验证 loss 会和训练 loss 一起降下去很久；或者把模型缩小，它背不下那么多东西，过拟合就来得晚、来得轻。dropout、权重衰减这类正则化也能推迟过拟合，但它们只是让模型“背得慢一点”，不能凭空变出数据。下一讲会把 dropout 加大到 0.2 再跑一次，看看能推迟多少。

## 模型说话的样子

每 1000 步的样例，都是从“KV Cache”开始贪心生成 30 个 token：

- **第 1000 步**：“KV Cache Cache 的空间，decode 时吞吐和 TPOT 几乎不变。prefill 和 decode 每步只量化权重……”
- **第 2000 步**：“KV Cache 也被别人的池子里的池子。KV Cache 是计算受限的，是‘我’……”
- **第 3000 步**：“KV Cache。为什么今天的主权重 下面的代码完整行 前两篇到这里，进入不依赖的 KV Cache 默认的 KV……”

第 1000 步的句子读起来已经很像讲义了：有术语（decode、吞吐、TPOT、prefill），有标点，句子结构完整，只是内容经不起推敲。第 2000、3000 步反而更怪：这时模型已经在背训练集，它把几段不相干的原文片段拼在了一起，到第 3000 步连句子都不成形了。验证 loss 最低的时候，生成的句子往往也最“通顺”，这不是巧合。

<Note kind="point">语言模型预训练就是在每个位置上做“下一个 token 是哪个”的分类题，loss 是正确答案概率的负对数，起点约为 ln V。数据远少于参数量的 20 倍时，训练 loss 会一直降，验证 loss 先降后升：模型从学规律变成了背原文。</Note>

## 算力用了多少

最后从 Infra 的角度看一眼这次训练。第 35、46 讲说过，训练一个 token 大约要 6N 次浮点运算（前向 2N，反向 4N），N 是参数量：

```python
N, tokens, seconds = 5_319_168, 3000 * 16 * 256, 569
flops = 6 * N * tokens
print(f"6N × token 数 = {flops:.2e} 次浮点运算")
print(f"用了约 {seconds} s，平均 {flops / seconds / 1e12:.2f} TFLOPS")
print(f"M2 的 10 核 GPU 标称 FP32 约 3.6 TFLOPS，利用率约 {flops / seconds / 3.6e12:.0%}")
```

```text
6N × token 数 = 3.92e+14 次浮点运算
用了约 569 s，平均 0.69 TFLOPS
M2 的 10 核 GPU 标称 FP32 约 3.6 TFLOPS，利用率约 19%
```

不到五分之一。原因有好几个：6N 没有算注意力打分本身的运算（T = 256 时约占一成）；每 100 步要停下来估 40 个 batch 的 loss；矩阵太小（256 × 1024 这种尺寸，GPU 的计算单元喂不饱，第 62 讲的 Roofline）；还有 Python 和 PyTorch 每次调用的开销。大模型训练的利用率（MFU）通常在 40%–60%，靠的是大矩阵、算子融合和更少的调度开销，这些正是第三、四章讲的东西。

第二条检查是调试训练代码最有用的一招：**拿一个 batch 反复训练，看 loss 能不能降到接近 0**。一个正常的模型一定能背下一个 batch；如果连这都做不到，问题一定出在代码里（梯度没清零、学习率没生效、目标错位），而不是数据或超参数。

## 容易写错的地方

- **忘了 `zero_grad`。**梯度一步步累加，相当于学习率越来越大，loss 先降后炸。
- **估 loss 时忘了 `eval()`。**dropout 还开着，估出来的 loss 偏高，而且每次不一样，训练、验证两条线的比较也失去意义。
- **验证集混进了训练集。**最常见的形式是先打乱再切分。验证 loss 会和训练 loss 一起降，看不出过拟合。

## 回顾

g4 加了 `train.py`：`loss_batch` 把 [B, T, V] 摊平后算交叉熵；`estimate_loss` 在 eval 模式下取 20 个 batch 的平均；学习率预热 100 步再余弦下降；AdamW 加权重衰减；梯度裁剪到 1。3000 步约 10 分钟，训练 loss 从 8.45 降到 1.0，验证 loss 在第 900 步达到最低 4.84，之后回升到 5.86。数据只有计算最优的三百五十分之一，模型在训练集上过了 41 遍，后面三分之二的训练是在背原文。

问题来了：我们最后存下的是第 3000 步的模型，验证 loss 5.86，而第 900 步那个更好的模型已经找不回来了。训练应该在什么时候存档？另外，到现在为止生成都是贪心的，同一个开头永远是同一句话。下一讲：**g5 · 解码与存档**。
