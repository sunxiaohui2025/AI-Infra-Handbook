上一讲算出，H100 的 Tensor Core 每秒能做约 989 万亿次运算。可运算需要数据：矩阵乘法的每一次乘加，都要有两个数送到 Tensor Core 面前。这些数平时存在哪里？送过来要多久？

答案是：GPU 里有好几层存储，**离计算单元越近的越快，也越小**。大模型的权重有几十 GB，只能放在最外层的显存里；可显存相对于算力来说太慢了。这一讲把这几层存储的容量、带宽排出来，算一笔账：从显存每读一个字节，计算单元要等多久？这笔账是第 54 讲 Roofline 模型的基础，也贯穿了整个第三章。

## 从近到远

以 H100 为例，从计算单元往外数（数字是公开规格或常见测量的量级）：

**寄存器。**每个 SM 256 KB，全卡约 35 MB。每个线程的局部变量、矩阵乘法的累加结果放在这里。访问几乎没有延迟（约 1 个周期）。

**L1 缓存 / 共享内存。**每个 SM 256 KB 的 SRAM（静态随机存储器，做在芯片上），全卡也约 35 MB。其中最多 228 KB 可以由程序员当作“共享内存”直接管理（第 77 讲）。每个 SM 每周期能读写 128 字节，全卡合计约 **31 TB/s**。访问延迟约几十个周期。

**L2 缓存。**全卡共享，约 **50 MB**，也是芯片上的 SRAM。带宽约 **5.5 TB/s**（测量值的量级），延迟两三百个周期。从显存读来的数据先经过这里，被多个 SM 重复读时可以直接命中。

**HBM 显存。**高带宽内存（High Bandwidth Memory）：几个 DRAM 芯片垂直堆叠成一摞，放在 GPU 芯片旁边，通过很宽的接口相连。H100 有 **80 GB**，带宽 **3.35 TB/s**，访问延迟几百个周期。模型的权重、KV Cache、每层的激活都在这里。

**CPU 内存。**再往外，GPU 要经过 PCIe 访问 CPU 的内存：容量可以有 1 到 2 TB，可带宽只有约 64 GB/s（PCIe 5.0 x16，标称），比 HBM 慢了 50 倍。

一句话：**片上的 SRAM 快，但全卡只有几十 MB；HBM 有 80 GB，却慢了一个数量级。**

## 读 1 字节，能算多少次

现在把算力和带宽放在一起。H100 的 Tensor Core 每秒 989 万亿次运算，HBM 每秒 3.35 万亿字节。两者相除：

<div class="ai-formula">989 TFLOPS ÷ 3.35 TB/s ≈ 295 次运算 / 字节</div>

意思是：**从显存每读 1 个字节的时间里，Tensor Core 能做约 295 次运算。**如果一个运算对读进来的每个字节只做不到 295 次运算，计算单元就会有一部分时间在等数据；只做 1 次，就有 99% 以上的时间在等。

同样的比例：从 L2 每读 1 字节能做约 180 次，从共享内存约 32 次。层级越近，这个比例越小，也就越容易“喂饱”计算单元。

## 两个例子

**矩阵乘法。**一个 n × n 的 BF16 矩阵乘法 C = A · B，做 2n³ 次运算，至少要从显存读 A、B，写 C，共 3n² 个数、6n² 字节。每字节的运算次数是 2n³ ÷ 6n² = n/3：

- n = 256：约 85 次/字节，低于 295，**喂不饱** Tensor Core，会卡在显存带宽上。
- n = 4096：约 1365 次/字节，远高于 295，**喂得饱**。

所以大矩阵乘法能接近峰值算力，小矩阵乘法不能。注意这里说的是“至少”：实际实现中，A、B 的每个数要被用 n 次，如果每次都从显存重新读，读写量会大得多。这正是第 77 讲用共享内存分块的原因：把一小块数据搬进片上，在那里被反复使用。

**逐元素运算。**每个 BF16 数读一次、写一次（4 字节），只做 1 次运算，每字节 0.25 次，比 295 小了一千多倍。读写一个 1 GB 的张量要 0.60 ms，运算本身只要 0.5 μs。这类运算的时间几乎全是搬数据，所以第 74 讲要把它们融合起来，少读写几遍。

<Note kind="point">GPU 的存储分好几层：寄存器和共享内存（片上 SRAM）最快，全卡只有几十 MB；L2 约 50 MB；HBM 显存 80 GB，带宽 3.35 TB/s，比片上慢一个数量级。H100 从 HBM 每读 1 字节的时间里能做约 295 次运算，所以一个运算要对每个读进来的字节做足够多的运算（让数据在片上被反复使用），才不会让计算单元空等。</Note>

## 为什么不把显存都做成 SRAM

既然 SRAM 这么快，为什么不多做一些？因为它**贵**：一个 SRAM 存储单元要 6 个晶体管，占的芯片面积是 DRAM 单元的好几倍。H100 的芯片面积有 800 多平方毫米，几十 MB 的片上存储已经占了相当一部分。要把 80 GB 都做成 SRAM，需要几千个这样大的芯片。

所以 GPU 的设计一直在平衡：在芯片上放多少 SRAM、多少计算单元，外面接多少 HBM、多快。每一代 GPU 的算力增长都比显存带宽快，“每读 1 字节能做的运算次数”越来越大，访存问题也越来越突出：A100 约 150 多，H100 约 295，B200 的 BF16 约 280，FP8 时还要翻倍（第 55 讲）。

## 到了大模型里

**decode 卡在 HBM 带宽上。**第 60 讲会算出，decode 每一步要把 16 GB 的权重从 HBM 读一遍，却只对每个字节做约 1 次运算，远低于 295。所以 decode 的速度几乎完全由显存带宽决定。

**片上存储是优化的主战场。**算子融合（第 74 讲）、FlashAttention（第 75 讲）、分块矩阵乘法（第 77 讲），做的都是同一件事：让数据留在片上，少碰 HBM。

**新的显存技术。**H200 把显存换成了 HBM3e，容量 141 GB、带宽 4.8 TB/s；B200 是 192 GB、约 8 TB/s。显存的容量和带宽，往往比算力更直接地决定推理的速度和成本。

## 用代码复现

下面的代码列出 H100 各层存储的容量、带宽、延迟（量级），算出从每层读 1 GB 要多久、每读 1 字节 Tensor Core 能做多少次运算；然后看两个矩阵乘法和逐元素运算的“每字节运算次数”。

```python
# H100 SXM 的存储层级（容量、带宽取公开规格或常见测量的量级；片上带宽 = SM 数 × 每周期字节 × 频率）
SM, CLK, PEAK = 132, 1.83e9, 989e12
LEVELS = [
    # 名字，容量（字节），带宽（字节/秒），访问延迟（示意，GPU 周期）
    ("寄存器", SM * 256 * 1024, None, 1),
    ("L1 / 共享内存", SM * 256 * 1024, SM * 128 * CLK, 30),
    ("L2 缓存", 50e6, 5.5e12, 250),
    ("HBM 显存", 80e9, 3.35e12, 500),
    ("CPU 内存（经 PCIe）", 2e12, 64e9, None),
]
print("层级 | 容量 | 带宽 | 延迟 | 读 1 GB | 每读 1 字节，Tensor Core 能做几次运算")
for name, cap, bw, lat in LEVELS:
    cap_s = f"{cap / 1e6:.0f} MB" if cap < 1e9 else f"{cap / 1e9:.0f} GB"
    bw_s = f"{bw / 1e12:.2f} TB/s" if bw else "—"
    t = f"{1e9 / bw * 1e3:.2f} ms" if bw else "—"
    ratio = f"{PEAK / bw:.0f}" if bw else "—"
    print(f"{name} | {cap_s} | {bw_s} | {f'约 {lat} 周期' if lat else '微秒级'} | {t} | {ratio}")

# 复用：一个 n×n 的 BF16 矩阵乘法 C = A·B，A、B 至少要从显存读一遍
for n in [256, 4096]:
    flops, bytes_ = 2 * n**3, 3 * n * n * 2               # 读 A、B，写 C，各 n² 个 BF16
    print(f"{n}×{n} 矩阵乘法：{flops / 1e9:.2f} GFLOP，至少读写 {bytes_ / 1e6:.1f} MB，"
          f"每字节 {flops / bytes_:.0f} 次运算 → {'能' if flops / bytes_ > PEAK / 3.35e12 else '不能'}喂饱 Tensor Core（需要 {PEAK / 3.35e12:.0f}）")
# 逐元素运算（比如每个数乘一个常数）：每个 BF16 数读一次、写一次（共 4 字节），只做 1 次运算
print(f"逐元素运算：每 4 字节 1 次运算，每字节 0.25 次；读写 1 GB 的张量要 {2e9 / 3.35e12 * 1e3:.2f} ms，算只要 {0.5e9 / PEAK * 1e6:.1f} μs")
```

输出：

```text
层级 | 容量 | 带宽 | 延迟 | 读 1 GB | 每读 1 字节，Tensor Core 能做几次运算
寄存器 | 35 MB | — | 约 1 周期 | — | —
L1 / 共享内存 | 35 MB | 30.92 TB/s | 约 30 周期 | 0.03 ms | 32
L2 缓存 | 50 MB | 5.50 TB/s | 约 250 周期 | 0.18 ms | 180
HBM 显存 | 80 GB | 3.35 TB/s | 约 500 周期 | 0.30 ms | 295
CPU 内存（经 PCIe） | 2000 GB | 0.06 TB/s | 微秒级 | 15.62 ms | 15453
256×256 矩阵乘法：0.03 GFLOP，至少读写 0.4 MB，每字节 85 次运算 → 不能喂饱 Tensor Core（需要 295）
4096×4096 矩阵乘法：137.44 GFLOP，至少读写 100.7 MB，每字节 1365 次运算 → 能喂饱 Tensor Core（需要 295）
```

表格就是上面的五层存储：HBM 每字节 295 次，L2 180 次，共享内存 32 次。接着两行是矩阵乘法：256 的每字节 85 次，喂不饱；4096 的 1365 次，喂得饱。最后一行是逐元素运算：读写 1 GB 要 0.60 ms，算只要 0.5 μs。

## 容易混淆的地方

1. **“显存”和“内存”。**本站说的显存指 GPU 上的 HBM；内存指 CPU 那边的 DRAM。两者之间要经过 PCIe，慢得多。（有些设备，比如第 59 讲的 DGX Spark，CPU 和 GPU 共享同一块内存，情况不同。）
2. **带宽和延迟是两回事。**带宽是每秒能搬多少字节，延迟是一次访问要等多久。GPU 靠大量线程同时访问来掩盖延迟，所以对大多数大模型的运算，带宽才是关键。
3. **L2 和共享内存的带宽是量级。**它们取决于访问方式，不同的测量结果差别不小；本站只用它们说明数量级的关系，算时间时用的是 HBM 的带宽。

## 回顾

GPU 的存储从近到远：寄存器、L1/共享内存（片上 SRAM，全卡各约 35 MB，共享内存约 31 TB/s）、L2（约 50 MB、约 5.5 TB/s）、HBM 显存（80 GB、3.35 TB/s）、CPU 内存（经 PCIe 约 64 GB/s）。越近越快、越近越小，因为 SRAM 占的面积大、贵。H100 从 HBM 每读 1 字节的时间里能做约 295 次运算：n × n 矩阵乘法每字节约 n/3 次，n = 4096 时喂得饱 Tensor Core，n = 256 时喂不饱；逐元素运算每字节只有 0.25 次，时间全花在搬数据上。

“每字节做多少次运算”这个量，决定了一个运算是卡在算力上还是卡在带宽上。把它画到一张图上，就能一眼看出任何一个运算的速度上限。下一讲：**Roofline 模型**。
