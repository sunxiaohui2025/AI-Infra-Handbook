第 47–49 讲的 SFT、DPO、强化学习，默认都要更新模型的全部参数。第 19 讲算过，用 Adam 和混合精度训练，每个参数要 16 字节：Llama-3-8B 全量微调光是这些就要 128.5 GB，一张 80 GB 的卡放不下。可很多时候，我们只是想让一个通用模型适应某个具体的任务：用公司内部的文档风格写作、按固定的格式抽取信息。为此动用全部 80 亿个参数，太浪费了。

**LoRA**（Low-Rank Adaptation，低秩适配，2021 年提出）是最常用的**参数高效微调**方法：原来的权重一个都不动，只在旁边加上很少的新参数来训练。Llama-3-8B 用 LoRA 微调，可训练的参数可以只有 0.5% 左右。这一讲看它的原理、能省多少，以及它给推理系统带来的一个新机会。

## 冻结 W，只学一个“小修改”

微调本质上是给每个权重矩阵加一个修改量：W 变成 W + ΔW。全量微调直接学 ΔW，它和 W 一样大（比如 4096 × 4096）。

LoRA 的假设是：**微调需要的修改量 ΔW 是“低秩”的**，可以写成两个瘦长矩阵的乘积：

<div class="ai-formula">Δ<i>W</i> = <i>A</i> · <i>B</i>，　<i>A</i>: d<sub>in</sub> × r，　<i>B</i>: r × d<sub>out</sub></div>

r 叫**秩**（rank），远小于 d，常用 8、16、64。第 40 讲的 MLA 用的也是“先压到低维、再展开”的同一个想法。前向计算时，原来的 W 冻结不动，旁边多走一条“小路”：

$$
\mathbf{y} = \mathbf{x}\,W + (\mathbf{x}\,A)\,B
$$

**x** 先乘 A 压到 r 维，再乘 B 展开回 d<sub>out</sub> 维，加到原来的输出上。训练时只更新 A 和 B。B 初始化为全 0，所以一开始这条小路的输出是 0，模型和原来完全一样，微调从原模型平稳地出发。

参数省了多少？W 有 d<sub>in</sub> × d<sub>out</sub> 个参数，A 和 B 合起来只有 r × (d<sub>in</sub> + d<sub>out</sub>) 个。以 4096 × 4096 的 q_proj、r = 16 为例：W 有 1678 万个参数，A、B 只有 13.1 万个，不到 1%。

为什么这样就够了？LoRA 论文的实验发现，微调带来的权重变化确实集中在少数几个方向上：预训练已经学会了绝大部分东西，适应一个新任务只需要在少数几个方向上做调整。

## 能省多少

给 Llama-3-8B 每层的 7 个线性层（q、k、v、o、gate、up、down）都加上 LoRA：

| 秩 r | 可训练参数 | 占全模型 |
| --- | --- | --- |
| 8 | 2100 万 | 0.26% |
| 16 | 4194 万 | 0.52% |
| 64 | 1.68 亿 | 2.09% |

显存的账更直观。全量微调要 128.5 GB（还不含激活值）。LoRA 微调时，原模型的权重冻结，只要用 BF16 存一份（16.1 GB），不需要它们的梯度和 Adam 状态；只有那 4194 万个 LoRA 参数需要每个 16 字节，0.67 GB。合起来不到 17 GB，一张消费级的大显存显卡就能放下。

更进一步，**QLoRA** 把冻结的原模型量化成 4 位（第 12 篇），权重只要约 4 GB，LoRA 部分仍用较高的精度训练。这让在单张普通显卡上微调几十亿甚至上百亿参数的模型成为可能。

## 训练完以后：合并，或者不合并

LoRA 训练完，推理时有两种用法。

**合并**：直接算出 W + A·B，替换原来的 W。合并后的模型和原模型结构完全一样，推理没有任何额外开销。下面的代码验证了，“旁路计算”和“合并后计算”的结果完全相同。

**不合并**：原模型保持不动，A 和 B 作为一个很小的“适配器”单独存放。一个 r = 16 的适配器只有几十 MB，而原模型有十几 GB。这带来了一个有用的可能：**一个基座模型，挂很多个适配器**，每个用户、每个任务一个。

## 用代码复现

下面的代码在 TinyLM 的一个 4 × 8 矩阵上演示 LoRA：B 初始为 0 时输出不变；A·B 的秩是 r；旁路计算和合并后计算结果相同。然后算出 Llama-3-8B 在不同秩下的 LoRA 参数，以及三种微调方式的显存。

```python
import json
import numpy as np

t = json.load(open("tinylm.json", encoding="utf-8"))
W = np.array(t["weights"]["layers"][0]["W_1"])          # TinyLM 第 1 层 FFN 的升维矩阵，4×8
X = np.array(t["examples"]["03"]["X"])                   # “我 爱 学 AI”的嵌入，4×4

# 1. LoRA：W 不动，旁边加两个小矩阵 A（4×r）和 B（r×8），更新量是 A·B
r = 1
rng = np.random.default_rng(50)
A = rng.standard_normal((4, r)) * 0.5
B = np.zeros((r, 8))                                     # B 从 0 开始：一开始完全不改变模型
print("初始时输出不变：", np.allclose(X @ W + (X @ A) @ B, X @ W))
B = rng.standard_normal((r, 8)) * 0.5                   # 假设训练之后 B 变成了这样
delta = A @ B
print("参数：W", W.size, "个；A、B 共", A.size + B.size, "个；A·B 的秩：", np.linalg.matrix_rank(delta))

# 2. 两种算法一样：先算 x·A 再乘 B（训练时），或把 A·B 加进 W 再乘（推理时“合并”）
y_side = X @ W + (X @ A) @ B
y_merged = X @ (W + delta)
print("旁路算 = 合并后算：", np.allclose(y_side, y_merged))

# 3. Llama-3-8B：每层 7 个线性层都加 LoRA，r = 16
shapes = {"q": (4096, 4096), "k": (4096, 1024), "v": (4096, 1024), "o": (4096, 4096),
          "gate": (4096, 14336), "up": (4096, 14336), "down": (14336, 4096)}
N = 8_030_261_248
for r in [8, 16, 64]:
    lora = 32 * sum(r * (a + b) for a, b in shapes.values())
    print(f"r = {r:2d}：LoRA 参数 {lora / 1e6:6.1f}M，占全模型 {lora / N:.2%}")

# 4. 显存：全量微调（每参数 16 字节，第 19 讲） vs LoRA（权重冻结用 BF16，只有 LoRA 参数要梯度和 Adam）
lora = 32 * sum(16 * (a + b) for a, b in shapes.values())
print(f"全量微调：{N * 16 / 1e9:.1f} GB；LoRA：冻结权重 {N * 2 / 1e9:.1f} GB + LoRA {lora * 16 / 1e9:.2f} GB；"
      f"QLoRA（权重 4 位）：{N * 0.5 / 1e9:.1f} GB + {lora * 16 / 1e9:.2f} GB（都不含激活值）")
```

输出：

```text
初始时输出不变： True
参数：W 32 个；A、B 共 12 个；A·B 的秩： 1
旁路算 = 合并后算： True
r =  8：LoRA 参数   21.0M，占全模型 0.26%
r = 16：LoRA 参数   41.9M，占全模型 0.52%
r = 64：LoRA 参数  167.8M，占全模型 2.09%
全量微调：128.5 GB；LoRA：冻结权重 16.1 GB + LoRA 0.67 GB；QLoRA（权重 4 位）：4.0 GB + 0.67 GB（都不含激活值）
```

## 到了大模型里

**多 LoRA 服务。**如果一家公司有 100 个客户，每个都微调了自己的模型，全量微调就要部署 100 份 16 GB 的模型；用 LoRA，只需要部署一份基座模型，再加 100 个几十 MB 的适配器。推理时，同一批请求可能属于不同的适配器：基座模型的大矩阵乘法所有请求一起算，各自的 (xA)B 小路分别算。S-LoRA、Punica 等工作专门设计了这种“一批里混着多个 LoRA”的高效算子，vLLM 等推理引擎也支持同时加载多个 LoRA 适配器。

**小路的计算很便宜，但不是免费。**不合并时，每个线性层多了两次小矩阵乘法。r 很小，计算量可以忽略，但多一次读写和算子调用，对延迟有一点影响。只服务一个适配器时，通常直接合并。

**LoRA 不只用于微调对话。**它也广泛用于图像生成模型等其他领域，是今天最普遍的定制大模型的方式。

## 容易混淆的地方

1. **LoRA 不改变推理的计算量（合并后）。**它省的是训练时的显存和存储，合并后的模型和原模型一样大、一样快。
2. **秩不是越大越好。**r 越大，能表达的修改越丰富，但参数和显存也越多，在小数据上还更容易过拟合。很多任务用 r = 8 或 16 就够了。
3. **LoRA 学不进大量新知识。**和 SFT 一样（第 47 讲），它擅长调整模型的行为和格式；要灌入大量新知识，低秩的修改往往不够。

## 回顾

全量微调要为每个参数存梯度和优化器状态，Llama-3-8B 需要 128.5 GB。LoRA 冻结原权重，在旁边训练两个瘦长矩阵 A（d<sub>in</sub> × r）和 B（r × d<sub>out</sub>），用它们的乘积作为修改量；B 初始化为 0，从原模型平稳出发。r = 16 时，Llama-3-8B 的可训练参数只占 0.52%，微调显存降到约 17 GB；QLoRA 把原模型量化到 4 位，进一步降到约 5 GB。训练完可以把 A·B 合并进 W，推理零开销；也可以不合并，一个基座模型挂很多个适配器，同时服务不同的任务。
