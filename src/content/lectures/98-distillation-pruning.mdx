量化让每个参数占的比特变少，投机解码让每一步多出几个 token，它们都不改变模型有多少个参数。另一条路是直接得到一个**更小的模型**：参数少了，显存、计算、带宽全都跟着省。

从头训练一个小模型当然可以，但效果往往不如同样大小、却“向大模型学过”的模型。这一讲讲两种办法：**蒸馏**（distillation），让小模型学习大模型的输出；**剪枝**（pruning），把大模型里不重要的部分剪掉。实际中它们经常一起用：先剪，再蒸馏，把剪掉造成的损失补回来。

## 蒸馏：学老师的“分寸”

第 16 讲的交叉熵损失，训练时只告诉模型“正确答案是哪个”。比如“一只可爱的___”，标准答案是“猫”，模型只知道“猫”对、其他都错。

一个训练好的大模型（**老师**）给出的却是一个分布。代码里的示意：老师觉得“猫”0.744、“狗”0.166、“老虎”0.082，“汽车”“桌子”“苹果”都只有千分之几。这个分布里藏着标准答案没有的信息：狗和老虎也说得通，汽车完全不行。Hinton 等人在 2015 年把这叫作“暗知识”（dark knowledge）。**蒸馏**就是让小模型（**学生**）去拟合老师的整个分布，而不只是那一个标准答案。

为了让这些小概率的信息更明显，蒸馏时常把老师和学生的 logits 都除以一个**温度** T（第 73 讲）再做 softmax。T = 4 时，老师的分布变成“猫”0.336、“狗”0.231、“老虎”0.194，“汽车”等也有 0.08 左右，各个词之间的相对关系一目了然。损失是两个分布之间的 KL 散度 KL(p老师 ‖ p学生)。

两种训练信号的差别，看梯度最清楚。学生现在的打分把“老虎”排得比“狗”高：

- **只用标准答案**：梯度是 p − y = [−0.526, 0.064, 0.288, 0.106, 0.039, 0.029]。它只说“提高猫，压低其他所有词”，“狗”和“汽车”一起被压低。
- **蒸馏**（T = 4）：梯度是 (p学生 − p老师) ÷ T = [−0.024, −0.022, 0.004, 0.02, 0.012, 0.01]。它说“提高猫，**也提高狗**；稍微压低老虎；压低汽车、桌子、苹果”。

每个样本都带着这么丰富的信号，学生用更少的数据就能学得更好。

**大模型的蒸馏有两种做法。**一种是上面这样按 token 拟合老师的分布（logit 蒸馏），要求学生和老师用同一个词表，训练时还要跑老师的前向。另一种更简单：让老师生成大量的回答，学生直接在这些回答上做 SFT（第 47 讲），叫**数据蒸馏**。DeepSeek 用 R1 生成的约 80 万条数据，微调出了一系列 Qwen 和 Llama 的小模型，让它们也学会了长思维链（第 49 讲）。Meta 的 Llama 3.2 的 1B、3B 模型，在预训练时也用到了更大的 Llama 3.1 模型的输出。

## 剪枝：哪些权重可以不要

**剪枝**是把一部分权重设成 0，或者整块地去掉。核心问题是：剪哪些？

最朴素的想法是剪掉**绝对值最小**的权重。可第 91 讲说过，权重的重要性还取决于它乘的激活：激活大的输入通道，对应的权重哪怕很小，也可能对输出影响很大。2023 年的 **Wanda** 方法就用 |w| × ‖xⱼ‖（权重大小乘以对应输入通道激活的大小）作为重要性，只需要一小批校准数据，不用再训练。

代码比较了一个 64 × 64 的层，校准激活里有 4 个离群通道，每种方法都剪掉一半权重：

- **按 |w| 剪**：输出误差 27.12%。离群通道那几行的权重和别的行差不多大，被剪掉了不少。
- **按 |w|·‖x‖ 剪（Wanda）**：10.72%。离群通道的权重被保住了。

## 剪了能变快吗：稀疏的结构

把一半权重设成 0，模型就快一倍吗？不一定。这取决于 0 的分布方式：

- **非结构化**：0 零散地分布在矩阵里。矩阵的形状没变，普通的 GPU 矩阵乘法照样要把这些 0 读进来、乘一遍，几乎不会变快。除非稀疏到 90% 以上，用专门的稀疏格式和 kernel 才有收益。
- **半结构化 2:4**：沿输入方向，每 4 个连续的权重里恰好保留 2 个。这种规则的稀疏，NVIDIA 从 Ampere（A100）开始有专门的**稀疏 Tensor Core** 支持，只存非零值和它们的位置，理论上矩阵乘法快一倍、权重小将近一半。代价是约束更强，误差 13.92%，比非结构化大一些。
- **结构化**：整行、整列、整个注意力头，甚至整层地去掉。矩阵直接变小，任何硬件都能变快、变省。但一次去掉的东西多，误差也最大：去掉一半输入通道，误差 23.43%。通常要配合再训练（最好是蒸馏）来恢复。

## 先剪，再蒸馏

把两者结合起来，就是一条得到小模型的实用路线：

1. 从一个大模型出发，用校准数据估计每个注意力头、每个 FFN 神经元、每一层的重要性；
2. 按重要性做结构化剪枝，比如把 FFN 的宽度砍掉一部分，或者去掉若干层，得到一个更小的模型；
3. 用原来的大模型当老师，对剪完的模型做蒸馏，只用很少的数据（远少于从头训练）就能恢复大部分效果。

NVIDIA 的 Minitron 系列就是这样做的，比如从 Llama 3.1 8B 剪枝、蒸馏得到 4B 的模型。它比从头训练同样大小的模型省下了大量训练算力。

## 到了大模型里

**蒸馏是小模型的标配。**今天很多小尺寸的开源模型，都在训练中用到了同家族大模型的输出，或者大模型生成的数据。对推理来说，这意味着在同样的延迟和成本下，能用上一个更聪明的小模型。

**剪枝在推理部署中用得不如量化多。**非结构化剪枝难以加速；2:4 稀疏的实际加速通常不到理论的两倍，效果损失也比同等压缩的量化更明显；结构化剪枝需要再训练，更像是“训练一个新模型”。所以部署现成的模型时，量化（第 90–94 讲）是首选；剪枝和蒸馏更多地用在**模型厂商制作小模型**的环节。

**和 MoE 的关系。**MoE（第 41 讲）每个 token 只激活一部分专家，可以看作一种“动态的结构化稀疏”。也有工作对 MoE 剪掉不常用的专家，或者把专家合并，以降低显存。

## 用代码复现

下面的代码先用示意的老师和学生打分，对比只用标准答案和蒸馏时的梯度；再在一个有离群通道的线性层上，比较几种剪掉一半权重的方式的输出误差。

```python
import numpy as np

# 1. 蒸馏：老师的输出分布里，除了“正确答案”，还有“哪些词也说得通”的信息
words = ["猫", "狗", "老虎", "汽车", "桌子", "苹果"]
t_logits = np.array([6.0, 4.5, 3.8, 0.5, 0.2, 0.1])    # 老师看到“一只可爱的___”时的打分（示意）
def softmax(z, T=1.0): e = np.exp((z - z.max()) / T); return e / e.sum()
for T in [1, 4]:
    print(f"温度 T = {T}：老师的分布 " + "  ".join(f"{w} {p:.3f}" for w, p in zip(words, softmax(t_logits, T))))
s_logits = np.array([3.0, 1.0, 2.5, 1.5, 0.5, 0.2])    # 学生现在的打分
T = 4
pt, ps = softmax(t_logits, T), softmax(s_logits, T)
print(f"只用标准答案“猫”训练：损失 {-np.log(softmax(s_logits)[0]):.3f}，梯度（p − y）= {np.round(softmax(s_logits) - np.eye(6)[0], 3).tolist()}")
print(f"蒸馏（T = 4）：KL(老师 ‖ 学生) = {np.sum(pt * np.log(pt / ps)):.3f}，梯度（p学生 − p老师）/ T = {np.round((ps - pt) / T, 3).tolist()}")

# 2. 剪枝：一个线性层（64 → 64），校准激活里有 4 个离群通道。剪掉一半的权重，看输出误差
rng = np.random.default_rng(0)
d = 64
X = rng.standard_normal((256, d)); X[:, [3, 17, 40, 58]] *= 10
W = rng.standard_normal((d, d)) * 0.05                   # y = X · W，W 的第 j 行对应第 j 个输入通道
err = lambda Wp: np.linalg.norm(X @ W - X @ Wp) / np.linalg.norm(X @ W)

def prune_by(score, keep_mask_fn):
    return W * keep_mask_fn(score)
def unstructured(score, ratio=0.5):                      # 全局（每一列内）去掉分数最小的一半
    thr = np.quantile(score, ratio, axis=0, keepdims=True); return score > thr
def two_four(score):                                     # 2:4：沿输入方向每 4 个里保留分数最大的 2 个
    s = score.reshape(d // 4, 4, d); r = s.argsort(1).argsort(1)
    return (r >= 2).reshape(d, d)

mag = np.abs(W)                                          # 只看权重大小
wanda = np.abs(W) * np.linalg.norm(X, axis=0)[:, None]   # Wanda：权重大小 × 这个输入通道激活的大小
print(f"非结构化 50%，按 |w|：输出误差 {err(prune_by(mag, unstructured)):.2%}")
print(f"非结构化 50%，按 |w|·‖x‖（Wanda）：输出误差 {err(prune_by(wanda, unstructured)):.2%}")
print(f"2:4 半结构化，按 |w|·‖x‖：输出误差 {err(prune_by(wanda, two_four)):.2%}")
ch = np.argsort(np.linalg.norm(X, axis=0) * np.linalg.norm(W, axis=1))[: d // 2]   # 结构化：整行（整个输入通道）去掉
Wc = W.copy(); Wc[ch] = 0
print(f"结构化，去掉一半输入通道：输出误差 {err(Wc):.2%}（矩阵直接变成 32 × 64）")
```

输出：

```text
温度 T = 1：老师的分布 猫 0.744  狗 0.166  老虎 0.082  汽车 0.003  桌子 0.002  苹果 0.002
温度 T = 4：老师的分布 猫 0.336  狗 0.231  老虎 0.194  汽车 0.085  桌子 0.079  苹果 0.077
只用标准答案“猫”训练：损失 0.746，梯度（p − y）= [-0.526, 0.064, 0.288, 0.106, 0.039, 0.029]
蒸馏（T = 4）：KL(老师 ‖ 学生) = 0.082，梯度（p学生 − p老师）/ T = [-0.024, -0.022, 0.004, 0.02, 0.012, 0.01]
非结构化 50%，按 |w|：输出误差 27.12%
非结构化 50%，按 |w|·‖x‖（Wanda）：输出误差 10.72%
2:4 半结构化，按 |w|·‖x‖：输出误差 13.92%
结构化，去掉一半输入通道：输出误差 23.43%（矩阵直接变成 32 × 64）
```

前两行是老师在 T = 1 和 T = 4 时的分布，温度高时小概率词的信息更明显。接着两行是梯度：只用标准答案时“狗”被压低（+0.064），蒸馏时“狗”被提高（−0.022）。最后四行是剪枝：按 |w| 27.12%，Wanda 10.72%，2:4 13.92%，结构化 23.43%。

## 容易混淆的地方

1. **蒸馏不是压缩一个已有的模型。**它训练的是另一个（通常从别处初始化的）小模型，只是用大模型当老师。剪枝才是在原模型上动刀。
2. **稀疏不等于快。**零散的 0 在普通的矩阵乘法里照样要算；只有硬件支持的稀疏格式（2:4）或者真正变小的矩阵（结构化）才能加速。
3. **剪枝后的误差可以靠训练补回来。**Wanda 这类方法追求“不再训练就能用”；结构化剪枝则默认要再训练，单看剪完那一刻的误差并不公平。

## 回顾

蒸馏让学生拟合老师的整个输出分布（常除以温度 T），学到“哪些答案也说得通”：只用标准答案时“狗”和“汽车”一起被压低，蒸馏时“狗”被提高、“汽车”被压低。大模型多用数据蒸馏，让老师生成训练数据。剪枝去掉不重要的权重，重要性要结合激活：剪掉一半时，按 |w| 输出误差 27.12%，按 |w|·‖x‖ 10.72%。非结构化稀疏难以加速，2:4 半结构化有稀疏 Tensor Core 支持，结构化剪枝让矩阵真正变小，通常再用蒸馏恢复效果。部署现成模型首选量化，剪枝和蒸馏更多用在制作小模型上。
