第 3 讲算完 TinyLM 的 4 × 4 矩阵乘法，数了一下：64 次乘加。这个“数一数要算多少次”的习惯，是整个 AI Infra 的起点。一个模型生成一个词要算多少次？训练一个模型要算多少次？一张 GPU 每秒能算多少次？有了这几个数，就能估出时间、估出要几张卡、估出要花多少钱。

这一讲讲怎么数：计算量的单位 FLOPs，矩阵乘法的 2mnk 公式，以及把它推广到整个模型的 2N 和 6N。

## FLOPs 和 FLOPS

**FLOP**（floating-point operation）是一次浮点运算：一次加法或一次乘法。一个任务要做多少次浮点运算，叫它的**计算量**，单位写作 **FLOPs**（复数，注意小写 s）。

硬件每秒能做多少次浮点运算，叫**算力**，单位写作 **FLOPS**（FLOP per second，大写 S）。常用的量级：

- GFLOP：10⁹（十亿）；TFLOP：10¹²（万亿）；PFLOP：10¹⁵。
- H100 的 BF16 算力约 989 TFLOPS（第 52 讲），即每秒 989 万亿次。

两者相除就是理想情况下的时间：

<div class="ai-formula">时间 ≈ 计算量（FLOPs）÷ 算力（FLOPS）</div>

“理想”是因为硬件很少能满负荷工作，第 54 讲会讲为什么、能达到多少。

## 矩阵乘法：2mnk

第 3 讲说过，[m, k] @ [k, n] 的结果有 m × n 格，每一格是一个 k 维点积：k 次乘法，再把 k 个乘积加起来。

代码老老实实地数了一遍 TinyLM 的 [4, 4] @ [4, 4]：乘法 64 次，加法 48 次（每格 k 个乘积只需要加 k − 1 次），合计 112 次。

实际估算时，通常把**一次乘法加一次加法（一次乘加）算 2 次运算**，于是

<div class="ai-formula">[m, k] @ [k, n] 的计算量 ≈ 2 · m · n · k FLOPs</div>

TinyLM 这一例是 2 × 4 × 4 × 4 = **128**。和精确的 112 有一点差别，那是因为每格少了一次加法；k 很大时（真实模型里是几千），这点差别可以忽略。而且硬件做乘加时通常就是“乘完加到累加器上”，累加器从 0 开始，确实是 k 次加法。

第 13 讲的线性层 [4, 4] @ [4, 8]，按 2mnk 是 256 次，再加上偏置的 4 × 8 = 32 次加法。偏置、激活函数这类逐元素运算，计算量和矩阵乘法相比小得多，估算时常常忽略。

## 推广到整个模型：2N

大模型的计算几乎全是矩阵乘法：一个 token 的向量 [1, d] 乘以一个 [d, d<sub>out</sub>] 的权重矩阵，就是 2 × d × d<sub>out</sub> 次运算。而 d × d<sub>out</sub> 正好是这个权重矩阵的参数个数。所以：

<div class="ai-formula">一个 token 经过一个权重矩阵 ≈ 2 × 这个矩阵的参数量</div>

把模型里所有的权重矩阵加起来：**一个 token 前向走一遍，约 2N 次运算**，N 是参数量（嵌入表除外，查表不是乘法）。

Llama-3-8B 有 80.3 亿参数，去掉 5.3 亿的嵌入表，是 75.0 亿，所以每个 token 约 **15.0 GFLOP**。第 35 讲会按层、按矩阵细算一遍，结果一致。

这里还没算注意力里 q 和 k、权重和 v 的乘法：它们和前面的 token 数（上下文）成正比，每个 token 约 4 × 层数 × d × 上下文。上下文 2048 时，每个 token 多 1.07 GFLOP，占 7%。上下文越长，这部分越大（第 42、44 讲）。

## 从计算量到时间

有了计算量，就能估时间。H100 按 989 TFLOPS：

- **处理一段 1000 个 token 的提示**：15.0 TFLOP，满算力约 **15.2 ms**。
- **生成 1 个 token**：15.0 GFLOP，满算力只要 **15.2 μs**。

可实际上，生成一个 token 在 H100 上要好几毫秒，比这个估算慢几百倍。原因不在计算，而在“把 16 GB 的权重从显存读一遍”（第 53、60 讲）。计算量只是故事的一半，另一半是数据搬运。

## 训练：6N

训练时每个 token 不只要前向，还要反向传播（第 18 讲）算梯度。反向的计算量约是前向的 2 倍：对每个权重矩阵，既要算对输入的梯度，又要算对权重的梯度，各相当于一次前向的矩阵乘法。所以训练每个 token 约 **6N**。

训练整个模型的计算量 ≈ 6 × N × 训练的 token 数。Llama 3 的 8B 模型用了约 15 万亿个 token 预训练：6 × 8.03 × 10⁹ × 15 × 10¹² ≈ **7.2 × 10²³** FLOP。如果用 1000 张 H100、实际只用到 40% 的算力，大约要 **21 天**。这个 6NT 公式是第 46 讲 Scaling Laws 估算训练成本的基础。

## 到了大模型里

**估算的套路。**看到一个模型，先数参数量 N：推理每个 token 约 2N，训练约 6N。再除以硬件的算力和利用率，就得到时间的量级。这个粗算在本站后面会用无数次。

**稀疏的模型要看激活参数。**MoE 模型（第 41 讲）每个 token 只用到一部分专家。DeepSeek-V3 总共 6710 亿参数，每个 token 只激活约 370 亿，计算量按 370 亿算。

**计算量不等于时间。**同样的 FLOPs，矩阵大的跑得快，矩阵小、数据搬运多的跑得慢。第 54 讲的 Roofline 会把“算多少”和“搬多少”放在一起考虑。

## 用代码复现

下面的代码逐次数出两个小矩阵乘法的乘法和加法次数，和 2mnk 对比；算 Llama-3-8B 每个 token 的计算量和注意力的额外部分；换算成 H100 上的理想时间；最后估算训练 8B 模型的总计算量和天数。

```python
# 1. 数一数：矩阵乘法 [m, k] @ [k, n] 到底做了多少次乘法、多少次加法
def count(m, k, n):
    mul = add = 0
    for i in range(m):
        for j in range(n):
            acc = None
            for t in range(k):
                mul += 1                                 # 一次乘法
                if acc is None: acc = 1
                else: add += 1                           # 累加：k 个乘积要加 k − 1 次
    return mul, add
mul, add = count(4, 4, 4)
print(f"TinyLM 的 [4, 4] @ [4, 4]：乘法 {mul} 次，加法 {add} 次，合计 {mul + add}；按 2mnk 估算 {2 * 4 * 4 * 4}")
mul, add = count(4, 4, 8)
print(f"第 13 讲的线性层 [4, 4] @ [4, 8]：{mul + add} 次，2mnk = {2 * 4 * 4 * 8}；再加偏置 4 × 8 = 32 次")

# 2. Llama-3-8B：每个 token 过一遍模型，约 2 × 参数量 次运算（不算嵌入表，查表不算乘法）
N, N_emb, L, d = 8.03e9, 128256 * 4096, 32, 4096
per_tok = 2 * (N - N_emb)
print(f"Llama-3-8B：参数 {N / 1e9:.2f}B，去掉嵌入表 {(N - N_emb) / 1e9:.2f}B → 每个 token 约 {per_tok / 1e9:.1f} GFLOP")
ctx = 2048
attn = 4 * L * d * ctx                                   # 注意力：和前面 ctx 个 token 算打分、加权求和
print(f"上下文 {ctx} 时，注意力每个 token 再加 {attn / 1e9:.2f} GFLOP（占 {attn / (per_tok + attn):.0%}）")

# 3. 换算成时间：FLOPs（运算次数）÷ FLOPS（每秒运算次数）
F = 989e12                                               # H100 的 BF16 稠密算力
print(f"prefill 1000 个 token：{1000 * per_tok / 1e12:.1f} TFLOP → H100 满算力 {1000 * per_tok / F * 1e3:.1f} ms")
print(f"生成 1 个 token：{per_tok / 1e9:.1f} GFLOP → 满算力只要 {per_tok / F * 1e6:.1f} μs（实际慢得多，第 60 讲会讲原因）")

# 4. 训练：每个 token 约 6N（前向 2N + 反向 4N）
T = 15e12                                                # Llama 3 的预训练用了约 15 万亿个 token
train = 6 * N * T
print(f"训练 8B 模型、{T / 1e12:.0f}T token：6NT = {train:.1e} FLOP；1000 张 H100、按 40% 利用率约 {train / (1000 * F * 0.4) / 86400:.0f} 天")
```

输出：

```text
TinyLM 的 [4, 4] @ [4, 4]：乘法 64 次，加法 48 次，合计 112；按 2mnk 估算 128
第 13 讲的线性层 [4, 4] @ [4, 8]：224 次，2mnk = 256；再加偏置 4 × 8 = 32 次
Llama-3-8B：参数 8.03B，去掉嵌入表 7.50B → 每个 token 约 15.0 GFLOP
上下文 2048 时，注意力每个 token 再加 1.07 GFLOP（占 7%）
prefill 1000 个 token：15.0 TFLOP → H100 满算力 15.2 ms
生成 1 个 token：15.0 GFLOP → 满算力只要 15.2 μs（实际慢得多，第 60 讲会讲原因）
训练 8B 模型、15T token：6NT = 7.2e+23 FLOP；1000 张 H100、按 40% 利用率约 21 天
```

前两行是逐次数出来的结果和 2mnk 的对比（112 对 128，224 对 256）。接着是 Llama-3-8B 每个 token 15.0 GFLOP，注意力在上下文 2048 时再加 1.07 GFLOP。然后是时间：prefill 1000 个 token 15.2 ms，生成 1 个 token 15.2 μs。最后是训练：7.2 × 10²³ FLOP，约 21 天。

## 容易混淆的地方

1. **FLOPs 和 FLOPS。**前者是计算量（多少次），后者是算力（每秒多少次）。有的资料写作 FLOP 和 FLOP/s 以示区分。
2. **一次乘加算 1 次还是 2 次。**有的规格表和论文按乘加（MAC）计数，数字是按 FLOPs 计的一半。比较时要看清楚。本站一律按 2 次计。
3. **参数量 ≠ 计算量。**参数量是存多少个数，计算量是算多少次。一个 token 的计算量约是参数量的 2 倍；处理 s 个 token，就是 2N × s。

## 回顾

计算量用 FLOPs 计（运算次数），算力用 FLOPS 计（每秒运算次数），两者相除是理想时间。矩阵乘法 [m, k] @ [k, n] 约 2mnk FLOPs：TinyLM 的 4 × 4 例子是 128（逐次数是 112）。一个 token 经过一个权重矩阵约是这个矩阵参数量的 2 倍，所以整个模型前向约 2N 每 token：Llama-3-8B 约 15.0 GFLOP，注意力在上下文 2048 时再加 7%。训练每 token 约 6N，训练 8B 模型、15 万亿 token 约 7.2 × 10²³ FLOP。按 H100 的算力，生成一个 token 只要 15 微秒，实际却慢得多，因为还要搬数据。
