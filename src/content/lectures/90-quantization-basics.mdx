第 11 篇的结论可以归成一句话：推理快不快，往往取决于从显存里读了多少字节。decode 的每一步要把 16 GB 的权重读一遍（第 68 讲），一张 80 GB 的卡装下权重之后，剩下的才能放 KV Cache（第 71 讲）。

既然字节数这么关键，一个很自然的想法是：**让每个数少占几个比特**。权重现在用 BF16 存，每个数 16 比特；如果每个数只用 8 比特、甚至 4 比特，权重就小了一半、四分之三，读得也快了一倍、几倍。这就是**量化**（quantization）。第 12 篇讲模型压缩，这一讲先从最基本的问题开始：怎么用 4 个比特表示 2.31 这样一个数？

## 把实数放到格点上

4 个比特只能表示 16 个不同的值。有符号的 4 位整数（INT4）能表示 −8 到 7；为了正负对称，通常只用 −7 到 7 这 15 个整数。要用它们表示一组实数，就得先把实数按比例“缩放”到这个范围里。

做法分三步：

1. **算 scale**：找出这组数里绝对值最大的那个，让它对应到最大的整数 7。scale = max|x| ÷ 7。
2. **量化**：每个数除以 scale，四舍五入成整数，q = round(x ÷ scale)。存下来的就是这些整数 q，加上一个 scale。
3. **反量化**：要用的时候，乘回去，x̂ = q × scale。

x̂ 和原来的 x 不完全一样，差别就是**量化误差**。因为取整最多差 0.5，所以误差不超过 scale ÷ 2。

一般地，b 比特的对称量化，最大的整数是 2^(b−1) − 1：8 比特是 127，4 比特是 7。

## 算一个例子

取 8 个权重：0.82, −1.47, 0.05, 2.31, −0.66, 1.12, −0.29, 0.94。

**INT8**：最大的绝对值是 2.31，scale = 2.31 ÷ 127 = 0.01819。0.82 ÷ 0.01819 = 45.08，取整得 45；反量化 45 × 0.01819 = 0.8185，误差不到 0.002。8 个数的量化结果是 [45, −81, 3, 127, −36, 62, −16, 52]，最大误差 0.0077，确实不超过 scale ÷ 2 = 0.0091。

**INT4**：scale = 2.31 ÷ 7 = 0.33，q = [2, −4, 0, 7, −2, 3, −1, 3]，平均误差 0.0725。格点稀了 18 倍，误差也大了 20 倍。

位宽再往下，误差急剧变大：INT3 平均误差 0.1362，INT2 只剩 −1、0、1 三个值，8 个数里有 5 个变成了 0，平均误差 0.59，基本不能用了。

**非对称量化。**如果这组数不是围绕 0 对称的（比如都是正数），对称量化会浪费一半的格点。非对称量化把 [最小值, 最大值] 映射到 [0, 2^b − 1]，多存一个**零点** z，表示实数 0 对应哪个整数：scale = (max − min) ÷ (2^b − 1)，q = round(x ÷ scale) + z，反量化 x̂ = (q − z) × scale。上面 8 个数用 INT4 非对称量化，scale = 0.252，z = 6，平均误差 0.064，比对称的 0.0725 小一点，因为 16 个格点都用上了。

## 一个离群值毁掉一组数

scale 由最大的那个数决定，这是量化最大的弱点。把上面的 2.31 换成 12.0（一个**离群值**，outlier），INT4 的 scale 变成 12 ÷ 7 = 1.714，格点间隔 1.7，0.82、−0.66、0.05、−0.29 都被量化成了 0。除了 12 本身，其余 7 个数的平均误差从不到 0.1 变成了 **0.49**。

大模型的权重和激活里恰恰有不少离群值（第 91、92 讲细说）。应对的第一个办法是**缩小共用一个 scale 的范围**：

- **逐张量**（per-tensor）：整个权重矩阵共用一个 scale。最省，但最怕离群值。
- **逐通道**（per-channel）：权重矩阵的每一行（每个输出通道）一个 scale。
- **逐组**（per-group）：每一行再切成若干组，每组比如 128 个数，一个 scale。

上面的例子分成两组、每 4 个一组：离群值所在的组 scale 是 1.714，另一组只有 0.16，另一组的数又能被精细地表示了。其余 7 个数的平均误差从 0.49 降到 **0.17**。

代价是要多存 scale。每 128 个 4 比特的权重配一个 16 比特的 scale，平均每个权重多 16 ÷ 128 = 0.125 比特，实际是 4.125 比特。组越小，精度越好，存 scale 的开销越大，128 是常用的折中。

<Note kind="point">量化用 scale 把一组实数映射到少数几个整数格点上：q = round(x ÷ scale)，用时 x̂ = q × scale，误差不超过 scale ÷ 2。scale 由组里最大的数决定，离群值会让格点变稀、其他数的误差变大，所以要让更少的数共用一个 scale（逐通道、逐组）。</Note>

## 量化换来了什么

对 Llama-3-8B（约 80.3 亿个参数）：

- **BF16**：16.06 GB，decode 一步读一遍约 4.79 ms；
- **INT8**：8.03 GB，约 2.40 ms；
- **INT4**（每组 128 个）：4.14 GB，约 1.24 ms。

INT4 让权重小了将近四分之三。省下的显存可以放更多的 KV Cache、服务更多的请求；读权重的时间也少了将近四分之三，小批量的 decode（卡在读权重上）能快好几倍。一个 70B 的模型，BF16 要 140 GB，两张卡才放得下；INT4 只要 35 GB 左右，一张卡就够了。

## 量化什么，算的时候用什么

量化有两种用法，加速的原理不同：

**只量化权重**（weight-only，比如 W4A16：权重 4 比特，激活 16 比特）。权重以 INT4 存在显存里，kernel 读进片上以后，先反量化成 BF16，再和 BF16 的激活做矩阵乘法。计算还是 BF16 的，但从显存读的字节少了四分之三。decode 是带宽受限的，所以收益明显；prefill 是计算受限的，几乎没有收益，反量化还多了一点计算。第 91 讲的 GPTQ、AWQ 就是这一类。

**权重和激活都量化**（比如 W8A8）。矩阵乘法直接用 INT8 或 FP8 的硬件单元来算，第 63 讲说过，它们的算力是 BF16 的两倍。这样 prefill 这种计算受限的阶段也能加速。难点是激活里的离群值，第 92 讲讲 SmoothQuant 怎么处理它。

另外，量化可以在训练完以后直接做，叫**训练后量化**（PTQ）：拿一小批校准数据，算出 scale，几分钟到几小时就能完成，这是推理里最常用的方式。也可以在训练时就模拟量化误差，让模型适应它，叫**量化感知训练**（QAT），效果更好，但要重新训练。

## 用代码复现

下面的代码实现了对称和非对称量化，用上面 8 个数演示不同位宽的误差、离群值的影响和分组的效果，最后算出 Llama-3-8B 在不同位宽下的大小和读一遍的时间。

```python
import numpy as np

x = np.array([0.82, -1.47, 0.05, 2.31, -0.66, 1.12, -0.29, 0.94])   # 8 个权重（FP32）

def quant_sym(x, bits):
    """对称量化：scale = max|x| / (2^(bits−1) − 1)，q = round(x / scale)，反量化 x̂ = q · scale"""
    qmax = 2 ** (bits - 1) - 1
    scale = np.abs(x).max() / qmax
    q = np.clip(np.round(x / scale), -qmax, qmax).astype(int)
    return q, scale, q * scale

def quant_asym(x, bits):
    """非对称量化：把 [min, max] 映射到 [0, 2^bits − 1]，多一个零点 z"""
    qmax = 2 ** bits - 1
    scale = (x.max() - x.min()) / qmax
    z = int(np.round(-x.min() / scale))
    q = np.clip(np.round(x / scale) + z, 0, qmax).astype(int)
    return q, scale, z, (q - z) * scale

q, s, xh = quant_sym(x, 8)
print(f"INT8 对称：scale = 2.31 / 127 = {s:.5f}")
print("  q  =", q.tolist())
print("  x̂ =", np.round(xh, 4).tolist())
print(f"  最大误差 {np.abs(x - xh).max():.4f}（不超过 scale / 2 = {s / 2:.4f}）")
for bits in [8, 4, 3, 2]:
    q, s, xh = quant_sym(x, bits)
    print(f"INT{bits} 对称：q = {q.tolist()}，平均误差 {np.abs(x - xh).mean():.4f}")
q, s, z, xh = quant_asym(x, 4)
print(f"INT4 非对称：scale = {s:.4f}，零点 z = {z}，q = {q.tolist()}，平均误差 {np.abs(x - xh).mean():.4f}")

# 一个离群值会拉大 scale，让其他数都变粗
y = x.copy(); y[3] = 12.0
q, s, yh = quant_sym(y, 4)
print(f"把 2.31 换成 12.0 后 INT4：scale = {s:.3f}，q = {q.tolist()}，其余 7 个数的平均误差 {np.abs(np.delete(y - yh, 3)).mean():.4f}")

# 分组：每 4 个数一组各算各的 scale
g = y.reshape(2, 4); sc = np.abs(g).max(1, keepdims=True) / 7
gh = np.clip(np.round(g / sc), -7, 7) * sc
print(f"每 4 个一组：两组的 scale = {np.round(sc.ravel(), 3).tolist()}，其余 7 个数的平均误差 {np.abs(np.delete((g - gh).ravel(), 3)).mean():.4f}")

# Llama-3-8B 的权重，不同位宽下的大小（每 128 个权重存一个 FP16 的 scale）和 decode 一步读权重的时间
N = 8.03e9
for name, bits in [("BF16", 16), ("INT8", 8), ("INT4（每组 128 个）", 4 + 16 / 128)]:
    gb = N * bits / 8 / 1e9
    print(f"{name}：{gb:5.2f} GB，读一遍 ≈ {gb / 3.35:.2f} ms")
```

## 容易混淆的地方

1. **量化误差小不等于模型效果好。**每个数的误差只是起点，真正关心的是模型的输出变了多少、在评测上掉了几分。有的权重误差大一点无所谓，有的一点误差就会放大。第 91 讲正是从“哪些误差更重要”出发的。
2. **存成 INT4 不等于用 INT4 计算。**W4A16 存的是 INT4，算的是 BF16；它省的是读取的字节，不是计算。
3. **“4 比特”的实际大小比四分之一多一点。**要算上 scale（和零点）的开销，以及通常不量化的部分（比如嵌入层、输出层、归一化的权重）。

## 回顾

量化用更少的比特表示一个数：选一个 scale 把一组实数缩放到整数范围里，取整存下来，用的时候乘回去。对称量化 scale = max|x| ÷ (2^(b−1) − 1)，误差不超过 scale ÷ 2；非对称量化多一个零点，能用满所有的格点。8 个示例权重用 INT8 量化，最大误差 0.0077；INT4 平均误差 0.0725；INT2 基本不能用。离群值会拉大 scale、毁掉同组的其他数，所以要逐通道、逐组量化，每组 128 个时实际约 4.125 比特。Llama-3-8B 的权重从 BF16 的 16.06 GB 降到 INT4 的 4.14 GB，decode 读一遍从 4.79 ms 降到 1.24 ms。

逐组量化能缓解离群值，但 4 比特的格点终究很粗，直接四舍五入（RTN）在一些模型上会掉不少精度。能不能在取整的时候“聪明”一点，让误差落在不那么重要的地方？下一讲：**权重量化：GPTQ 与 AWQ**。
