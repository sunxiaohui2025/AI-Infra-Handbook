有了反向传播，任何网络的梯度都能算出来了。接下来要决定的是：**拿到梯度之后，参数具体怎么改？**第 17 讲的答案是最简单的一种：沿着梯度的反方向走一步，步长是学习率乘梯度。那一讲的结尾也留下了两个麻烦：在一个“扁”的碗里，它会在陡的方向来回震荡，在平的方向上慢慢挪；实际训练中每步只用一小批数据算梯度，梯度还带着噪声。

决定“拿到梯度后怎么更新参数”的那部分程序，叫**优化器**（optimizer）。这一讲在同一个曲面上比较三种：最朴素的 SGD、带惯性的 Momentum，以及大模型训练几乎都在用的 Adam，看它们各自解决了什么问题，又要付出什么代价。

## 同一组数据，换一个碗

还是第 17 讲那 4 个点，只把 x 整体加 2，变成 (2, 3, 4, 5)，y 不变。最好的直线还是斜率 1.6，只是截距变成了 1.1 − 1.6 × 2 = −2.1。问题本质上一点没变。

可是损失曲面变了很多。把曲面在各个方向上有多“弯”算出来（下面的代码会算）：原来的数据，最陡的方向和最平的方向，弯曲程度相差 14 倍；x 平移 2 以后，相差 166 倍。碗被压成了一条又窄又长的山谷。

这对梯度下降很不友好。第 17 讲说过，学习率的上限由**最弯**的方向决定：原来是 0.238，现在只有 0.069。而在**最平**的方向上，每一步的进展又和那里的坡度成正比，坡度很小，进展就很慢。学习率被陡的方向卡住，又要在平的方向上走很远，结果就是：用 0.03 的学习率走 300 步，损失还停在 0.127，离最低的 0.05 差得很远；就算把学习率开到接近上限的 0.065，也要 228 步。作为对比，原来的数据用 0.1 的学习率只要 39 步。

为什么平移一下 x 就会这样？粗略地说，x 都是正数、而且离 0 比较远时，*w* 和 *b* 的作用纠缠在一起：*w* 增加一点，几乎相当于 *b* 增加 3.5 倍那么多。两个参数“绑”在一起，就形成了一条斜斜的窄谷。真实的网络里，各个参数的尺度、各层输入的分布千差万别，这样的窄谷到处都是。解决的思路有两种：一是把数据“摆正”，让输入居中、尺度统一，这是第 30 讲归一化要做的事；二是换一个更聪明的优化器，这是这一讲的内容。

## SGD：每次只看一小批

先给最朴素的方法正个名。第 17 讲的“沿梯度反方向走一步”，在实际训练中是这样用的：每一步不用全部数据，而是随机抽一小批（一个 **mini-batch**）算梯度，然后更新：

<div class="ai-formula"><b><i>θ</i></b> ← <b><i>θ</i></b> − <i>η</i> · <b><i>g</i></b>，　<b><i>g</i></b> = 这一小批数据上的梯度</div>

这叫**随机梯度下降**（stochastic gradient descent，SGD）。“随机”指的是每步用哪些数据是随机抽的，所以算出来的梯度只是全体数据梯度的一个**估计**，有时偏这边，有时偏那边。平均来看方向是对的，但每一步都带着噪声。

这样做是不得已：大模型的训练数据有上万亿个 token，每走一步都把它们全过一遍是不可能的。好在噪声也不全是坏事，它在一定程度上能帮助参数跳出一些不好的平坦区域。习惯上，这个最朴素的更新规则不管用不用小批量，都叫 SGD。

## Momentum：带上惯性

在窄谷里，SGD 的问题是：陡的方向上，梯度一会儿指向左壁、一会儿指向右壁，来回抵消；平的方向上，梯度每次都指向同一边，但很小。

**Momentum**（动量）的想法是让参数像一个有质量的小球那样滚下去。小球不会每一刻都完全听当前坡度的指挥，它有惯性：之前的速度会保留下来。写成式子，多了一个“速度”**v**：

<div class="ai-formula"><b><i>v</i></b> ← <i>β</i> · <b><i>v</i></b> + <b><i>g</i></b>，　<b><i>θ</i></b> ← <b><i>θ</i></b> − <i>η</i> · <b><i>v</i></b></div>

*β* 通常取 0.9：每一步，旧的速度保留 90%，再加上当前的梯度。这样一来，

- 在**平的方向**上，梯度每次都指向同一边，速度不断累积。如果梯度一直是 *g*，速度最终会到 *g* / (1 − *β*) = 10*g*，相当于在这个方向上把学习率放大了 10 倍。
- 在**陡的方向**上，梯度正负交替，加进速度时互相抵消，震荡被压了下去。

速度是对过去梯度的一种平均，所以它也顺带平滑了小批量带来的噪声。效果很明显：同样的学习率 0.03，SGD 走 300 步还没到，Momentum 只用 39 步就把损失降到了 0.06 以下，300 步后精确地停在 (1.6, −2.1)。

## Adam：每个参数自己的步长

Momentum 解决了“一致的方向要加速”，但所有参数还是共用一个学习率。窄谷的根本问题是**不同方向的尺度差别太大**：陡的方向梯度大，平的方向梯度小。如果每个参数能按照自己梯度的大小，自动调整步长就好了。

**Adam**（Adaptive Moment Estimation）就是这样做的。它为每个参数维护两个量：

<div class="ai-formula"><b><i>m</i></b> ← 0.9 · <b><i>m</i></b> + 0.1 · <b><i>g</i></b>，　<b><i>v</i></b> ← 0.999 · <b><i>v</i></b> + 0.001 · <b><i>g</i></b>²</div>

**m** 是梯度的滑动平均，作用和 Momentum 的速度类似，代表“最近一段时间梯度的方向”；**v** 是梯度**平方**的滑动平均，代表“这个参数的梯度一般有多大”。这里的平方是逐元素的，每个参数各算各的。更新时，用 **m** 除以 **v** 的平方根：

$$
\boldsymbol{\theta} \leftarrow \boldsymbol{\theta} - \eta\cdot\frac{\hat{m}}{\sqrt{\hat{v}} + \epsilon}
$$

除以 √*v* 是关键。一个参数的梯度一直很大，√*v* 也大，步长就被缩小；梯度一直很小，√*v* 也小，步长就被放大。结果是**每个参数走的距离差不多都在 η 这个量级**，不管它的梯度本身是大是小。窄谷里陡的方向和平的方向，被自动拉到了同一个尺度上。

式子里还有两个小细节。*m̂* 和 *v̂* 是“偏差修正”后的值：**m** 和 **v** 都从 0 开始，刚开始几步会偏小，所以分别除以 1 − 0.9<sup>t</sup> 和 1 − 0.999<sup>t</sup>（t 是步数）把它们放大回来。*ε* 是一个很小的数（比如 10<sup>−8</sup>），防止除以 0。

看第一步最清楚。起点的梯度是 (−28, −6.5)，*w* 方向的梯度是 *b* 方向的 4 倍多。SGD 用 0.03 的学习率，两个参数分别变化 0.84 和 0.195，步长也差了 4 倍多。Adam 第一步时，*m̂* 就是 **g**，√*v̂* 就是 |**g**|，两者相除只剩下符号，于是两个参数**都正好走了 0.3**，也就是学习率那么远。

几个值得看的地方：

- **SGD**：第一步几乎是横着冲向山谷中线（因为那个方向陡），之后沿着谷底一点一点往右下方挪，300 步还没到。把学习率往上拉，超过 0.069 就会在陡的方向上来回震荡，最后发散。
- **Momentum**：前几步冲过了谷底，在两侧壁之间摆了几下，但摆动很快衰减，同时沿谷底的速度越积越大，很快就到了终点。
- **Adam**：路线最直，因为它把两个方向的步长拉平了。离终点越近，梯度越小，**m** 跟着变小，而 **v** 衰减得慢（0.999），于是步子也自动变小，最后稳稳停在终点。

勾选“随机小批量”后，每一步只随机用 1 个样本算梯度，三者的表现就拉开了。SGD 的路线变得歪歪扭扭，到了终点附近也停不下来。Momentum 在学习率 0.03 下反而最糟：它把带噪声的梯度累积成速度，相当于把步长放大了约 10 倍，而单个样本的梯度又比 4 个样本的平均大得多，于是在山谷两壁之间越摆越大，损失冲到几百；把学习率降到 0.005，它才重新稳定下来。Adam 最稳：它按梯度的典型大小给步长“定标”，噪声再大，每步也只走 *η* 左右那么远，200 到 300 步之间的平均损失约 0.1，三种学习率下都一样。这也是 Adam 在大模型训练里受欢迎的原因之一：它对学习率没那么敏感。

<Note kind="point">SGD 只看当前梯度；Momentum 把过去的梯度累积成速度，一致的方向加速、来回的方向抵消；Adam 再用梯度平方的平均给每个参数单独定步长，让不同尺度的参数走得一样远。</Note>

## 用代码复现

下面的代码先算出两组数据下曲面的弯曲程度和学习率上限，然后在平移后的山谷里比较三种优化器，并单独看 Adam 的第一步；最后算一算 Adam 训练时的显存账（下一节用）。

```python
import numpy as np

y = np.array([1.0, 3.0, 4.0, 6.0])

def make(x):
    loss = lambda t: np.mean((t[0] * x + t[1] - y) ** 2)
    grad = lambda t: np.array([np.mean(2 * (t[0] * x + t[1] - y) * x), np.mean(2 * (t[0] * x + t[1] - y))])
    return loss, grad

def run(opt, x, lr, start, steps=300):
    loss, grad = make(x)
    t, m, v, hit = np.array(start), np.zeros(2), np.zeros(2), None
    for k in range(1, steps + 1):
        g = grad(t)
        if opt == "SGD":
            t = t - lr * g
        elif opt == "Momentum":
            m = 0.9 * m + g                       # 速度：把过去的梯度累积起来
            t = t - lr * m
        else:                                     # Adam
            m = 0.9 * m + 0.1 * g                 # 梯度的滑动平均（方向）
            v = 0.999 * v + 0.001 * g * g         # 梯度平方的滑动平均（尺度）
            m_hat, v_hat = m / (1 - 0.9 ** k), v / (1 - 0.999 ** k)
            t = t - lr * m_hat / (np.sqrt(v_hat) + 1e-8)
        if hit is None and loss(t) < 0.06:
            hit = k
    return hit, t, loss(t)

x_c = np.array([0.0, 1.0, 2.0, 3.0])              # 第 17 讲的数据
x_s = x_c + 2                                     # 同一组数据，x 整体平移 2
for x, name in [(x_c, "原来的 x"), (x_s, "x 平移 2")]:
    H = 2 * np.array([[np.mean(x * x), np.mean(x)], [np.mean(x), 1.0]])   # 曲面的“弯曲程度”矩阵
    ev = np.linalg.eigvalsh(H)
    print(f"{name}：最陡方向的弯曲 {ev[1]:.2f}，最平方向 {ev[0]:.2f}，相差 {ev[1] / ev[0]:.0f} 倍，学习率上限 {2 / ev[1]:.3f}")

print(run("SGD", x_c, 0.1, (-0.5, -2.0))[0], "步（原来的 x，SGD，η = 0.1）")
for opt, lr in [("SGD", 0.03), ("SGD", 0.065), ("Momentum", 0.03), ("Adam", 0.3)]:
    hit, t, l = run(opt, x_s, lr, (-0.5, 2.0))
    print(f"{opt:8s} η = {lr:<5}：{'没到' if hit is None else f'{hit:3d} 步'}　300 步后 (w, b) = ({t[0]:.3f}, {t[1]:.3f})，L = {l:.4f}")

# Adam 的第一步：每个参数都只走 η 那么远，不管梯度本身多大
loss, grad = make(x_s)
g = grad(np.array([-0.5, 2.0]))
step = -0.3 * (0.1 * g / 0.1) / (np.sqrt(0.001 * g * g / 0.001) + 1e-8)
print("第一步的梯度：", g.round(2), "  SGD 的变化：", (-0.03 * g).round(4), "  Adam 的变化：", step.round(4))

# 训练时每个参数要存的东西（混合精度 + Adam）
N = 8.03e9
per = {"BF16 权重": 2, "BF16 梯度": 2, "FP32 主权重": 4, "Adam m": 4, "Adam v": 4}
print(per, "合计", sum(per.values()), "字节/参数")
print(f"Llama-3-8B：{N * sum(per.values()) / 1e9:.1f} GB（推理只需 BF16 权重 {N * 2 / 1e9:.1f} GB）")
```

## 到了大模型里

今天训练大模型，几乎都用 Adam 的一个变体 **AdamW**。它和 Adam 的区别只在“权重衰减”（weight decay）的做法：每一步把参数往 0 的方向拉一点点，防止某些权重长得过大。AdamW 把这一步和梯度更新分开做，效果更稳定。Llama 系列的论文里用的就是 AdamW。

Adam 好用，但它有一个直接的代价：**每个参数要多存两个数 m 和 v**。再加上第 10 讲会讲的混合精度训练：前向和反向用 BF16 计算，但为了让微小的更新不被舍入掉，还要另存一份 FP32 的“主权重”。于是每个参数要存：

| 内容 | 精度 | 字节 |
| --- | --- | --- |
| 权重 | BF16 | 2 |
| 梯度 | BF16 | 2 |
| 主权重 | FP32 | 4 |
| Adam 的 m | FP32 | 4 |
| Adam 的 v | FP32 | 4 |
| 合计 | | 16 |

Llama-3-8B 约 80.3 亿个参数，乘以 16 字节，约 128.5 GB，这还没算第 18 讲说的激活值。而推理只需要 BF16 的权重，16.1 GB。一张 80 GB 显存的 GPU，放得下推理用的权重，却放不下训练要的这些状态。所以大模型训练一定是多卡的，而且要把优化器状态、梯度、权重切开分到不同的卡上去，这就是第 103 讲的 ZeRO 和 FSDP。

## 容易混淆的地方

1. **不同优化器的学习率不能直接比。**SGD 的步长是 *η* × 梯度，梯度大步子就大；Adam 的步长大约就是 *η*，和梯度大小关系不大。所以 SGD 的 0.03 和 Adam 的 0.3 不是同一回事。大模型用 Adam 时，学习率通常在 10<sup>−4</sup> 这个量级，比这一讲的玩具例子小得多。
2. **Adam 也不是万能的。**它把每个参数的步长拉平，但并不知道参数之间怎么“纠缠”，在斜着的窄谷里仍然会走一些弯路。它的超参数 *β*<sub>1</sub>、*β*<sub>2</sub>、*ε* 也会影响稳定性，大模型训练常把 *β*<sub>2</sub> 从 0.999 调小到 0.95 左右。
3. **优化器状态也是“模型的一部分”。**训练中途保存检查点时，除了权重，还要保存 m 和 v，否则恢复训练时 Adam 要从头积累，前几步会走得很乱。所以训练检查点通常比最终发布的模型文件大好几倍。

## 回顾

优化器决定拿到梯度后怎么更新参数。SGD 直接沿负梯度走 *η* × **g**，实际中每步只用一小批数据，梯度带噪声；在不同方向尺度相差很大的窄谷里，它的学习率被最陡的方向卡住，在平的方向上走得很慢。Momentum 把过去的梯度累积成速度，一致的方向加速、来回震荡的方向互相抵消。Adam 在此基础上再用梯度平方的滑动平均给每个参数单独定步长，让每个参数都走大约 *η* 那么远，在窄谷里路线最直。代价是每个参数要多存两个数：混合精度加 Adam，每个参数 16 字节，Llama-3-8B 光这些就要约 128.5 GB。

到这里，训练需要的零件都齐了：模型（第 12–15 讲）、损失函数（第 16 讲）、梯度（第 17 讲）、反向传播（第 18 讲）、优化器（这一讲）。把它们组装成一个真正能跑起来的训练程序，还要回答几个实际的问题：数据怎么分批喂进去？要过几遍？学习率要不要随时间变化？下一讲：**完整的训练循环**。
