到这里，现代大模型的各种改进，都还保留着注意力最根本的一点：生成每个新 token 时，它都要和前面**所有**的 token 打分，并且所有 token 的 k、v 都要缓存。上下文长度 n 翻一倍，每个 token 的注意力计算翻一倍，KV Cache 也翻一倍。GQA、MLA 能把常数压小，滑动窗口能截掉远处，但只要用的是完整的 softmax 注意力，这个“随 n 增长”的本性就改变不了。

有没有一种结构，处理每个新 token 的代价和 n 无关，像循环神经网络（RNN）那样，只带着一个固定大小的“记忆”往前走？这一讲是选读，介绍这条路上的两类做法，**线性注意力**和**状态空间模型**，以及今天更现实的方案：把它们和普通注意力混着用的**混合架构**。

## 换一个乘法顺序

回顾注意力的公式（第 26 讲）：先算 *QK*<sup>T</sup>（n × n），softmax，再乘 *V*。如果没有中间那个 softmax，就可以利用矩阵乘法的结合律，换一个顺序：

$$
(QK^{T})\,V = Q\,(K^{T}V)
$$

左边要先算一个 n × n 的矩阵；右边先算 *K*<sup>T</sup>*V*，它只是 d × d 的，和 n 无关。第 40 讲的矩阵吸收用的也是同一个结合律。

麻烦在于 softmax 不能这样拆。**线性注意力**（Linear Attention）的做法是用另一种打分代替 softmax：先用一个核函数 φ 把 q、k 映射成非负特征，打分直接用 φ(**q**) · φ(**k**)，再除以分数之和做归一化。这样乘法顺序就能交换了。

更妙的是，加上因果掩码后，它可以写成一个**循环递推**的形式。维护一个 d × d 的状态矩阵 *S*：每来一个 token，就把 φ(**k**<sub>t</sub>)<sup>T</sup>**v**<sub>t</sub> 累加进 *S*；输出就是用 φ(**q**<sub>t</sub>) 去“读”这个状态：

<div class="ai-formula"><i>S</i><sub>t</sub> = <i>S</i><sub>t−1</sub> + φ(<b><i>k</i></b><sub>t</sub>)<sup>T</sup> <b><i>v</i></b><sub>t</sub>，　<b><i>o</i></b><sub>t</sub> ∝ φ(<b><i>q</i></b><sub>t</sub>) <i>S</i><sub>t</sub></div>

前面所有 token 的信息都被“压”进了这一个 d × d 的矩阵里。生成新 token 时，不需要回头看任何历史 token，只要更新一次状态、读一次状态，代价是 d<sup>2</sup>，和上下文长度完全无关。

## 代价对比

每层每个头，生成一个新 token 时，注意力部分的代价（也正比于要存的东西）：

| 上下文长度 n | 普通注意力 ~ n·d | 线性注意力 ~ d² | 普通注意力的 KV | 线性注意力的状态 |
| --- | --- | --- | --- | --- |
| 1,024 | 随 n 增长 | 固定 | 262,144 个数 | 16,384 个数 |
| 131,072 | 随 n 增长 | 固定 | 33,554,432 个数 | 16,384 个数 |

（d = 128。）处理一整段长度为 n 的文本时，普通注意力的总计算约是 n<sup>2</sup>d，线性注意力是 nd<sup>2</sup>：n = 131072 时，前者约 2.2 × 10<sup>12</sup>，后者约 2.15 × 10<sup>9</sup>，差了一千倍。两者在 n = d 附近交叉：上下文比 d 还短时，线性注意力反而更贵；越长，它的优势越大。

## 固定大小的记忆，代价是什么

线性注意力这么省，为什么没有取代普通注意力？问题就出在“固定大小的状态”上。

普通注意力的 KV Cache 把每个历史 token 都原样存着，需要哪个就能精确地“看”哪个。线性注意力把所有历史挤进一个 d × d 的矩阵，就像把很多张照片叠印在同一张底片上：存得越多，越难把某一张单独取出来。代码里做了一个简单的实验：往一个 16 × 16 的状态里存 m 对（k, v），再用 k 去取回 v。存 4 对时取回的相对误差是 0.67，存 16 对是 0.95，存 64 对是 1.83，已经完全取不准了。

所以线性注意力擅长的是“总体把握”上下文，不擅长“精确回忆”某个很远的细节，比如在一长段文本里准确找出一个电话号码。早期的线性注意力模型在语言建模上一直明显不如 Transformer，主要原因就在这里。

## 状态空间模型（Mamba）的突破

2023 年前后，这条路线有了革命性进展。**状态空间模型**（State Space Model，SSM）一系的 **Mamba**，解决了两个传统死穴：

### 1. 选择性机制（Selective Mechanism）

传统的循环模型和早期 SSM（如 S4）的状态转移矩阵是固定的（时不变系统）。无论当前输入是一个关键的专有名词还是一个毫无用处的逗号，状态更新的权重都一模一样，导致有限的状态容量很快被垃圾信息填满。

Mamba 的突破在于**让参数根据当前输入动态变化**：
步长参数 $\Delta_t$、输入矩阵 $B_t$ 和输出矩阵 $C_t$ 都是当前输入 $x_t$ 的线性投影函数。
- 遇到停用词或填充符号时，网络可以主动让 $\Delta_t \to 0$，**状态完全不更新、直接跳过**；
- 遇到关键实体信息时，$\Delta_t$ 变大，快速清空旧记忆、将新特征强行写入状态。有了这种动态的“内容感知过滤”，固定大小的状态被利用得聪明得多。

### 2. 硬件感知并行扫描（Hardware-aware Parallel Scan）

既然每一步的参数都在随输入变化，怎么在训练时实现 GPU 高度并行？

如果逐 step 串行循环，GPU 算力利用率会跌到冰点。Mamba 利用矩阵变换的结合律，将动态循环重写为**并行前缀和扫描（Parallel Associative Scan）**；
更关键的是底层的系统优化：Mamba 将离散化、并行扫描和状态更新完全封装在单个定制的 GPU Kernel 内，**将状态保留在片上高速 SRAM 中流转，中间的庞大状态矩阵绝不写入全局显存 HBM**。这让它在 $O(n)$ 线性的同时，在 GPU 硬件上跑出了比 FlashAttention 还要高得多的执行吞吐。

## 混合架构：现实的折中

即便如此，纯线性的模型在超长距离的“大海捞针”和精确细节检索上，依然在数学上受限于固定容量的瓶颈。

今天最现实、最具工业落地价值的方案是**混合架构（Hybrid Architecture）**：
- **绝大部分层（如 7/8 的层）使用 Mamba 或线性注意力**：以极低的线性计算代价和零 KV Cache 吞吐，快速压缩和提炼长文本的主干语义；
- **极少数层（如 1/8 的层）保留完整的 Softmax 注意力**：作为全方位的全局路由中枢，负责精确定位、细节核对与长程引用。

AI21 的 Jamba 模型（混合了 Mamba 层、注意力层与 MoE）以及 MiniMax-01 均采用了这种混合结构。这种设计把 85% 以上的 KV Cache 显存彻底消除，同时在下游能力上几乎无损匹敌纯 Transformer，是长序列推理的重要演进方向。

<Note kind="point">线性注意力把历史压进一个 d × d 的状态，每步代价和上下文无关；Mamba 通过选择性机制和片上并行扫描大幅弥补了容量缺陷。混合架构让绝大部分层用线性结构、少数层保留完整注意力，是兼顾吞吐与精确召回的最佳折中。</Note>

## 到了大模型里

**硬件效率往往比理论复杂度更关键。**在很多早期线性注意力论文中，虽然理论复杂度是 $O(n)$，但由于没有写出匹配 GPU 硬件架构的片上 SRAM 算子，在短文本下甚至比调用 FlashAttention 的纯 Transformer 还慢。Mamba 之所以能引发巨大关注，正是因为其作者将算法重构与 GPU 内存层级（SRAM 与 HBM 传输）做了端到端的硬件感知联合设计。

## 容易混淆的地方

1. **线性注意力不是“把注意力做成线性的”。**注意力依然在模拟软寻址，只是通过核函数技巧让矩阵乘法结合律得以生效。
2. **状态固定不等于无损。**状态大小与序列长度无关固然极其节省显存，但这意味着它无法无损保留所有的局部历史。

## 回顾

线性注意力利用矩阵乘法结合律把计算重构为状态循环递推，每步代价与上下文长度无关，不需要庞大的 KV Cache；Mamba 则引入了动态选择性机制与片上并行扫描，弥补了时不变系统的表现瓶颈。但受限于固定大小的状态容量，纯线性结构在精细检索上仍有短板。今天更成熟的工业方案是混合架构：以 7:1 等比例混合线性层与全注意力层，将显存带宽开销削减近九成，同时完整保留复杂逻辑与长程回溯能力。
