假设你手里有一笔固定的算力预算，比如一千张 GPU 用一个月。你可以训练一个很大的模型，但只够让它看比较少的数据；也可以训练一个小一些的模型，让它看更多的数据。第 18、35 讲说过，训练的总计算量约是 C ≈ 6ND（N 是参数量，D 是训练的 token 数），所以 N 和 D 此消彼长。**怎么分最划算？**

回答这个问题的，是一组叫 **Scaling Laws**（缩放定律）的经验规律：模型的损失，随着参数量、数据量和算力的增长，以非常规则的方式下降。它们让训练大模型从“试试看”变成了可以事先估算的工程。这一讲介绍其中最有影响的一个结论（Chinchilla），以及今天的模型为什么又“故意”偏离它。

## 损失是可以预测的

2020 年前后，OpenAI 和 DeepMind 的研究者训练了大量不同大小的模型，用不同数量的数据，然后把最终的损失画出来。他们发现了一个惊人的规律：在对数坐标下，损失随参数量、数据量的变化几乎是一条条平滑的直线（幂律）。只要在小规模上做足够多的实验，就能比较准确地预测大规模时的损失。

2022 年 DeepMind 的 Chinchilla 论文给出了一个拟合公式：

$$
L(N, D) = 1.69 + \frac{406.4}{N^{0.34}} + \frac{410.7}{D^{0.28}}
$$

三项各有含义：

- **1.69**：即使模型和数据都无限大，损失也降不到这以下。这是语言本身的不确定性（第 23 讲说过，损失的下限不是 0）。
- **406.4 / N<sup>0.34</sup>**：模型不够大带来的损失。参数越多，这一项越小。
- **410.7 / D<sup>0.28</sup>**：数据不够多带来的损失。数据越多，这一项越小。

（这里的损失是在他们的数据上、按他们的分词方式算的交叉熵，具体数值不能和别的模型直接比，但趋势是普遍的。）

## 固定算力，找最低点

现在固定算力 C，把 D = C / (6N) 代进去，损失就只是 N 的函数。N 太小，模型容量不够，第二项大；N 太大，分到的数据太少，第三项大。中间有一个最低点。

拿 C = 10<sup>22</sup> FLOPs 试一下（大致是一个几十亿参数的模型训练几千亿 token 的量级）：

| 模型参数 N | 数据 D | 损失 |
| --- | --- | --- |
| 1 亿 | 16.7 万亿 token | 2.546 |
| 10 亿 | 1.67 万亿 | 2.199 |
| 51.5 亿 | 3235 亿 | 2.139 |
| 100 亿 | 1667 亿 | 2.148 |
| 1000 亿 | 167 亿 | 2.328 |

损失在 51.5 亿参数附近最低，每个参数配约 63 个 token。往两边走，损失都变大。

下面的演示画出了这条 U 形曲线。拖动算力预算，看最低点怎么移动；琥珀色的点是同样算力下训练一个 8B 模型的位置。

算力越大，最优模型越大，数据也越多，两者大致按同样的比例增长：算力从 10<sup>20</sup> 到 10<sup>24</sup>，最优模型从 6.4 亿涨到 413 亿参数，数据从 260 亿涨到 4 万亿 token。

关于“每个参数配多少 token”，常被引用的说法是“约 20 个”，那来自 Chinchilla 论文里另外两种估计方法。用这个拟合公式直接算，比例会随算力变化，从几十到上百不等。不同方法的结论不完全一致，但都指向同一个方向：**模型和数据应该一起放大**。在 Chinchilla 之前，主流的做法是把模型做得很大、数据给得相对少（比如 GPT-3 有 1750 亿参数，只训练了约 3000 亿 token），Chinchilla 表明这样并不划算：一个只有 700 亿参数、但训练了 1.4 万亿 token 的模型，效果超过了大得多的模型。

<Note kind="point">Scaling Laws：损失随参数量和数据量按幂律平滑下降，可以从小实验预测大模型的效果。固定训练算力时，模型和数据应按比例一起放大，太大或太小都浪费。</Note>

## 为什么今天的模型“过度训练”

按这个公式，Llama-3-8B 并不“最优”。它的训练算力约 7.23 × 10<sup>23</sup> FLOPs，每个参数配了约 1868 个 token，远远超过“最优”比例。同样的算力，公式给出的最优模型约 360 亿参数、3.4 万亿 token，损失 1.923，比 8B 的 1.948 还低一点。

Meta 为什么要这样做？因为 Chinchilla 只算了**训练**的账，没有算**推理**的账。模型训练一次，却要被使用千百万次。推理每个 token 的计算量是 2N（第 35 讲），360 亿参数的模型推理成本是 8B 的 4.4 倍，显存也大得多。如果一个模型要服务大量用户，宁可在训练时多花一些算力，把一个小模型训练得尽可能好（多喂数据），推理时就能省下大得多的成本。

所以今天常见的做法是：根据**训练加推理的总成本**，选一个推理上负担得起的模型大小，然后用远超 Chinchilla 比例的数据把它训练到底。数据越多，小模型的损失还会继续下降，只是越来越慢。这也是为什么高质量数据成了越来越稀缺的资源（第 45 讲）。

## 用代码复现

下面的代码用 Chinchilla 的拟合公式，在三个算力下找最优的 N 和 D；在 10<sup>22</sup> 下比较不同的模型大小；最后算出 Llama-3-8B 的位置和同算力的“最优”模型。

```python
import numpy as np

# Chinchilla 论文（Hoffmann 等，2022）拟合的损失公式：L(N, D) = E + A / N^α + B / D^β
E, A, B, alpha, beta = 1.69, 406.4, 410.7, 0.34, 0.28
loss = lambda N, D: E + A / N ** alpha + B / D ** beta

# 1. 固定算力 C ≈ 6ND（第 18 讲），在不同的 N 之间找损失最低的那个
def optimum(C):
    Ns = np.logspace(7, 13, 4001)
    Ls = loss(Ns, C / (6 * Ns))
    i = int(Ls.argmin())
    return Ns[i], C / (6 * Ns[i]), Ls[i]

for C in [1e20, 1e22, 1e24]:
    N, D, L = optimum(C)
    print(f"C = {C:.0e} FLOPs：最优 N ≈ {N / 1e9:7.2f}B，D ≈ {D / 1e9:8.0f}B token，每个参数 {D / N:5.1f} 个 token，损失 {L:.3f}")

# 2. 同一笔算力，模型做大或做小
C = 1e22
for N in [1e8, 1e9, optimum(C)[0], 1e10, 1e11]:
    print(f"  C = 1e22，N = {N / 1e9:6.2f}B：D = {C / 6 / N / 1e9:7.1f}B token，损失 {loss(N, C / 6 / N):.3f}")

# 3. Llama-3-8B：8B 参数、15T token
N, D = 8.03e9, 15e12
C = 6 * N * D
No, Do, Lo = optimum(C)
print(f"Llama-3-8B：C = {C:.2e}，每个参数 {D / N:,.0f} 个 token，按公式损失 {loss(N, D):.3f}")
print(f"同样算力的“最优”模型：N ≈ {No / 1e9:.0f}B，D ≈ {Do / 1e12:.1f}T，损失 {Lo:.3f}；推理每 token 计算量是 8B 的 {No / N:.1f} 倍")
```

## 到了大模型里

**预测训练结果。**训练一个大模型动辄花费几千万美元，在开始之前，团队会先用小模型做一系列实验，拟合出自己的 Scaling Law，再预测大模型能达到的损失，决定模型多大、数据多少、训练多久。

**推理侧的 Scaling。**近两年出现了另一类“缩放”：在推理时花更多的计算，让模型先“想”很久再回答，效果随推理时的计算量增长（第 49 讲）。这让推理成本变成了提升能力的一个新旋钮，也让推理系统的效率变得更加重要。

**算力换算。**第 20 讲用 6ND 估算了训练时间；结合这一讲，可以反过来问：给定一千张 H100、一个月，能训练多大的模型、用多少数据？这正是做训练规划时最常算的账。

## 容易混淆的地方

1. **损失更低不等于每项能力都更好。**Scaling Law 预测的是平均的交叉熵损失。某些具体能力（比如做多位数乘法）可能在某个规模附近突然出现，和平均损失的平滑下降并不完全同步。
2. **公式里的常数不通用。**E、A、B、α、β 依赖于数据、分词器、模型结构。换一套数据，要重新拟合。能推广的是“幂律”这个形式和“一起放大”的结论。
3. **“最优”只针对训练算力。**加上推理成本、数据是否够用等约束，实际的最优选择会偏向更小的模型、更多的数据。

## 回顾

Scaling Laws 发现，损失随参数量和数据量按幂律平滑下降，可以用小规模实验预测大模型。Chinchilla 拟合的公式是 L = 1.69 + 406.4/N<sup>0.34</sup> + 410.7/D<sup>0.28</sup>；固定算力 C ≈ 6ND 时，损失随模型大小呈 U 形，最低点给出最优的分配，模型和数据应一起放大。今天的模型往往故意“过度训练”：Llama-3-8B 每个参数用了约 1868 个 token，因为推理成本和模型大小成正比，训练时多花算力把小模型训好，推理时更省。
