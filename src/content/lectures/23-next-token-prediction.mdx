前两讲把文字变成了 token，又把 token 变成了向量。现在终于可以问那个最根本的问题了：**一个大模型，到底在学什么？**

答案只有一句话：**看前面的文字，预测下一个 token。**GPT、Llama、DeepSeek 这些大模型，预训练阶段做的全是这一件事，没有别的任务。这一讲先把这个任务说清楚：它的输入是什么、输出是什么、一段文本怎么变成训练题目；再用上一讲那个在小语料上训练过的模型，亲手看看它学到了什么；最后讨论一个看上去很奇怪的事实：为什么只靠“猜下一个词”，模型就能学会语法、知识甚至推理。

## 一个词一个词地猜

假设前面已经有了“我 吃”，下一个词是什么？可能是“苹果”，也可能是“香蕉”，没法确定。所以模型的输出不是一个词，而是一个**概率分布**：词表里每个 token 各有一个概率，加起来是 1。用数学的写法，模型给出的是

<div class="ai-formula"><i>P</i>(下一个 token | 前面所有的 token)</div>

竖线读作“在……的条件下”。整个过程是第 16 讲已经讲过的：模型最后一层给词表里的每个 token 打一个分（logit），再用 softmax 变成概率。

“输出一个分布”而不是“输出一个答案”，是理解语言模型的关键。语言本身就是不确定的：同样的开头，可以有很多种合理的接法。一个好的语言模型，不是每次都“猜中”，而是给每种接法分配合理的概率：常见的接法概率高，罕见但合理的接法概率低，不合理的接法概率接近 0。

## 一句话就是好几道题

这个任务最妙的地方在于：**训练数据不需要任何人工标注**。随便一段文字，本身就带着答案。

以“我 学 AI”为例。按上一讲的小模型，每次看前两个词（句子开头不够两个，用句号“。”补齐），一句话可以拆出 4 道题：

| 输入（前两个词） | 正确答案（下一个词） |
| --- | --- |
| 。 。 | 我 |
| 。 我 | 学 |
| 我 学 | AI |
| 学 AI | 。 |

文本有多少个 token，就有多少道题。互联网上有几万亿个 token 的文字，就是几万亿道现成的、带答案的练习题。这种“从数据本身构造答案”的训练方式，叫**自监督学习**（self-supervised learning）。

每道题的损失是第 16 讲的交叉熵：−ln（模型给正确答案的概率）。整段文本的损失，就是所有位置的交叉熵取平均。训练让这个平均值尽量小，也就是让模型给真实出现的下一个词，分配尽量高的概率。

## 模型学到的就是统计规律

上一讲的小模型，就是在 16 种句子（重复后一共 24 句、96 道题）上用这个目标训练出来的。下面的演示可以自己拼一个前缀：点词把它接到后面，下面会列出模型对下一个词给出的概率，从高到低排列。最右一列是在训练语料里实际数出来的：同样的两个词后面，各个词出现过几次。

试几个前缀：

- **“我 吃”**：苹果 0.501、香蕉 0.499。语料里“我 吃”后面是苹果 2 次、香蕉 2 次。
- **“小猫 吃”**：鱼的概率是 1.0。语料里小猫只吃过鱼。
- **“我 学”**和**“你 学”**：前者 AI 0.667、推理 0.333，后者正好反过来。语料里“我学 AI”出现 2 次、“我学推理”1 次，“你”则相反。
- **清空前缀**（从句子开头预测）：我 0.416、你 0.25、小猫 0.167，对应语料里 24 句话有 10 句以“我”开头、6 句以“你”开头、4 句以“小猫”开头。

模型给出的概率，几乎就是语料里的频率。**训练的结果，是让模型记住了“什么后面跟着什么、跟多少次”的统计规律。**

损失能低到多少？就算模型完全学会了这些频率，“我 吃”后面是苹果还是香蕉，仍然只能五五开，每次都要付出 −ln 0.5 ≈ 0.69 的损失。把所有题目的这种“不可避免的损失”平均起来，就是这份语料的理论下限：0.6681。下面的代码显示，模型的平均交叉熵也是 0.6681，已经降到了下限。对应的困惑度是 1.951：平均来说，模型每一步相当于在不到 2 个词之间犹豫。

<Note kind="point">语言模型学的是条件概率 P(下一个 token | 前文)。训练数据就是普通文本本身，每个位置一道题，损失是交叉熵的平均。损失的下限不是 0，因为语言本来就有不确定性。</Note>

在演示里也能看到这个小模型的局限。把前缀拼成“我 喜欢 小猫 。 小猫 吃”，前面的词全部变淡，它只看“小猫 吃”。它永远不知道更早发生了什么。如果语料里有“小猫 在 河边 吃”这样隔了几个词的句子，它就无能为力了。真实的大模型能看前面几千、几万甚至上百万个 token，这正是第 4 篇注意力机制要解决的问题。

## 为什么猜下一个词这么厉害

在我们的小语料上，“预测下一个词”只能学到简单的搭配。可当语料变成几万亿个 token、包含了百科、教材、代码、对话、论文时，这个任务就变得极其困难，困难到模型必须学会很多东西，才能把损失降下去。看几个例子：

- “法国的首都是 ___”：要给“巴黎”高概率，模型得**记住事实**。
- “他们昨天去了公园，今天又 ___”：要接得通顺，模型得**懂语法和时态**。
- “37 + 25 = ___”：要猜对“62”，模型得**会算术**，至少得学会某种算法。
- “小明打碎了妈妈最喜欢的花瓶，他很 ___”：要给“害怕”“内疚”高概率，模型得**理解人的情绪和因果**。
- 一段 Python 代码写到一半：要猜对下一行，模型得**懂编程**。

任何一种能力的缺失，都会体现为在某类文本上猜不准、损失降不下去。于是，在足够大的模型、足够多的数据上，把这一个目标优化到底，就“逼”出了这些能力。这是大模型最让人意外、也最重要的一个发现：一个极其简单的训练目标，配合足够的规模，可以学出极其复杂的行为（第 46 讲的 Scaling Laws 会定量地讨论“足够”是多少）。

## 用代码复现

下面的代码加载上一讲的小模型，先把“我 学 AI”拆成训练题目；然后对几个前缀，把模型的预测和语料里数出来的频率并排打印；最后算出模型的平均交叉熵和理论下限。

```python
import json
from collections import Counter, defaultdict
import numpy as np

ex = json.load(open("tinylm.json", encoding="utf-8"))["examples"]["22"]
V = ex["vocab"]
E, W1, b1, W2, b2 = (np.array(ex[k]) for k in ["E", "W1", "b1", "W2", "b2"])

def probs(a, b):                                  # 只看最后两个词
    x = np.concatenate([E[V.index(a)], E[V.index(b)]])
    z = np.maximum(0, x @ W1 + b1) @ W2 + b2      # 14 个词的打分（logit）
    p = np.exp(z - z.max())
    return p / p.sum()                            # softmax

# 1. 一句话怎么变成训练样本：每个位置都要预测下一个词
toks = ["。", "。"] + "我 学 AI".split() + ["。"]
for i in range(2, len(toks)):
    print(f"输入“{toks[i-2]} {toks[i-1]}”→ 目标“{toks[i]}”")

# 2. 语料里数出来的频率
count = defaultdict(Counter)
for sent, n in ex["corpus"]:
    s = ["。", "。"] + sent.split() + ["。"]
    for i in range(2, len(s)):
        count[(s[i-2], s[i-1])][s[i]] += n

# 3. 模型的预测 vs 语料的频率
for a, b in [("。", "。"), ("我", "吃"), ("小猫", "吃"), ("我", "学"), ("你", "学")]:
    p = probs(a, b)
    top = [(V[i], round(float(p[i]), 3)) for i in np.argsort(-p)[:3]]
    tot = sum(count[(a, b)].values())
    freq = {w: f"{c}/{tot}" for w, c in count[(a, b)].most_common(3)}
    print(f"“{a} {b}”→ 模型 {top}  语料 {freq}")

# 4. 训练损失 vs 理论下限（语料本身的不确定性）
pairs = [(a, b, w, c) for (a, b), cnt in count.items() for w, c in cnt.items()]
total = sum(c for *_, c in pairs)
H = -sum(c * np.log(c / sum(count[(a, b)].values())) for a, b, w, c in pairs) / total
loss = -sum(c * np.log(probs(a, b)[V.index(w)]) for a, b, w, c in pairs) / total
print(f"样本 {total} 个；模型的平均交叉熵 {loss:.4f}，下限 {H:.4f}，困惑度 {np.exp(loss):.3f}")
```

输出：

```text

输入“。 我”→ 目标“学”
输入“我 学”→ 目标“AI”
输入“学 AI”→ 目标“。”
“。 。”→ 模型 [('我', 0.416), ('你', 0.25), ('小猫', 0.167)]  语料 {'我': '10/24', '你': '6/24', '小猫': '4/24'}
“我 吃”→ 模型 [('苹果', 0.501), ('香蕉', 0.499), ('骨头', 0.0)]  语料 {'苹果': '2/4', '香蕉': '2/4'}
“小猫 吃”→ 模型 [('鱼', 1.0), ('。', 0.0), ('香蕉', 0.0)]  语料 {'鱼': '3/3'}
```

## 到了大模型里

**预训练就是这一讲的目标，放大到几万亿个 token。**Llama-3 在 15T 以上的 token 上做的，就是让平均交叉熵尽量小。第 20 讲算过，这需要约 7 × 10<sup>23</sup> 次浮点运算。

**一次前向，所有位置的题一起做。**我们的小模型每道题单独算一次。Transformer 处理一段 s 个 token 的文本时，一次前向就给出每个位置的下一个词分布，s 道题同时完成，这是训练效率高的关键之一。它能这样做的前提是：预测第 i 个位置时，不能偷看第 i 个位置之后的词（否则答案就泄露了），这由第 27 讲的因果掩码来保证。

**推理时只需要最后一个位置。**训练时每个位置的预测都有用；推理时，我们只关心“整段话之后接什么”，所以只需要最后一个位置的分布。输出层（第 33 讲）把一个 4096 维的向量变成 128256 个打分，只对最后一个位置做一次就行。但前面的每个 token 仍然要完整地算一遍，因为最后一个位置要“看”到它们，这就是第 68 讲要讲的 prefill。

## 容易混淆的地方

1. **模型输出的是分布，不是词。**“模型说了某句话”，其实是：模型给出一个分布，再由一个**选词的规则**从分布里挑出一个词。选词规则是独立于模型的（下一讲和第 73 讲），同一个模型配不同的规则，说出来的话可以很不一样。
2. **预训练出来的模型不会“对话”。**只做过“预测下一个 token”的模型（叫基座模型，base model）会接着你的话往下写，而不是回答你的问题。你写“怎么做红烧肉？”，它可能接着写出另外几个菜谱问题，因为网上的问题列表常常就是这样的。会对话、遵循指令，是第 47、48 讲的监督微调和偏好对齐的结果。
3. **“只是统计”不等于“只是记忆”。**我们的小模型确实只记住了 96 道题的频率。但大模型的参数远远不够把训练数据逐字存下来（80 亿个参数，对上 15 万亿个 token），它必须找出数据背后可以复用的规律，才能在没见过的文本上也猜得准。

## 回顾

大模型预训练只做一件事：看前面的 token，给下一个 token 一个概率分布。训练数据就是普通文本，文本有多少个 token 就有多少道带答案的题，损失是每道题交叉熵的平均。在我们的小语料上，训练出来的概率几乎就等于语料里数出来的频率，损失降到了理论下限 0.6681：语言本身的不确定性让损失不可能是 0。当语料大到包罗万象时，为了猜准下一个 token，模型被迫学会了语法、事实、计算和推理。

可是，一个只会“给下一个 token 一个分布”的模型，是怎么写出一整段话的？从分布里该怎么挑词？挑出来的词又怎么接着用？下一讲：**自回归生成**。
