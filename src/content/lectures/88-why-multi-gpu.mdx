第三章的所有讨论都发生在一张卡上：Llama-3-8B 的权重 16 GB，一张 80 GB 的 H100 绰绰有余，剩下的空间放 KV Cache（第 63 讲）。可是今天常用的大模型，很多比它大一个甚至两个数量级。从这一讲开始的第四章，我们要把模型和请求分到多张卡、多台机器上。

这一讲先回答最基本的问题：**为什么一张卡不够？**原因有三个：放不下、算不快、扛不住。

## 放不下

先算权重。参数量乘以每个参数的字节数（第 80 讲）：

- **Llama-3-8B**：BF16 16 GB，FP8 8 GB。
- **Llama-3.1-70B**：BF16 141 GB，FP8 71 GB。
- **Llama-3.1-405B**：BF16 812 GB，FP8 406 GB。
- **DeepSeek-V3**（6710 亿参数，第 41 讲的 MoE）：BF16 1342 GB，原生的 FP8 权重也有 671 GB。

一张 H100 是 80 GB。70B 的模型用 BF16 就已经放不下了；405B 和 DeepSeek-V3 即使用 FP8，也要好几张卡才装得下权重。

再加上 KV Cache。每个 token 的 KV：Llama-3.1-70B 有 80 层，每个 token 320 KiB；405B 有 126 层，504 KiB；DeepSeek-V3 用了 MLA（第 40 讲），每层每个 token 只存 576 个数，61 层加起来只有 68.6 KiB。32 个请求、每个 8192 个 token 时，70B 的 KV 有 86 GB，405B 有 135 GB。

把权重和 KV 加起来，按每张卡 90% 可用：70B BF16 至少要 **4 张** H100，405B 要 14 张，DeepSeek-V3（BF16）要 19 张。这还没算激活和框架本身的开销。

## 算不快

就算放得下，速度也是问题。第 60 讲说过，decode 每一步要把权重从显存读一遍。H100 的带宽是 3.35 TB/s：

- 70B 的 BF16 权重，读一遍约 **42 ms**，单个请求最多每秒 24 个 token，勉强能用；
- 405B 读一遍约 242 ms，每秒 4 个 token，用户等不起。

如果把权重分到 8 张卡上，每张卡只读自己的八分之一，**8 张卡同时读**，一步就只要 70B 的 5.3 ms、405B 的 30.3 ms。多卡不只是为了装下，也是为了把“读权重”这件事并行起来：8 张卡的总带宽是一张卡的 8 倍。

prefill 是计算受限的，道理一样：一个几万 token 的长提示，一张卡要算好几秒，分到 8 张卡上就快得多。

## 扛不住

第三个原因是流量。一个线上服务每秒可能要处理成百上千个请求。第 73 讲的压测告诉我们，一张卡的容量是有限的，超过饱和点，延迟就失控了。这时要做的是**多复制几份**：同一个模型在很多组卡上各跑一份，请求分摊到各组上。

这三个原因对应着不同的做法：放不下、算不快，就要把**一个模型切开**，放到几张卡上合作完成一次计算；扛不住，就把**整个模型复制**几份，各自独立地服务。后面几讲会看到，“切开”的方式有好几种：按层切、按矩阵切、按专家切、按序列切，每种都要卡与卡之间交换数据，交换的代价取决于卡与卡之间的连接（第 56 讲）。

## 训练更需要多卡

训练对显存的要求比推理高得多。混合精度训练加 Adam 优化器（第 19 讲），每个参数要存：BF16 的权重 2 字节、梯度 2 字节、FP32 的主权重 4 字节、Adam 的两个状态各 4 字节，一共约 **16 字节**，还没算激活。

- Llama-3-8B：128 GB，一张 H100 都放不下，至少 2 张；
- Llama-3.1-70B：1130 GB，至少 16 张。

而训练的计算量更是巨大（第 46 讲），实际的预训练动辄用上千、上万张卡。分布式训练的方法（数据并行、ZeRO、张量并行、流水并行）是在训练里发展起来的，推理借用了其中的很多。第 92 讲会讲训练特有的 ZeRO。

## 换更大的卡不行吗

显卡的显存确实在变大：H200 有 141 GB，B200 有 192 GB。用 H200，70B 的 FP8 版本一张卡就放得下了。但模型也在变大，而且单卡的带宽和算力终究有限：405B 的模型即使放进一张卡，decode 一步也要读几百 GB。

所以业界的方向是把**更多的卡连得更紧**。一台 DGX H100 服务器里有 8 张卡，用 NVLink 互连，卡与卡之间每个方向约 450 GB/s；服务器之间用 InfiniBand 等网络连接，每张卡约 50 GB/s，慢了一个数量级。NVIDIA 的 GB200 NVL72 把 72 张卡放进同一个 NVLink 域，就是为了让更多的卡之间都能高速通信（第 57 讲的超节点）。哪种切法放在哪一层连接上，是第 97 讲的话题。

## 用代码复现

下面的代码算出四个模型的权重、每个 token 的 KV，以及 32 个 8K 请求时至少要几张 H100；再算单卡和 8 卡读一遍权重的时间；最后估算训练时参数相关的显存。

```python
import math
# 几个模型：参数量，每个 token 的 KV Cache 字节数（BF16）
MODELS = {
    "Llama-3-8B":     (8.03e9,  2 * 32 * 8 * 128 * 2),       # 32 层、8 个 KV 头、每头 128 维
    "Llama-3.1-70B":  (70.6e9,  2 * 80 * 8 * 128 * 2),       # 80 层
    "Llama-3.1-405B": (405.9e9, 2 * 126 * 8 * 128 * 2),      # 126 层
    "DeepSeek-V3":    (671e9,   61 * (512 + 64) * 2),        # 61 层，MLA 每个 token 每层存 576 个数（第 40 讲）
}
GPU, USABLE = 80e9, 0.9                                      # H100 80 GB，按 90% 可用
print("模型 | 权重 BF16 / FP8 | 每 token KV | 32 个请求 × 8K token 的 KV | BF16 至少几张卡")
for name, (n, kv) in MODELS.items():
    w16, w8 = n * 2, n * 1
    kv_total = kv * 32 * 8192
    cards = math.ceil((w16 + kv_total) / (GPU * USABLE))
    print(f"{name} | {w16 / 1e9:6.0f} / {w8 / 1e9:4.0f} GB | {kv / 1024:5.1f} KiB | {kv_total / 1e9:6.1f} GB | {cards}")

# 算力：decode 每一步要把权重读一遍；单卡带宽 3.35 TB/s
for name in ["Llama-3.1-70B", "Llama-3.1-405B"]:
    n = MODELS[name][0]
    t = n * 2 / 3.35e12 * 1e3
    print(f"{name}：一张卡读一遍 BF16 权重 {t:.0f} ms（如果放得下）→ 单个请求最多 {1000 / t:.0f} token/s；8 张卡各读 1/8 → {t / 8:.1f} ms")

# 训练：每个参数约 16 字节（BF16 权重 2 + 梯度 2 + FP32 主权重 4 + Adam 两个状态 8），还没算激活
for name in ["Llama-3-8B", "Llama-3.1-70B"]:
    n = MODELS[name][0]
    print(f"训练 {name}：参数相关的状态 {n * 16 / 1e9:.0f} GB，至少要 {math.ceil(n * 16 / (GPU * USABLE))} 张 H100")
```

## 容易混淆的地方

1. **“放得下”只是最低要求。**卡数刚好装下权重时，留给 KV Cache 的空间很少，并发上不去。实际部署通常会用比最低要求更多的卡。
2. **多卡不是免费的加速。**切开的模型每算一层，卡与卡之间都可能要交换数据；交换的时间如果和计算差不多，多卡的收益就被吃掉了。后面几讲的核心就是算清楚这笔账。
3. **复制和切分可以叠加。**一个大模型先切到 8 张卡上组成一组，再复制成很多组，是最常见的部署方式。

## 回顾

一张卡不够，有三个原因：放不下（70B 的 BF16 权重 141 GB，405B 812 GB，DeepSeek-V3 671 GB 的 FP8，再加上 KV Cache）；算不快（decode 每步读一遍权重，70B 单卡 42 ms，分到 8 张卡上同时读只要 5.3 ms）；扛不住（流量超过单卡容量）。前两个要把模型切开，第三个要把模型复制。训练每个参数约要 16 字节，比推理更依赖多卡。卡与卡之间的连接有快有慢：同一台服务器里的 NVLink 每个方向约 450 GB/s，跨服务器的网络约 50 GB/s。

把模型切开以后，几张卡要合作完成一次计算：有时要把各自的部分结果加起来，有时要把各自的一块拼成整体，有时要互相交换一部分数据。这些固定的通信模式有专门的名字。下一讲：**集合通信原语**。
