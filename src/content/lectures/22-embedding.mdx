上一讲把文字切成了 token，又换成了编号：“爱”是 1，“学AI”是 14，“推理”是 11。可编号只是词表里的位置，像学号一样。模型要做的是乘法、加法、点积，拿学号来做这些运算没有意义。

这一讲要解决的是：**怎么把一个编号，变成一个能参与计算、而且带着含义的向量？**答案出奇地简单：查一张表。这张表叫**嵌入表**，查出来的向量叫**词嵌入**（embedding）。第 1 讲里“我”的向量 (0.7, −0.6, −0.9, 0.3)，就是从 TinyLM 的嵌入表里查出来的。这一讲把这件事讲透，再用一个真正训练过的小模型，看看嵌入里的“含义”是怎么来的。

## 为什么不能直接用编号

最省事的做法是把编号本身当成输入：“爱”输入 1，“推理”输入 11。这样不行，因为数字自带了大小和距离：11 比 1 大 10 倍；11 和 14 只差 3，看起来“推理”和“学AI”很接近，而和“爱”离得很远。这些关系完全是分词时编号的顺序碰巧造成的，没有任何语言上的意义。如果模型拿编号直接做乘法、加法，它就会把这些虚假的关系当真。

另一种做法是**独热向量**（one-hot）：词表有 V 个 token，就用一个 V 维向量，第 id 位是 1，其余全是 0。TinyLM 的词表是“我、爱、学、AI、推理、`<eos>`”，“爱”（编号 1）就是 (0, 1, 0, 0, 0, 0)。这样所有 token 一律平等，没有谁大谁小。

可是平等得过了头。任意两个不同的独热向量，点积都是 0，余弦相似度也是 0（第 2 讲）：在它们眼里，“苹果”和“香蕉”的距离，与“苹果”和“推理”的距离一模一样，没有“相近”的概念。而且向量太长：Llama-3 的词表有 128256 个 token，每个独热向量就有 128256 维，几乎全是 0。

我们想要的是一种折中：**每个 token 一个不太长的向量（比如 4096 维），每一维都是可以调整的实数，意思相近的 token，向量也相近。**

## 查一张表

做法是准备一张 V 行、d 列的表 *E*，叫**嵌入表**（embedding table）或嵌入矩阵。第 i 行就是编号为 i 的 token 的向量，d 叫嵌入维度。要把编号变成向量，就取出表里对应的那一行：

$$
\mathbf{x} = E[\mathrm{id}]
$$

TinyLM 的嵌入表是 6 × 4 的：6 个 token，每个 4 维。“我爱学AI”的 4 个 token 编号是 [0, 1, 2, 3]，依次取出第 0、1、2、3 行，叠在一起，就得到一个 4 × 4 的矩阵 *X*。这正是第 3 讲做矩阵乘法时用的那个 *X*：从那时起，我们一直在用查表查出来的向量。

一句话有 s 个 token，查表的结果就是 s × d 的矩阵，每一行是一个 token 的向量。这就是模型真正的输入，后面所有的计算都从这里开始。

## 查表就是矩阵乘法

查表看起来和前面学的东西不一样，其实它就是一次矩阵乘法。

把“爱”的独热向量 (0, 1, 0, 0, 0, 0) 乘以嵌入表 *E*。按第 3 讲的“行乘列”，结果的第 j 个数是这个独热向量和 *E* 第 j 列的点积：0 × *E*<sub>0j</sub> + 1 × *E*<sub>1j</sub> + 0 × *E*<sub>2j</sub> + …，只有乘 1 的那一项留了下来，等于 *E*<sub>1j</sub>。所以整个结果就是 *E* 的第 1 行：

<div class="ai-formula">onehot(id) · <i>E</i> = <i>E</i> 的第 id 行</div>

一整句话也一样：把 s 个独热向量叠成 s × V 的矩阵，乘以 V × d 的 *E*，得到 s × d 的 *X*，和直接查表完全相同。

这告诉我们两件事。第一，**嵌入层就是一个线性层**（第 13 讲）：没有偏置，输入是独热向量，权重矩阵就是 *E*。所以它的参数可以和其他权重一样，用反向传播和梯度下降来训练。第二，实际计算时从不真的去乘那个几乎全是 0 的独热向量，那样做 V 倍的乘法，结果却只是取一行。直接取行，又快又省。

反向传播时也一样：一个 token 的梯度只会加回到它自己那一行上。一个 batch 里没出现的 token，它们的行这一步收不到梯度，原样不动。

<Note kind="point">嵌入表 E 有 V 行 d 列，每个 token 一行。查表 E[id] 等价于“独热向量 × E”，所以嵌入层就是一个输入为独热向量、没有偏置的线性层，它的每一个数都是要训练的参数。</Note>

## 嵌入是学出来的

TinyLM 的嵌入表是随机生成的，“我”的向量 (0.7, −0.6, −0.9, 0.3) 没有任何含义。嵌入里的“含义”从哪来？从训练来。

为了看清这一点，我们在一份很小的语料上真正训练了一个模型（代码在 `tinylm.py` 的 `lecture_22`）。语料是 16 种简单的句子，有的重复几遍，一共 14 个不同的词：

<div class="ai-formula">小猫 吃 鱼 · 小狗 吃 骨头 · 我 吃 苹果 · 我 吃 香蕉 · 你 学 推理 · 我 喜欢 小猫 · 我 学 AI ……</div>

模型的任务是：看前两个词，预测下一个词。比如看到“小猫 吃”，要预测“鱼”。它的结构是：两个词各查一次嵌入表（每个词 8 维），拼成 16 维，经过一个线性层和 ReLU，再经过一个线性层，得到 14 个词的打分，用交叉熵训练（第 16–20 讲的全套流程）。下一讲会细讲这个“预测下一个词”的任务，这一讲只关心训练完以后，嵌入表变成了什么样。

训练前，嵌入是随机数。和“苹果”余弦相似度最高的三个词是“学”（0.67）、“香蕉”（0.33）、“你”（0.27），毫无道理。训练后，变成了“香蕉”（0.99）、“鱼”（0.97）、“AI”（0.93）。和“我”最像的，训练前是“骨头”（0.69），训练后是“你”（0.64）。

为什么苹果、香蕉、鱼、骨头、AI、推理会挤在一起？它们在语料里的“作用”完全一样：都出现在句子的末尾，前面是“吃”“学”“喜欢”，后面跟着句号。模型用前两个词预测下一个词，当这些词作为前文出现时，下一个词都是句号，模型没有理由区分它们，于是它们的嵌入被推到了一起。“我”和“你”也类似：后面都可以接“吃”“喜欢”“学”，只是“我”更常学 AI、“你”更常学推理，所以相似但不完全相同。

有意思的是“小猫”和“小狗”并没有靠在一起。在这份语料里，小猫吃鱼，小狗吃骨头，作为前文时它们引出的下一个词不同，模型必须把它们区分开。

这就是嵌入的“含义”的本质：**两个词的嵌入相近，是因为它们在上下文中起的作用相近**。语言学里有一句老话：要了解一个词，就看它周围的词（分布假说）。大模型在海量文本上训练，嵌入学到的是一种比我们这个小例子丰富得多的“作用”：词性、意思、情感色彩、领域……每一种都对应向量空间里的某些方向。

## 用代码复现

下面的代码演示了查表、查表和独热乘法的等价、训练前后的相似词，以及反向传播时只有用到的行收到梯度；最后算一下 Llama-3-8B 的嵌入表有多大。

```python
import json
import numpy as np

t = json.load(open("tinylm.json", encoding="utf-8"))

# 1. TinyLM：编号 → 查表
vocab, E = t["config"]["vocab"], np.array(t["weights"]["embedding"])     # E: 6×4
ids = [vocab.index(w) for w in ["我", "爱", "学", "AI"]]
X = E[ids]                                                                # 一次取出 4 行
print("编号：", ids, " X 的形状：", X.shape)
print(X)

# 2. 查表 = 独热向量 × E
onehot = np.eye(len(vocab))[ids]                                          # 4×6，每行只有一个 1
print("独热 × E 和查表一样：", np.array_equal(onehot @ E, X))

# 3. 小语料上训练的嵌入：训练前后，和“苹果”“我”最像的词
ex = t["examples"]["22"]
V = ex["vocab"]
def nearest(E, word, k=3):
    En = E / np.linalg.norm(E, axis=1, keepdims=True)
    sims = En @ En[V.index(word)]
    order = [j for j in np.argsort(-sims) if V[j] != word][:k]
    return [(V[j], round(float(sims[j]), 2)) for j in order]
for name, key in [("训练前", "E0"), ("训练后", "E")]:
    Ek = np.array(ex[key])
    print(f"{name}：苹果 →", nearest(Ek, "苹果"), " 我 →", nearest(Ek, "我"))

# 4. 训练时，一步里只有用到的那几行会收到梯度
dX = np.ones_like(X)                                                      # 假设从上面传下来的梯度
dE = np.zeros_like(E)
np.add.at(dE, ids, dX)                                                    # 反向：梯度加回到对应的行
print("收到梯度的行：", [vocab[i] for i in range(len(vocab)) if dE[i].any()])

# 5. Llama-3-8B 的嵌入表
Vl, d = 128256, 4096
print(f"嵌入表 {Vl} × {d} = {Vl * d / 1e6:.0f}M 个参数，BF16 下 {Vl * d * 2 / 2**30:.2f} GiB；每个 token 只读其中 {d * 2 / 1024:.0f} KiB")
```

输出：

```text
编号： [0, 1, 2, 3]  X 的形状： (4, 4)
[[ 0.7 -0.6 -0.9  0.3]
 [-0.3 -0.1 -0.8 -0.2]
 [ 0.3 -0.3  0.6  0.6]
 [ 0.4  0.8  0.4 -0.6]]
独热 × E 和查表一样： True
训练前：苹果 → [('学', 0.67), ('香蕉', 0.33), ('你', 0.27)]  我 → [('骨头', 0.69), ('推理', 0.47), ('吃', 0.39)]
训练后：苹果 → [('香蕉', 0.99), ('鱼', 0.97), ('AI', 0.93)]  我 → [('你', 0.64), ('骨头', 0.33), ('推理', 0.28)]
收到梯度的行： ['我', '爱', '学', 'AI']
嵌入表 128256 × 4096 = 525M 个参数，BF16 下 0.98 GiB；每个 token 只读其中 8 KiB
```

前几行：“我爱学AI”的编号 [0, 1, 2, 3]，查出 4 × 4 的 *X*，和第 3 讲的一样；独热乘 *E* 的结果和查表完全相同。接着是训练前后的相似词，和正文里的数字一致。然后，假设上面传下来的梯度全是 1，加回嵌入表时，只有“我、爱、学、AI”这 4 行收到了梯度，“推理”和 `<eos>` 没有。最后一行是下一节要用的数。

## 到了大模型里

Llama-3-8B 的嵌入表是 128256 × 4096，约 5.25 亿个参数，用 BF16 存约 0.98 GiB。每个 token 被表示成 4096 维空间里的一个点。

查表本身几乎不花计算：每个 token 只是从显存里读出 4096 个数，8 KiB。和后面动辄几千万次乘加的线性层相比，可以忽略不计。但整张表必须放在显存里，因为下一个 token 是什么，事先不知道。多卡推理用张量并行（第 105、110 讲）时，嵌入表通常也会按词表切开，分到各张卡上。

嵌入表还有一个“镜像”：模型最后的输出层（第 33 讲），要把一个 4096 维的向量变成 128256 个词的打分，它的权重也是 4096 × 128256。有的模型让这两张表共用同一份参数，叫**权重绑定**（tied embeddings），能省下一份参数；GPT-2 就是这样做的。Llama-3-8B 没有绑定，两张表各自训练，合起来是上一讲算的 10.5 亿个参数。

## 容易混淆的地方

1. **嵌入的单独一维一般没有明确的意思。**我们说“意思相近的词向量相近”，指的是整个向量的方向和距离，而不是“第 3 维代表动物”。训练只关心整体效果，含义通常分散在很多维度的组合里。
2. **同一个词，嵌入永远是同一个向量。**“苹果”不管出现在“我吃苹果”还是“苹果发布了新手机”里，查表查出来的都是同一行。区分这两种意思，是后面的注意力层的工作（第 26 讲）：它根据上下文，把每个词的向量改造成“在这句话里”的意思。
3. **嵌入里没有位置信息。**“我爱你”和“你爱我”查出来的是同一组向量，只是顺序不同。模型怎么知道谁在前、谁在后，要靠第 25 讲的位置编码和第 37 讲的 RoPE。

## 回顾

编号本身没有可以计算的含义，独热向量又太长、而且所有词彼此一样远。词嵌入的做法是准备一张 V × d 的嵌入表，每个 token 一行，用编号查表取出对应的行，一句话就变成一个 s × d 的矩阵。查表等价于“独热向量 × E”，所以嵌入层就是一个没有偏置的线性层，表里的每个数都是参数，靠训练得到。训练之后，在上下文中作用相近的词，嵌入也相近：在我们的小语料里，句末的宾语挤成了一团，“我”和“你”靠在一起，而吃的东西不同的“小猫”和“小狗”被区分开了。

我们一直说模型的任务是“看前面的词，预测下一个词”。这个看起来很简单的任务，到底在学什么？为什么只靠它，就能学出嵌入里的“含义”，甚至学会写文章、做推理？下一讲：**预测下一个 token**。
