前两讲的注意力，每个词只算一组权重：它“看”句子里每个词的程度只有一套。可一个词和其他词的关系往往不止一种。读到“他把书还给了她，因为她明天要考试”里的第二个“她”时，你会同时想到好几件事：这个“她”指的是前面的哪个人（指代）；“考试”是谁的事（主语）；这一句和上一句是什么关系（因果）。如果只有一套 softmax 权重，它很难同时把高权重精准地分给好几个互不相关的词，往往只能折中平均一下。

**多头注意力**（multi-head attention）的做法是：把注意力拆成好几份，叫好几个**头**（head），每个头各算一套 q、k、v 和注意力权重，各看各的，最后把结果拼起来。这一讲先在 TinyLM 上把拆分和拼接算一遍，看清楚为什么多了头却没多参数，再看复读模型的两个头各学会了什么，最后看看 Llama-3 的 32 个头。

## 把向量切成几段

多头注意力不需要新的权重矩阵。*Q* = *XW*<sub>q</sub>、*K* = *XW*<sub>k</sub>、*V* = *XW*<sub>v</sub> 照常算，只是算完以后，**按列切成 n<sub>h</sub> 段**，每段交给一个头。TinyLM 的 d = 4，拆成 2 个头，每个头 *d*<sub>h</sub> = 2 维：*Q* 的前 2 列给头 1，后 2 列给头 2，*K*、*V* 也一样。

每个头用自己那 2 列，独立地做一遍上一讲的全套计算：打分、除以 √*d*<sub>h</sub>（现在是 √2）、因果掩码、softmax、加权求和。每个头得到一个 4 × 2 的输出。

两个头的输出**拼接**（concatenate）起来，又是 4 × 4；最后再乘一个 4 × 4 的输出矩阵 *W*<sub>o</sub>，把各个头的信息混合起来，就是这一层注意力的最终输出：

<div class="ai-formula">输出 = [head<sub>1</sub>, head<sub>2</sub>] · <i>W</i><sub>o</sub></div>

拿 TinyLM 算一下（带因果掩码）。两个头的注意力权重是：

| 提问的词 | 头 1 | 头 2 |
| --- | --- | --- |
| 我 | 1, 0, 0, 0 | 1, 0, 0, 0 |
| 爱 | 0.504, 0.496, 0, 0 | 0.484, 0.516, 0, 0 |
| 学 | 0.321, 0.32, 0.359, 0 | 0.414, 0.32, 0.266, 0 |
| AI | 0.222, 0.266, 0.231, 0.281 | 0.197, 0.265, 0.337, 0.201 |

两个头的权重已经不一样了：“学”这一行，头 1 最看重自己（0.359），头 2 最看重“我”（0.414）。因为两个头用的是 q、k 的不同的列，比较的是向量的不同“侧面”。不过 TinyLM 没有训练过，这些差别没有什么含义，也都不大。

下面的演示可以切换两个头，右边的 *Q*、*K*、*V* 只显示当前这个头用到的 2 列。下方的计算最后一行，写出了两个头拼接后乘 *W*<sub>o</sub> 的结果。

## 参数没有变多

一个容易误会的地方：多头并不意味着多了几倍的参数。*W*<sub>q</sub>、*W*<sub>k</sub>、*W*<sub>v</sub> 还是 d × d，*W*<sub>o</sub> 也是 d × d，和一个头时一模一样，TinyLM 里每个都是 16 个参数。变的只是**怎么用**：一个头时，4 维的 q 和 k 整体做一次点积，算出一套权重；两个头时，前 2 维和后 2 维各做一次点积、各自 softmax，算出两套独立的权重。

计算量也几乎一样。打分时，一个头是每对词做一次 4 维点积；两个头是每对词做两次 2 维点积，乘法总次数完全相同。多出来的只是 softmax 要做两遍。

既然几乎不花额外的参数和算力，多头就是一个非常划算的设计：把一次“看”拆成几次“从不同角度看”，每个头的权重可以集中在不同的地方，互不干扰。

## 两个头各学会了什么

TinyLM 没训练过，看不出头的分工。看复读模型：它的 d = 8，拆成 2 个头，每头 4 维。

<AttentionView model="copy" caption="图 28-2　复读模型的两个头。头 1：第 4–6 行回头看第 1–3 个词，负责复读。头 2：第 4–6 行几乎都盯着第 4 个词“。”。切换头、换几个词看看。" />

头 1 我们上一讲见过：在第二遍时，每个位置“回头看 3 格”，把第一遍对应的词搬过来。

切到头 2，图案完全不同：第 4、5、6 行的权重几乎都落在第 4 个词，也就是句号“。”上。它像是在标记“复读从这里开始”。

两个头哪个更重要？下面的代码做了一个实验：把某个头的输出强行置 0（相当于关掉它），看复读的正确率。两个头都在时是 100%；关掉头 1，正确率跌到 8.1%，几乎完全失败；关掉头 2，正确率还是 100%。

也就是说，在这个任务上，头 2 其实可有可无，所有的工作都是头 1 做的。这不是我们的小模型特有的现象。研究者在大模型里也发现：不同的头确实学会了各种不同的模式，有的看前一个词，有的看句首，有的跟踪指代关系；但同时，相当一部分头是冗余的，剪掉之后效果几乎不变。多头给了模型“分工”的机会，模型并不一定把每个头都用满。

## 用代码复现

下面的代码写了一个通用的多头因果注意力函数：先在 TinyLM 上拆成 2 个头，打印两个头的权重和最终输出；然后在复读模型上看两个头各看哪里，并分别关掉一个头，比较复读的正确率。

```python
import json
import numpy as np

t = json.load(open("tinylm.json", encoding="utf-8"))

def softmax(S):
    e = np.exp(S - S.max(axis=-1, keepdims=True))
    return e / e.sum(axis=-1, keepdims=True)

def multi_head(X, Wq, Wk, Wv, Wo, n_heads, off=()):
    """多头因果自注意力：Q、K、V 按列切成 n_heads 份，各算各的，拼起来再乘 W_o。off 里的头输出置 0。"""
    s, d = X.shape[-2], Wq.shape[1]
    d_h = d // n_heads
    Q, K, V = X @ Wq, X @ Wk, X @ Wv
    mask = np.triu(np.full((s, s), -np.inf), k=1)
    heads, weights = [], []
    for h in range(n_heads):
        c = slice(h * d_h, (h + 1) * d_h)                    # 第 h 个头用第 h 段列
        A = softmax(Q[..., c] @ np.swapaxes(K[..., c], -1, -2) / np.sqrt(d_h) + mask)
        weights.append(A)
        heads.append(np.zeros_like(V[..., c]) if h in off else A @ V[..., c])
    return np.concatenate(heads, axis=-1) @ Wo, weights      # 拼接：[s, d_h] × n_heads → [s, d]

# 1. TinyLM：d = 4 拆成 2 个头，每头 2 维
X = np.array(t["examples"]["03"]["X"])
L0 = t["weights"]["layers"][0]
Wq, Wk, Wv, Wo = (np.array(L0[k]) for k in ["W_q", "W_k", "W_v", "W_o"])
out, (A1, A2) = multi_head(X, Wq, Wk, Wv, Wo, 2)
print("头 1 的权重：\n", A1.round(3), "\n头 2 的权重：\n", A2.round(3))
print("“AI”的最终输出：", out[3].round(3), "  参数：W_q、W_k、W_v、W_o 各", Wq.size, "个，和一个头时一样")

# 2. 复读模型：两个头各看哪里，关掉一个头会怎样
ex = t["examples"]["27"]
p = {k: np.array(ex[k]) for k in ["E", "P", "Wq", "Wk", "Wv", "Wo", "WU"]}
vocab = ex["vocab"]
def run(seq, off=()):
    x = p["E"][seq] + p["P"][: seq.shape[-1]]
    o, W = multi_head(x, p["Wq"], p["Wk"], p["Wv"], p["Wo"], 2, off)
    return ((x + o) @ p["WU"]).argmax(-1), W
seq = np.array([vocab.index(w) for w in "我 学 AI 。 我 学 AI".split()])
_, (H1, H2) = run(seq)
print("头 1，第 4–6 行最大权重的位置：", (H1[3:6].argmax(1) + 1).tolist(), "  头 2：", (H2[3:6].argmax(1) + 1).tolist())
rng = np.random.default_rng(5)
tri = rng.integers(1, 14, (500, 3))
seqs = np.concatenate([tri, np.zeros((500, 1), int), tri], 1)
for off, name in [((), "两个头都在"), ((0,), "关掉头 1"), ((1,), "关掉头 2")]:
    pred = run(seqs, off)[0][:, 3:6]
    print(f"{name}：复读正确率 {np.mean(pred == seqs[:, 4:7]):.3f}")

# 3. Llama-3-8B：32 个查询头 × 128 维 = 4096
d, n_h = 4096, 32
print(f"Llama-3-8B：{n_h} 个头 × {d // n_h} 维 = {d}；每层每个 token 有 {n_h} 行注意力权重")
```

## 到了大模型里

**Llama-3-8B 的注意力有 32 个头**，每个头 128 维，32 × 128 = 4096，正好是隐藏维度。每一层、每个 token，都有 32 行各不相同的注意力权重。头的维度 *d*<sub>h</sub> = 128，就是上一讲缩放时除以的 √*d*<sub>k</sub> 里的那个 *d*<sub>k</sub>。

**多头天然适合并行。**每个头的计算完全独立，GPU 上可以同时算所有头。用多张 GPU 推理时，第 105、110 讲的张量并行最常见的切法，就是把头分给不同的卡：8 张卡，每张负责 4 个头，各算各的，最后在乘 *W*<sub>o</sub> 时再把结果合起来。

**KV Cache 是按头存的。**上一讲算 KV Cache 大小时用的是“8 个 KV 头”，而不是 32 个。这是第 39 讲的 **GQA**（分组查询注意力）：32 个查询头共用 8 组 k、v，每 4 个查询头共享一组。查询头还是 32 个，各看各的，但要缓存的 k、v 少到四分之一，KV Cache 也就小到四分之一。这一点对推理的显存和速度影响巨大，是从多头注意力出发做的第一个重要改进。

## 容易混淆的地方

1. **头的维度是切出来的，不是复制出来的。**每个头只拿到 *d* / *n*<sub>h</sub> 维，而不是完整的 *d* 维。头越多，每个头越“窄”。所以头数也不是越多越好：每个头太窄，它的 q、k 点积就分辨不出足够多的东西。
2. ***W*<sub>o</sub> 不是可有可无的。**拼接只是把各个头的结果并排放在一起，*W*<sub>o</sub> 才把它们真正混合起来，让后面的层能用到所有头的信息。它是注意力里的第四个权重矩阵，和 *W*<sub>q</sub>、*W*<sub>k</sub>、*W*<sub>v</sub> 一样大。
3. **头的分工不是设计出来的。**我们从来没有告诉复读模型“头 1 负责复读”，这是训练自己选出来的。同样的结构换一个随机种子重新训练，可能就变成头 2 负责复读，或者两个头各分担一部分。

## 回顾

多头注意力把 *Q*、*K*、*V* 按列切成几段，每段一个头，各自独立地做打分、缩放、掩码、softmax 和加权求和，再把各头的输出拼起来乘 *W*<sub>o</sub>。参数和计算量都和一个头时差不多，却让模型可以同时从几个角度看句子。复读模型的头 1 学会了“回头看 3 格”，关掉它复读就失败；头 2 盯着句号，关掉它毫无影响，大模型里也常有这样冗余的头。Llama-3-8B 每层 32 个头、每头 128 维；头与头互相独立，便于在 GPU 和多卡上并行；而 GQA 让多个查询头共享 k、v，大大缩小了 KV Cache。

注意力让每个词从上下文里收集了信息。可是 Transformer 往往有几十层，层数一深，训练就会变得很困难：第 18 讲说过，梯度要一层一层地往回传，传得越远越容易衰减。怎么让一个几十层的网络依然训得动？下一讲：**残差连接**。
