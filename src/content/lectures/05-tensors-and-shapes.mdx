读大模型的代码或论文，到处是这样的形状注释：`x: [b, s, d]`、`q: [b, h, s, d_h]`、`scores: [b, h, s, s]`。第 3 讲的矩阵只是两个数描述的一张平面表：几行、几列。这里却突然冒出了三个、四个数。

这一讲讲**张量**和它的**形状**。我们要弄清楚三件事：为什么矩阵不够用、非得引入三维和四维的张量；每次做运算（尤其是拆头、转置、求和）后，形状是怎么跟着变的；以及形状不同的两个张量，为什么有时候也能直接相加（广播）。这几条规则不涉及高深数学，却是读懂大模型代码最顺手的工具：看一段陌生代码，先盯住每一步的形状变化，往往就明白了它在做什么。

## 从数到张量：为什么需要更高维

先把熟悉的东西按维度从小到大排一排：

- 一个单独的数，比如 0.7，叫**标量**（scalar），形状是 `[]`（没有维度）。
- 一串有顺序的数，比如第 1 讲“我”的向量 (0.7, −0.6, −0.9, 0.3)，是**向量**（vector），形状 `[4]`：1 个维度，长度 4。
- 一张平面表，比如第 3 讲 4 个词叠成的 X，是**矩阵**（matrix），形状 `[4, 4]`：2 个维度，4 行 4 列。

那什么时候二维矩阵不够用呢？想象一下真实的大模型服务器：同一时刻可能有 2 个用户（甚至 64 个用户）同时发来请求，GPU 为了吃满算力，要把这几句话打包在一起算。1 句话是 1 张 `[4, 4]` 的表；2 句话就是把 2 张 `[4, 4]` 的表叠在一起，变成一个立体的小方块，形状 `[2, 4, 4]`。

到了第 28 讲的多头注意力，还要把每个词的 4 维向量拆成 2 个独立的“注意力头”，每个头看 2 维。于是维度又多了一层，变成 `[2, 2, 4, 2]`。

这种任意维度的“数字阵列”，统称**张量**（tensor）。标量、向量、矩阵其实都是张量的特例：0 维张量、1 维张量、2 维张量。**形状**（shape）就是把每个维度的长度按从外到内的顺序列出来；维度的个数叫张量的**阶**或**维数**（注意区分：4 维向量说的是长度 `[4]`，4 维张量说的是有 4 个轴，比如 `[2, 2, 4, 2]`）。

## [b, s, d] 读作什么

大模型里最核心、最常见的形状是 `[b, s, d]`（全站的符号约定）：

<dl class="ai-defs"><dt>b</dt><dd>批大小（batch）：一次同时处理几个序列（几句话、几个请求）</dd><dt>s</dt><dd>序列长度（sequence）：每个序列有几个 token</dd><dt>d</dt><dd>隐藏维度：每个 token 用几维的向量表示</dd></dl>

读一个多维形状，最好的办法是**从左往右“剥洋葱”**：
- `x` 的形状是 `[b, s, d]`：最外层有 `b` 句话；
- 选定第 `i` 句话 `x[i]`，剥掉第一层，剩下形状 `[s, d]`（一张二维矩阵，s 个词）；
- 再选定第 `j` 个词 `x[i, j]`，剥掉第二层，剩下形状 `[d]`（一个 d 维向量）；
- 最后选定第 `t` 个分量 `x[i, j, t]`，就是一个具体的数。

用 TinyLM 举例：一批 2 句话，“我 爱 学 AI”和“AI 爱 学 推理”。先分词得到编号（第 21 讲），形状 `[2, 4]`：第一句是 [0, 1, 2, 3]，第二句是 [3, 1, 2, 4]。再查嵌入表（第 22 讲）把每个编号换成一个 4 维向量，就得到形状 `[2, 4, 4]` 的 x。`x[1, 3]` 是第 2 句（下标从 0 算起，所以 1 是第 2 句）第 4 个词“推理”的向量 (0.7, 0.3, −0.8, −0.4)。

## 运算之后形状怎么变

大模型里反复出现的张量运算，形状的变化都可以归结为下面五条规则。

**1. 矩阵乘法只看最后两维。**第 3 讲的规则是 `[m, k] @ [k, n] → [m, n]`。对更高阶的张量，矩阵乘法只作用在**最后两个维度**上，前面多出来的维度全都当作“批”，一一对应地各自算：

<div class="ai-formula">[..., m, k] @ [..., k, n] → [..., m, n]</div>

比如 x 是 `[2, 4, 4]`，权重 W 是 `[4, 4]`（前面缺的维度会自动对齐）：`x @ W` 得到 `[2, 4, 4]`，相当于 2 句话各自独立做一次第 3 讲的矩阵乘法。第一句算出的结果，和第 3 讲的 C 完全一样。

**2. reshape：换一种切法，不搬动数据。**`reshape` 只改变看待同一串数字的“分组方式”，不改变数字在内存里的先后顺序。比如把 `[2, 4, 4]` 改成 `[2, 4, 2, 2]`：每句话的 4 个词不动，只是把每个词原本 4 维的向量，拆成 2 个头、每个头 2 维（d = h · d<sub>h</sub>）。

**3. transpose：真正交换两个维度。**看到这里你可能会想：既然目标是把 `[b, s, d]` = `[2, 4, 4]` 变成 `[b, h, s, d_h]` = `[2, 2, 4, 2]`，为什么不一步直接 `reshape(2, 2, 4, 2)`，非要多此一举先 `reshape` 再 `transpose`？

这就是初学者最容易踩的坑！假设一句话有 2 个词（s = 2），每个词 4 维，记成 `[词0前2维, 词0后2维, 词1前2维, 词1后2维]`。如果直接 `reshape(1, 2, 2, 2)`，计算机会按顺序把前 4 个数全塞给第 1 组、后 4 个数全塞给第 2 组——结果“词 0 的全部 4 维”全跑进了头 0，“词 1 的全部 4 维”全跑进了头 1，词和头彻底乱套了！

正确的做法分两步：先 `reshape(2, 4, 2, 2)`，确保每个词的前 2 维归头 0、后 2 维归头 1；然后用 `transpose(1, 2)` 交换第 1 维（s）和第 2 维（h），变成 `[2, 2, 4, 2]`。这时每个头内部才真正把 4 个词的 2 维向量排在了一起，可以独立算注意力。接着做 `q @ kᵀ`（最后两维 `[s, d_h] @ [d_h, s]`），就得到每个头里两两的打分 `[b, h, s, s]` = `[2, 2, 4, 4]`。

**4. 逐元素运算：形状不变。**两个形状相同的张量相加、相乘，或者对每个数过一次激活函数（第 14 讲），形状完全不变。

**5. 归约（reduce）：沿哪一维，哪一维消失。**对 `[2, 4, 4]` 沿最后一维求和（`sum(axis=-1)`），得到 `[2, 4]`：每个 token 的 4 个分量加成一个数，长度为 4 的那一维被“压扁”消失了；沿第 1 维（token 维）求平均，得到 `[2, 4]`：每句话的 4 个 token 平均成一个 4 维向量。softmax（第 6 讲）、归一化（第 30 讲）都要指定沿哪一维做。

## 广播：形状不同也能相加

第 13 讲的线性层要给 `[s, d]` 的结果加上一个偏置向量 **b**，形状只有 `[d]`，两者维数都不一样，怎么加？约定的做法叫**广播**（broadcasting）：在逻辑上把小的那个自动复制对齐，再逐元素相加。

怎么知道两个形状能不能广播？记住一条死规则：**从最后一维（最右边）开始向左对齐比较**：

1. 对齐的这一维，要么两个长度相等，要么其中一个是 1；
2. 维数少的那个，左边缺的维度全部当成 1；
3. 长度为 1 的维度，会被逻辑复制到和另一个一样长。

举两个例子就明白了：
- `[2, 4, 4]` 加 `[4]`：最右边都是 4（相等）；`[4]` 左边缺两维，补成 `[1, 1, 4]`；再把两个 1 复制成 2 和 4，对齐成 `[2, 4, 4]`。效果就是同一个 4 维偏置加到每句话的每一个词上。
- `[2, 4, 4]` 加 `[2]`：最右边 4 和 2 不相等，且都不是 1——直接报错！如果你想给每句话加不同的数，必须写成 `[2, 1, 1]`。

广播在大模型里到处都是：注意力的掩码 `[s, s]` 加到打分 `[b, h, s, s]` 上（第 27 讲），归一化的缩放参数 `[d]` 乘到 `[b, s, d]` 上（第 30 讲）。它既省去了手写循环的麻烦，也不会真的在显存里复制出好几份拷贝。

<Note kind="point">张量是任意维度的数的阵列，形状是每一维的长度。大模型最常见的是 [b, s, d]：b 个序列、每个 s 个 token、每个 d 维。矩阵乘法作用在最后两维；reshape 改分组不动数据，transpose 交换维度；逐元素运算形状不变，沿哪一维归约哪一维就消失；形状不同时按广播规则从最后一维向左对齐。</Note>

## 形状决定了大小

张量占多少显存，算起来非常简单：把形状里所有的数乘起来（总共有多少个数字），再乘以每个数字占的字节数（第 10 讲）。换成 Llama-3-8B 的尺寸（一批 8 个请求、每个 2048 个 token、d = 4096、32 个头）：

- 一层的输入 `[8, 2048, 4096]`：8 × 2048 × 4096 ≈ 6710 万个数，BF16（每数 2 字节）下约 **134 MB**。
- 注意力的打分 `[8, 32, 2048, 2048]`：8 × 32 × 2048 × 2048 ≈ 10.7 亿个数，BF16 下约 **2.1 GB**，而这仅仅是一层的一个中间结果。

后者里出现了 s × s，序列长度翻倍，这个张量就变成 4 倍大。这是第 84 讲 FlashAttention 要解决的核心痛点。习惯了看形状，这类显存炸弹一眼就能看出来。

## 用代码复现

下面的代码用 NumPy 和 TinyLM 的数据，把演示里的步骤走一遍，打出每一步的形状；最后算 Llama-3-8B 尺寸下两个张量的大小。（先在 `tinylm/` 目录运行一次 `python tinylm.py`。）

```python
import json
import numpy as np

tl = json.load(open("tinylm.json", encoding="utf-8"))
vocab, E = tl["config"]["vocab"], np.array(tl["weights"]["embedding"])     # 词表 6 个词，嵌入表 [6, 4]
W = np.array(tl["examples"]["03"]["W"])                                     # 第 3 讲那个 4×4 的权重矩阵

# 一批 2 句话，每句 4 个词：先变成编号，形状 [b, s] = [2, 4]
sents = [["我", "爱", "学", "AI"], ["AI", "爱", "学", "推理"]]
ids = np.array([[vocab.index(w) for w in s] for s in sents])
print("编号 ids：", ids.shape, ids.tolist())

x = E[ids]                                        # 查表：每个编号换成一个 4 维向量 → [b, s, d]
print("查嵌入表 x：", x.shape, "，x[1, 3] 是第 2 句第 4 个词“推理”的向量", x[1, 3].tolist())

q = x @ W                                         # 最后一维和 W 相乘：[2, 4, 4] @ [4, 4] → [2, 4, 4]
print("乘权重 q = x @ W：", q.shape, "，和第 3 讲的 C 一样：", np.allclose(q[0], np.array(tl["examples"]["03"]["C"]), atol=0.006))

h, dh = 2, 2                                      # 拆成 2 个头，每头 2 维
qh = q.reshape(2, 4, h, dh).transpose(0, 2, 1, 3) # [b, s, d] → [b, s, h, dh] → [b, h, s, dh]
print("拆成多头：", q.shape, "→", q.reshape(2, 4, h, dh).shape, "→ 交换第 1、2 维", qh.shape)

scores = qh @ qh.transpose(0, 1, 3, 2)            # [b, h, s, dh] @ [b, h, dh, s] → [b, h, s, s]
print("每个头里两两打分：", scores.shape)

b = np.array([0.1, 0.2, 0.3, 0.4])                # 广播：[2, 4, 4] + [4]，b 被复制到每句话的每个词上
print("加偏置（广播）：", (q + b).shape, "，q[1, 2] + b 和 (q + b)[1, 2] 一样：", np.allclose(q[1, 2] + b, (q + b)[1, 2]))
print("对最后一维求和：", q.sum(axis=-1).shape, "；对第 1 维（词）求平均：", q.mean(axis=1).shape)

# 换成 Llama-3-8B 的尺寸：一批 8 个请求、每个 2048 个 token、d = 4096、32 个头
B, S, D, H = 8, 2048, 4096, 32
print(f"Llama-3-8B：一层的输入 [b, s, d] = [{B}, {S}, {D}]，{B * S * D / 1e6:.0f}M 个数，BF16 {B * S * D * 2 / 1e6:.0f} MB；"
      f"注意力打分 [b, h, s, s] = [{B}, {H}, {S}, {S}]，{B * H * S * S * 2 / 1e9:.1f} GB")
```

输出：

```text
编号 ids： (2, 4) [[0, 1, 2, 3], [3, 1, 2, 4]]
查嵌入表 x： (2, 4, 4) ，x[1, 3] 是第 2 句第 4 个词“推理”的向量 [0.7, 0.3, -0.8, -0.4]
乘权重 q = x @ W： (2, 4, 4) ，和第 3 讲的 C 一样： True
拆成多头： (2, 4, 4) → (2, 4, 2, 2) → 交换第 1、2 维 (2, 2, 4, 2)
每个头里两两打分： (2, 2, 4, 4)
加偏置（广播）： (2, 4, 4) ，q[1, 2] + b 和 (q + b)[1, 2] 一样： True
对最后一维求和： (2, 4) ；对第 1 维（词）求平均： (2, 4)
```

## 容易混淆的地方

1. **“4 维向量”和“4 维张量”不是一回事。**前者是有 4 个分量的一串数，形状 `[4]`；后者有 4 个维度，比如 `[2, 2, 4, 2]`。说的时候最好直接报出形状。
2. **reshape 和 transpose 不能互换。**`[s, h, d_h]` 直接 reshape 成 `[h, s, d_h]` 会把不同词和不同头的数据混在一起；要让每个头的 token 排在一起，必须用 transpose。
3. **广播是从右往左对齐的。**`[4, 4] + [4]` 是给每一行加，不是给每一列加；要给每一列加，需要把后者写成 `[4, 1]`。

## 回顾

张量是任意维度的数的阵列：标量、向量、矩阵是 0、1、2 维的特例。形状是每一维的长度，`[b, s, d]` 表示 b 个序列、每个 s 个 token、每个 token d 维，`x[i, j]` 是第 i 个序列第 j 个 token 的向量。矩阵乘法作用在最后两维，前面的维度当作批；reshape 只改分组不动数据，transpose 交换维度；逐元素运算形状不变，归约让那一维消失；形状不同时按广播规则从最后一维向左对齐。TinyLM 一批 2 句经过嵌入、乘权重、拆头、打分，形状从 `[2, 4]` 变到 `[2, 2, 4, 4]`。张量的大小等于形状的乘积乘以每个数的字节数，Llama-3-8B 的一层输入就有 134 MB。

形状为 `[b, h, s, s]` 的注意力打分，每个数都是一个“分数”，有正有负、可大可小。模型最后要的却是“概率”：都在 0 到 1 之间，加起来等于 1。怎么把任意一组分数变成概率？下一讲：**指数、对数与 softmax**。
