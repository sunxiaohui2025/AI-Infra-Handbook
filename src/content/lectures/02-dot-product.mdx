上一讲结尾，我们用“距离”判断一种新水果像哪种水果：离苹果最近，就说它像苹果。这个办法很自然，在水果的例子里也确实好用。

可是到了大模型里，判断两个向量像不像，最常用的并不是距离，而是一种叫**点积**的量法，以及由它派生出来的**余弦相似度**。这一讲就来回答两个问题：距离到底哪里不够好？点积又是怎么量“像不像”的？

## 用距离量，会出什么问题

换一个例子。假设我们想让电脑判断两篇文章是不是在讲同一件事。最简单的办法是数关键词：每篇文章数一数“GPU”出现了几次、“美食”出现了几次，得到一个 2 维向量。

现在有三篇文章：

| 文章 | “GPU”出现次数 | “美食”出现次数 | 向量 |
| --- | --- | --- | --- |
| 一篇讲 GPU 的短文 | 4 | 1 | (4, 1) |
| 一篇讲 GPU 的长文 | 12 | 3 | (12, 3) |
| 一篇讲美食的文章 | 1 | 5 | (1, 5) |

凭常识就知道：前两篇都在讲 GPU，只是一篇短、一篇长，长文里每个词出现的次数都是短文的 3 倍而已；第三篇讲的是完全不同的话题。所以“GPU 短文”应该更像“GPU 长文”。

我们用上一讲的距离来算一算。短文到长文的距离是 √((4−12)² + (1−3)²) = √68 ≈ 8.25；短文到美食文章的距离是 √((4−1)² + (1−5)²) = √25 = 5。**按距离，短文反而更像美食文章**——和常识正好相反。

在下面的演示里亲手试一下。绿色箭头是“新文章”，默认就是那篇 GPU 短文 (4, 1)。右边的表同时列出它到两篇文章的距离和“余弦相似度”（这个量马上就会讲到），每一列里“最像”的那一项会标绿：

<VectorPlane mode="compare" aName="新文章" xLabel="“GPU”次数" yLabel="“美食”次数" points={[{ name: 'GPU 长文', x: 12, y: 3 }, { name: '美食文章', x: 1, y: 5 }]} caption="图 2-1　同一篇 GPU 短文，按距离量最像美食文章，按余弦相似度量最像 GPU 长文。拖动绿色箭头，看两种量法什么时候一致、什么时候分歧。" />

问题出在哪里？看图就明白了。GPU 长文 (12, 3) 和短文 (4, 1) 指向**完全相同的方向**，只是长文的箭头长了 3 倍——上一讲学过，这正是数乘：(12, 3) = 3 × (4, 1)。距离把“长度不同”也算成了差别，而文章长短恰恰是我们不关心的。

## 方向比长度更重要

从这个例子可以看出，判断两篇文章“讲的是不是同一件事”，真正有用的信息是**箭头的方向**，而不是箭头的长短。方向一致，说明各个关键词出现的比例一致；长短不同，只说明文章篇幅不同。

那么怎么量两个方向是否一致？最直接的想法是量两个箭头之间的**夹角** θ：夹角越小，方向越接近。θ = 0° 时两个箭头完全同向；θ = 90° 时互相垂直，可以理解为“毫不相关”；θ = 180° 时方向完全相反。

问题是，直接量角度并不方便——给你两串几千维的数字，角度要怎么量？这时候就轮到点积出场了。它只用乘法和加法，就能把夹角的信息算出来。

## 点积：对应分量相乘再相加

两个维度相同的向量 **a** 和 **b**，它们的点积定义为：**把对应分量相乘，再全部加起来**。

<div class="ai-formula"><b><i>a</i></b> · <b><i>b</i></b> = <i>a</i><sub>1</sub><i>b</i><sub>1</sub> + <i>a</i><sub>2</sub><i>b</i><sub>2</sub> + … + <i>a</i><sub>n</sub><i>b</i><sub>n</sub></div>

注意结果是**一个数**，不是向量。这一点和上一讲的加法、数乘不同：加法和数乘的结果还是向量，点积则把两个向量“压缩”成了一个数。

拿刚才的文章算一下：

<div class="ai-formula">(4, 1) · (12, 3) = 4×12 + 1×3 = 51　　(4, 1) · (1, 5) = 4×1 + 1×5 = 9</div>

GPU 短文和 GPU 长文的点积是 51，和美食文章只有 9。这次的排序符合常识了。但只看这两个数还说明不了太多：51 大，有一部分原因只是长文的数字本身就大。点积和夹角之间到底是什么关系，我们需要再往前走一步。

## 点积和夹角的关系

结论先写出来：

<div class="ai-formula"><b><i>a</i></b> · <b><i>b</i></b> = |<b><i>a</i></b>| |<b><i>b</i></b>| cos <i>θ</i></div>

**点积等于两个向量的长度相乘，再乘以夹角的余弦**。这个式子是这一讲的核心。你在大学里大概见过它，这里我们用余弦定理把它推一遍，每一步都写出来。

把 **a**、**b** 画成从原点出发的两个箭头，再把两个箭头的末端连起来，就得到一个三角形。第三条边就是向量 **a** − **b**，它的长度是 |**a** − **b**|。

第一步，对这个三角形用余弦定理。夹角 θ 对着的边是 |**a** − **b**|，所以

<div class="ai-formula">|<b><i>a</i></b> − <b><i>b</i></b>|<sup>2</sup> = |<b><i>a</i></b>|<sup>2</sup> + |<b><i>b</i></b>|<sup>2</sup> − 2 |<b><i>a</i></b>| |<b><i>b</i></b>| cos <i>θ</i></div>

第二步，换一种方法算左边。上一讲说过，长度的平方就是各分量平方之和。以 2 维为例：

<div class="ai-formula">|<b><i>a</i></b> − <b><i>b</i></b>|<sup>2</sup> = (<i>a</i><sub>1</sub> − <i>b</i><sub>1</sub>)<sup>2</sup> + (<i>a</i><sub>2</sub> − <i>b</i><sub>2</sub>)<sup>2</sup></div>

把两个平方展开：

<div class="ai-formula">= <i>a</i><sub>1</sub><sup>2</sup> − 2<i>a</i><sub>1</sub><i>b</i><sub>1</sub> + <i>b</i><sub>1</sub><sup>2</sup> + <i>a</i><sub>2</sub><sup>2</sup> − 2<i>a</i><sub>2</sub><i>b</i><sub>2</sub> + <i>b</i><sub>2</sub><sup>2</sup></div>

把同类的项归到一起：*a*<sub>1</sub><sup>2</sup> + *a*<sub>2</sub><sup>2</sup> 正好是 |**a**|<sup>2</sup>，*b*<sub>1</sub><sup>2</sup> + *b*<sub>2</sub><sup>2</sup> 正好是 |**b**|<sup>2</sup>，剩下的两项是 −2(*a*<sub>1</sub>*b*<sub>1</sub> + *a*<sub>2</sub>*b*<sub>2</sub>)，括号里的正是点积。所以

<div class="ai-formula">|<b><i>a</i></b> − <b><i>b</i></b>|<sup>2</sup> = |<b><i>a</i></b>|<sup>2</sup> + |<b><i>b</i></b>|<sup>2</sup> − 2 <b><i>a</i></b> · <b><i>b</i></b></div>

第三步，对比第一步和第二步的两个式子。左边一样，右边的 |**a**|<sup>2</sup> + |**b**|<sup>2</sup> 也一样，于是剩下的部分必须相等：2 **a** · **b** = 2 |**a**| |**b**| cos θ，两边除以 2 就得到了结论。

这个推导在 n 维时一字不改地成立：展开平方时，每个分量各自贡献一项，归类后依然是“两个长度的平方”减去“两倍点积”。

<Note kind="point">点积里同时混着两样东西：两个向量的长度，和它们之间夹角的余弦。长度越长、方向越一致，点积越大。</Note>

## 拖动两个向量看一看

有了 **a** · **b** = |**a**| |**b**| cos θ，就能看出点积的正负直接反映方向关系：长度总是正的，所以点积的符号和 cos θ 的符号一样。

在下面的演示里拖动 **a** 和 **b**。右边会逐项算出点积、两个长度、cos θ 和夹角；图里的弧线标出夹角 θ，那条半透明的粗线是 **b** 在 **a** 方向上的投影——可以想象成从 **b** 的末端往 **a** 所在的直线上垂直打一束光，**b** 在这条直线上留下的“影子”。

<VectorPlane mode="dot" caption="图 2-2　点积、夹角与投影。默认 a = (3, 1)、b = (1, 3)，a · b = 6，夹角约 53°。试着把 b 拖到和 a 垂直、和 a 反向的位置。" />

默认状态下 **a** = (3, 1)**，b** = (1, 3)。点积是 3×1 + 1×3 = 6；两个向量的长度都是 √10 ≈ 3.16；于是 cos θ = 6 ÷ (3.16 × 3.16) = 0.6，夹角约 53°。

接着做三个小实验：

- **把 b 拖到 (−1, 3)**。点积变成 3×(−1) + 1×3 = 0，夹角正好 90°，投影的影子缩成了一个点**。点积为 0，就表示两个向量互相垂直。**
- **把 b 拖到 (−3, −1)**，也就是 **a** 的正对面。点积变成 −9 − 1 = −10，是负数，夹角 180°。点积为负，说明两个向量大致反向。
- **把 b 拖到 (1.5, 0.5)**，和 **a** 同向、长度是 **a** 的一半。点积是 4.5 + 0.5 = 5；再拖到 (3, 1)，和 **a** 完全重合，点积变成 10。方向没变，只是长度变了，点积就跟着变——点积对长度是敏感的。

最后一个实验说明了点积的局限：它既量方向，也量长度。想只比较方向，就得把长度的影响去掉。

## 余弦相似度：去掉长度的影响

去掉长度的办法很直接：既然 **a** · **b** = |**a**| |**b**| cos θ，那就把两个长度除掉，只留下 cos θ。

<div class="ai-formula">cos <i>θ</i> = <b><i>a</i></b> · <b><i>b</i></b> ÷ (|<b><i>a</i></b>| |<b><i>b</i></b>|)</div>

这个量叫做**余弦相似度**（cosine similarity）。它的取值范围是 −1 到 1：1 表示方向完全相同，0 表示互相垂直，−1 表示方向完全相反。不管向量本身有多长，结果都落在这个范围里。

回到文章的例子：

- GPU 短文和 GPU 长文：51 ÷ (√17 × √153) = 51 ÷ 51 = **1**。方向完全相同，余弦相似度达到最大值。
- GPU 短文和美食文章：9 ÷ (√17 × √26) ≈ 9 ÷ 21.02 ≈ **0.43**。

这次的结论和常识完全一致。回到图 2-1 再拖一拖，你会发现：只要沿着 GPU 长文的方向拖，不管拖多远，余弦相似度一直是 1；而距离会随着你拖动不停变化。

<Note kind="column" title="专栏　先把长度变成 1">
如果事先把所有向量的长度都缩放成 1（每个向量除以它自己的长度，这叫**归一化**），那么 |**a**| = |**b**| = 1，点积就直接等于余弦相似度，连除法都省了。

很多做“语义检索”的系统就是这么做的：先把每段文字变成一个向量并归一化，存起来；用户提问时，把问题也变成归一化的向量，再和库里的向量逐个算点积，点积最大的几段就是最相关的资料。第 22 讲讲词嵌入时还会提到这类用法。
</Note>

## 在 TinyLM 的词向量上算一遍

上一讲我们看过 TinyLM 的词向量表，每个词是一个 4 维向量。点积的规则在 4 维时完全一样，我们拿“我”和“推理”来算一遍：

<div class="ai-formula">“我”= (0.7, −0.6, −0.9, 0.3)　“推理”= (0.7, 0.3, −0.8, −0.4)</div>

第一步，对应分量相乘：0.7×0.7 = 0.49，(−0.6)×0.3 = −0.18，(−0.9)×(−0.8) = 0.72，0.3×(−0.4) = −0.12。

第二步，加起来：0.49 − 0.18 + 0.72 − 0.12 = **0.91**。这就是点积。

第三步，算两个长度。|我| = √(0.49 + 0.36 + 0.81 + 0.09) = √1.75 ≈ 1.32，|推理| = √(0.49 + 0.09 + 0.64 + 0.16) = √1.38 ≈ 1.17。

第四步，除一下：0.91 ÷ (1.32 × 1.17) ≈ **0.59**。夹角大约 54°。

## 大模型为什么偏爱点积

讲到这里，你可能会问：既然余弦相似度更“干净”，大模型为什么还到处用点积？

第一个原因是**便宜**。一个 d 维的点积，只要 d 次乘法和 d − 1 次加法，大约 2d 次浮点运算（FLOPs）。4096 维的向量算一次点积，大约 8192 次运算。没有开方，也没有除法。

第二个原因是**适合成批计算**。下一讲（第 3 讲）会看到，矩阵乘法本质上就是一大张点积表：把一批向量和另一批向量两两做点积。GPU 上专门有一种硬件单元来做这件事，速度极快。能写成点积的计算，就能交给这种硬件。

第三个原因是**长度有时候也是信息**。点积对长度敏感，在有些场景里这反而是我们想要的。第 26 讲的注意力机制，就是用点积给“每个词该关注哪些词”打分；向量的长度也会影响打分的高低，模型会在训练中学会利用这一点。

从 Infra 的角度看，点积的计算量会以一种很有意思的方式增长。注意力机制里，一句话中的**每个词都要和每个词**做一次点积。假设一段输入有 s = 1000 个词，就要算 1000 × 1000 = 100 万个点积，而且模型的每一层、每一个注意力头都要算一遍。按大纲里 Llama-3-8B 的配置（32 层、每层 32 个注意力头、每个头 128 维，写正文前请对照官方配置核实）粗略算：

<div class="ai-formula">1000² × 32 个头 × 2 × 128 ≈ 8.2 × 10<sup>9</sup> FLOPs（每层）　× 32 层 ≈ 2.6 × 10<sup>11</sup> FLOPs</div>

这还只是“打分”这一步。更值得注意的是它的增长方式：输入长度 s 变成原来的 10 倍，点积的个数会变成原来的 **100 倍**，因为它和 s² 成正比。为什么长文本推理又慢又贵，这里就埋下了第一个伏笔。（第 27 讲会讲到，生成文字时每个词只需要看前面的词，实际计算量大约能减半，但仍然和 s² 成正比。）

## 用代码试一试

在 `tinylm/` 目录先运行一次 `python tinylm.py`，再运行下面的代码。NumPy 里，`a @ b` 对两个一维数组就是点积（写成 `np.dot(a, b)` 也一样）：

```python
import json
import numpy as np

short_gpu = np.array([4, 1])    # 讲 GPU 的短文：“GPU”4 次，“美食”1 次
long_gpu = np.array([12, 3])    # 同一主题的长文：每个词的次数都是短文的 3 倍
food = np.array([1, 5])         # 讲美食的文章

def cos_sim(a, b):
    return (a @ b) / (np.linalg.norm(a) * np.linalg.norm(b))

print(np.linalg.norm(short_gpu - long_gpu), np.linalg.norm(short_gpu - food))  # 距离
print(short_gpu @ long_gpu, short_gpu @ food)                                   # 点积
print(cos_sim(short_gpu, long_gpu), cos_sim(short_gpu, food))                   # 余弦相似度

tiny = json.load(open("tinylm.json", encoding="utf-8"))
vocab = tiny["config"]["vocab"]
E = np.array(tiny["weights"]["embedding"])
wo, tl = E[vocab.index("我")], E[vocab.index("推理")]
print(wo * tl)                   # 对应分量相乘
print(wo @ tl)                   # 再加起来：点积
print(cos_sim(wo, tl), np.degrees(np.arccos(cos_sim(wo, tl))))
```

输出：

```text
8.246211251235321 5.0
51 9
1.0 0.4280863447390447
[ 0.49 -0.18  0.72 -0.12]
0.9099999999999999
0.585575401399886 54.156350110779144
```

逐行对照：距离 8.25 和 5，按距离量短文更像美食文章；点积 51 和 9；余弦相似度 1.0 和 0.43。后三行是“我”和“推理”：先得到对应分量的乘积 (0.49, −0.18, 0.72, −0.12)，加起来是点积 0.91，余弦相似度 0.59，夹角约 54°，和手算一致。

你可能注意到了，点积打印出来是 0.9099999999999999 而不是 0.91。这不是算错了，而是计算机存小数时的精度限制：0.49、0.72 这样的小数在二进制里存不准，加起来就差了一点点。这个现象在大模型里非常重要，第 10 讲会专门讲。

## 容易混淆的地方

1. **点积和“对应分量相乘”不是一回事**。在 NumPy 里，`a * b` 只做了第一步，得到的还是一个向量 (0.49, −0.18, 0.72, −0.12)；`a @ b` 或 `np.dot(a, b)` 才会再加起来，得到一个数 0.91。
2. **余弦相似度为 0 不代表“相反”**。0 表示互相垂直，可以理解为“没关系”；方向相反是 −1。
3. **余弦相似度高不等于两个向量相同**。(4, 1) 和 (12, 3) 的余弦相似度是 1，但它们并不相等，只是方向相同。如果长度本身也有意义，就不能只看余弦相似度。

## 回顾

这一讲从一个反例出发：用距离量文章的相似程度，会把“篇幅不同”误当成“内容不同”。真正有用的是方向，而点积能用乘法和加法把方向的信息算出来：**a** · **b** = |**a**| |**b**| cos θ。点积的正负告诉我们两个向量同向、垂直还是反向；再除以两个长度，就得到只看方向的余弦相似度。大模型偏爱点积，因为它便宜，又能成批地交给 GPU 计算；注意力机制里每个词都要和每个词做点积，这也让计算量随输入长度的平方增长。

这一讲每次只算一个点积。可是在注意力机制里，一次要算成千上万个：一批向量和另一批向量两两之间都要算。有没有一种写法，能把“一批向量对一批向量”的所有点积一次表达出来，一次交给硬件去算？这就是下一讲的内容：**矩阵与矩阵乘法**。
