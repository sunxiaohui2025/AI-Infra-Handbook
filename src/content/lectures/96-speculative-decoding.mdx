自回归生成（第 24 讲）有一个根本的限制：一步只能生成一个 token，因为下一个 token 要等上一个出来才能算。而第 68 讲算过，小批量的 decode 一步几乎全花在读权重上，Llama-3-8B 一步约 4.83 ms，算力只用了不到 1%。

这里藏着一个机会。代码算了一下：让大模型一次前向处理 **1 个** token 约 4.83 ms，处理 **5 个**也是 4.83 ms，**32 个**还是 4.83 ms。因为读权重的时间是固定的，多处理几个 token 只是多做一点计算，而计算单元本来就闲着。

可是生成的时候，我们不知道接下来的 5 个 token 是什么，没法一次喂进去。**投机解码**（speculative decoding）的想法是：**先找一个便宜的办法把接下来几个 token 猜出来，再让大模型一次前向把它们全部验证一遍。**猜对了几个，就一步前进几个。

## 先猜，再验证

做法需要两个模型：要用的**大模型**（目标模型），和一个同词表的**小模型**（草稿模型），比如用 Llama-3.2-1B 给 Llama-3.1-70B 打草稿。每一轮：

1. **起草**：小模型照常自回归地生成 k 个 token，比如 k = 4。小模型很小，这 4 步加起来也只相当于大模型一步的零头。
2. **验证**：把这 4 个草稿 token 接在已有文本后面，让大模型做**一次**前向。因果注意力（第 27 讲）保证，这一次前向会同时给出 5 个位置的预测：草稿第 1 个 token 之前那个位置应该接什么、第 1 个之后应该接什么……一直到第 4 个之后。
3. **对答案**：从前往后比较。以贪心解码（第 73 讲）为例：草稿第 1 个 token 和大模型在那个位置的预测一样，就接受，看下一个；遇到第一个不一样的，就停下，把这个位置换成大模型的预测，后面的草稿全部作废。如果 4 个全对，大模型在最后一个位置的预测也白送一个。

所以每一轮至少前进 1 个 token（最坏情况：第一个就猜错，用大模型的预测，和不用投机解码一样），最多前进 k + 1 个。被作废的草稿在 KV Cache 里留下的那几个位置，回退掉就行。

**结果和大模型自己一个个生成完全一样**：每个留下来的 token，都是大模型在那个位置认可的。投机解码不改变输出，只改变速度。

## 一轮能前进几个

设小模型每个草稿 token 被接受的概率是 α（**接受率**），并且假设各个位置相互独立。一轮前进的 token 数：前面连续接受了几个，再加上大模型给的 1 个。第 1 个被接受的概率 α，前 2 个都被接受 α²……平均下来

<div class="ai-formula">E = 1 + α + α² + … + α^k = (1 − α^(k+1)) ÷ (1 − α)</div>

α = 0.8、k = 4 时，E = 3.362：一轮平均前进 3.36 个 token。代码模拟了 10 万轮，平均 3.361 个，和公式一致。

一轮的耗时是大模型一步，加上小模型 k 步。设小模型一步的耗时是大模型的 c 倍，一轮就是 1 + k·c 个大模型步。所以

<div class="ai-formula">加速比 = E ÷ (1 + k·c)</div>

c = 5% 时，代码列出了不同 α 和 k 的加速比：

- **α = 0.6**：k = 4 最好，1.92 倍。猜得不准，多猜也是浪费。
- **α = 0.8**：k = 4 时 2.80 倍，k = 8 时达到 3.09 倍，再往后反而下降。
- **α = 0.9**：k 越大越好，k = 10 时 4.57 倍。

接受率是关键：小模型和大模型越“像”，α 越高，能放心地多猜几个。k 不是越大越好：猜得越多，后面的 token 被接受的概率越小（要前面全对），而小模型的成本却是线性增长的。

## 采样时也不改变结果：拒绝采样

贪心解码时，“一样就接受”很直观。可如果用温度、Top-p 采样（第 73 讲），大模型每个位置给出的是一个概率分布 p，小模型给出的是 q，怎么判断“接受”，又保证最终的分布不变？

投机解码的论文（2022–2023 年，Google 和 DeepMind 分别独立提出）给出了一个精巧的办法，叫**拒绝采样**：

1. 小模型按 q 抽出草稿 token x。
2. 以概率 min(1, p(x) / q(x)) 接受它。大模型也觉得 x 很可能（p(x) ≥ q(x)），就一定接受；大模型觉得 x 没那么可能，就按比例接受。
3. 如果拒绝，从分布 max(0, p − q)（归一化后）里重新抽一个，作为这个位置的 token。

可以证明，这样得到的 token 的分布**恰好是 p**。代码验证了一下：大模型 p = [0.5, 0.3, 0.15, 0.05]，小模型 q 是均匀的 [0.25, 0.25, 0.25, 0.25]，抽 20 万次，输出的分布是 [0.5, 0.3, 0.15, 0.05]，和 p 一模一样。接受率 0.699，和理论值 Σ min(p, q) = 0.700 相符。

所以 α 本质上是两个分布的重合程度：小模型越像大模型，重合越多，接受率越高。

## 到了大模型里

**什么时候有用。**投机解码的前提是“大模型一次处理多个 token 几乎不多花时间”，也就是 decode 卡在带宽上。批量越大，大模型的 decode 越接近计算受限（第 70 讲），多验证的那几个 token 就不再免费，加速比随之下降，大批量时甚至会变慢。所以它最适合延迟敏感、并发不高的场景，比如单个用户的对话、代码补全、智能体的长链条调用。

**草稿从哪里来。**单独的小模型要和大模型用同一个词表，还要占显存、要单独部署。更轻量的办法有：从输入里找现成的片段当草稿（比如修改代码时，输出大段重复输入，叫 n-gram 或提示查找，几乎零成本）；给大模型加几个小的预测头（下一讲的 Medusa、EAGLE）；或者模型训练时就带上多 token 预测（DeepSeek-V3 的 MTP 模块，可以直接用来打草稿）。

**推理引擎的支持。**vLLM、SGLang 都支持多种投机解码方式，和连续批处理、分页结合在一起。验证时被拒绝的草稿 token 占用的 KV 位置要回退，调度器也要为每个请求多预留 k 个位置。

**接受率依赖任务。**写代码、改写文本这类“可预测”的输出，α 很高；开放式创作、高温采样，α 低。实际部署要在真实流量上测加速比（第 82 讲）。

## 用代码复现

下面的代码先用第 68 讲的方法算出大模型一次前向处理不同个数 token 的耗时；再验证每轮期望产出的公式、算出不同 α、k 的加速比；最后用拒绝采样抽 20 万次，验证输出分布和大模型相同。

```python
import numpy as np

# 1. 验证 k+1 个 token 和 decode 1 个 token 差不多一样快（Llama-3-8B，H100，上下文 1000）
N, NE, L, d, F, BW, KV = 8.03e9, 128256 * 4096, 32, 4096, 989e12, 3.35e12, 131072
def fwd_ms(n, ctx=1000):
    return max((2 * (N - NE) + 4 * L * d * ctx) * n / F, (N * 2 + KV * (ctx + n)) / BW) * 1e3
print(f"大模型前向：1 个 token {fwd_ms(1):.2f} ms，5 个 token {fwd_ms(5):.2f} ms，32 个 token {fwd_ms(32):.2f} ms")

# 2. 每猜一个 token 被接受的概率是 α，一次猜 k 个：一轮平均产出 E = (1 − α^(k+1)) / (1 − α) 个 token
def expected(a, k): return (1 - a ** (k + 1)) / (1 - a)
rng = np.random.default_rng(0)
def simulate(a, k, rounds=100_000):                      # 模拟：从第一个被拒绝的位置截断，再加上大模型自己给出的 1 个
    acc = rng.random((rounds, k)) < a
    n_ok = np.where(acc.all(1), k, acc.argmin(1))
    return (n_ok + 1).mean()
print(f"α = 0.8、k = 4：公式 {expected(0.8, 4):.3f} 个/轮，模拟 {simulate(0.8, 4):.3f} 个/轮")

# 3. 加速比：一轮的耗时 = 小模型猜 k 次（每次是大模型一步的 c 倍）+ 大模型验证一次
c = 0.05
print("加速比（小模型一步的耗时是大模型的 5%）：")
for a in [0.6, 0.8, 0.9]:
    sp = [expected(a, k) / (1 + k * c) for k in range(1, 11)]
    print(f"  α = {a}：k = 1..10 → {' '.join(f'{s:.2f}' for s in sp)}，最好的 k = {int(np.argmax(sp)) + 1}")

# 4. 拒绝采样：按 min(1, p/q) 接受小模型的猜测，拒绝时从 max(0, p − q) 里重新抽——结果的分布和大模型一模一样
p = np.array([0.5, 0.3, 0.15, 0.05])                     # 大模型的分布
q = np.array([0.25, 0.25, 0.25, 0.25])                   # 小模型的分布
n = 200_000
x = rng.choice(4, n, p=q)
keep = rng.random(n) < np.minimum(1, p[x] / q[x])
resid = np.maximum(p - q, 0); resid /= resid.sum()
out = np.where(keep, x, rng.choice(4, n, p=resid))
print(f"接受率 {keep.mean():.3f}（理论 Σ min(p, q) = {np.minimum(p, q).sum():.3f}）；输出的分布 {np.round(np.bincount(out) / n, 3).tolist()}，大模型 {p.tolist()}")
```

输出：

```text
大模型前向：1 个 token 4.83 ms，5 个 token 4.83 ms，32 个 token 4.83 ms
α = 0.8、k = 4：公式 3.362 个/轮，模拟 3.361 个/轮
加速比（小模型一步的耗时是大模型的 5%）：
  α = 0.6：k = 1..10 → 1.52 1.78 1.89 1.92 1.91 1.87 1.82 1.77 1.71 1.66，最好的 k = 4
  α = 0.8：k = 1..10 → 1.71 2.22 2.57 2.80 2.95 3.04 3.08 3.09 3.08 3.05，最好的 k = 8
  α = 0.9：k = 1..10 → 1.81 2.46 2.99 3.41 3.75 4.01 4.22 4.38 4.49 4.57，最好的 k = 10
接受率 0.699（理论 Σ min(p, q) = 0.700）；输出的分布 [0.5, 0.3, 0.15, 0.05]，大模型 [0.5, 0.3, 0.15, 0.05]
```

第一行：1 个、5 个、32 个 token 的前向都约 4.83 ms。第二行：公式 3.362，模拟 3.361。接下来三行是加速比的表格。最后一行是拒绝采样的验证。

## 容易混淆的地方

1. **投机解码不降低质量。**无论贪心还是采样，输出的分布都和大模型单独生成完全一样（不考虑浮点误差）。它和量化、蒸馏这类“用质量换速度”的方法不同。
2. **它不减少计算量，反而增加了。**被拒绝的草稿白算了，小模型也要算。它是用闲着的算力换延迟，所以在算力本来就紧张的大批量场景里不划算。
3. **加速比不等于平均接受的 token 数。**E 是每轮前进的 token 数，还要除以一轮的耗时 1 + k·c；小模型越慢，抵消得越多。

## 回顾

小批量 decode 卡在读权重上，大模型一次前向处理 1 个和 32 个 token 都约 4.83 ms。投机解码让小模型先猜 k 个 token，大模型一次前向验证所有位置，接受到第一个错误为止，再补上自己的预测，所以每轮前进 1 到 k + 1 个，结果与大模型单独生成完全一样。每轮期望前进 E = (1 − α^(k+1)) ÷ (1 − α)，加速比 E ÷ (1 + k·c)：α = 0.8、k = 4、c = 5% 时约 2.80 倍。采样时用拒绝采样：以 min(1, p/q) 接受，拒绝时从 max(0, p − q) 重抽，输出分布恰好是 p。它最适合并发不高、对延迟敏感的场景。

单独的草稿模型要和大模型同词表、要占显存、要单独维护，而且它只看得到文字，看不到大模型内部已经算好的东西。能不能直接让大模型“顺便”多猜几个 token？下一讲：**EAGLE 与 Medusa**。
