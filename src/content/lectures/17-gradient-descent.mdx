上一讲有了一把尺子：损失函数，把“错了多少”量成一个数。训练的目标是让这个数变小。可是一个网络有成千上万个参数，Llama-3-8B 有 80 亿个，不可能一个一个地去试。我们需要一个办法，能直接告诉每个参数：**往哪个方向改，改多少，损失才会下降。**

这个办法就是**梯度下降**（gradient descent）。它的想法非常朴素：蒙着眼睛站在山坡上想下山，就用脚试一试哪边往下倾，然后往那边迈一小步，再试，再迈。这一讲先只调一个参数，把“斜率”和“步子多大”讲清楚；再调两个参数，引出梯度；最后看看在大模型里，这件事意味着什么。

## 一个最小的问题

为了能把损失画出来，问题要足够小。有 4 个数据点：

| x | 0 | 1 | 2 | 3 |
| --- | --- | --- | --- | --- |
| y | 1 | 3 | 4 | 6 |

我们想用一条直线 *ŷ* = *w*·x + *b* 去拟合它们。这其实就是第 13 讲的一个神经元：一个输入、一个权重、一个偏置、不加激活。损失用上一讲的均方误差：

$$
L(w, b) = \frac{1}{4}\sum \left(w x_i + b - y_i\right)^2
$$

注意这里的视角变了。上一讲里，损失是预测 *ŷ* 的函数；现在数据是固定的，**损失是参数 *w*、*b* 的函数**。换一组参数，就得到一个不同的损失。训练要找的，就是让 *L* 最小的那组参数。

这个问题小到可以直接解方程：最好的直线是 *w* = 1.6、*b* = 1.1，损失 0.05（4 个点不在一条直线上，所以损失不会是 0）。我们知道答案，正好可以检验梯度下降能不能自己找到它。

## 只调一个参数：沿着斜率往下走

先把 *b* 固定在 1.1，只调 *w*。这时 *L* 只是 *w* 的函数，画出来是一条抛物线，谷底在 *w* = 1.6。

假设我们从 *w* = 0 出发。此时 4 个点的误差 *w*x + *b* − y 分别是 0.1、−1.9、−2.9、−4.9，损失是它们平方的平均：9.01。

下一步该往左走还是往右走？看**斜率**（slope），也就是**导数**（derivative）*dL*/*dw*：*w* 增加一点点，*L* 跟着变化多少倍（第 8 讲）。斜率是负的，说明往右走（*w* 增大）损失会下降；斜率是正的，就该往左走。总之，**往斜率的反方向走**。

斜率怎么算？*L* 是 4 项平方的平均，每一项 (*w*x + *b* − y)² 对 *w* 求导，按链式法则是 2(*w*x + *b* − y) · x：外层平方的导数是“2 倍里面”，再乘上里面对 *w* 的导数 x。所以

$$
\frac{dL}{dw} = \frac{1}{4}\sum 2\left(w x_i + b - y_i\right)\cdot x_i = \frac{1}{4}\times 2\times \left(0.1\times 0 - 1.9\times 1 - 2.9\times 2 - 4.9\times 3\right) = -11.2
$$

斜率是 −11.2，所以往右走。走多远？用斜率乘一个小小的系数 *η*（读作 eta）：

$$
w \leftarrow w - \eta\cdot\frac{dL}{dw} = 0 - 0.05\times(-11.2) = 0.56
$$

*η* 叫**学习率**（learning rate），控制每一步迈多大。这里取 0.05，*w* 从 0 走到了 0.56，损失从 9.01 降到 3.84。在新的位置再算斜率（−7.28），再走一步，*w* 到 0.924；再一步，1.161……损失 9.01 → 3.84 → 1.65 → 0.73，一路下降。

注意一个现象：越靠近谷底，斜率越小，步子也越小。这是自动发生的：步长是“学习率 × 斜率”，而抛物线越接近底部越平。所以不用担心冲过头，它会自然地慢下来。

下面的演示可以一步一步地走。绿色曲线是 *L*(*w*)，黑色短线是当前位置的切线，它的倾斜程度就是斜率；琥珀色的点和虚线是走过的每一步。在图上点一下可以换起点。

## 学习率：太小太慢，太大发散

拖一拖学习率的滑块，会看到三种完全不同的走法。

- **η 比较小（比如 0.05）**：每一步都在谷底的同一侧，稳稳地往下挪。20 步以后 *w* = 1.5997，已经非常接近 1.6。再小下去当然也能到，只是步数要多得多。
- **η 稍大（比如 0.2）**：第一步就冲过了谷底，跑到对面；下一步又冲回来。在两边来回跳，但每次都比上一次近，20 步以后同样到了 1.6000。
- **η 太大（比如 0.3）**：每一跳都跳到对面更高的地方，越跳越远。20 步以后 *w* 已经到了 −9.164，**发散**了。

这三种情况的分界在哪里？对这条抛物线，可以精确算出来。斜率是 *w* 的一次函数：*dL*/*dw* = 7(*w* − 1.6)，其中 7 = 2 × (0² + 1² + 2² + 3²) / 4，是抛物线的“弯曲程度”。代进更新公式：

<div class="ai-formula"><i>w</i><sub>新</sub> − 1.6 = (<i>w</i> − 1.6) − <i>η</i> × 7(<i>w</i> − 1.6) = (1 − 7<i>η</i>) × (<i>w</i> − 1.6)</div>

也就是说，每走一步，到谷底的距离乘以 (1 − 7*η*)。*η* = 0.05 时这个系数是 0.65，距离每步缩小到 65%；*η* = 0.2 时是 −0.4，符号翻转（跳到对面），大小缩到 40%；*η* = 0.3 时是 −1.1，绝对值大于 1，每步离得更远。所以 *η* 小于 1/7 时单侧下降，在 1/7 到 2/7 之间来回震荡但收敛，大于 2/7 ≈ 0.286 就发散。

<Note kind="point">学习率决定步子大小。太小，走得慢；太大，越过谷底甚至发散。能用的上限，取决于损失曲面有多“弯”：越弯，学习率就得越小。</Note>

真实的网络里，曲面的弯曲程度没法事先算出来，学习率只能靠经验和试验来定。它几乎是训练里最重要的一个超参数（不是训练出来的、要人来设定的参数）。第 20 讲还会看到，实际训练中学习率通常不是一个固定值，而是随着训练的进行先升后降。

## 两个参数：梯度

现在让 *w* 和 *b* 一起动。损失 *L*(*w*, *b*) 是两个变量的函数，画出来是一个碗形的曲面。从上往下看，可以画成**等高线图**：每条线上的损失相同，像地图上的等高线。

两个参数，就有两个斜率。固定 *b*、只看 *w* 变化时的斜率，记作 ∂*L*/∂*w*；固定 *w*、只看 *b* 变化时的斜率，记作 ∂*L*/∂*b*。这种“其他变量不动、只看一个”的导数叫**偏导数**（partial derivative）。∂*L*/∂*w* 就是刚才算过的式子；∂*L*/∂*b* 也一样推，只是里面对 *b* 的导数是 1：

<div class="ai-formula">∂<i>L</i>/∂<i>w</i> = (1/4) Σ 2(<i>w</i> x<sub>i</sub> + <i>b</i> − y<sub>i</sub>) · x<sub>i</sub>，　∂<i>L</i>/∂<i>b</i> = (1/4) Σ 2(<i>w</i> x<sub>i</sub> + <i>b</i> − y<sub>i</sub>)</div>

把所有偏导数排成一个向量，就是**梯度**（gradient），记作 ∇*L*（∇ 读作 nabla）：

$$
\nabla L = \left(\frac{\partial L}{\partial w},\ \frac{\partial L}{\partial b}\right)
$$

梯度有一个重要的几何性质：**它指向损失上升最快的方向**，而且垂直于所在位置的等高线。所以往梯度的反方向走，就是下降最快的方向。更新公式和一个参数时一模一样，只是现在每个参数都按自己的偏导数走：

$$
(w, b) \leftarrow (w, b) - \eta\cdot\nabla L
$$

从 (−0.5, −2) 出发算一下。这时的直线是 *ŷ* = −0.5x − 2，4 个点的预测是 −2、−2.5、−3、−3.5，减去 y 得到误差 −3、−5.5、−7、−9.5，损失是 (9 + 30.25 + 49 + 90.25) / 4 = 44.625。梯度的两个分量：

<div class="ai-formula">∂<i>L</i>/∂<i>w</i> = (1/2) × (−3×0 − 5.5×1 − 7×2 − 9.5×3) = (1/2) × (−48) = −24，　∂<i>L</i>/∂<i>b</i> = (1/2) × (−3 − 5.5 − 7 − 9.5) = (1/2) × (−25) = −12.5</div>

（式子里的 1/2 来自“平均的 1/4”乘“求导出来的 2”。）

梯度是 (−24, −12.5)，两个分量都是负的，说明 *w* 和 *b* 都该增大。用 *η* = 0.1 走一步：

$$
(w, b) \leftarrow (-0.5, -2) - 0.1\times(-24, -12.5) = (1.9, -0.75)
$$

损失从 44.625 一下子降到 2.12。接着走：第 10 步 (2.04, 0.16)，损失 0.37；第 50 步 (1.64, 1.02)，损失 0.052；第 200 步，(1.6, 1.1)，损失 0.05，和解方程得到的答案完全一样。

下面的演示画的就是这个过程。灰色的线是等高线，实心小圆是谷底 (1.6, 1.1)，空心圆是起点，琥珀色的折线是走过的路。点“走一步”，右边会写出这一步的梯度和更新。

仔细看路线，会发现它不是一条直奔谷底的直线：第一步几乎垂直地冲向了山谷的“底线”附近，然后沿着山谷的方向一点点挪过去。原因是这个碗不是圆的，而是有点扁：沿某个方向很陡，沿另一个方向很平。梯度只管“眼下最陡”，于是先在陡的方向上把损失降下来，平的方向上进展就慢。把学习率调到 0.12 以上，在陡的方向上就会来回震荡；超过约 0.24，就会发散。这个界限比一个参数时的 2/7 ≈ 0.286 还小，因为两个参数一起动时，最陡的那个方向比单看 *w* 更弯。这个“扁碗”问题，第 19 讲还会专门来解决。

## 用代码复现

下面的代码依次算了：只调 *w* 时的前几步；三个学习率各走 20 步的结果；两个参数一起走 200 步；最后用解方程的方法得到的最优解作对照。

```python
import numpy as np

x = np.array([0.0, 1.0, 2.0, 3.0])
y = np.array([1.0, 3.0, 4.0, 6.0])

def loss(w, b):
    return np.mean((w * x + b - y) ** 2)

def grad(w, b):                                   # 两个偏导数
    r = w * x + b - y                             # 每个点的误差
    return np.mean(2 * r * x), np.mean(2 * r)     # (∂L/∂w, ∂L/∂b)

# 1. 只调 w（b 固定为 1.1），学习率 0.05
w = 0.0
for t in range(4):
    g = grad(w, 1.1)[0]
    print(f"第 {t} 步：w = {w:.4f}，L = {loss(w, 1.1):.4f}，斜率 = {g:.4f}")
    w = w - 0.05 * g

# 2. 学习率不同，走 20 步以后离谷底 w = 1.6 有多远
for lr in [0.05, 0.2, 0.3]:
    w = 0.0
    for _ in range(20):
        w -= lr * grad(w, 1.1)[0]
    print(f"η = {lr}：20 步后 w = {w:.4f}")

# 3. 两个参数一起：从 (−0.5, −2) 出发，学习率 0.1
w, b = -0.5, -2.0
gw, gb = grad(w, b)
print(f"起点 L = {loss(w, b):.4f}，梯度 = ({gw:.2f}, {gb:.2f})")
for t in range(1, 201):
    gw, gb = grad(w, b)
    w, b = w - 0.1 * gw, b - 0.1 * gb
    if t in (1, 10, 50, 200):
        print(f"第 {t:3d} 步：(w, b) = ({w:.4f}, {b:.4f})，L = {loss(w, b):.4f}")

# 4. 对照：直接解方程得到的最优解
A = np.column_stack([x, np.ones(4)])
print("最小二乘解：", np.linalg.lstsq(A, y, rcond=None)[0].round(4), " 最小损失：", round(loss(1.6, 1.1), 4))
```

## 到了大模型里

这一讲的两个参数，换成 Llama-3-8B 就是 80 亿个。梯度下降的公式一个字都不用改：**θ** 是一个 80 亿维的向量，梯度 ∇*L* 也是一个 80 亿维的向量，每个参数按自己的偏导数走一小步。

由此马上得到一个工程上的结论：**训练比推理费显存得多**。推理只要存权重；训练还要为每个参数存一个梯度，梯度和权重一样多。Llama-3-8B 的权重用 BF16 存是 16 GB，梯度同样是 16 GB，这还没算第 19 讲优化器要额外保存的东西，也没算第 18 讲反向传播需要的中间结果。

还有一个问题：梯度是在数据上算出来的。这一讲的数据只有 4 个点，每一步都用全部 4 个点算梯度。大模型的训练数据有上万亿个 token，不可能每走一步都把全部数据过一遍。实际的做法是每一步只取一小批数据（一个 batch）来估计梯度，这会让梯度带上噪声，第 19、20 讲会讲它的影响。用多张 GPU 训练时，每张卡各算一部分数据的梯度，然后把梯度加起来求平均，这一步叫 All-Reduce，是分布式训练里最主要的通信（第 89、92 讲）。

## 容易混淆的地方

1. **梯度指向“上坡”，下降要取负号。**梯度是损失增长最快的方向，更新时要减去它。代码里写成加号，模型就会越训越差。
2. **梯度是对参数求的，不是对输入。**这一讲的 x 和 y 是固定的数据，求导的对象是 *w* 和 *b*。第 18 讲会看到，反向传播的过程中也会顺带算出对中间结果的导数，但最后用来更新的，只有对参数的那部分。
3. **学习率不是越小越好。**太小的学习率不仅慢，在真实的网络里还可能卡在一些平坦的地方出不来。学习率要在“不发散”的前提下尽量大一些，这正是调学习率难的地方。

## 回顾

训练要让损失变小，而梯度告诉我们怎么改参数：对每个参数求偏导数，排成梯度向量 ∇*L*，它指向损失上升最快的方向；沿着它的反方向走一小步，就是梯度下降 **θ** ← **θ** − *η*∇*L*。步子大小由学习率 *η* 控制：太小走得慢，稍大会来回震荡，超过某个界限就发散，这个界限取决于损失曲面有多弯。在我们的小例子里，梯度下降从任意起点出发，都能走到解方程得到的最优解 (1.6, 1.1)。在大模型里，梯度和参数一样多，这让训练比推理费显存得多。

这一讲的梯度能直接写出公式，是因为模型只有一层、只有一个神经元。可一个真正的网络有很多层，参数藏在一层套一层的函数里面，每个参数离损失隔着好几层计算。80 亿个偏导数，怎么才能高效地全部算出来？下一讲：**反向传播**。
