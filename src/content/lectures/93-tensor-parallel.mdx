上一讲的 ZeRO-3 把权重切开存，可算的时候还要拼回完整的矩阵，推理时每一步都要搬一遍权重，太慢。**张量并行**（tensor parallelism，TP）换了一个思路：把一个矩阵乘法本身拆开，**每张卡只用自己那一块权重，算出结果的一部分**，卡与卡之间只交换小得多的激活。

这是推理里最常用的模型切分方式。它最早由 2019 年的 Megatron-LM 系统化地提出。这一讲先看一个矩阵乘法有哪两种切法，再看怎么把 FFN 和注意力切得巧妙，让每层只通信两次。

## 一个矩阵乘法的两种切法

Y = X · A（第 13 讲），X 是 [token 数, d_in]，A 是 [d_in, d_out]。要拆到两张卡上：

**按列切 A**：卡 0 拿 A 的前一半列，卡 1 拿后一半列。每张卡用完整的 X 乘自己那一半，得到 Y 的一半列：Y = [X·A₀, X·A₁]。每张卡算出的都是**完整的值**，只是只有一部分列。

**按行切 A**：卡 0 拿 A 的前一半行，卡 1 拿后一半行，对应地 X 也按列切开。每张卡算 Xᵢ·Aᵢ，得到的是一个和 Y 形状相同的矩阵，但只是**部分和**：Y = X₀·A₀ + X₁·A₁，要加起来（All-Reduce）才是完整的 Y。

## FFN：先按列，再按行

FFN（第 31 讲）是两个矩阵乘法，中间夹一个激活函数：Z = ReLU(X·A)·B。（Llama 用的 SwiGLU 多一个门控矩阵，切法相同。）

Megatron 的切法是：**A 按列切，B 按行切**。

1. 每张卡用完整的 X 乘 Aᵢ，得到中间结果的第 i 组列。
2. ReLU 是逐元素的，每张卡对自己那几列做就行，**不需要通信**。
3. 中间结果的第 i 组列，正好就是 B 按行切时第 i 张卡需要的输入。每张卡算 Yᵢ·Bᵢ，得到 Z 的部分和。
4. 一次 **All-Reduce** 把部分和加起来，每张卡都得到完整的 Z。

整个 FFN 只在最后通信一次。

如果反过来，A 按行切，X·A 在每张卡上只是部分和，而 ReLU 是非线性的：ReLU(部分和₀) + ReLU(部分和₁) ≠ ReLU(部分和₀ + 部分和₁)。所以在 ReLU 之前就得先 All-Reduce，FFN 要通信两次。

代码用 4 张卡验证了“先列后行”的结果和单卡完全一样，也验证了“A 按行切”时先做 ReLU 再相加是错的。下面的演示用两张卡和小整数，一步步地看。

## 注意力：按头切

多头注意力（第 28 讲）本来就是好几个独立的头。张量并行就**按头切**：

1. Q、K、V 的投影矩阵**按列切**，每张卡拿到其中几个头对应的列。每张卡算出自己那几个头的 q、k、v。
2. 每个头的注意力计算只用到自己的 q、k、v，各卡独立完成，不需要通信。
3. 输出投影 W_O **按行切**，每张卡用自己那几个头的输出乘 W_O 对应的行，得到部分和。
4. 一次 **All-Reduce**。

和 FFN 一模一样：先列后行，最后通信一次。所以**每个 Transformer 层的前向只需要 2 次 All-Reduce**：注意力之后一次，FFN 之后一次。

按头切还有一个好处：**KV Cache 也自然地切开了**。每张卡只存自己那几个头的 K、V，KV Cache 的显存也分成了 t 份，并发能力随卡数增加。

不过有个限制：Llama-3.1-70B 用 GQA（第 39 讲），只有 8 个 KV 头。TP = 8 时每张卡正好分到 1 个 KV 头；TP 再大，KV 头不够分，只能在几张卡之间复制，KV Cache 就不再随卡数减少了。

<Note kind="point">张量并行把每个矩阵乘法拆到 t 张卡上：FFN 的第一个矩阵按列切、第二个按行切，注意力的 QKV 按头（按列）切、输出投影按行切。每张卡只用自己那块权重独立计算，每层前向只在注意力和 FFN 之后各做一次 All-Reduce。KV Cache 也随头一起切开。</Note>

## 收益与代价

每张卡只存、只读 1/t 的权重，decode 时读权重的时间降到 1/t。可每层 2 次 All-Reduce 的次数不随 t 减少，每次同步的数据量也不小。代码算了 Llama-3.1-70B、32 个请求 decode 一步（用第 91 讲的 NVLink 数字和一步到位的 All-Reduce）：

- **TP = 1**：每卡 141 GB（放不下），读权重 42.1 ms。
- **TP = 2**：70.5 GB，读 21.0 ms，通信 0.67 ms，合计 21.7 ms。
- **TP = 4**：35.2 GB，读 10.5 ms，通信 1.04 ms，合计 11.6 ms。
- **TP = 8**：17.6 GB，读 5.3 ms，通信 1.78 ms，合计 **7.0 ms**。

卡数翻倍，读权重的时间减半，通信却在增加，所占的比例从 3% 涨到了 25%。如果 TP 跨出一台机器，走 InfiniBand，α 更大、β 小了九倍，通信很快就会超过计算。所以**张量并行通常只在一台机器内部做**（最多 8 张卡），更大的规模要和其他并行方式组合（第 94、97 讲）。

## 到了大模型里

**推理引擎的默认选择。**vLLM 和 SGLang 用 `tensor_parallel_size`（`--tp`）设置张量并行。70B 级别的模型在 8 张 H100 上用 TP = 8，是最常见的部署之一。模型代码里的 `ColumnParallelLinear`、`RowParallelLinear` 就是这一讲的两种切法。

**嵌入层和输出层。**词表有十几万，嵌入表和输出层（第 33 讲）也很大，通常按词表切开（vocab parallel），每张卡负责一部分词，最后再合并。

**通信和计算重叠。**每层的 All-Reduce 要等这一层算完才能开始，下一层又要等它结束，很难完全藏起来。一些实现会把 All-Reduce 和下一步的 RMSNorm 融合，或者把一个批次切成两半交替计算和通信，尽量减少等待。

**训练里也一样。**训练时反向传播也要对应地做 All-Reduce，每层前向 2 次、反向 2 次。训练的激活更大，第 95 讲的序列并行会进一步优化它。

## 用代码复现

下面的代码先用 NumPy 验证 FFN 的“A 按列、B 按行”切法与单卡结果一致，并演示 A 按行切时先做 ReLU 是错的；再估算 Llama-3.1-70B 在不同 TP 卡数下 decode 一步的读权重时间和通信时间。

```python
import numpy as np
rng = np.random.default_rng(0)

# 1. 一个 FFN：Z = ReLU(X·A)·B。A 按列切、B 按行切到 t 张卡上，只需要最后一次 All-Reduce
d, dff, t = 8, 32, 4
X = rng.standard_normal((5, d)); A = rng.standard_normal((d, dff)); B = rng.standard_normal((dff, d))
relu = lambda v: np.maximum(v, 0)
Z = relu(X @ A) @ B
A_parts, B_parts = np.split(A, t, axis=1), np.split(B, t, axis=0)       # 卡 i：A 的第 i 组列，B 的第 i 组行
partial = [relu(X @ A_parts[i]) @ B_parts[i] for i in range(t)]          # 每张卡独立算，不用通信
print("A 按列切、B 按行切，各卡部分和 All-Reduce 后 = 原结果：", np.allclose(sum(partial), Z))
print("每张卡上：X·A_i 的形状", (X @ A_parts[0]).shape, "，部分和的形状", partial[0].shape)
# 反过来：A 按行切，X·A 只能得到部分和，ReLU 之前必须先加起来——多一次通信
bad = [X[:, i * 2:(i + 1) * 2] @ A[i * 2:(i + 1) * 2] for i in range(t)]
print("如果 A 按行切：ReLU(部分和) 之和 ≠ ReLU(总和)：", not np.allclose(sum(relu(b) for b in bad), relu(X @ A)))

# 2. Llama-3.1-70B decode 一步（32 个请求），张量并行 t 张卡：每卡读的权重变少，通信次数不变
W, L, dm, BW = 141e9, 80, 8192, 3.35e12
a, beta = 3e-6, 450e9                                    # NVLink（第 91 讲的示意数字），用一步到位的 All-Reduce
m = 32 * dm * 2
print("TP 卡数 | 每卡权重 | 读权重 | 通信（160 次 All-Reduce） | 合计")
for tp in [1, 2, 4, 8]:
    read = W / tp / BW
    comm = 0 if tp == 1 else 2 * L * (a + (tp - 1) * m / beta)   # 每卡同时读其余 tp−1 张卡的部分和
    print(f"{tp:5d} | {W / tp / 1e9:6.1f} GB | {read * 1e3:5.1f} ms | {comm * 1e3:5.2f} ms | {(read + comm) * 1e3:5.1f} ms")
```

输出：

```text
A 按列切、B 按行切，各卡部分和 All-Reduce 后 = 原结果： True
每张卡上：X·A_i 的形状 (5, 8) ，部分和的形状 (5, 8)
如果 A 按行切：ReLU(部分和) 之和 ≠ ReLU(总和)： True
TP 卡数 | 每卡权重 | 读权重 | 通信（160 次 All-Reduce） | 合计
    1 |  141.0 GB |  42.1 ms |  0.00 ms |  42.1 ms
    2 |   70.5 GB |  21.0 ms |  0.67 ms |  21.7 ms
    4 |   35.2 GB |  10.5 ms |  1.04 ms |  11.6 ms
    8 |   17.6 GB |   5.3 ms |  1.78 ms |   7.0 ms
```

前三行是验证：4 张卡的部分和加起来等于原结果；每张卡的中间结果是 5 × 8（32 列里的 8 列）；A 按行切时先 ReLU 再相加不等于正确结果。表格是 70B 的估算：TP = 8 时一步约 7.0 ms，其中通信 1.78 ms。

## 容易混淆的地方

1. **张量并行要求每张卡同时参与每一层。**每层都要 All-Reduce，任何一张卡慢了，所有卡都要等。所以它要求卡之间的连接又快又稳，适合机内。
2. **它不减少每张卡要算的 token 数。**每张卡都处理全部的 token，只是每个 token 只算一部分权重。这和数据并行（每张卡处理一部分 token）正好相反。
3. **TP 不能超过头数的约束。**按头切要求头数能被 t 整除；KV 头数小于 t 时，KV 头要复制，KV Cache 的切分效果打折扣。

## 回顾

张量并行把每个矩阵乘法拆到多张卡上，每张卡只用自己那块权重计算。矩阵按列切得到完整值的部分列，按行切得到部分和。FFN 先按列、再按行，中间的激活函数各卡独立做，最后一次 All-Reduce；注意力按头切 QKV、按行切输出投影，也是最后一次 All-Reduce。每层前向 2 次 All-Reduce，KV Cache 也随头切开。Llama-3.1-70B、TP = 8 时，每卡权重 17.6 GB，decode 一步读权重 5.3 ms、通信 1.78 ms；卡数越多，通信占比越高，所以张量并行一般限制在一台机器内部。

张量并行每层都要通信，跨机就太慢了。还有一种切法：不拆矩阵，而是把不同的**层**放到不同的卡上，卡与卡之间只在层的交界处传一次激活。下一讲：**流水并行**。
