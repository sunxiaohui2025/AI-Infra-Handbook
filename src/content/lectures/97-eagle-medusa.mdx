上一讲的投机解码要一个单独的草稿模型。它带来不少麻烦：要和大模型用同一个词表；要占显存、单独部署；很多大模型根本没有合适的“小弟”。更可惜的是，草稿模型从头开始读文字，大模型已经算好的那些丰富的内部表示，它一点也用不上。

这一讲的两种方法都换了一个思路：**不要单独的小模型，在大模型自己身上接几个轻量的预测头来打草稿。**Medusa 一次并行地猜后面好几个位置，EAGLE 在大模型的“特征”层面一步步地猜。它们还一起推广了一个重要的技巧：一次验证一整棵候选树。

## Medusa：多长几个头

第 33 讲说过，大模型最后一层的隐藏状态，经过输出层（LM head）变成下一个 token 的概率。这个隐藏状态里，其实已经包含了不少关于“再往后几个 token”的信息。

**Medusa**（2024 年）在最后一层的隐藏状态上，额外接几个小小的**预测头**（一两层的小网络）：第 1 个头猜下一个 token 之后的那个（第 t + 2 个），第 2 个头猜第 t + 3 个，以此类推。原来的输出层照常预测第 t + 1 个。一次前向，就同时得到了后面好几个位置的猜测，不需要额外的模型，也不需要额外的前向。

训练这些头很便宜：大模型的参数冻结不动，只用一些数据训练这几个小头（Medusa-1）；也可以和大模型一起微调，猜得更准（Medusa-2）。

问题是，越往后的头猜得越不准：它要跳过中间的几个 token 直接猜，而中间那几个 token 到底是什么，它并不知道。我们假设四个头只看第 1 名时，猜对的概率分别是 0.60、0.45、0.35、0.28（示意数字），按上一讲的方法，一轮平均只前进 **1.99** 个 token。

## 一次验证一棵树

改进的办法是：**每个头不只取第 1 名，而是取前几名。**第 1 名不对的时候，正确答案常常在第 2 名。假设各个头的前 2 名里包含正确答案的概率是 0.78、0.62、0.52、0.44。

可是前 2 名组合起来就不是一条链了，而是一棵**树**：第 1 个位置有 a、b 两个候选，每个候选后面第 2 个位置又有两个候选……深度 3 的树一共 2 + 4 + 8 = 14 个候选 token。要一个个地验证，就失去了意义。

**树形注意力**（tree attention）让这 14 个候选一次前向全部验证完：把它们排成一排送进大模型，但不用普通的因果掩码（第 27 讲），而是用一个特殊的掩码，**每个候选只看得见前文和自己在树上的祖先**。比如节点“ab”（第 1 个位置取第 1 名、第 2 个位置取第 2 名）能看见“a”，看不见“b”，也看不见同一层的“aa”。这样，每个候选得到的预测，和它所在的那条路径单独送进去时完全一样。

验证完后，从根开始，沿着大模型认可的方向往下走，能走多深就接受多少个。代码里的例子：大模型认可的路径是“第 1 个位置第 1 名、第 2 个位置第 2 名”，在树里走到“ab”，接受 2 个，这一轮前进 3 个；如果只用一条链（每层只取第 1 名），在第 2 个位置就停了，只前进 2 个。

按示意数字算：深度 2 的树（6 个候选）平均每轮前进 2.26 个，深度 3（14 个候选）2.52 个，深度 4（30 个候选）2.63 个。候选越多，收益越小，而验证的成本（大模型一次多处理多少个 token）越来越大。实际的实现会根据每个头各个名次的命中率，挑出一棵“性价比”最高的、不对称的树。

## EAGLE：在特征层面一步步地猜

Medusa 的头是“跳着猜”的，第 3 个头要在不知道第 t + 1、t + 2 个 token 的情况下猜第 t + 3 个，所以越往后越不准。

**EAGLE**（2024 年）回到了一步一步地猜，但猜的不是 token，而是大模型的**特征**（最后一层、输出层之前的隐藏状态）。它的草稿模型只是一个很小的网络（大约一层 Transformer），输入是大模型当前位置的特征，加上刚刚确定的那个 token 的嵌入，输出是下一个位置的特征；再用大模型自己的输出层，把这个特征变成 token 的概率。然后把猜出的 token 和特征接回去，继续猜下一个。

这样做有两个好处：

- **特征比 token 好猜。**隐藏状态是连续的、平滑的，比离散的 token 更有规律，小网络更容易学。
- **知道上一步选了哪个 token。**把上一步的 token 一起喂进去，消除了“上一步其实有好几种可能”带来的不确定性。这正是 Medusa 的头做不到的。

论文报告，EAGLE 的接受率明显高于 Medusa。后续的 EAGLE-2 根据草稿模型自己的置信度**动态地**决定候选树的形状（有把握的分支多展开，没把握的少展开）；EAGLE-3 改用大模型好几层的特征，并改进了训练方式，加速比进一步提高。EAGLE 系列是目前推理引擎里最常用的投机解码方法之一。

## 训练时就学会多猜几个：MTP

还有一种做法是在**训练大模型的时候**就让它学会预测后面好几个 token，叫**多 token 预测**（MTP）。DeepSeek-V3 在主模型之外加了一个 MTP 模块，训练时用来提供更多的学习信号；推理时，这个模块正好可以拿来打草稿。DeepSeek-V3 的技术报告说，它对第二个 token 的预测接受率在 85% 到 90% 之间，生成速度提高到约 1.8 倍。

## 到了大模型里

**推理引擎的支持。**vLLM、SGLang 都支持 EAGLE（包括 EAGLE-3）、Medusa、MTP 和单独的草稿模型等多种方式，树形注意力也集成在它们的注意力 kernel 里。很多开源模型会同时发布配套的 EAGLE 草稿头。

**和批大小的关系没有变。**这些方法和上一讲一样，依赖“大模型一次多处理几个 token 几乎免费”。树越大，每轮要验证的 token 越多；批大小大时，这些额外的 token 不再免费，所以引擎会根据负载调小候选树，甚至关掉投机解码。

**草稿头要和模型匹配。**预测头或 EAGLE 的草稿网络是针对某一个大模型训练的，换了模型（哪怕只是微调过）就要重新训练，否则接受率会下降。

## 用代码复现

下面的代码按上面的示意数字，计算链和不同深度的树平均每轮前进的 token 数；构造一棵深度 2 的小树，打出它的树形注意力掩码；最后演示沿树接受最长路径。

```python
import numpy as np
from itertools import product

# 1. Medusa：在大模型最后一层的隐藏状态上接 4 个小头，第 i 个头猜“往后第 i+1 个 token”。
#    假设各个头猜对的概率（示意数字）：只看第 1 名 / 看前 2 名
top1 = [0.60, 0.45, 0.35, 0.28]
top2 = [0.78, 0.62, 0.52, 0.44]
def accepted(ps):                                        # 一轮期望前进几个：1 +（前 1 个都对）+（前 2 个都对）+ …
    return 1 + sum(np.prod(ps[:i + 1]) for i in range(len(ps)))
print(f"一条链（每个头取第 1 名，4 个候选 token）：平均每轮前进 {accepted(top1):.2f} 个")
for depth in [2, 3, 4]:
    nodes = sum(2 ** i for i in range(1, depth + 1))
    print(f"一棵树（每个头取前 2 名，深度 {depth}，{nodes} 个候选 token）：平均每轮前进 {accepted(top2[:depth]):.2f} 个")

# 2. 树形注意力：把整棵树的候选 token 排成一排，一次前向验证。每个候选只能看见自己的祖先（和已有的前文）
paths = [p for depth in [1, 2] for p in product([0, 1], repeat=depth)]      # 深度 2、每层 2 个分支：6 个节点
names = {p: "".join("ab"[x] for x in p) for p in paths}
mask = np.array([[1 if q == p[:len(q)] else 0 for q in paths] for p in paths])
print("节点：", [names[p] for p in paths], "（a、b 是第 1 名、第 2 名；“ab”= 第一位取第 1 名、第二位取第 2 名）")
print("树形注意力掩码（行看列，1 = 看得见）：")
for p, row in zip(paths, mask):
    print(f"  {names[p]:>2s}  " + " ".join(map(str, row)))

# 3. 验证：大模型在每个位置的预测，从根开始沿着树往下走，能走多深就接受多少
truth = (0, 1)                                           # 假设大模型认可的是“第一位第 1 名、第二位第 2 名”
depth = next((d for d in range(2, 0, -1) if truth[:d] in names), 0)
print(f"大模型认可的路径是 {names[truth]}：在树里找到长度 {depth} 的路径，这一轮前进 {depth + 1} 个 token（链只取第 1 名，只能接受 1 个，前进 2 个）")
```

输出：

```text
一条链（每个头取第 1 名，4 个候选 token）：平均每轮前进 1.99 个
一棵树（每个头取前 2 名，深度 2，6 个候选 token）：平均每轮前进 2.26 个
一棵树（每个头取前 2 名，深度 3，14 个候选 token）：平均每轮前进 2.52 个
一棵树（每个头取前 2 名，深度 4，30 个候选 token）：平均每轮前进 2.63 个
节点： ['a', 'b', 'aa', 'ab', 'ba', 'bb'] （a、b 是第 1 名、第 2 名；“ab”= 第一位取第 1 名、第二位取第 2 名）
树形注意力掩码（行看列，1 = 看得见）：
   a  1 0 0 0 0 0
   b  0 1 0 0 0 0
  aa  1 0 1 0 0 0
  ab  1 0 0 1 0 0
  ba  0 1 0 0 1 0
  bb  0 1 0 0 0 1
大模型认可的路径是 ab：在树里找到长度 2 的路径，这一轮前进 3 个 token（链只取第 1 名，只能接受 1 个，前进 2 个）
```

前四行：一条链 1.99 个，树的深度 2、3、4 时分别是 2.26、2.52、2.63 个，候选数是 6、14、30。中间是 6 个节点的树形注意力掩码：比如“ab”这一行，只有“a”和它自己是 1。最后一行是验证的例子：树能接受到“ab”，比链多前进 1 个 token。

## 容易混淆的地方

1. **这些方法也不改变输出。**和上一讲一样，最终留下的 token 都经过大模型验证，结果和大模型单独生成相同（采样时配合拒绝采样或类似的规则）。
2. **Medusa 的头和 MoE 的专家不是一回事。**预测头是额外接在最后的小网络，用来猜后面的 token；MoE 的专家（第 41 讲）是模型主体的一部分。
3. **树形注意力不是新的注意力机制。**它只是换了一个掩码，让多条候选路径挤在一次前向里而互不干扰，计算方式和普通的注意力一样。

## 回顾

单独的草稿模型要同词表、占显存，还用不上大模型的内部表示。Medusa 在大模型最后一层的隐藏状态上接几个预测头，一次前向同时猜后面好几个位置，但越往后越不准。每个头取前几名组成候选树，用“只看得见祖先”的树形注意力掩码一次验证整棵树，沿大模型认可的路径接受最长的一段：示意数字下，链平均每轮前进 1.99 个，深度 3 的树 2.52 个。EAGLE 用一个很小的网络在特征层面一步步地猜，并把上一步的 token 喂回去，接受率更高；DeepSeek-V3 的 MTP 模块在训练时就学会了多猜一个，推理时直接用来打草稿。

量化、投机解码都在不改模型大小的前提下加速。另一条路是直接得到一个更小的模型：让小模型向大模型学习，或者把大模型里不重要的部分剪掉。下一讲：**蒸馏与剪枝**。
