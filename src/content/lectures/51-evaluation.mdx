每次有新模型发布，都会附上一张表：在某某测试上得了多少分，比上一代、比竞争对手高了多少。这些分数是怎么来的？一个模型“好”，到底指什么？

这一讲是第 6 篇的最后一讲，介绍评测大模型的几类主要方法，以及每一类在衡量什么、有什么陷阱。对做推理系统的人来说，评测还有一个更直接的用处：每做一次优化（量化、换算子、改解码策略），都要用评测确认模型没有变笨。

## 困惑度：最原始的尺子

第 16 讲的困惑度，是衡量语言模型最直接的指标：在一份标准文本上，模型平均每一步相当于在几个词里犹豫。它不需要任何人工标注，算起来也快，非常适合比较**同一个模型的不同版本**，比如量化前后（第 16 讲提过，量化论文最常用的就是 WikiText-2 上的困惑度）。

但困惑度有明显的局限：它只衡量“预测下一个 token”有多准，不直接告诉你模型能不能解数学题、会不会写代码、回答是否有帮助。而且不同分词器切出的 token 不同，不同模型的困惑度不能直接比。

## 基准测试：考试

更常用的是**基准测试**（benchmark）：准备一套有标准答案的题，让模型做，算正确率。按题型和判分方式，大致分几类：

- **选择题**：比如 MMLU，覆盖 57 个学科的多项选择题。判分常用的办法是：把每个选项接在题目后面，看模型给哪个选项的概率最高，就算它选了哪个。这不需要模型生成任何东西。
- **答案匹配**：比如 GSM8K（小学数学应用题），让模型生成完整的解答，提取最终答案，和标准答案比是否一致。
- **代码测试**：比如 HumanEval，让模型写函数，用测试用例检验，报告 pass@k（第 49 讲：采样 k 次，至少一次通过的概率）。

下面的演示用 ToyLM 做了一个 5 道题的“选择题基准”：每道题给出一个前缀和 4 个选项，模型给哪个选项的概率最高就算选哪个。点一道题，看各选项的概率。

<EvalView caption="图 51-1　上：ToyLM 做 5 道选择题，对 4 道，准确率 80%。后两道题的两个主要选项概率几乎相同，对错只差千分之几。下：Elo 对战排名，点“A 赢”“B 赢”看分数怎么变。" />

前三道题，模型都很确定：“小猫 吃”后面是“鱼”的概率 1.000。后两道题却很微妙。“我 喜欢 __”，“小狗”0.335、“小猫”0.332，模型选了“小狗”，碰巧对了；“我 吃 __”，“苹果”0.501、“香蕉”0.499，模型选了“苹果”，答案是“香蕉”，错了。准确率 4/5 = 80%。

这两道题暴露了基准测试的一个本质问题：在 ToyLM 的训练语料里，“我喜欢小猫”和“我喜欢小狗”一样多，“标准答案”其实是出题人随意定的。真实的基准里也有这样的问题：答案有歧义、题目本身有错、选项的措辞让模型偏向某一个。好的基准要尽量让每道题有明确、唯一的正确答案，而解读分数时，要知道几个百分点的差距可能来自这些噪声。

## 题目泄露

基准测试还有一个越来越严重的问题：**数据污染**（contamination）。基准测试的题目和答案大多公开在网上，而预训练的数据又是从网上抓的（第 45 讲）。如果测试题混进了训练数据，模型就可能“背过答案”，分数虚高，却不代表真实的能力。

对策包括：在训练数据里查重、剔除测试题；定期发布新的、没公开过的题目；用私有的测试集。看到一个模型在某个老基准上分数异常地高，要多一个心眼。

## 开放式回答：让裁判打分

写作、对话、解释这类任务没有标准答案，没法用正确率衡量。常用的办法有两种。

**模型当裁判**（LLM-as-a-judge）：让一个很强的模型阅读回答，按照给定的标准打分，或者在两个回答里挑更好的一个。它便宜、快，但裁判模型也有偏好：比如偏爱更长的回答、偏爱和自己风格相近的回答。

**人类对战排名**：最有影响的是 Chatbot Arena（LMArena）的做法。用户输入一个问题，两个匿名的模型各自回答，用户投票选更好的那个。大量这样的“对战”结果，用国际象棋的 **Elo 等级分**算出每个模型的分数。

Elo 的规则是：两个模型各有一个分数，分差决定预期的胜率：

<div class="ai-formula"><i>P</i>(A 赢) = 1 / (1 + 10<sup>(<i>R</i><sub>B</sub> − <i>R</i><sub>A</sub>) / 400</sup>)</div>

每比一场，双方按“实际结果 − 预期”调整分数：<i>R</i> ← <i>R</i> + <i>K</i> × (实际 − 预期)，*K* 是一个常数（比如 32）。A 有 1200 分、B 有 1000 分时，A 赢的预期概率是 0.760。如果 A 赢了，只加 32 × 0.24 ≈ 7.7 分；如果爆冷输了，A 掉到 1175.7，B 升到 1024.3。比赛足够多以后，分数会收敛到反映真实水平的位置。上面的演示可以自己点几场试试。

<Note kind="point">评测大模型有多种尺子：困惑度适合比较同一模型的不同版本；基准测试用选择题、答案匹配、代码测试算正确率；开放式任务靠模型当裁判或人类对战排名（Elo）。每种都有陷阱：答案歧义、数据污染、裁判偏好。</Note>

## 用代码复现

下面的代码用 ToyLM 做了 5 道选择题（给每个选项算概率，取最大的），计算准确率；然后算一场 Elo 对战的预期胜率和分数变化。

```python
import json
import numpy as np

ex = json.load(open("tinylm.json", encoding="utf-8"))["examples"]["22"]
V = ex["vocab"]
E, W1, b1, W2, b2 = (np.array(ex[k]) for k in ["E", "W1", "b1", "W2", "b2"])

def probs(a, b):
    z = np.maximum(0, np.concatenate([E[V.index(a)], E[V.index(b)]]) @ W1 + b1) @ W2 + b2
    p = np.exp(z - z.max()); return p / p.sum()

# 1. 选择题：给每个选项算模型的概率，选最大的，和标准答案比
items = [
    ("小猫 吃", ["鱼", "骨头", "苹果", "AI"], "鱼"),
    ("小狗 吃", ["鱼", "骨头", "香蕉", "推理"], "骨头"),
    ("你 学", ["AI", "推理", "鱼", "小狗"], "推理"),
    ("我 喜欢", ["小猫", "小狗", "苹果", "学"], "小狗"),
    ("我 吃", ["苹果", "香蕉", "骨头", "鱼"], "香蕉"),
]
right = 0
for prefix, opts, ans in items:
    p = probs(*prefix.split())
    scores = {o: float(p[V.index(o)]) for o in opts}
    pick = max(scores, key=scores.get)
    right += pick == ans
    print(f"“{prefix} __”：{', '.join(f'{o} {s:.3f}' for o, s in scores.items())} → 选 {pick}，答案 {ans}，{'对' if pick == ans else '错'}")
print(f"准确率 {right}/{len(items)} = {right / len(items):.0%}")

# 2. Elo（对战排名）：A 1200 分，B 1000 分；A 输了会怎样
def expect(ra, rb):
    return 1 / (1 + 10 ** ((rb - ra) / 400))
ra, rb, K = 1200, 1000, 32
ea = expect(ra, rb)
print(f"A 赢的预期概率 {ea:.3f}；A 输了：A {ra} → {ra + K * (0 - ea):.1f}，B {rb} → {rb + K * (1 - (1 - ea)):.1f}")
```

输出：

```text
“小猫 吃 __”：鱼 1.000, 骨头 0.000, 苹果 0.000, AI 0.000 → 选 鱼，答案 鱼，对
“小狗 吃 __”：鱼 0.000, 骨头 1.000, 香蕉 0.000, 推理 0.000 → 选 骨头，答案 骨头，对
“你 学 __”：AI 0.334, 推理 0.666, 鱼 0.000, 小狗 0.000 → 选 推理，答案 推理，对
“我 喜欢 __”：小猫 0.332, 小狗 0.335, 苹果 0.000, 学 0.000 → 选 小狗，答案 小狗，对
“我 吃 __”：苹果 0.501, 香蕉 0.499, 骨头 0.000, 鱼 0.000 → 选 苹果，答案 香蕉，错
准确率 4/5 = 80%
A 赢的预期概率 0.760；A 输了：A 1200 → 1175.7，B 1000 → 1024.3
```

## 到了大模型里

**评测本身就是大规模推理。**一次完整的评测要跑几十个基准、几万到几十万道题，有的还要多次采样，本质上是一个大批量的离线推理任务。推理引擎的吞吐（第 62 讲）直接决定评测要跑多久。

**选择题只要 prefill。**用“比较各选项的概率”来判分时，模型不需要生成任何 token，只需要把题目加选项送进去做一次前向（prefill），读出选项那几个位置的概率。同一道题的 4 个选项共享相同的题目前缀，正好可以用前缀缓存（第 68 讲）省掉重复计算。而需要生成完整解答的基准（数学、代码），就要做大量的 decode，推理模型的评测尤其昂贵。

**每次优化都要回归评测。**做推理优化时，速度变快了，还要确认结果没变差。量化到 4 位后困惑度涨了多少、基准分数掉了多少，换了一个新的注意力算子后输出是否和原来一致（数值误差在可接受范围内），这些都要靠评测来把关。第三章讲量化、算子时会反复用到。

## 容易混淆的地方

1. **基准分数不等于实际好用。**一个模型可能在某些基准上分数很高，用起来却不如人意，反过来也可能。基准只是能力的一个侧面，最终还要看在自己的任务上的表现。
2. **评测的细节会大幅影响分数。**提示的写法、几个示例（few-shot）、是否用思维链、答案的提取规则，都能让同一个模型的分数差好几个百分点。比较不同模型的分数时，要确认评测设置相同。
3. **Elo 分数是相对的。**它反映的是在同一个竞技场里、和同一批对手比较的相对强弱，不同排行榜的分数不能直接比较。

## 回顾

判断模型好不好，有好几把尺子：困惑度直接衡量预测下一个 token 的能力，适合比较同一模型的不同版本；基准测试用选择题（比较选项的概率）、答案匹配、代码测试（pass@k）算正确率；开放式任务靠模型当裁判或人类对战排名，Elo 用“实际 − 预期”调整分数。ToyLM 的 5 道选择题对了 4 道，但后两道的对错只差千分之几，因为答案本身有歧义。评测要警惕答案歧义、数据污染和裁判偏好；对推理系统来说，评测本身是大规模推理，也是每次优化之后必须做的回归检查。
