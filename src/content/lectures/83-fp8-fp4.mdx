前三讲的量化，都是把实数映射成**整数**：INT8、INT4。整数的格点是等间隔的，0.01 附近和 100 附近的间隔一样大。可是神经网络里的数大多聚在 0 附近，偶尔有几个很大（第 80、82 讲的离群值），等间隔的格点对它们并不友好：小数附近不够密，大数附近又浪费。

**浮点数**正好相反：0 附近格点密，越往外越疏，每个数的**相对**误差差不多。BF16 就是一种浮点格式。H100 这一代 GPU 开始支持 8 位的浮点数 **FP8**，计算速度是 BF16 的两倍；更新的 Blackwell 系列（B200 等）又加入了 4 位的 **FP4**。这一讲看看这些格式是怎么表示数的，以及为什么 FP4 必须和“分组缩放”一起用。

## 8 个比特怎么拼成一个浮点数

一个浮点数由三部分组成：**符号** S（1 位）、**指数** E、**尾数** M。它表示的值是

<div class="ai-formula">(−1)^S × (1 + M / 2^m) × 2^(E − bias)</div>

m 是尾数的位数，bias 是一个固定的偏移，让指数可以取负值。指数决定数的“量级”（是 2 的几次方），尾数决定在这个量级里的精细位置。指数全为 0 时是**次正规数**，(−1)^S × (M / 2^m) × 2^(1 − bias)，用来表示非常接近 0 的数。

8 位可以有不同的分法，FP8 有两种：

- **E4M3**：4 位指数、3 位尾数，bias = 7。最大 448，最小的正数 2⁻⁹ ≈ 0.00195。尾数 3 位，所以每个 2 的幂之间有 8 个格点：1 到 2 之间是 1, 1.125, 1.25, …, 1.875，间隔 0.125。
- **E5M2**：5 位指数、2 位尾数，bias = 15。最大 57344，最小的正数约 1.5 × 10⁻⁵。范围大得多，但每个 2 的幂之间只有 4 个格点，精度更粗。

E4M3 精度更好，推理时权重和激活一般都用它；E5M2 范围更大，主要用在训练时数值范围很大的梯度上。

FP4 只有一种常用的分法，**E2M1**：2 位指数、1 位尾数。它一共只能表示 8 个非负值：**0, 0.5, 1, 1.5, 2, 3, 4, 6**。

## 为什么浮点更适合神经网络

整数格式 INT8 的格点是 −127 到 127 乘以一个 scale，等间隔。E4M3 的格点在对数坐标上均匀：从 2⁻⁶ 到 2⁸，每段 8 个格点。同样是 8 位，INT8 在大数附近更精细，E4M3 在小数附近更精细、能覆盖的范围大得多。

神经网络的权重和激活大多是“重尾”的：大部分数很小，少数很大。代码造了 4096 个这样的数，用一个整体的 scale 量化：

- **INT8**：相对误差 3.22%；**FP8 E4M3**：2.44%。
- **INT4**：51.25%；**FP4 E2M1**：34.02%。

同样的位数，浮点格式都更好，4 位时差别尤其大：INT4 只有 15 个等间隔的格点，scale 被最大的数撑开以后，大量小数都被量化成了 0；FP4 在 0 附近还有 0.5、1 这样的格点。

不过 34% 的误差显然还是不能用。FP4 只有 8 个非负值，单靠格式本身扛不住一整个张量的数值范围。

## FP4 离不开分组缩放

办法还是第 80 讲的分组：每一小组数配一个自己的 scale。到了 4 位，组要分得很小，scale 本身也要尽量便宜。目前有两种标准做法：

- **MXFP4**（开放计算项目 OCP 的 Microscaling 标准）：每 **32** 个数一组，scale 用 8 位的 E8M0 存，也就是只能是 2 的幂。好处是乘 scale 只要改指数，硬件实现简单；代价是 scale 只能取 2 的幂，最多会浪费将近一个二进制位的精度。平均每个数 4 + 8 ÷ 32 = **4.25** 位。
- **NVFP4**（NVIDIA 在 Blackwell 上推出）：每 **16** 个数一组，scale 用 FP8 E4M3 存，可以取非 2 的幂的值；整个张量再配一个 FP32 的总系数。组更小、scale 更精细，平均每个数 4 + 8 ÷ 16 = **4.5** 位。

对那 4096 个数：INT4 每 32 个一组，误差 15.09%；MXFP4 15.91%；NVFP4 降到 **9.25%**。

关键是，这些分组的 scale **由硬件直接支持**：Blackwell 的 Tensor Core 在做 FP4 矩阵乘法时，自动把每组的 scale 乘进去。所以分组再细，也不会拖慢计算。这和第 82 讲说的“激活的 scale 必须能提到求和号外面”不矛盾：硬件把 K 方向切成了 16 或 32 一段，每段内部用同一个 scale，段与段之间的累加用高精度完成。

<Note kind="point">FP8 有 E4M3（精度好，最大 448）和 E5M2（范围大，最大 57344）两种，推理多用 E4M3。浮点格式的格点在对数坐标上均匀，比同位数的整数更适合大多是小数、偶有大数的分布。FP4（E2M1）只有 0、0.5、1、1.5、2、3、4、6 八个非负值，必须配合由硬件支持的细粒度分组缩放：MXFP4 每 32 个数一个 2 的幂的 scale，NVFP4 每 16 个数一个 FP8 的 scale。</Note>

## 换来的速度

第 55 讲说过，Tensor Core 的算力随精度翻倍：

- **H100**：FP8 的稠密算力约 1979 TFLOPS，是 BF16（989 TFLOPS）的两倍。
- **Blackwell**：FP4 的算力又是 FP8 的两倍。

对计算受限的 prefill 和大批量 decode，矩阵乘法用 FP8 就能快将近一倍；对带宽受限的小批量 decode，权重从 16 位变成 8 位、4 位，读得也快一倍、三倍多。显存方面，Llama-3-8B 用 FP8 是 8 GB 左右，NVFP4 约 4.5 GB。

## 到了大模型里

**FP8 推理已经很成熟。**vLLM、SGLang、TensorRT-LLM 都支持 FP8 的权重和激活（W8A8），常见的 scale 粒度是权重每个输出通道一个、激活每个 token 一个（动态计算）。对大多数模型，FP8 的效果和 BF16 几乎看不出差别，是 H100 上部署的常见选择。

**FP8 训练也在普及。**DeepSeek-V3 用 FP8 训练：激活每 1 × 128 个数一组、权重每 128 × 128 一块，各配一个 scale，再把累加放在更高的精度里做。这种细粒度的分组思路，和 MXFP、NVFP4 一脉相承。

**FP4 主要用在 Blackwell 上。**有的模型直接发布 FP4 的权重（比如 OpenAI 的 gpt-oss 用 MXFP4 存 MoE 专家的权重），也有工具把 BF16 模型训练后量化成 NVFP4。4 位的误差毕竟大，通常要配合第 81、82 讲的方法（校准、平滑、旋转），或者在训练时就让模型适应它。

**KV Cache 也能用 FP8。**下一讲专门讲。

## 用代码复现

下面的代码按格式的定义列出 E4M3、E5M2、E2M1 能表示的所有值，然后用一组重尾分布的数，比较整数和浮点、整体 scale 和分组 scale 的量化误差。

```python
import numpy as np

def fp_values(e, m, bias, ieee_inf):
    """列出一种小浮点格式能表示的全部非负有限值：符号 1 位，指数 e 位，尾数 m 位"""
    vals = set()
    for E in range(2 ** e):
        for M in range(2 ** m):
            if ieee_inf and E == 2 ** e - 1: continue                  # E5M2：指数全 1 留给 inf / NaN
            if not ieee_inf and E == 2 ** e - 1 and M == 2 ** m - 1 and e > 2: continue   # E4M3：只有全 1 是 NaN
            vals.add(M / 2 ** m * 2.0 ** (1 - bias) if E == 0 else (1 + M / 2 ** m) * 2.0 ** (E - bias))
    return np.array(sorted(vals))

E4M3, E5M2, E2M1 = fp_values(4, 3, 7, False), fp_values(5, 2, 15, True), fp_values(2, 1, 1, False)
for name, v in [("FP8 E4M3", E4M3), ("FP8 E5M2", E5M2), ("FP4 E2M1", E2M1)]:
    print(f"{name}：{len(v)} 个非负值，最大 {v.max():g}，最小的正数 {v[1]:g}")
print("FP4 E2M1 的全部非负值：", E2M1.tolist())
print("E4M3 在 1 附近的间隔：", (E4M3[(E4M3 >= 1) & (E4M3 <= 2)]).tolist())

def to_grid(x, grid):                                    # 取最近的可表示值（带符号）
    g = np.concatenate([-grid[::-1], grid])
    return g[np.abs(x[..., None] - g).argmin(-1)]

# 一组“像权重/激活”的数：大多数很小，少数很大（重尾分布）
rng = np.random.default_rng(0)
x = rng.standard_t(3, 4096) * 0.02
rel = lambda xh: np.linalg.norm(x - xh) / np.linalg.norm(x)
amax = np.abs(x).max()

def int_q(x, bits, group):
    qm = 2 ** (bits - 1) - 1; g = x.reshape(-1, group)
    s = np.abs(g).max(1, keepdims=True) / qm
    return (np.round(g / s) * s).ravel()

def fp_q(x, grid, group, scale_kind):
    g = x.reshape(-1, group); a = np.abs(g).max(1, keepdims=True)
    if scale_kind == "fp32": s = a / grid.max()
    elif scale_kind == "e8m0": s = 2.0 ** np.ceil(np.log2(a / grid.max()))          # MXFP4：scale 只能是 2 的幂
    else:                                                                            # NVFP4：scale 本身用 E4M3 存，外加一个整体的 FP32 系数
        t = amax / (grid.max() * E4M3.max()); s = to_grid(a / grid.max() / t, E4M3) * t
    return (to_grid(g / s, grid) * s).ravel()

print("同一组 4096 个数（重尾分布）的相对误差：")
print(f"  INT8，整体一个 scale：{rel(int_q(x, 8, 4096)):.2%}")
print(f"  FP8 E4M3，整体一个 scale：{rel(fp_q(x, E4M3, 4096, 'fp32')):.2%}")
print(f"  INT4，整体一个 scale：{rel(int_q(x, 4, 4096)):.2%}")
print(f"  FP4 E2M1，整体一个 scale：{rel(fp_q(x, E2M1, 4096, 'fp32')):.2%}")
print(f"  INT4，每 32 个一组：{rel(int_q(x, 4, 32)):.2%}")
print(f"  MXFP4（每 32 个一组，scale 是 2 的幂）：{rel(fp_q(x, E2M1, 32, 'e8m0')):.2%}")
print(f"  NVFP4（每 16 个一组，scale 用 E4M3）：{rel(fp_q(x, E2M1, 16, 'e4m3')):.2%}")
print(f"每个数平均占几位：MXFP4 = 4 + 8/32 = {4 + 8 / 32}，NVFP4 = 4 + 8/16 = {4 + 8 / 16}")
```

输出：

```text
FP8 E4M3：127 个非负值，最大 448，最小的正数 0.00195312
FP8 E5M2：124 个非负值，最大 57344，最小的正数 1.52588e-05
FP4 E2M1：8 个非负值，最大 6，最小的正数 0.5
FP4 E2M1 的全部非负值： [0.0, 0.5, 1.0, 1.5, 2.0, 3.0, 4.0, 6.0]
E4M3 在 1 附近的间隔： [1.0, 1.125, 1.25, 1.375, 1.5, 1.625, 1.75, 1.875, 2.0]

  INT8，整体一个 scale：3.22%
  FP8 E4M3，整体一个 scale：2.44%
  INT4，整体一个 scale：51.25%
  FP4 E2M1，整体一个 scale：34.02%
  INT4，每 32 个一组：15.09%
```

前三行是三种格式的值的个数和范围（E4M3 的 127 个非负值里，扣掉了唯一的 NaN）；第四行是 FP4 的全部 8 个非负值；第五行是 E4M3 在 1 到 2 之间的格点。后面是量化误差的比较：整体 scale 时浮点都比整数好；分组以后，NVFP4 的 9.25% 最好。最后一行是两种 FP4 方案每个数平均占的位数。

## 容易混淆的地方

1. **FP8 有两种，不能混用。**E4M3 和 E5M2 的位含义不同，存储和计算时要明确用哪一种。说“FP8 推理”时，一般指 E4M3。
2. **FP4 不是“FP8 再砍一半”那么简单。**8 个非负值的格式，离开分组缩放几乎不能用；它的效果很大程度上取决于组的大小和 scale 的格式。
3. **硬件不支持，就没有加速。**在不支持 FP8 计算的 GPU（比如 A100）上，FP8 权重只能先转回 BF16 再算，省的是显存和带宽，不是计算；FP4 的计算加速同样只在 Blackwell 这类新硬件上才有。

## 回顾

浮点数用符号、指数、尾数表示：(−1)^S × (1 + M/2^m) × 2^(E − bias)。FP8 有 E4M3（最大 448、精度较好）和 E5M2（最大 57344、范围大）两种；FP4 E2M1 只有 0、0.5、1、1.5、2、3、4、6 八个非负值。浮点的格点在对数坐标上均匀，比同位数的整数更适合重尾分布：整体 scale 下，FP4 的误差 34.02%，INT4 是 51.25%。FP4 必须配合细粒度的分组缩放，MXFP4 每 32 个数一个 2 的幂的 scale，NVFP4 每 16 个数一个 E4M3 的 scale，后者误差降到 9.25%，而且由 Blackwell 的 Tensor Core 直接支持。H100 上 FP8 的算力是 BF16 的两倍，Blackwell 上 FP4 又翻一倍。

权重和激活都可以用低精度了。还有一大块显存是 KV Cache：它决定能同时服务多少个请求，decode 时还要每一步都读一遍。把它也压缩成 8 位、4 位，会怎样？下一讲：**KV Cache 量化**。
