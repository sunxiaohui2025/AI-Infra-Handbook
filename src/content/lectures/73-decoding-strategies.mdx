第 9 篇的前几讲都在算速度和成本。这一讲回到推理流程的最后一步：模型给出了下一个 token 的概率分布，**到底选哪一个？**

第 24 讲介绍过两种最基本的做法：贪心（每次选概率最大的）和采样（按概率随机抽），以及用温度调整分布的尖平。实际的推理服务里，还有几个几乎每个 API 都提供的参数：**Top-k**、**Top-p**、**Min-p**。它们都在做同一件事：**在随机抽样之前，先把那些不太可能、一旦抽中就会“跑偏”的候选词去掉**。这一讲把它们放在一个例子里比较。

## 一个例子

假设模型看到“今天天气真”，给 12 个候选词的概率如下（示意的数字）：

| 好 | 不错 | 晴朗 | 热 | 冷 | 糟糕 | 适合 | 闷 | 美 | 差 | 蓝 | 猫 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0.321 | 0.215 | 0.144 | 0.097 | 0.072 | 0.043 | 0.036 | 0.026 | 0.024 | 0.016 | 0.006 | 0.001 |

前几个词都很合理；“适合”“美”勉强说得通，但可能要接着补全才通顺（“今天天气真适合出门”）；“蓝”“猫”就很奇怪了。真实的模型面对的是十几万个词的词表，长长的“尾巴”上有成千上万个这样概率很小、但加起来不可忽略的词。

**贪心**每次只选“好”，稳定，但单调，长文本里还容易陷入重复（第 24 讲）。**直接采样**丰富多样，但尾巴上那些奇怪的词加起来也有一定的概率，生成一段长文本，总会在某一步抽中一个，然后后面就越说越偏。

## 温度：调整尖平

第 24 讲讲过，温度 T 把每个 logit 除以 T 再做 softmax。T = 0.5 时，“好”的概率从 0.321 升到 0.544，分布变尖；T = 1.5 时降到 0.235，分布变平，“猫”从 0.001 涨到 0.004。

温度改变的是概率的**大小**，但不会把任何一个词彻底去掉：只要 T 不是 0，“猫”的概率总大于 0。

## Top-k：只留前 k 个

**Top-k** 很直接：只保留概率最高的 k 个词，其余的概率设为 0，再把留下的重新归一化。k = 3 时只剩“好、不错、晴朗”，概率变成 0.472、0.316、0.212。

它的问题是 k 是固定的。有时模型很确定，前 2 个词就占了 99% 的概率，k = 50 会留下很多垃圾；有时模型很不确定，合理的候选有几百个，k = 50 又切掉了很多好词。

## Top-p：凑够概率就停

**Top-p**（也叫 nucleus sampling，核采样）换了一种切法：把词按概率从高到低排好，依次累加，**累计概率第一次达到 p 时就停**，只保留前面这些。

p = 0.8 时：0.321、0.536、0.680、0.777，加到第 5 个“冷”时是 0.849，超过了 0.8，于是保留前 5 个。它会自动适应：模型确定时，一两个词就凑够了 p，保留得少；模型不确定时，要很多词才凑够，保留得多。这比固定的 k 合理，所以 Top-p 是最常用的设置之一。

## Min-p：按最大概率定门槛

**Min-p** 是近两年流行起来的另一种切法：去掉概率小于“最大概率 × min-p”的词。min-p = 0.1 时，门槛是 0.321 × 0.1 = 0.0321，保留了概率在 0.036 以上的 7 个词。

它的想法是：模型越自信（最大概率越高），门槛越高，砍掉的越多；模型越犹豫，门槛越低，保留的越多。和 Top-p 相比，它在高温度下更不容易放进奇怪的词。

这几种方法可以组合使用，常见的顺序是：先调温度，再依次用 Top-k、Top-p、Min-p 去掉候选，最后对剩下的重新归一化，随机抽一个。比如 T = 0.7 加上 Top-p = 0.9，保留 5 个词，“好”的概率是 0.458；按这个分布抽 1000 次，“好”被抽中 448 次，“不错”274 次，“晴朗”127 次，“热”86 次，“冷”65 次，奇怪的词一次也不会出现。

## 怎么选

没有一组“最好”的参数，要看任务：

- **需要确定、准确的任务**（数学、代码、信息抽取、事实问答）：温度低（0 到 0.3），或者直接贪心。同样的输入最好得到同样的输出。
- **需要多样性的任务**（写作、头脑风暴、对话）：温度 0.7 到 1 左右，配合 Top-p 0.9 或 Min-p 0.05 之类，既有变化又不跑偏。
- **推理模型**：很多推理模型的官方建议是温度 0.6 左右、Top-p 0.95，而不是贪心。贪心在长长的思考过程里容易陷入重复的循环。

此外常见的还有**重复惩罚**（降低已经出现过的词的 logit，避免车轱辘话）和**随机种子**（固定种子，让采样的结果可以复现）。

## 用代码复现

下面的代码按“温度 → Top-k → Top-p → Min-p → 重新归一化”的顺序实现了解码策略，打印各种设置下保留的词和概率，最后按“T = 0.7 + Top-p = 0.9”抽 1000 次。

```python
import numpy as np

# “今天天气真 ___”：一个示意的模型给 12 个候选词的打分（logits）
words = ["好", "不错", "晴朗", "热", "冷", "糟糕", "适合", "闷", "美", "差", "蓝", "猫"]
logits = np.array([3.0, 2.6, 2.2, 1.8, 1.5, 1.0, 0.8, 0.5, 0.4, 0.0, -1.0, -3.0])

def decode_probs(logits, T=1.0, top_k=0, top_p=1.0, min_p=0.0):
    """按常见的顺序：温度 → Top-k → Top-p → Min-p → 重新归一化。返回最终的概率。"""
    z = logits / T                                         # 1. 温度（第 24 讲）
    p = np.exp(z - z.max()); p /= p.sum()
    keep = np.ones(len(p), bool)
    order = np.argsort(-p)
    if top_k:                                              # 2. 只留概率最高的 k 个
        keep[order[top_k:]] = False
    if top_p < 1.0:                                        # 3. 从高到低累加，够 p 就停
        cum = np.cumsum(p[order])
        cut = np.searchsorted(cum, top_p) + 1             # 保留到累计概率第一次 ≥ p 的那个词
        keep[order[cut:]] = False
    if min_p > 0:                                          # 4. 概率低于“最大概率 × min_p”的去掉
        keep &= p >= min_p * p.max()
    q = np.where(keep, p, 0); return q / q.sum()

def show(name, q):
    kept = [(words[i], round(float(q[i]), 3)) for i in np.argsort(-q) if q[i] > 0]
    print(f"{name}：保留 {len(kept)} 个", kept)

base = decode_probs(logits)
print("原始分布：", [(w, round(float(x), 3)) for w, x in zip(words, base)])
print("贪心：", words[int(base.argmax())])
show("T = 0.5", decode_probs(logits, T=0.5))
show("T = 1.5", decode_probs(logits, T=1.5))
show("Top-k = 3", decode_probs(logits, top_k=3))
show("Top-p = 0.8", decode_probs(logits, top_p=0.8))
show("Min-p = 0.1", decode_probs(logits, min_p=0.1))
show("T = 0.7 + Top-p = 0.9", decode_probs(logits, T=0.7, top_p=0.9))

# 按最后一种设置抽 1000 次（固定种子），看每个词被抽中的次数
q = decode_probs(logits, T=0.7, top_p=0.9)
draws = np.random.default_rng(65).choice(len(words), size=1000, p=q)
print("抽 1000 次：", {words[i]: int(c) for i, c in zip(*np.unique(draws, return_counts=True))})
```

## 到了大模型里

**采样也在 GPU 上做。**每一步，每个请求都有一个 128256 维的 logits 向量（第 33 讲）。Top-p 需要排序，对十几万个数排序并不便宜；一个批里每个请求的参数还可能都不一样（有的贪心，有的 T = 0.8、Top-p = 0.95）。推理引擎会用专门的 GPU 算子来做这一步，比如不完整排序、只找出需要的前若干个，避免把 logits 搬回 CPU。

**采样影响可复现性。**同样的输入、同样的参数，采样的结果取决于随机数。即使固定了种子，批里的请求组合、GPU 的并行计算顺序带来的微小浮点差异，也可能让结果不完全一样。需要严格复现时，用贪心并固定推理配置。

**投机解码要保持分布不变。**第 96 讲的投机解码，用一个小模型先猜几个 token，再让大模型一次验证。为了保证最终的输出和“直接用大模型采样”完全同分布，验证时要用一个专门设计的接受规则，这和这一讲的采样参数紧密相关。

## 容易混淆的地方

1. **温度为 0 等于贪心。**不是真的除以 0，推理引擎会直接取概率最大的词（第 24 讲）。
2. **Top-p 不是“概率大于 p 的词”。**它是“从高到低累加，凑够 p”。p = 0.9 通常会保留很多个词，而不是只保留概率大于 0.9 的那一个。
3. **解码策略不改变模型。**它只决定怎么从模型给出的分布里选词。模型本身的知识和能力没有变，但不合适的解码参数确实会让同一个模型看起来“变笨”或“胡言乱语”。

## 回顾

模型给出下一个 token 的分布之后，还要决定怎么选。贪心稳定但单调；直接采样多样，但长尾上的奇怪词总会被抽中。温度调整分布的尖平；Top-k 只留概率最高的 k 个；Top-p 从高到低累加到 p 为止，能适应模型的确定程度；Min-p 按最大概率定一个门槛。它们组合起来，先砍掉长尾，再随机抽样，在多样性和可靠性之间取得平衡。准确性要求高的任务用低温或贪心，创作类任务用较高的温度配合 Top-p 或 Min-p。

第 9 篇到这里结束：我们知道了一个请求怎么被处理、瓶颈在哪、显存怎么分配、成本怎么算、最后怎么选词。可这些都是“一个请求”或“一批固定的请求”的视角。真实的服务里，请求随时到达、长短不一、随时结束，GPU 怎样才能一刻不停地满负荷工作？第 10 篇从这个问题开始：**Continuous Batching**。
