## CPU 和 GPU：少数强核与大量简单核

CPU 的设计目标是**让一个任务尽快完成**。它有几个到几十个强大的核心，每个核心有复杂的分支预测、乱序执行、大容量的缓存，擅长处理逻辑复杂、前后依赖多的程序：操作系统、数据库、网页服务器。

GPU 的设计目标是**让大量相同的任务一起完成**。它有成千上万个简单的计算单元，每个单元没有那么聪明，但数量多。只要任务能拆成大量互不依赖、做同样运算的小份，GPU 就能一起算。

矩阵乘法正是这样的任务。C = A · B 的每一个元素都是一行和一列的点积，彼此完全独立；一个 4096 × 4096 的结果矩阵，就是 1600 多万个可以同时算的点积。

## SM：GPU 的基本单元

GPU 由很多个相同的 **SM**（流式多处理器，streaming multiprocessor）组成。NVIDIA H100 有 **132 个** SM。每个 SM 可以看作一个小处理器，有自己的：

- **计算单元**：做矩阵乘加的 **Tensor Core**（每个 SM 4 个），做通用标量运算的 **CUDA 核**（每个 SM 128 个 FP32 核），以及加载存储单元、特殊函数单元（算指数、开方等）。
- **寄存器文件**：每个 SM 256 KB，分给在上面运行的各个线程。
- **L1 缓存 / 共享内存**：每个 SM 256 KB 的片上存储（第 53 讲）。
- **线程调度器**：每个 SM 分成 4 个分区，每个分区有一个调度器，每个周期挑一组线程（一个 warp，32 个线程，第 77 讲）发射指令。

所有 SM 共享一个约 50 MB 的 **L2 缓存**，再往外是 80 GB 的 **HBM 显存**。

## Tensor Core：专门做矩阵乘法的单元

早期的 GPU 只有 CUDA 核：每个核每个周期做一次乘加（a × b + c），算矩阵乘法就是让大量的核各自做一个个乘加。

从 2017 年的 V100 开始，NVIDIA 加入了 **Tensor Core**：一种专门做**小矩阵乘加**的单元。它一次就能完成一小块矩阵的乘法再累加（V100 的是两个 4 × 4 的矩阵），相当于很多次乘加。H100 的每个 Tensor Core 每个周期能做 **512 次** BF16 乘加（稠密）。

于是峰值算力可以一层层乘出来：

<div class="ai-formula">132 个 SM × 4 个 Tensor Core × 512 次乘加 × 2（一次乘加 = 2 次运算）× 1.83 GHz ≈ 989 TFLOPS</div>

这就是第 60 讲以来一直用的 989 TFLOPS（BF16，稠密）。同样的方法算 CUDA 核：132 × 128 × 2 × 1.83 GHz ≈ **62 TFLOPS**（官方的 67 TFLOPS 按更高的频率算），只有 Tensor Core 的 6%。

**一个矩阵乘法要用上 Tensor Core，才能接近 GPU 的峰值。**这也是为什么大模型的计算几乎都被组织成矩阵乘法：线性层、注意力的 QKᵀ 和 PV，都是。逐元素的运算（激活函数、归一化）只能用 CUDA 核，但它们的计算量很小，瓶颈在别处（第 74 讲）。

<Note kind="point">GPU 由大量相同的 SM 组成（H100 有 132 个），每个 SM 有 Tensor Core、CUDA 核、寄存器和共享内存。Tensor Core 专门做小矩阵乘加，一个周期完成几百次乘加，H100 合计约 989 TFLOPS（BF16 稠密），是普通 CUDA 核的十几倍。矩阵乘法要用上 Tensor Core，才能接近峰值。</Note>

## 和 CPU 比一比

一颗 64 核的服务器 CPU，每个核有 2 个 AVX-512 向量单元，每个单元每周期做 16 个 FP32 乘加，按 2.5 GHz 算，约 **10 TFLOPS**。H100 的 Tensor Core 是它的近 **100 倍**。

算一个 4096 × 4096 × 4096 的矩阵乘法（约 1370 亿次运算），都按峰值：H100 的 Tensor Core 约 **0.14 ms**，只用 CUDA 核约 2.2 ms，CPU 约 13 ms。

GPU 的另一个特点是**同时在飞的线程数**。H100 每个 SM 最多驻留 2048 个线程，全卡约 27 万个；64 核的 CPU 开了超线程也只有 128 个。GPU 的单个线程很慢，访问显存要等几百个周期，但它不靠单个线程快，而是靠**线程多**：一个 warp 在等数据时，调度器立刻换另一个 warp 执行，计算单元始终有活干。这种“用并行掩盖延迟”的思路，是理解 GPU 性能的关键。

## 算力不是全部

峰值算力只是上限。要真的达到它，还需要两个条件：

1. **数据要供得上。**Tensor Core 一个周期吃进去的数据，要从显存、缓存里及时送到。如果每个数只用一两次就扔，计算单元大部分时间在等数据。下一讲讲存储，第 54 讲讲怎么判断一个运算是卡在算力还是卡在数据上。
2. **任务要足够多。**132 个 SM 都要有活干。第 76 讲的 decode 注意力里，批小时只有几个工作单元，大部分 SM 闲着，就是这个原因。

## 到了大模型里

**每一代 GPU 的变化。**从 V100、A100、H100 到 B200，SM 数量变化不大（80 到 140 多个），增长最快的是每个 Tensor Core 的能力和支持的精度：A100 支持 TF32、BF16，H100 加入 FP8，B200 加入 FP4。精度越低，算力越高（第 55 讲）。

**稀疏的 Tensor Core。**从 A100 开始，Tensor Core 支持 2:4 稀疏（第 87 讲），规格表上常写“稀疏算力”，是稠密算力的两倍。本站的估算一律用**稠密**算力。

**别家的加速器也是类似的结构。**AMD 的 MI300 系列、华为的昇腾、Google 的 TPU，名字不同（计算单元、矩阵单元、脉动阵列），思路一样：大量并行的单元 + 专门的矩阵乘法硬件 + 片上存储 + 高带宽显存。

## 用代码复现

下面的代码按 H100 的公开规格，一层层乘出 Tensor Core 和 CUDA 核的峰值算力；和一颗 64 核 CPU 对比；最后按峰值估算 4096³ 矩阵乘法在三者上的时间。

```python
# H100 SXM 的峰值算力，从硬件结构一层层乘出来（规格取 NVIDIA 公开资料的数字，以白皮书为准）
SM, CLOCK = 132, 1.83e9                                  # SM 个数、Tensor Core 跑满时的时钟频率
TC_PER_SM, BF16_FMA_PER_TC = 4, 512                      # 每个 SM 4 个 Tensor Core；每个每周期做 512 次 BF16 乘加（稠密）
FP32_CORES_PER_SM = 128                                  # 每个 SM 128 个 FP32 CUDA 核，每周期 1 次乘加

tc = SM * TC_PER_SM * BF16_FMA_PER_TC * 2 * CLOCK        # 一次乘加 = 2 次浮点运算
cuda = SM * FP32_CORES_PER_SM * 2 * CLOCK
print(f"Tensor Core（BF16 稠密）：{SM} × {TC_PER_SM} × {BF16_FMA_PER_TC} × 2 × {CLOCK / 1e9:.2f} GHz = {tc / 1e12:.0f} TFLOPS")
print(f"普通 CUDA 核（FP32）：{SM} × {FP32_CORES_PER_SM} × 2 × {CLOCK / 1e9:.2f} GHz = {cuda / 1e12:.0f} TFLOPS，只有 Tensor Core 的 {cuda / tc:.0%}")

# 对比：一颗 64 核的服务器 CPU（示意），每核 2 个 AVX-512 单元，每个每周期 16 个 FP32 乘加
cpu = 64 * 2 * 16 * 2 * 2.5e9
print(f"64 核 CPU（AVX-512，2.5 GHz）：约 {cpu / 1e12:.0f} TFLOPS，H100 的 Tensor Core 是它的 {tc / cpu:.0f} 倍")

# 同时在飞的线程数：GPU 靠海量线程掩盖等待
print(f"H100 每个 SM 最多驻留 2048 个线程，全卡 {SM * 2048:,} 个；64 核 CPU 开超线程也只有 128 个")

# 4096 × 4096 × 4096 的矩阵乘法：2·n³ 次运算
n = 4096
flops = 2 * n**3
print(f"{n}³ 矩阵乘法 {flops / 1e9:.0f} GFLOP：H100 Tensor Core 约 {flops / tc * 1e3:.2f} ms，CUDA 核约 {flops / cuda * 1e3:.1f} ms，CPU 约 {flops / cpu * 1e3:.0f} ms（都按峰值）")
```

输出：

```text
Tensor Core（BF16 稠密）：132 × 4 × 512 × 2 × 1.83 GHz = 989 TFLOPS
普通 CUDA 核（FP32）：132 × 128 × 2 × 1.83 GHz = 62 TFLOPS，只有 Tensor Core 的 6%
64 核 CPU（AVX-512，2.5 GHz）：约 10 TFLOPS，H100 的 Tensor Core 是它的 97 倍
H100 每个 SM 最多驻留 2048 个线程，全卡 270,336 个；64 核 CPU 开超线程也只有 128 个
4096³ 矩阵乘法 137 GFLOP：H100 Tensor Core 约 0.14 ms，CUDA 核约 2.2 ms，CPU 约 13 ms（都按峰值）
```

前两行是 GPU 的两种算力：989 TFLOPS 和 62 TFLOPS。第三行是 CPU：约 10 TFLOPS，差近 100 倍。第四行是同时驻留的线程数。最后一行是 4096³ 矩阵乘法的时间。

## 容易混淆的地方

1. **“CUDA 核数”不代表算力。**规格表上的 CUDA 核数（H100 是 16,896 个）是 FP32 标量单元的数量，大模型的矩阵乘法主要用的是 Tensor Core，它的算力要看 Tensor Core 的规格。
2. **峰值算力要看精度和稠密/稀疏。**同一张卡，FP64、TF32、BF16、FP8 的峰值差好几倍；规格表常把稀疏算力写在前面。比较时要对齐精度和是否稀疏。
3. **峰值只在理想条件下达到。**实际的矩阵乘法能达到峰值的 60% 到 80% 已经很好；第 59 讲会用实测来校准。

## 回顾

CPU 是少数强核，擅长复杂逻辑；GPU 是大量简单核，擅长大量相同、互不依赖的运算，矩阵乘法正是这种运算。GPU 由很多个 SM 组成（H100 有 132 个），每个 SM 有 Tensor Core、CUDA 核、寄存器和共享内存，所有 SM 共享 L2 和 HBM 显存。Tensor Core 专门做小矩阵乘加，H100 的峰值 132 × 4 × 512 × 2 × 1.83 GHz ≈ 989 TFLOPS（BF16 稠密），是 CUDA 核的十几倍、64 核 CPU 的近 100 倍。GPU 靠同时驻留的大量线程掩盖访存的等待。

Tensor Core 一个周期吃进去很多数据，这些数据从哪里来？显存有 80 GB，却比片上存储慢得多；片上存储很快，却只有几百 KB。数据在哪里、搬一次要多久？下一讲：**存储层级：HBM 与 SRAM**。
