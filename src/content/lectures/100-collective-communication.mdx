上一讲说，大模型要切到多张卡上。切开以后，几张卡要合作完成一次计算，就得交换数据。好在这些交换的“形状”很固定，归纳起来只有几种：大家的结果要加起来，大家的一块要拼起来，大家要互相交换一部分……这几种模式叫**集合通信**（collective communication），每一种叫一个**原语**。

NVIDIA 的 NCCL、AMD 的 RCCL、华为的 HCCL 等通信库，提供的就是这几个原语的高效实现。PyTorch 的 `torch.distributed` 也是对它们的封装。后面讲到的每一种并行方式，最后都会落到这几个原语上。这一讲用一个 4 张卡的小例子，把它们一个个看清楚。

## 设定

4 张卡，编号 0 到 3（通信库里叫 **rank**）。每张卡上有一个长度为 4 的向量，切成 4 段，每段一个数。为了看清数据从哪来，让卡 r 的数据是 [10r, 10r+1, 10r+2, 10r+3]：十位数就是它来自哪张卡。

- 卡 0：[0, 1, 2, 3]
- 卡 1：[10, 11, 12, 13]
- 卡 2：[20, 21, 22, 23]
- 卡 3：[30, 31, 32, 33]

## 一对多、多对一

**Broadcast**（广播）：把一张卡（比如卡 0）的数据复制给所有卡。之后每张卡都是 [0, 1, 2, 3]。用来分发同一份东西，比如启动时的初始权重。

**Reduce**（归约）：所有卡的数据**按位置相加**（也可以取最大值等），结果只放在一张卡上。4 张卡按位置相加是 [0+10+20+30, …] = [60, 64, 68, 72]，放在卡 0。

## 大家都要结果：All-Reduce

**All-Reduce**：按位置相加，**每张卡都拿到**完整的和。之后 4 张卡都是 [60, 64, 68, 72]。

它是分布式计算里最常用的原语。张量并行（第 105 讲）把一个矩阵乘法拆到几张卡上，每张卡算出一部分和，要用 All-Reduce 加起来，所有卡才能接着算下一层；数据并行训练（第 103 讲）每张卡算出自己那批数据的梯度，要 All-Reduce 求和，所有卡才能用同样的梯度更新参数。

## 切开和拼起来：Reduce-Scatter 与 All-Gather

**Reduce-Scatter**：也是按位置相加，但结果切成 p 段，卡 r 只拿第 r 段。之后卡 0 是 [60]、卡 1 是 [64]、卡 2 是 [68]、卡 3 是 [72]。每张卡只负责和的一部分。

**All-Gather**：每张卡手里有一段，拼起来，让每张卡都有完整的。如果每张卡分别有 [60]、[64]、[68]、[72]，All-Gather 之后每张卡都是 [60, 64, 68, 72]。

注意这两步连起来：先 Reduce-Scatter，再 All-Gather，结果恰好就是 All-Reduce。

<div class="ai-formula">All-Reduce = Reduce-Scatter + All-Gather</div>

这不只是一个巧合。下一讲会看到，最高效的 All-Reduce 实现就是这么做的；而且很多场景里，我们其实只需要其中一半。比如 ZeRO（第 103 讲）只需要每张卡拿到自己负责的那部分梯度，用 Reduce-Scatter 就够了，省掉一半通信；用到参数时，再用 All-Gather 临时拼出完整的。

## 互相交换：All-to-All

**All-to-All**：每张卡把自己的数据切成 p 段，第 j 段发给卡 j。卡 r 收到每张卡的第 r 段。之后卡 0 是 [0, 10, 20, 30]（每张卡的第 0 段），卡 1 是 [1, 11, 21, 31]……把 4 张卡的数据排成一个 4 × 4 的矩阵，All-to-All 就是把它**转置**。

和前面几个不同，All-to-All 里每对卡之间交换的数据都不一样，没有求和，也没有复制。它是 MoE 专家并行（第 108 讲）的核心：每张卡上的 token 要去的专家分散在各张卡上，每张卡要给每张卡发一批不同的 token。

<Note kind="point">集合通信有几种固定的模式：Broadcast 一对多复制，Reduce 多对一求和，All-Reduce 求和后人人都有，Reduce-Scatter 求和后每人一段，All-Gather 每人一段拼成完整，All-to-All 每对卡交换不同的数据。All-Reduce = Reduce-Scatter + All-Gather。</Note>

## 每张卡要收发多少

通信要花时间，时间取决于数据量。设每张卡的数据量是 n（字节），p 张卡：

- **All-Gather**：每张卡已有 1/p，还缺另外 p − 1 段，至少要收 (p − 1)/p · n。
- **Reduce-Scatter**：每张卡要算出 1/p 的和，需要其他 p − 1 张卡在这一段上的数据，至少也是 (p − 1)/p · n。
- **All-Reduce**：等于前两者相加，至少 2(p − 1)/p · n。
- **All-to-All**：每张卡留下自己的 1/p，其余 (p − 1)/p · n 发出去，也收进同样多。

4 张卡时，All-Reduce 每张卡至少要收发 1.5n，其他三个各 0.75n。有意思的是，卡数越多，(p − 1)/p 越接近 1，**每张卡的通信量几乎不随卡数增长**。这是因为好的实现会让所有卡同时收发，把任务分摊开（下一讲）。

## 到了大模型里

**通信库。**NCCL 是 NVIDIA GPU 上的事实标准，PyTorch、vLLM、SGLang、Megatron 都用它。它会根据卡之间的连接（NVLink、PCIe、InfiniBand）自动选择算法和路径。

**哪个原语出现在哪里。**推理里最常见的是张量并行的 All-Reduce（每层两次，第 105 讲）和 MoE 的 All-to-All（每层两次，第 108 讲）；训练里还有数据并行和 ZeRO 的 All-Reduce、Reduce-Scatter、All-Gather。

**点对点通信。**除了集合通信，还有最简单的 Send/Recv：一张卡发、一张卡收。流水并行（第 106 讲）把一层的输出传给下一段的卡，用的就是它；PD 分离（第 14 篇）把 KV Cache 从 prefill 的卡传到 decode 的卡，也是点对点。

## 用代码复现

下面的代码用 NumPy 模拟 4 张卡上的六种原语，打出每种原语之后每张卡的数据，验证 Reduce-Scatter 加 All-Gather 等于 All-Reduce，并列出每张卡至少要收发的数据量。

```python
import numpy as np

p = 4                                                    # 4 张卡（rank 0–3），每张卡上有一个长度 4 的向量，切成 4 段
data = [10 * r + np.arange(p) for r in range(p)]         # 卡 r 的数据：[10r, 10r+1, 10r+2, 10r+3]，十位数 = 来自哪张卡
def show(name, xs):
    print(f"{name:15s}" + "  ".join(f"卡{r}:{x.tolist() if x is not None else '—'}" for r, x in enumerate(xs)))

show("初始", data)
show("Broadcast", [data[0].copy() for _ in range(p)])                  # 卡 0 的数据复制给所有卡
total = sum(data)                                                      # 按位置相加：[60, 64, 68, 72]
show("Reduce", [total] + [None] * (p - 1))                             # 相加，结果只在卡 0
show("All-Reduce", [total.copy() for _ in range(p)])                   # 相加，所有卡都有结果
rs = [total[r:r + 1] for r in range(p)]
show("Reduce-Scatter", rs)                                             # 相加的结果切成 p 段，卡 r 拿第 r 段
show("All-Gather", [np.concatenate(rs) for _ in range(p)])             # 每张卡各一段，拼成完整的给所有卡
show("All-to-All", [np.array([data[j][r] for j in range(p)]) for r in range(p)])   # 卡 j 的第 r 段发给卡 r

print("Reduce-Scatter 之后再 All-Gather，结果和 All-Reduce 相同：", np.array_equal(np.concatenate(rs), total))
n = 1.0                                                                # 每张卡的数据量记为 n，看每张卡要收发多少
print(f"每张卡至少要收的数据量（p = {p}）：All-Gather {(p - 1) / p * n:.2f}n，Reduce-Scatter {(p - 1) / p * n:.2f}n，"
      f"All-Reduce {2 * (p - 1) / p * n:.2f}n，All-to-All {(p - 1) / p * n:.2f}n")
```

## 容易混淆的地方

1. **All-Reduce 和 Reduce 不同。**Reduce 的结果只在一张卡上，All-Reduce 每张卡都有。
2. **All-Gather 和 All-to-All 不同。**All-Gather 后每张卡的数据都一样（完整的拼接）；All-to-All 后每张卡的数据都不一样（各自收到的那一列）。
3. **集合通信要所有卡一起参加。**只要有一张卡还没算完、没调用这个原语，其他卡都得等着。所以负载不均衡时，最慢的那张卡决定了所有卡的速度。

## 回顾

多张卡合作计算时，要用固定的几种模式交换数据：Broadcast（一对多复制）、Reduce（求和到一张卡）、All-Reduce（求和后每张卡都有）、Reduce-Scatter（求和后每张卡一段）、All-Gather（每张卡一段拼成完整）、All-to-All（每对卡交换不同的数据，像转置）。All-Reduce 等于 Reduce-Scatter 加 All-Gather。每张卡至少要收发的数据量：All-Reduce 2(p − 1)/p · n，其余三种 (p − 1)/p · n，几乎不随卡数增长。张量并行用 All-Reduce，ZeRO 用 Reduce-Scatter 和 All-Gather，MoE 用 All-to-All。

“每张卡至少收发 2(p − 1)/p · n”是理论下限。最直接的实现，所有卡把数据发给卡 0 求和、卡 0 再发回去，卡 0 要收发 2(p − 1)·n，卡越多越慢。怎么组织通信才能达到下限？下一讲：**Ring 与 Tree All-Reduce**。
