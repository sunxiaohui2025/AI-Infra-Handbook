Transformer 的每一层有两个子模块。前面几讲讲的注意力是第一个：它让词与词之间交换信息，每个词从上下文里收集它需要的东西。这一讲讲第二个：**前馈网络**（feed-forward network，FFN），也常叫 MLP。

FFN 做的事情和注意力正好互补：**每个词各自独立地做一次计算，词与词之间完全不交流。**它的结构就是第 15 讲的多层感知机：先用一个线性层把向量变宽，过一个激活函数，再用一个线性层变回原来的宽度。这一讲把这三步在 TinyLM 上算一遍，再说说这个“先变宽、再变窄”的结构到底在做什么，以及为什么它是大模型参数和计算的大头。

## 升维、激活、降维

FFN 对每个词的向量 **x**（d 维）做三步：

$$
\mathrm{FFN}(\mathbf{x}) = \mathrm{ReLU}(\mathbf{x}\cdot W_1)\cdot W_2
$$

1. **升维**：乘 *W*<sub>1</sub>（d × d<sub>ff</sub>），从 d 维变成 d<sub>ff</sub> 维。d<sub>ff</sub> 通常是 d 的 4 倍左右。
2. **激活**：逐元素过 ReLU（第 14 讲），负数变 0。
3. **降维**：乘 *W*<sub>2</sub>（d<sub>ff</sub> × d），变回 d 维。

降回 d 维是必须的：FFN 的输出要和输入相加（残差连接，第 29 讲），形状必须一样。原始 Transformer 的线性层还带偏置，TinyLM 和 Llama 都没有，这里也省掉。

TinyLM 的 d = 4，d<sub>ff</sub> = 8。拿第 1 层里“AI”这个词算一下，它的输入是上一讲 LayerNorm 的输出 (−0.533, −1.309, 0.53, 1.312)：

- **升维**：乘 4 × 8 的 *W*<sub>1</sub>，得到 8 个数 (1.598, −0.232, 0.083, −0.393, 1.342, −1.602, −0.586, 1.528)。
- **ReLU**：4 个负数变成 0，剩下 (1.598, 0, 0.083, 0, 1.342, 0, 0, 1.528)。8 个神经元里“亮了”4 个。
- **降维**：乘 8 × 4 的 *W*<sub>2</sub>，回到 4 维 (2.828, 1.673, 2.837, −0.636)。

这个结果随后加回残差流，再做一次 LayerNorm，就是第 1 层的输出。

## 每个词各算各的

FFN 里没有任何一步会把不同的词混在一起：升维、ReLU、降维，都是对每一行单独做的。所以整句话一起算（4 × 4 的矩阵乘 *W*<sub>1</sub>）和一个词一个词地算，结果完全一样，下面的代码会验证。这种“对序列里每个位置独立地做同样的事”的网络，原论文里叫 position-wise feed-forward network。

这和注意力形成了分工：

| | 注意力 | FFN |
| --- | --- | --- |
| 词与词之间 | 交换信息 | 不交流 |
| 做什么 | 决定从上下文的哪些词收集什么 | 对每个词收集到的信息各自做加工 |
| 依赖序列长度 | 打分矩阵 s × s | 不依赖，每个词一样的计算 |

一个常见的比喻是：注意力是“开会”，大家互相交换消息；FFN 是“各自回去干活”，每个人消化自己拿到的消息。每一层都是先开会、再干活，重复几十次。

## 先变宽，再变窄，在做什么

为什么要先升到 8 维、再降回 4 维，而不是直接用一个 4 × 4 的矩阵？第 14 讲已经回答了一半：两个线性层之间如果没有激活函数，会合并成一个线性层；有了 ReLU，网络才能表达非线性的东西。而中间层越宽，能拼出来的“折线”越多（第 15 讲），能表达的函数越丰富。

还有一个更具体的看法，把 FFN 看成一张**“键—值”表**。把降维那一步拆开看：

<div class="ai-formula">FFN(<b><i>x</i></b>) = Σ<sub>j</sub> ReLU(<b><i>x</i></b> · <i>W</i><sub>1</sub> 的第 j 列) × <i>W</i><sub>2</sub> 的第 j 行</div>

中间层的第 j 个神经元做两件事。*W*<sub>1</sub> 的第 j 列像一个“键”：**x** 和它的点积越大，说明 **x** 越符合这个神经元要找的模式，它就亮得越厉害（负数就完全不亮）。*W*<sub>2</sub> 的第 j 行像一个“值”：这个神经元亮了以后，就把这一行按自己的亮度加到输出上。所以 FFN 的输出，就是所有被激活的神经元各自贡献的“值”按亮度相加。

“AI”那一行，亮的是第 1、3、5、8 个神经元，亮度分别是 1.598、0.083、1.342、1.528；把 *W*<sub>2</sub> 的这 4 行按这些亮度加起来，正好就是输出 (2.828, 1.673, 2.837, −0.636)。

在训练好的大模型里，研究者发现很多这样的神经元确实对应着可以解释的模式：有的在看到某类词时亮起，有的在特定的语境下亮起，它们写回残差流的“值”，往往会提高某些下一个词的概率。所以也有人说，**模型记住的大量知识，就存在 FFN 的权重里**：注意力负责把相关的信息收集到一起，FFN 负责根据这些信息“回忆”出相应的知识。

<Note kind="point">FFN = 升维 → 激活 → 降维，每个词独立计算，词与词不交流。可以把它看成一张键—值表：W₁ 的每一列是一个“模式”，W₂ 的对应一行是匹配上之后要写回的内容。</Note>

## 用代码复现

下面的代码对“AI”一个词手算 FFN 的三步，并和 TinyLM 的前向结果核对；然后用“键—值”的看法重算一遍输出；验证整句一起算和逐个词算相同；最后比较参数量和计算量。

```python
import json
import numpy as np

t = json.load(open("tinylm.json", encoding="utf-8"))
st = {s["key"]: np.array(s["v"]) for s in t["examples"]["34"]["steps"]}
L0 = t["weights"]["layers"][0]
W1, W2 = np.array(L0["W_1"]), np.array(L0["W_2"])          # 4×8、8×4

# 1. “AI”这一个词：升维 → ReLU → 降维
x = st["L1ln1"][3]
up = x @ W1
act = np.maximum(0, up)
down = act @ W2
print("输入 ", x.round(3), x.shape)
print("升维 ", up.round(3), up.shape)
print("ReLU ", act.round(3), " 亮了", int((act > 0).sum()), "个")
print("降维 ", down.round(3), down.shape)
print("和 tinylm.json 一致：", np.allclose(down, st["L1down"][3], atol=1e-3))

# 2. 降维 = 被激活的神经元，各自把 W_2 的一行按自己的大小加起来
contrib = [(j + 1, round(float(act[j]), 3)) for j in range(8) if act[j] > 0]
print("亮了的神经元（编号, 输出）：", contrib)
print("加权求和 W_2 的这几行：", sum(act[j] * W2[j] for j in range(8)).round(3))

# 3. 每个词各算各的：整句一起算和一个词一个词算，结果一样
X = st["L1ln1"]
together = np.maximum(0, X @ W1) @ W2
one_by_one = np.array([np.maximum(0, X[i] @ W1) @ W2 for i in range(4)])
print("整句一起算 = 逐个词算：", np.allclose(together, one_by_one))

# 4. 参数和计算量
d, f = 4, 8
print("TinyLM 每层 FFN 参数：", 2 * d * f, "个；注意力 4 个矩阵：", 4 * d * d, "个")
d, f = 4096, 14336
print(f"Llama-3-8B 每层 FFN（3 个矩阵）：{3 * d * f / 1e6:.1f}M 个参数，每个 token {2 * 3 * d * f / 1e6:.0f}M 次浮点运算")
```

输出：

```text
输入  [-0.533 -1.309  0.53   1.312] (4,)
升维  [ 1.598 -0.232  0.083 -0.393  1.342 -1.602 -0.586  1.528] (8,)
ReLU  [1.598 0.    0.083 0.    1.342 0.    0.    1.528]  亮了 4 个
降维  [ 2.828  1.673  2.837 -0.636] (4,)
和 tinylm.json 一致： True
亮了的神经元（编号, 输出）： [(1, 1.598), (3, 0.083), (5, 1.342), (8, 1.528)]
加权求和 W_2 的这几行： [ 2.828  1.673  2.837 -0.636]
整句一起算 = 逐个词算： True
TinyLM 每层 FFN 参数： 64 个；注意力 4 个矩阵： 64 个
Llama-3-8B 每层 FFN（3 个矩阵）：176.2M 个参数，每个 token 352M 次浮点运算
```

前几行是“AI”的三步：4 维 → 8 维 → 亮了 4 个 → 4 维，和 TinyLM 的前向结果一致。接着两行是“键—值”的看法：亮了第 1、3、5、8 个神经元，按亮度加起来的 *W*<sub>2</sub> 的这几行，和降维的结果一模一样。然后是“整句一起算 = 逐个词算”。最后两行是参数和计算量，下一节用。

## 到了大模型里

**FFN 是参数的大头。**TinyLM 每层 FFN 有 2 × 4 × 8 = 64 个参数，和注意力的 4 个 4 × 4 矩阵（64 个）一样多。到了 Llama-3-8B，d = 4096，d<sub>ff</sub> = 14336（3.5 倍），而且用的是带门控的 SwiGLU（第 38 讲），有三个矩阵：每层 FFN 约 1.762 亿个参数，占这一层参数的约 81%（第 15 讲算过）。

**FFN 也是计算的大头。**每个 token 经过一层 FFN，要做约 3.52 亿次浮点运算（每个参数一次乘加，即 2 次运算）。在序列不太长时，FFN 的计算量比注意力大得多；只有序列很长时，注意力的 s<sup>2</sup> 项才会追上来（第 26 讲）。所以 FFN 里那几个大矩阵乘法，是推理时 GPU 最主要的工作，也是量化（第 12 篇）最想压缩的对象。

**FFN 好拆分。**因为每个词独立计算，FFN 在多卡上很容易并行：把 *W*<sub>1</sub> 按列切、*W*<sub>2</sub> 按行切，每张卡负责一部分神经元，最后把各卡的结果加起来（第 105 讲的张量并行）。第 41 讲的 MoE 走得更远：把一个大 FFN 拆成很多个小 FFN（专家），每个 token 只用其中几个，参数可以很多，每个 token 的计算量却不变。

## 容易混淆的地方

1. **“前馈”和“反向”不是一对概念。**这里的“前馈”只是说数据从输入一路流到输出、没有回路（第 15 讲），和反向传播无关。注意力其实也是前馈的，只是习惯上把这个“升维—降维”的部分专门叫做 FFN 或 MLP。
2. **d<sub>ff</sub> 不一定是 4 倍。**原始 Transformer 是 4 倍；用 SwiGLU 的模型因为多了一个矩阵，为了保持参数量相近，常用约 8/3 倍再取整，Llama-3-8B 是 14336 / 4096 = 3.5 倍。
3. **FFN 里的神经元不一定都有清晰的含义。**“键—值”是一个有用的理解方式，但很多神经元同时参与好几种模式，单独看一个神经元往往解释不清。

## 回顾

FFN 是 Transformer 每层的第二个子模块：升维（d → d<sub>ff</sub>）、ReLU、降维（d<sub>ff</sub> → d），输出加回残差流。它对每个词独立计算，词与词之间不交流，和负责交换信息的注意力形成分工。可以把它看成一张键—值表：*W*<sub>1</sub> 的每一列是一个要匹配的模式，*W*<sub>2</sub> 的对应一行是匹配上以后写回的内容，在大模型里，大量知识就存在这些权重中。FFN 占了每层参数和计算的大部分，Llama-3-8B 每层约 1.76 亿个参数、每个 token 约 3.5 亿次运算。

到这里，Transformer 一层里的所有零件都讲完了：注意力、残差、归一化、FFN。它们按什么顺序、怎样连起来，组成完整的一层？一层又怎样叠成一个模型？下一讲：**Transformer Block**。
