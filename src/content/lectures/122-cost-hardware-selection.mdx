第 72 讲我们算过一张理想卡在满载时的理论每百万 token 成本，第 116 讲算过满足 SLO 需要几张卡。但真到拍板采购或选云厂商方案的那一刻，你面对的往往不是“算一次 H100 跑多少 token”，而是三个更现实的问题：

1. 日均 QPS 才几个请求、波峰波谷差 3 倍，是**直接调外部商业 API** 划算，还是**自己租 GPU 部署开源模型**划算？
2. 同样是自建，选昂贵但算力极强的 **H100**、显存大但算力砍半的 **H20**、还是便宜的 **A100 / 消费级卡**，到底差在哪里？
3. 为什么很多团队按第 72 讲的公式一算“自建只要 API 价格的 1/5”，结果真买完卡上线三个月一算总账，反而比调 API 还贵？

这一讲把生产环境里的真实总账（Total Cost of Ownership，TCO）拆开，对比硬件特性、调度模式与外部 API 的盈亏平衡点，给出一套可直接落地的选型框架。

## 为什么自建的真实成本常常比纸面算贵 3 倍

第 72 讲算出 H100 满载跑 Llama-3-8B 时，每百万输出 token 只有几美分。可到了真实线上，三个折扣会把理论成本乘以 3 到 5 倍：

1. **波峰波谷导致的“时间利用率”损失**：如果白天峰值是日均流量的 2.5 倍，而你租的是包月常驻机器，那就必须按峰值配卡。这意味着一整天平均下来，你的卡有一半以上的时间只跑着 30%–40% 的负载，有效利用时间直接打四折。
2. **SLO 留余量与冷启动冗余**：为了守住 P99 延迟，单卡只能跑到最大能力的 70%（第 116 讲），再算上 1–2 台热备实例或高可用跨区冗余，又要多出 30%–50% 的机器。
3. **运维与平台隐性成本**：GPU 节点之上还有对象存储/高速 NVMe 盘、负载均衡网关、Prometheus 监控集群，以及最贵的**工程师人天**——搭一套高可用调度、监控、灰度和排障体系，至少需要 1–2 名全职 Infra 工程师。

## 自建 vs 调 API 的盈亏平衡点

什么时候该自建，什么时候该直接调商业 API？把公式写出来，答案一目了然：

<div class="ai-formula">月自建总成本 = 常驻卡数 × 月租 + 弹性卡数 × 峰值小时数 × Spot 单价 + 平台固定开销</div>
<div class="ai-formula">月 API 总成本 = 月总请求数 × (输入 token × 输入单价 + 输出 token × 输出单价)</div>

拿计算器里的常规任务（输入 1500、输出 400 token，峰值/均值 = 2.5×，H100 70% 水位下每秒能接 11×0.7 = 7.7 个请求）算一笔账：

- **当平均只有 1 QPS 时**：一个月总计 259 万次请求（约 38.9 亿输入 + 10.4 亿输出 token）。按示例 API 价（输入 $0.30/M、输出 $1.20/M）只要 **$2,411/月**。可如果是自己部署，为了扛住 2.5 QPS 的峰值（至少 1 张 H100 常驻，外加跨可用区双活最少 2 张卡），光卡钱就是 **$3,600/月**，还没算运维人力！**在低 QPS 下，调 API 是压倒性的划算。**
- **当平均涨到 10 QPS 时**：月请求量变成 2592 万次，API 账单直接飙到 **$24,106/月**。而此时自建采用“2 张包月 H100 扛均值 + 白天 8 小时开 2 张 Spot 弹性卡扛波峰”，卡钱总共只要约 **$3,192/月**，即使加上 1 台网关和监控节点，依然比 API 省下近八成。

**临界点就在这里：只要你的基线流量能稳定吃满 1–2 台多卡推理节点（通常日均 3–5 QPS 以上），或者有数据隐私合规、定制微调/LoRA、超低延迟等硬要求，自建就开始回本；在此之前，千万别为了“看起来单 token 便宜”过早自建。**

## 硬件怎么选：算力型、显存带宽型，还是消费级卡？

一旦决定自建，选错卡同样会让成本翻倍。第 8 篇讲过，推理的两个阶段瓶颈截然不同：prefill 卡在算力（FLOPs），decode 卡在显存带宽（BW）和显存容量。不同硬件的性格完全不同，选卡本质上是在找**你的负载落在哪个区间**：

1. **长输入、高吞吐在线主力（H100 / H200）**：算力和 HBM 带宽都很均衡，NVLink 互联拉满，FP8 原生翻倍。如果你的业务是长文档分析、代码库检索（输入动辄 8K–32K），prefill 算力直接决定 TTFT，选 H100/H200 的单位算力性价比最高。
2. **大并发、长输出 decode 主力（H20）**：H20 的 FP16 算力只有 H100 的约 15%（148 vs 989 TFLOPS），但它的显存高达 **96 GB**（甚至更大规格），HBM 带宽也有 **4.0 TB/s**。对于输出很长、并发很高、但输入不长（或者大量命中前缀缓存）的对话或推理模型，瓶颈完全在显存容量和带宽，租金更低的 H20 往往能跑出比 A100 高一倍的并发。
3. **小模型与离线批处理（A100 / L40S / 消费级卡）**：7B–14B 模型量化到 INT4/FP8 后只有 5–10 GB，单张 48 GB 的 L40S 或 24 GB 的消费级卡（如 RTX 4090，带宽约 1 TB/s）就能轻松塞下并跑得很快。但要注意两点：**消费级卡没有 NVLink，多卡跑大模型通信极慢；且多数云厂商和数据中心不提供消费级卡的企业级 SLA 与 ECC 显存保障**，适合离线批处理或边缘推理，慎用于高可用在线集群。

### 真正省钱的混部架构：包月基座 + Spot 弹性 + PD 异构

最高效的生产集群从来不是“清一色买同一种卡用到底”，而是把前面几章的技术拧成一股绳：

- **包月/预留实例（Reserved）兜底基线**：按全天最低谷或均值流量买包月机（通常比按需便宜 30%–40%），24 小时满载跑基础请求。
- **Spot 抢占式实例扛波峰**：云厂商的空闲 GPU（Spot）往往只有按需价格的 **1/3 到 1/2**，但缺点是随时可能被系统提前 30 秒回收。配合第 118 讲的**预分片快启动**和第 121 讲的**流式断点续传**，用 Spot 实例专门跑无状态或短生命周期的扩缩容副本，被回收前 30 秒优雅摘流，成本还能再砍一截。
- **异构 PD 池 + 量化与前缀缓存**：把算力要求高的 prefill 放在算力卡（如 H100/L40S）上，把显存和带宽敏感的 decode 放在大显存卡（如 H20）上（第 112 讲）；再叠加上 FP8 量化和 Prefix Cache，往往能把单集群的总硬件成本再压低 40%–60%。

## 用代码复现

下面的代码算出正文里 1 QPS 与 10 QPS 下“外部 API、纯常驻 H100、纯常驻 H20、包月基座 + 白天 Spot 弹性”四种方案的月账单对比，并打印出从 1 到 20 QPS 随流量增长的盈亏平衡点。

```python
def monthly_cost(qps, peak_ratio=2.5, inp=1500, out=400):
    req_m = qps * 30 * 86400
    api = (req_m * inp / 1e6) * 0.30 + (req_m * out / 1e6) * 1.20

    # 常规任务下，单卡 H100 约 11 QPS，H20 约 5.5 QPS（70% 水位上限）
    import math
    peak_qps = qps * peak_ratio
    n_h100_peak = math.ceil(peak_qps / (11.0 * 0.7))
    n_h20_peak = math.ceil(peak_qps / (5.5 * 0.7))

    h100_static = n_h100_peak * 2.5 * 720
    h20_static = n_h20_peak * 1.4 * 720

    # 包月基座 ($1.8/h) + 白天 8h/天 Spot 弹性 ($1.25/h)
    n_base = math.ceil(qps / (11.0 * 0.7))
    n_burst = max(0, n_h100_peak - n_base)
    hybrid = n_base * 1.8 * 720 + n_burst * 1.25 * 240
    return api, h100_static, h20_static, hybrid

print("日均QPS | 外部 API   | 常驻 H100  | 常驻 H20   | 包月+Spot混部")
for q in (1, 2, 3, 5, 10, 20):
    api, h100, h20, hyb = monthly_cost(q)
    print(f"{q:4d}    | ${api:8,.0f} | ${h100:8,.0f} | ${h20:8,.0f} | ${hyb:8,.0f}")
```

输出：

```text

   1    | $   2,411 | $   1,800 | $   1,008 | $   1,296
   2    | $   4,821 | $   1,800 | $   2,016 | $   1,296
   3    | $   7,232 | $   1,800 | $   2,016 | $   1,296
   5    | $  12,053 | $   3,600 | $   4,032 | $   1,596
  10    | $  24,106 | $   7,200 | $   7,056 | $   3,192
  20    | $  48,211 | $  12,600 | $  13,104 | $   5,088
```

对照正文：1 QPS 时外部 API（$2,411）与单卡相近，但若加上双活冗余与运维人力，API 明显更省；到了 5–10 QPS 以上，包月基座加白天 Spot 混部（$1,596–$3,192）把成本拉到外部 API 的约七分之一。

## 容易混淆的地方

1. **TFLOPS 高不代表推理一定更便宜。** 消费级卡或算力特化卡的 FP16 TFLOPS 可能很高，但如果显存只有 24 GB 放不下 32B 模型，或者 HBM 带宽不够，实际 decode 并发和延迟依然上不去。
2. **对比 API 和自建时，不能只拿“开源小模型自建”去比“闭源旗舰模型 API”。** 选型的前提是**效果达标**；只有在同级别模型能力下，算每百万 token 的 TCO 才有意义。
3. **Spot 实例省钱的前提是“快启动 + 优雅下线”。** 如果冷启动要 5 分钟、又没有断点续传，Spot 实例被频繁回收反而会严重拉低 Goodput，算“有效成本”（第 116 讲）时未必划算。

## 回顾

生产环境的推理成本不能只看理论满载单价，必须把日夜波峰波谷、70% SLO 水位余量和运维复杂度算进 TCO：低 QPS、高波峰比时直接调 API 最省钱省心；基线流量起来后，按负载特征选卡（长 prefill 选算力卡 H100，大并发长 decode 选大显存带宽卡 H20），再用“包月基座 + 白天弹性 Spot”和量化、前缀缓存、PD 分离一起把单价压到最低。
