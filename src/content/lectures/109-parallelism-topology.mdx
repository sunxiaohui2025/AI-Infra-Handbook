前面几讲给了我们五种并行方式：数据并行（DP）、张量并行（TP）、流水并行（PP）、上下文并行（CP）、专家并行（EP）。真实的系统几乎从不只用一种，而是把它们组合起来：比如 TP = 8、PP = 2、DP = 4，一共 64 张卡。

组合起来还不够，还要回答一个具体的问题：**这 64 张卡，哪些卡组成一个 TP 组，哪些组成一个 PP 组？**卡与卡之间的连接是分层的：同一台机器里的卡用 NVLink 相连，快；不同机器之间走网络，慢了一个数量级。同样的并行配置，分组的方式不同，性能可以差好几倍。这一讲把前面的通信分析汇总起来，讲清楚怎么把并行方式映射到拓扑上。

## 互联是分层的

以 H100 的集群为例（数字是第 102 讲用的量级）：

- **机内**：一台 DGX H100 有 8 张卡，通过 NVSwitch 两两全连，每张卡每个方向约 450 GB/s，延迟几微秒。
- **机间**：每张卡配一张 400 Gb/s 的 InfiniBand 网卡，约 50 GB/s，延迟更大，还要经过交换机。

带宽差了 9 倍。更大的系统还有更多层：同一个机柜、同一个网络交换层、跨数据中心……越往外越慢。

## 每种并行的通信特点

把前几讲的结论放在一起：

| 并行方式 | 每一步的通信 | 频率 | 能不能和计算重叠 |
| --- | --- | --- | --- |
| 张量并行 TP | All-Reduce，每层 2 次 | 最高 | 很难，下一层要等它 |
| 上下文并行 CP | 沿环传 K、V，每层 | 高，量大 | 可以，靠重叠 |
| 专家并行 EP | All-to-All，每个 MoE 层 2 次 | 高，量大且不均匀 | 部分可以 |
| 流水并行 PP | 段间点对点，每步几次 | 低，量小 | 容易 |
| 数据并行 DP | 推理时没有；训练时每步同步一次梯度 | 最低 | 容易 |

由此得出映射的原则：**通信越频繁、越需要同步等待的并行，放在越快的互联上**。TP 放在最里层（NVLink），CP、EP 尽量也在 NVLink 域内；PP 和 DP 放在外层，跨机器。

## 算一个例子

两台 8 卡的 H100 机器，一共 16 张卡，部署 Llama-3.1-70B（BF16 141 GB），每个微批次 32 个请求。代码估算了几种方案（TPOT = 读权重 + TP 通信 + 段间传输）：

- **TP = 8（机内）× 2 份**：每份模型在一台机器里，TP 走 NVLink。TPOT **7.0 ms**，其中通信 1.78 ms；全集群约 9083 token/s。
- **TP = 16（跨两台机器）**：每张卡只放 8.8 GB 权重，读权重快了一倍，可每层的 All-Reduce 都要走网络，TP 通信 31.95 ms，TPOT **34.6 ms**，吞吐只有 925 token/s。
- **TP = 8（机内）× PP = 2（跨机）**：机内 TP、机间 PP。段间每步只传一次 524 KB，TPOT 7.1 ms，和第一种几乎一样，而且每张卡只占 8.8 GB 权重，KV Cache 的空间更大。
- **TP = 8 但每组跨两台机器 × 2 份**：卡数和配置都和第一种一样，只是分组的方式错了：每个 TP 组有 4 张卡在机器 0、4 张在机器 1。All-Reduce 被迫走网络，TP 通信 16.38 ms，TPOT **21.6 ms**，是第一种的三倍。
- **TP = 4（机内）× 4 份**：单个请求慢一些（TPOT 11.6 ms），但份数多，全集群吞吐约 11,071 token/s，比 TP = 8 还高。

最后一个例子说明了另一个权衡：**TP 越大，单个请求越快，但通信占比越高；TP 越小，总吞吐可能越高，但延迟变大，每份的 KV Cache 空间也更少**。选哪个，取决于服务对延迟的要求（第 82 讲的 SLO）。

## 训练里的“4D 并行”

大规模训练把四五种并行全用上。Meta 的 Llama 3 技术报告描述了 405B 模型的训练：从里到外依次是张量并行、上下文并行、流水并行、数据并行（FSDP），正是按通信频率从高到低排列的。TP 在机内，CP 也尽量在机内，PP 跨机，DP 在最外层，梯度同步可以和反向传播重叠。

训练框架（Megatron、TorchTitan 等）的配置里，往往有一个参数决定这几个维度的嵌套顺序；卡的编号顺序和物理拓扑对齐，内层的维度自然落在同一台机器里。

## 超节点改变了什么

上面的原则有一个前提：NVLink 域只有 8 张卡。超过 8，就只能跨机。

NVIDIA 的 GB200 NVL72 把 72 张卡放进一个 NVLink 域，任意两张卡之间都是 NVLink 的带宽（第 65 讲的 scale-up）。这对两类负载影响最大：

- **更大的 TP。**70B 甚至更大的稠密模型，TP 可以超过 8，延迟进一步降低。
- **专家并行。**MoE 的 All-to-All 是所有卡两两通信，最怕慢速链路。第 108 讲说 DeepSeek-V3 的 decode 用 320 张卡、靠 InfiniBand 和大量通信优化；在 72 卡的 NVLink 域里，一整组 EP 的 All-to-All 都走高速链路，简单得多，也快得多。

更大的高速互联域，让原本必须放在慢速网络上的并行维度，可以搬到快速链路上。这正是超节点的价值，也是第四章从互联角度讲推理的原因。下一篇会接着讲：在这样的集群上，推理系统还有哪些专门的设计。

## 到了大模型里

**推理引擎的参数。**vLLM、SGLang 用 `--tp`、`--pp`、`--dp`、`--enable-expert-parallel` 等参数组合并行方式；多机部署时，通常每台机器内部做 TP，机器之间做 PP 或 DP。

**让编号和拓扑对齐。**通信库按 rank 的编号建立通信组。启动多机任务时，要保证同一个 TP 组的 rank 落在同一台机器上，否则就会出现上面“TP 组跨机”的情况，而且不会报错，只是悄悄地变慢。

**先测再定。**这一讲的数字是模型估算。实际选方案时，要用第 82 讲的压测方法，在目标负载下比较几种配置的 goodput。

## 用代码复现

下面的代码按 α-β 模型和第 68 讲的读权重时间，估算两台 8 卡机器上几种并行方案的每卡权重、TPOT（拆成读权重和 TP 通信）和全集群吞吐。

```python
# 2 台机器 × 8 张 H100，部署 Llama-3.1-70B（BF16 141 GB，80 层，d = 8192），每份模型每个微批次 32 个请求
W, L, D, BW, GPUS = 141e9, 80, 8192, 3.35e12, 16
NVL = (3e-6, 450e9); IB = (6e-6, 50e9)                  # （α, β）：机内 NVLink、跨机 InfiniBand（第 102 讲的示意数字）
m = 32 * D * 2                                           # 每次 All-Reduce / 段间传输的数据：32 个 token 的隐藏状态

def allreduce(t, link):
    if t == 1: return 0.0
    a, b = link
    return a + (t - 1) * m / b if link is NVL else 2 * (t - 1) * (a + m / t / b)   # 机内一步到位，跨机用 Ring

def plan(tp, pp, tp_cross_node):
    replicas = GPUS // (tp * pp)
    per_gpu = W / (tp * pp)
    read = W / tp / BW                                   # 一个 token 依次走完 pp 段，每段读 W/(tp·pp)，合计 W/tp
    comm = 2 * L * allreduce(tp, IB if tp_cross_node else NVL)
    p2p = 0 if pp == 1 else (pp - 1) * (IB[0] + m / IB[1])   # 段间点对点（这里都按跨机算）
    step = read + comm + p2p                             # 一个请求的 TPOT
    thru = replicas * pp * 32 / step                     # 流水线里同时有 pp 个微批次
    return per_gpu, step, thru, comm

print("方案 | 每卡权重 | TPOT（读权重 + TP 通信 + 段间） | 全集群吞吐")
for name, tp, pp, cross in [("TP=8（机内）× 2 份", 8, 1, False), ("TP=16（跨两台机器）", 16, 1, True),
                            ("TP=8（机内）× PP=2（跨机）", 8, 2, False), ("TP=8 但每组跨两台机器 × 2 份", 8, 1, True),
                            ("TP=4（机内）× 4 份", 4, 1, False)]:
    w, step, thru, comm = plan(tp, pp, cross)
    fit = "" if w + 20e9 < 72e9 else "（放不下：还要留 KV Cache）"
    print(f"{name} | {w / 1e9:5.1f} GB{fit} | {step * 1e3:5.1f} ms（TP 通信 {comm * 1e3:5.2f} ms） | {thru:6,.0f} token/s")
```

输出：

```text
方案 | 每卡权重 | TPOT（读权重 + TP 通信 + 段间） | 全集群吞吐
TP=8（机内）× 2 份 |  17.6 GB |   7.0 ms（TP 通信  1.78 ms） |  9,083 token/s
TP=16（跨两台机器） |   8.8 GB |  34.6 ms（TP 通信 31.95 ms） |    925 token/s
TP=8（机内）× PP=2（跨机） |   8.8 GB |   7.1 ms（TP 通信  1.78 ms） |  9,062 token/s
TP=8 但每组跨两台机器 × 2 份 |  17.6 GB |  21.6 ms（TP 通信 16.38 ms） |  2,958 token/s
TP=4（机内）× 4 份 |  35.2 GB |  11.6 ms（TP 通信  1.04 ms） | 11,071 token/s
```

五行对应上面的五种方案：TP 留在机内（第一、三、五行）通信都很少；TP 跨机（第二、四行）通信时间远超读权重的时间。

## 容易混淆的地方

1. **并行的“大小”和“放法”是两件事。**TP = 8 说的是切成几份，放在哪 8 张卡上是另一个决定，后者同样关键。
2. **更多的卡不一定更快。**TP = 16 比 TP = 8 每卡的权重少了一半，却因为跨机通信慢了五倍。增加并行度之前，先算通信。
3. **延迟和吞吐要分开看。**小的 TP 加更多份数，吞吐可能更高，但每个请求的 TPOT 更长。选方案要看服务的目标是哪一个。

## 回顾

真实的系统把多种并行方式组合起来，还要决定哪些卡组成一组。互联是分层的：机内 NVLink 约 450 GB/s，机间网络约 50 GB/s。按通信的频率和同步程度从里到外安排：TP 最里层，CP、EP 尽量在 NVLink 域内，PP、DP 在外层跨机。两台 8 卡机器跑 70B：TP = 8 机内 × 2 份，TPOT 7.0 ms；TP = 16 跨机，34.6 ms；TP = 8 但每组跨机，21.6 ms；TP = 8 × PP = 2（PP 跨机）几乎不受影响。Llama 3 的训练也按 TP、CP、PP、DP 从里到外排列。GB200 NVL72 这样的超节点把 NVLink 域扩大到 72 张卡，让 TP、EP 能用上更大的高速域。
