第 2 到 5 篇讲完了模型长什么样、怎么训练。这一篇（第 45–51 讲）是一条轻量线，概括地走一遍一个大模型从“一堆随机数”变成“一个会对话的助手”的全过程：预训练、规模的选择、监督微调、偏好对齐、强化学习、参数高效微调和评测。它们大多发生在训练侧，和推理没有直接关系，但理解它们，才知道交到推理系统手里的那个模型是怎么来的。

第一步是**预训练**（pre-training）。它的目标第 23 讲已经说过：在海量文本上预测下一个 token。这一讲关心的是另一半：**那些文本从哪里来，又是怎么挑出来的。**模型知道的一切，都来自这些数据。

## 数据从哪里来

预训练的数据主要有几类：

- **网页**：占了绝大部分。最常用的来源是 Common Crawl，一个从 2008 年起持续抓取互联网的公开项目，累积了数千亿个网页。
- **书籍、百科、论文**：质量高、知识密度大，但量相对少。
- **代码**：来自公开的代码仓库。代码不仅让模型会写程序，也被认为对推理能力有帮助。
- **数学和其他专门领域的数据**：比如数学题、教材。

这些数据要按一定的比例混在一起，叫**数据配比**（data mix）。比如 Llama-3 的论文报告，它的预训练数据大约一半是通用知识，四分之一是数学和推理相关的内容，约 17% 是代码，约 8% 是多语言的文本。配比和数据本身一样，是各家模型的核心机密之一。

规模有多大？Llama-3 的预训练用了 15T（15 万亿）个以上的 token。按每个 token 约 4 个字节粗算，大约是 60 TB 的纯文本。一个人每秒读 1000 个 token，不吃不睡也要读 476 年。

## 原始网页大多不能用

直接抓来的网页，绝大部分质量很差：导航栏、广告、版权声明、乱码、自动生成的垃圾页面，以及大量重复的内容。如果不清洗就拿去训练，模型会学会一堆没用甚至有害的东西，还会白白浪费算力。

所以预训练之前，要先把数据过一遍**清洗流水线**。常见的步骤是：

1. **文本抽取**：从 HTML 里取出正文，扔掉标签、脚本、导航。
2. **语言识别**：判断每篇文档是什么语言，分到不同的桶里。
3. **去重**：完全相同的文档只留一份；“几乎相同”的（比如只改了几个字的转载）也要去掉。
4. **质量过滤**：用规则（太短、符号太多、重复片段太多、脏话太多）和模型（训练一个小分类器判断“像不像高质量文本”）筛掉低质量的文档。
5. **安全和隐私过滤**：去掉有害内容，抹掉个人信息。
6. **配比和分词**：按配比混合，用第 21 讲的分词器切成 token。

几个步骤值得多说一句。

**近似去重**比完全去重难得多。代码里的做法是把文本切成长度为 3 的片段，算两篇文档片段集合的 Jaccard 相似度（交集大小除以并集大小）。第 3 篇只把“喜欢吃鱼”改成了“爱吃鱼”，和第 1 篇的相似度是 0.79，超过阈值 0.7，被当作重复丢掉。真实的数据有几十亿篇，不可能两两比较，实际用的是 MinHash 这类近似算法，先把每篇文档压成一个短的“指纹”，再快速找出相似的。

去重为什么这么重要？重复的内容会让模型反复看到同样的文本，倾向于把它们死记下来，而不是学到可以推广的规律；还会浪费训练的算力。研究发现，充分去重后的数据，往往能用更少的 token 训练出更好的模型。

**质量过滤**是最见功力的一步。规则只能抓出明显的垃圾（比如第 4 篇的广告，重复片段占了 61%）；更精细的判断要靠模型。很多团队会用一个已有的大模型给网页打“教育价值”之类的分，再训练一个小分类器去筛选海量数据。

<Note kind="point">预训练的数据主要来自网页，再加上书籍、代码、数学等高质量来源，按配比混合。原始网页要经过抽取、语言识别、去重、质量过滤、安全过滤等一整套清洗。数据的质量和配比，和模型结构一样决定了模型的能力。</Note>

## 用代码复现

下面的代码实现了演示里的清洗规则：用哈希做完全去重，用 3 字片段的 Jaccard 相似度做近似去重，再按长度、符号比例、重复片段比例过滤，最后按语言分桶；还算了一下 15T token 的数据有多大。

```python
import hashlib
import re

# 一批抓来的“网页”（示意）：有重复、有几乎重复、有乱码、有广告、有太短的
docs = [
    "猫是一种常见的家养动物，喜欢吃鱼，也喜欢晒太阳。很多家庭都养猫。",
    "猫是一种常见的家养动物，喜欢吃鱼，也喜欢晒太阳。很多家庭都养猫。",          # 完全重复
    "猫是一种常见的家养动物，爱吃鱼，也喜欢晒太阳。很多家庭都养猫。",            # 几乎重复
    "点击这里！！！免费领取！！！点击这里！！！免费领取！！！点击这里！！！",        # 广告、重复
    "首页 | 登录 | 注册",                                                       # 太短的导航栏
    "Transformer 由注意力和前馈网络组成，每层都有残差连接和归一化。",
    "@@#$%^&*()_+{}|:<>?@@#$%^&*()_+{}|:<>?",                                    # 乱码
    "梯度下降沿着损失下降最快的方向更新参数，学习率决定每一步走多远。",
    "The cat is a common domestic animal that likes fish and sunshine.",           # 英文（另一个语言桶）
]

def shingles(t, k=3):                    # 把文本切成长度为 k 的片段（用于“几乎重复”的判断）
    return {t[i:i + k] for i in range(len(t) - k + 1)}

def jaccard(a, b):
    return len(a & b) / len(a | b)

kept, seen_hash, kept_sh = [], set(), []
for i, t in enumerate(docs):
    h = hashlib.md5(t.encode()).hexdigest()
    if h in seen_hash:
        print(f"文档 {i + 1}：完全重复，丢弃"); continue
    seen_hash.add(h)
    sh = shingles(t)
    sim = max((jaccard(sh, s) for s in kept_sh), default=0)
    if sim > 0.7:
        print(f"文档 {i + 1}：和已保留的文档相似度 {sim:.2f}，几乎重复，丢弃"); continue
    if len(t) < 15:
        print(f"文档 {i + 1}：太短（{len(t)} 个字符），丢弃"); continue
    sym = len(re.findall(r"[^\w\s，。、；：？！,.\-]", t)) / len(t)
    if sym > 0.3:
        print(f"文档 {i + 1}：符号占 {sym:.0%}，像乱码，丢弃"); continue
    rep = 1 - len(shingles(t)) / max(1, len(t) - 2)
    if rep > 0.3:
        print(f"文档 {i + 1}：重复片段占 {rep:.0%}，像广告或模板，丢弃"); continue
    kept.append(t); kept_sh.append(sh)
lang = lambda t: "中文" if re.search(r"[一-鿿]", t) else "其他"
print(f"保留 {len(kept)} / {len(docs)} 篇：", [lang(t) for t in kept])

# 规模：15T 个 token 的文本有多大（按每个 token 约 4 个字节的 UTF-8 文本粗估）
T = 15e12
print(f"15T token ≈ {T * 4 / 1e12:.0f} TB 文本；按每秒读 1000 个 token，要读 {T / 1000 / 3600 / 24 / 365:,.0f} 年")
```

输出：

```text

文档 3：和已保留的文档相似度 0.79，几乎重复，丢弃
文档 4：重复片段占 61%，像广告或模板，丢弃
文档 5：太短（12 个字符），丢弃
文档 7：符号占 95%，像乱码，丢弃
保留 4 / 9 篇： ['中文', '中文', '中文', '其他']
15T token ≈ 60 TB 文本；按每秒读 1000 个 token，要读 476 年
```

前五行是被丢掉的 5 篇文档和原因，和演示一致。第六行：保留 4 篇，3 篇中文、1 篇其他语言。最后一行是数据规模的估算。

## 到了大模型里

**数据处理本身就是大工程。**几十 TB 的文本，要做抽取、去重、分类器打分，靠的是成千上万个 CPU 核的分布式集群，往往要跑几周。这部分计算不在 GPU 上，却是训练前必不可少的“基础设施”。

**训练时要“喂得上”。**第 20 讲算过，训练 Llama-3-8B 要用上千张 GPU 跑好几周。数据加载要跟得上 GPU 的速度：提前分好词、打乱、存成二进制分片，训练时多个进程并行地读，不能让 GPU 等数据。

**数据决定了推理时的“分布”。**模型在什么样的数据上训练，就擅长什么样的输入。分词器也是在预训练数据上训练出来的（第 21 讲），中文数据多，中文的切分就更省 token，推理就更便宜。

## 容易混淆的地方

1. **更多的数据不一定更好。**低质量、重复的数据会拖累模型。今天的趋势是在质量上下更多功夫，而不只是堆数量。
2. **预训练数据里没有“答案”。**预训练只是让模型学会“接着往下写”。它学到了大量知识，但还不会按照指令回答问题，那是第 47 讲 SFT 的事。
3. **知识有截止时间。**模型只知道训练数据收集截止之前的事。之后发生的事，它要么不知道，要么只能靠推理时额外提供的资料（比如检索、联网搜索）。

## 回顾

模型的知识全部来自预训练的数据：以网页为主，加上书籍、代码、数学等，按配比混合，Llama-3 用了 15T 以上的 token，约 60 TB 文本。原始网页质量很差，要经过文本抽取、语言识别、去重（完全去重和近似去重）、质量过滤、安全过滤等清洗。演示里 9 篇文档只留下了 4 篇。数据的质量、去重和配比，和模型结构一样决定了模型的能力。
