预训练完的模型叫**基座模型**（base model）。它从海量文本里学到了大量知识，但它只会做一件事：接着往下写（第 23 讲）。你问它“怎么做红烧肉？”，它可能接着写出另外几个菜谱问题，因为网上的问题列表常常就是这样排列的。它“知道”答案，却不知道你想要的是一个回答。

把基座模型变成一个会对话、会遵循指令的助手，第一步是**监督微调**（Supervised Fine-Tuning，SFT）：拿一批人工准备好的“提示—回答”对，继续用“预测下一个 token”的方式训练它，让它学会“看到这样的问题，就这样回答”。训练方法和预训练几乎一样，区别只在数据和两个细节：对话模板，以及只对回答算损失。

## 数据：提示和回答

SFT 的数据是一条条示范对话。比如：

- 提示：“用一句话解释什么是梯度下降。”
- 回答：“沿着损失下降最快的方向，一小步一小步地调整参数。”

这些数据通常由人工撰写，或者由更强的模型生成、再经过人工筛选。覆盖的范围尽量广：问答、写作、翻译、编程、数学、拒绝不当请求……数量一般是几万到几百万条，比预训练的数据少好几个数量级。研究发现，SFT 数据的**质量和多样性**远比数量重要：几千条精心挑选的高质量对话，就能让一个基座模型学会像助手一样说话。这背后的解释是：知识主要是预训练学到的，SFT 主要教的是“说话的格式和风格”。

## 对话模板

模型的输入是一串 token，怎么让它分清哪些是用户说的、哪些是它自己说的？办法是用一套**对话模板**（chat template），用特殊 token 把对话的结构标出来。以 Llama-3 的风格为例（示意）：

<div class="ai-formula">&lt;|start_header_id|&gt;user&lt;|end_header_id|&gt; 问题 &lt;|eot_id|&gt; &lt;|start_header_id|&gt;assistant&lt;|end_header_id|&gt; 回答 &lt;|eot_id|&gt;</div>

角色标记告诉模型“下面是谁在说话”，`<|eot_id|>` 表示一轮结束。推理时，系统把用户的问题套进模板，在末尾写上“assistant”的角色标记，然后让模型往下生成；模型生成出 `<|eot_id|>` 时，就知道该停了（第 24 讲）。

每个模型都有自己的模板，推理时必须用和训练时一模一样的模板。模板用错了，模型往往会胡言乱语，或者不知道何时停止。

## 只对回答算损失

SFT 的损失还是交叉熵（第 16 讲），但有一个关键细节：**只在回答部分的 token 上算**。系统提示和用户的问题是给定的输入，模型不需要学着生成它们；如果也算进去，模型会浪费力气去学“用户会怎么提问”，甚至学会替用户说话。实现上很简单：给每个位置一个 0 或 1 的标记，只有标 1 的位置参与损失的平均，这叫**损失掩码**（loss mask）。

## 在 ToyLM 上做一次 SFT

第 22–24 讲的 ToyLM 是在小语料上预训练过的“基座模型”：看到“你 学”，它认为下一个词是“推理”（0.67）或“AI”（0.33），和语料里的频率一致。

现在我们希望它学会：被问到“你 学”时，回答“AI 。”。SFT 数据只有这一条对话：提示是“你 学”，回答是“AI 。”。拆成训练题时，“你”和“学”这两个位置是提示，不算损失；“你 学 → AI”和“学 AI → 。”这两个位置算损失。为了简单，我们只训练输出层（第 33 讲），学习率 0.5，梯度下降 50 步。

结果：

- **“你 学”**：从“推理 0.67、AI 0.33”变成了“AI 1.00”。学会了。
- **“我 学”**：我们没有教过它，它也从“AI 0.67”变成了“AI 1.00”。
- **“小猫 吃”“我 吃”**：几乎没变。

第二条值得注意。“我 学”和“你 学”在模型内部的表示很相近（第 22 讲，“我”和“你”的嵌入相似），所以只教了“你 学”，“我 学”也被一起改变了。这既是 SFT 能“举一反三”的原因，也是它的风险：微调可能在你没注意的地方改变模型的行为。如果 SFT 的数据太窄、训练太猛，模型还会忘掉预训练时学到的东西，叫**灾难性遗忘**。所以实际的 SFT 学习率通常很小，训练的轮数也不多。

## 用代码复现

下面的代码在 ToyLM 上实现了这次 SFT：把对话拆成训练题并标出损失掩码，只用算损失的位置训练输出层，最后比较几个前缀在微调前后的预测。

```python
import json
import numpy as np

ex = json.load(open("tinylm.json", encoding="utf-8"))["examples"]["22"]   # 第 22–24 讲在小语料上预训练的 ToyLM
V = ex["vocab"]
E, W1, b1, W2, b2 = (np.array(ex[k]) for k in ["E", "W1", "b1", "W2", "b2"])

def hidden(a, b):                                   # 看最后两个词，得到隐藏层
    return np.maximum(0, np.concatenate([E[V.index(a)], E[V.index(b)]]) @ W1 + b1)

def probs(a, b, W2, b2):
    z = hidden(a, b) @ W2 + b2
    p = np.exp(z - z.max()); return p / p.sum()

def top(a, b, W2, b2, k=2):
    p = probs(a, b, W2, b2)
    return " ".join(f"{V[i]} {p[i]:.2f}" for i in np.argsort(-p)[:k])

# 1. SFT 数据：一条“对话”。提示是“你 学”，希望的回答是“AI 。”
prompt, answer = ["你", "学"], ["AI", "。"]
seq = ["。", "。"] + prompt + answer
pairs = [(seq[i - 2], seq[i - 1], seq[i]) for i in range(2, len(seq))]
mask = [0] * len(prompt) + [1] * len(answer)        # 只有回答部分算损失
for (a, b, y), m in zip(pairs, mask):
    print(f"  输入“{a} {b}”→ 目标“{y}”：{'算损失' if m else '不算（这是提示）'}")

# 2. 微调：只训练输出层，学习率 0.5，梯度下降 50 步
W2f, b2f = W2.copy(), b2.copy()
train = [(a, b, y) for (a, b, y), m in zip(pairs, mask) if m]
for step in range(50):
    gW, gb = np.zeros_like(W2f), np.zeros_like(b2f)
    for a, b, y in train:
        p = probs(a, b, W2f, b2f)
        p[V.index(y)] -= 1                          # 交叉熵对 logit 的梯度：p − y（第 16 讲）
        gW += np.outer(hidden(a, b), p) / len(train)
        gb += p / len(train)
    W2f -= 0.5 * gW
    b2f -= 0.5 * gb

for a, b in [("你", "学"), ("我", "学"), ("小猫", "吃"), ("我", "吃")]:
    print(f"“{a} {b}”→ 微调前：{top(a, b, W2, b2)}　｜　微调后：{top(a, b, W2f, b2f)}")
```

输出：

```text
  输入“。 。”→ 目标“你”：不算（这是提示）
  输入“。 你”→ 目标“学”：不算（这是提示）
  输入“你 学”→ 目标“AI”：算损失
  输入“学 AI”→ 目标“。”：算损失
“你 学”→ 微调前：推理 0.67 AI 0.33　｜　微调后：AI 1.00 推理 0.00
“我 学”→ 微调前：AI 0.67 推理 0.33　｜　微调后：AI 1.00 推理 0.00
“小猫 吃”→ 微调前：鱼 1.00 。 0.00　｜　微调后：鱼 1.00 。 0.00
“我 吃”→ 微调前：苹果 0.50 香蕉 0.50　｜　微调后：苹果 0.50 香蕉 0.50
```

## 到了大模型里

**SFT 的计算量很小。**和预训练动辄几万亿 token 比，SFT 的数据通常只有几亿到几十亿 token，计算量小几个数量级。但它要更新模型的全部参数，显存需求和预训练一样大（第 19 讲的每参数 16 字节）。这正是第 50 讲 LoRA 要解决的问题。

**对话模板影响推理系统。**推理服务（比如 OpenAI 兼容的接口）收到的是结构化的消息列表，要在服务端按模型的模板拼成 token 序列。系统提示、多轮对话的历史，每一轮都要重新放进输入，所以多轮对话的提示会越来越长。很多请求共享同一个系统提示，这就是第 68 讲前缀缓存的用武之地。

## 容易混淆的地方

1. **SFT 主要教格式，不是教知识。**用 SFT 往模型里灌大量新知识，效果往往不好，还容易让模型学会自信地编造。新知识主要靠预训练（或继续预训练）获得。
2. **指令模型和基座模型是两个模型。**很多模型同时发布两个版本，名字里带 Instruct 或 Chat 的是做过 SFT（和后续对齐）的，可以直接对话；基座版本适合在上面继续微调。
3. **掩码遮的是损失，不是注意力。**提示部分的 token 照常参与前向计算、照常被回答部分的 token 看到（因果掩码之内），只是它们自己的“预测下一个 token”不计入损失。

## 回顾

基座模型只会接着往下写。SFT 用一批“提示—回答”的示范对话继续训练它：用对话模板和特殊 token 标出角色和轮次，用损失掩码只对回答部分计算交叉熵。数据的质量和多样性比数量更重要，因为 SFT 主要教的是说话的格式。在 ToyLM 上，只用一条对话、只训练输出层，就让“你 学”后面从“推理”变成了“AI”，但相似的“我 学”也被一起改变了，这提醒我们微调的影响会扩散。

SFT 教会了模型“像助手一样说话”，但同一个问题可以有很多种回答，哪一种更好、更有帮助、更安全，示范数据很难穷尽。怎么让模型学会人的偏好？下一讲：**RLHF 与 DPO**。
