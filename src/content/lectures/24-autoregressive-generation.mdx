上一讲说，语言模型只做一件事：给下一个 token 一个概率分布。可我们用大模型时，看到的是它写出了一整段话。从“一个分布”到“一整段话”，中间只差两步：**从分布里挑一个 token，再把它接回输入，接着预测下一个。**一直重复，直到模型生成一个表示结束的 token。

这种“用自己刚才的输出作为下一步的输入”的方式，叫**自回归生成**（autoregressive generation）。这一讲用上一讲的小模型，一步一步地看它怎么生成句子，比较两种挑词的方法：贪心和采样；最后会看到，正是“一次只能出一个 token”这个特点，决定了大模型推理的速度瓶颈，也决定了第三章要讲的大半内容。

## 预测、选词、接回去

自回归生成是一个循环，每一圈做三件事：

1. **前向**：把已有的 token 送进模型，得到下一个 token 的分布。
2. **选词**：按某种规则从分布里挑出一个 token。
3. **接回去**：把它接到已有 token 的末尾。

直到挑出的是结束标记（我们的小模型里是句号“。”，真实模型里是 `<eos>` 这类特殊 token），或者达到了设定的最大长度，循环停止。

用上一讲的小模型，从空白开始，每次挑概率最大的词：

| 步 | 模型看的两个词 | 概率最大的下一个词 | 现在的句子 |
| --- | --- | --- | --- |
| 1 | 。 。 | 我（0.416） | 我 |
| 2 | 。 我 | 吃（0.398） | 我 吃 |
| 3 | 我 吃 | 苹果（0.501） | 我 吃 苹果 |
| 4 | 吃 苹果 | 。（接近 1） | 我 吃 苹果 。 |

4 次前向，生成了一句“我 吃 苹果 。”。注意第 3 步：模型的输入“我 吃”里，“吃”是它在第 2 步自己生成的。每一步的输出都成为下一步输入的一部分，这就是“自回归”的意思。

## 贪心：每次选最大的

刚才用的挑词规则叫**贪心解码**（greedy decoding）：每一步都选概率最大的那个。它简单、确定：同样的开头，永远生成同样的结果。从空白开始，永远是“我 吃 苹果 。”；从“小狗”开始，永远是“小狗 吃 骨头 。”。

问题也很明显。第 3 步，苹果的概率是 0.501，香蕉是 0.499，几乎一样，可贪心永远选苹果，“我 吃 香蕉”这句完全合理的话，它一辈子也说不出来。同样，“你”开头的句子（概率 0.25）、“小猫”开头的句子，也都不会出现。分布里明明有很多种可能，贪心只取了其中一条。

在大模型里，贪心解码还有一个出名的毛病：容易陷入重复，同一句话说了又说。因为一旦进入某个“高概率”的套路，下一步最可能的又是同一个套路。

## 采样：按概率抽

另一种规则是**采样**（sampling）：按照分布的概率，随机抽一个（第 7 讲）。苹果和香蕉各有约一半的机会被抽中；“我”开头的概率是 0.416，“你”开头是 0.25……这样，模型能说出的话就和训练语料一样丰富了。下面的代码从空白开始采样了 5 次，得到：你 吃 苹果 / 小猫 喜欢 鱼 / 你 学 推理 / 小狗 吃 骨头 / 小狗 吃 骨头。

采样带来了多样性，也带来了风险：偶尔会抽中一个概率很低、但不太合理的 token，一旦接进去，后面就可能越走越偏。为了控制这种“冒险的程度”，采样之前通常会用**温度**（temperature）*T* 调整一下分布：

$$
p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}
$$

也就是先把每个 logit 除以 *T*，再做 softmax（第 6 讲）。*T* = 1 时就是原来的分布。以句子开头为例：

| 温度 | 我 | 你 | 小猫 | 小狗 |
| --- | --- | --- | --- | --- |
| *T* = 0.3 | 0.782 | 0.143 | 0.037 | 0.037 |
| *T* = 1 | 0.416 | 0.25 | 0.167 | 0.167 |
| *T* = 3 | 0.29 | 0.245 | 0.214 | 0.214 |

*T* 小于 1，logit 之间的差距被放大，高的更高、低的更低，分布变“尖”，采样的结果越来越接近贪心；*T* 趋于 0 时就是贪心。*T* 大于 1，差距被缩小，分布变“平”，冷门的词也有了不小的机会。代码里 *T* = 3 采样的 5 句话中，出现了一句“小狗 小猫 骨头 。”：第二个词本该是“吃”或“喜欢”，却抽中了一个在那个位置几乎不可能的词。温度太高，就会这样胡言乱语。

<Note kind="point">自回归生成 = 前向得到分布 → 按规则选一个 token → 接回输入，重复到结束。贪心每次选最大的，确定但单调；采样按概率抽，丰富但有风险，温度控制分布的尖平。</Note>

## 一次只能出一个

自回归生成有一个根本的约束：**第 k 个 token 必须等第 k − 1 个 token 生成出来，才能开始算**，因为它的输入里就包含第 k − 1 个 token。所以生成 n 个 token，就要做 n 次前向，一次接一次，没法并行。这和训练时完全不同：训练时整段文本都是已知的，所有位置的“下一个词”可以在一次前向里同时算（上一讲）。

我们的小模型只看最后两个词，每一步的计算量是固定的。可第 4 篇的 Transformer 会看前面所有的 token。如果每一步都把整段话重新完整地算一遍，越往后要算的越多：提示有 1000 个 token、再生成 1000 个，每一步分别要处理 1000、1001、1002……个 token，一共要处理约 150 万个 token 位置。

但仔细想，前面那些 token 在上一步已经算过了，它们的中间结果并没有变。把这些中间结果存下来，每一步只算新来的那一个 token，总共只需要处理 1000 + 999 = 1999 个位置。这就是第 61 讲的 **KV Cache**：用显存换计算，是大模型推理里最重要的一项优化。至于具体要存什么、存多少，要等第 4 篇讲完注意力之后才能说清楚。

## 用代码复现

下面的代码实现了自回归生成的循环，分别用贪心和不同温度的采样生成句子；然后打印温度对分布的影响；最后算两个推理的工程数字（下一节用）。

```python
import json
import numpy as np

ex = json.load(open("tinylm.json", encoding="utf-8"))["examples"]["22"]
V = ex["vocab"]
E, W1, b1, W2, b2 = (np.array(ex[k]) for k in ["E", "W1", "b1", "W2", "b2"])

def logits(seq):                                   # 只看最后两个词，不够就用“。”补
    a, b = (["。", "。"] + seq)[-2:]
    x = np.concatenate([E[V.index(a)], E[V.index(b)]])
    return np.maximum(0, x @ W1 + b1) @ W2 + b2

def softmax(z, T=1.0):
    p = np.exp((z - z.max()) / T)
    return p / p.sum()

def generate(start, how="greedy", T=1.0, rng=None, max_len=10):
    seq = list(start)
    while len(seq) < max_len:
        p = softmax(logits(seq), T)                # ① 前向：得到下一个词的分布
        if how == "greedy":
            nxt = V[int(np.argmax(p))]             # ② 选词：概率最大的
        else:
            nxt = V[rng.choice(len(V), p=p)]       # ② 选词：按概率抽
        seq.append(nxt)                            # ③ 接回输入
        if nxt == "。":
            break
    return " ".join(seq)

print("贪心，从头开始：", generate([]))
print("贪心，从“小狗”开始：", generate(["小狗"]))
print("贪心，从“你 学”开始：", generate(["你", "学"]))
for T in [1.0, 0.3, 3.0]:
    rng = np.random.default_rng(0)
    print(f"采样 T = {T}：", " | ".join(generate([], "sample", T, rng) for _ in range(5)))

# 温度对分布的影响：前缀为空时
z = logits([])
for T in [0.3, 1.0, 3.0]:
    p = softmax(z, T)
    print(f"T = {T}：", {V[i]: round(float(p[i]), 3) for i in np.argsort(-p)[:4]})

# 没有缓存时的重复计算：提示 1000 个 token，再生成 1000 个
p_len, n = 1000, 1000
no_cache = sum(p_len + k for k in range(n))        # 每一步都把整段重新算一遍
print(f"不缓存：共处理 {no_cache:,} 个 token 位置；缓存：{p_len + n - 1:,} 个")

# 解码一个 token 至少要把全部权重从显存读一遍（Llama-3-8B，BF16；H100 显存带宽约 3.35 TB/s）
w_bytes, bw = 8.03e9 * 2, 3.35e12
print(f"每个 token 读 {w_bytes / 1e9:.1f} GB 权重：至少 {w_bytes / bw * 1e3:.1f} ms，单条请求最多约 {bw / w_bytes:.0f} token/s")
```

## 到了大模型里

**推理分两个阶段。**你把一段提示发给大模型，它先把整段提示一次性送进去做前向，这叫 **prefill**；然后才开始一个一个地生成，这叫 **decode**（第 60 讲）。prefill 可以并行处理成百上千个 token，主要受限于算力；decode 每一步只处理一个新 token，却要把整个模型的权重都用一遍。

**decode 受限于显存带宽。**每生成一个 token，模型的每一个权重都要从显存读到计算单元里参与一次乘法。Llama-3-8B 的权重用 BF16 存是 16.1 GB，H100 的显存带宽约 3.35 TB/s，光是把权重读一遍就要至少 4.8 毫秒。所以单独一条请求，每秒最多也就生成约 209 个 token，不管 GPU 的算力有多强。这个“搬数据比算还慢”的现象，第 54 讲的 Roofline 模型会讲透。

**解决办法是把很多请求凑在一起。**既然每一步都要把权重读一遍，那就让这一遍读进来的权重，同时服务几十、上百个请求：每个请求各出一个 token，权重只读一次。这就是批处理，第 66 讲的 Continuous Batching 让它在请求有长有短、随时进出的情况下也能高效进行。衡量推理快慢的指标也由此而来：第一个 token 出来要多久（TTFT），之后每个 token 隔多久（TPOT），以及整个系统每秒能生成多少 token（吞吐），见第 62 讲。

## 容易混淆的地方

1. **温度为 0 不是真的除以 0。**各种推理框架里“temperature = 0”都按贪心处理，直接取概率最大的。所以把温度设成 0，同样的输入会得到同样的输出（在不考虑浮点误差的前提下）。
2. **同样的问题得到不同的回答，是采样造成的，不是模型“变了”。**模型的权重在推理时不会改变，给同样的输入，分布永远是同一个。不同的是从分布里抽出了哪个 token，而一个 token 的不同，会让后面的整段话走向不同的方向。
3. **温度不是唯一的选词手段。**实际中常和 Top-k（只在概率最高的 k 个里抽）、Top-p（只在累计概率达到 p 的那些里抽）一起用，把概率极低的“离谱”选项直接排除。这些留到第 65 讲。

## 回顾

自回归生成是一个循环：把已有的 token 送进模型得到分布，按规则选一个，接到末尾，再来一遍，直到生成结束标记。贪心每次选概率最大的，结果确定但单调；采样按概率随机抽，结果丰富，温度 *T* 控制分布的尖平：*T* 越小越接近贪心，*T* 太大会说出病句。生成 n 个 token 要做 n 次前向，一次只能出一个；这让大模型推理的 decode 阶段受限于显存带宽，也催生了 KV Cache、批处理这些第三章的核心技术。

第 3 篇到这里结束。我们的小模型有一个致命的短板：它只看最后两个词。“我 喜欢 小猫 。 小猫 吃”，它对前面发生的事一无所知。真正的大模型要能看到前面成千上万个 token，并且知道每个词和哪些词有关。这是第 4 篇 Transformer 的任务。不过在讲注意力之前，还有一个小问题要先解决：第 22 讲说过，嵌入里没有位置信息，“我爱你”和“你爱我”查出来的是同一组向量。模型怎么知道每个词在第几个位置？下一讲：**位置编码**。
