三、分发是按设备键查表：给 MPS 换一份 mm 的实现，看调用被转到哪里
  注册之后 x @ w：进了我们的实现 1 次，输入形状 ((2, 3), (3, 4))，输出 (2, 4)，每个元素都是 3：True
  注销之后再算一次：进我们的实现 1 次（没有再进），结果仍然对：True
  一块新卡的接入就是这件事的规模化：几千个算子逐个注册到自己的键上。

三之二、注册一个全新的设备名（PrivateUse1）
  rename + 生成接口之后，Python 侧多出来的东西：Tensor.mychip -> True ，Tensor.is_mychip -> True ，Module.mychip -> True
  但 torch.empty(2, 2, device='mychip') 还不能用：显存分配器、流、事件、拷贝都要在 C++ 里实现。
  这就是 ROCm 式接法（沿用 CUDA 键）和 PrivateUse1 式接法的分界：前者白拿 CUDA 那一套，后者从零铺。

四、缺算子时的两种结局（以 MPS 上没有的 aten::_scaled_mm 为例）
  直接调用： The operator 'aten::_scaled_mm' is not currently implemented for the MPS device
  打开 PYTORCH_ENABLE_MPS_FALLBACK=1 后，PyTorch 会把它悄悄搬到 CPU 上算完再搬回来，
  正确性没问题，但一次调用要多两趟拷贝——第 140 讲量过这笔账。
