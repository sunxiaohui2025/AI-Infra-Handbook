计算机其实只会做一件事：算数。加、减、乘、除，再加上比大小。它不认识「苹果」，也不知道「我 爱 学 AI」这句话是什么意思。

可是大模型偏偏要处理文字、图片、声音。那它是怎么做到的？答案的第一步非常朴素：**先把要处理的东西变成一串数字**。变成数字以后，计算机就能对它做加减乘除了。

这串数字，就是这一讲的主角——向量。这一讲我们只做三件事：看看「变成一串数字」具体是怎么回事；看看一串数字能做哪两种最基本的运算；再看看在真实的大模型里，这串数字有多长、要占多少显存。

## 先给水果打个分

先不谈大模型，从一个更容易想象的例子开始。

假设你开了一家水果店，想让电脑帮你管理水果。电脑不认识水果，所以你得用数字来描述每一种水果。最简单的办法是挑几个特征打分，比如「甜度」和「酸度」，各打 0 到 10 分：

| 水果 | 甜度 | 酸度 |
| --- | --- | --- |
| 苹果 | 7 | 4 |
| 柠檬 | 2 | 9 |
| 香蕉 | 8 | 1 |
| 葡萄柚 | 4 | 7 |

这样一来，苹果就可以写成 (7, 4)，柠檬写成 (2, 9)。电脑不需要知道「苹果」是什么，它只需要记住 (7, 4) 这两个数。

这里有一个很容易忽略、但非常重要的约定：**顺序是固定的**。我们约好第一个数是甜度、第二个数是酸度，那 (7, 4) 和 (4, 7) 就是两种完全不同的水果——前者偏甜，后者偏酸。所以一串数字不只是「几个数」，而是「几个按约定顺序排好的数」。

## 把水果放进坐标系

两个数，正好可以当成平面上的坐标。把甜度当横轴、酸度当纵轴，每种水果就是平面上的一个点。

从原点 (0, 0) 向这个点画一条带箭头的线段，就得到了向量的另一种画法：**箭头**。点和箭头说的是同一件事，只是看的角度不同。当成点时，我们关心它「在哪里」；当成箭头时，我们关心它「朝哪个方向、有多长」。后面讲向量运算时，箭头的画法会更直观。

下面的演示里，灰色箭头是表格里的四种水果，绿色箭头是一种「新水果」。拖动绿色箭头的末端（也可以点一下圆点后用方向键微调），看看右边的数字怎么变。

<VectorPlane mode="explore" caption="图 1-1　甜度–酸度坐标系里的水果。拖动绿色箭头，右侧会实时算出坐标、长度和离它最近的水果。" />

默认位置的新水果是 (6, 5)。右边告诉我们三件事。

第一是**坐标**：(6, 5)，也就是甜度 6、酸度 5。

第二是**长度**：箭头从原点到 (6, 5) 有多长。这就是勾股定理，√(6² + 5²) ≈ 7.81。长度描述的是「这个向量有多大」，在水果的例子里大致对应「味道有多浓」。

第三是**离它最近的水果**：苹果。苹果在 (7, 4)，两点之间的距离是 √((6−7)² + (5−4)²) = √2 ≈ 1.41，比离其他几种水果都近。换句话说，这种新水果「尝起来最像苹果」。

最后这一点值得停下来想一想。我们原本只是想让电脑记住水果，结果顺手得到了一个能力：**「像不像」变成了一个可以计算的问题**。两种东西像不像，就看它们的向量离得近不近。大模型判断两个词意思是否相近、一句话和哪段资料最相关，用的都是这个思路，只不过量「近不近」的方法更讲究一些，下一讲专门讲。

<Note kind="point">把东西变成向量，最大的好处是：它们之间的关系（像不像、差多少）变成了可以算出来的数字。</Note>

## 向量就是一串有顺序的数

现在可以给向量下一个正式一点的定义了。

**n 个数按固定顺序排成一串，就叫一个 n 维向量**。写成

<div class="ai-formula"><b><i>v</i></b> = (<i>v</i><sub>1</sub>, <i>v</i><sub>2</sub>, …, <i>v</i><sub>n</sub>)</div>

其中 *v*<sub>1</sub> 是第 1 个数，*v*<sub>2</sub> 是第 2 个数，依此类推，每一个叫做向量的一个**分量**。分量的个数 n 叫做向量的**维度**。水果的向量有甜度、酸度两个分量，所以是 2 维的。

你在大学的线性代数里学过更抽象的定义（向量空间、满足某些运算规律的元素……）。那些都对，但在这门课里，绝大多数时候只需要记住最朴素的这一层：**向量就是一串有顺序的数，每个位置有它自己的含义。**

向量的长度也可以推广到 n 维：把每个分量平方、加起来、再开方，

<div class="ai-formula">|<b><i>v</i></b>| = √(<i>v</i><sub>1</sub><sup>2</sup> + <i>v</i><sub>2</sub><sup>2</sup> + … + <i>v</i><sub>n</sub><sup>2</sup>)</div>

苹果 (7, 4) 的长度就是 √(49 + 16) = √65 ≈ 8.06。这个「长度」在大模型里会反复出现：模型每算完一层，都要把向量的长度拉回到差不多的大小，防止数字越算越大或越算越小。这件事叫归一化，第 30 讲和第 36 讲会讲到。

## 两个向量相加

有了向量，就可以对它做运算了。最基本的运算只有两种：**加法**和**数乘**。先看加法。

还是水果店。你想做一款「加糖苹果」：在苹果的基础上加一勺糖。一勺糖只增加甜度、不影响酸度，可以写成向量 (2, 0)。加糖之后的苹果，就是把两个向量的**对应分量**分别相加：

<div class="ai-formula">(7, 4) + (2, 0) = (7 + 2, 4 + 0) = (9, 4)</div>

甜度从 7 变成 9，酸度还是 4。规则就这么简单：第 1 个分量和第 1 个分量相加，第 2 个和第 2 个相加。两个向量的维度必须相同，否则没有「对应分量」可以加。

几何上，向量加法有一个很好记的画法：**把第二个箭头接在第一个箭头的末端**，从原点走到最终的终点，就是两者之和。下面的演示里，你可以分别拖动 a 和 b：

<VectorPlane mode="add" caption="图 1-2　向量加法。黑色箭头是 a + b；两条虚线表示「把 b 接在 a 末端」和「把 a 接在 b 末端」，它们走到同一个点。" />

默认 a = (3, 1)，b = (1, 2)，所以 a + b = (4, 3)。试着拖动一下，注意两件事。

一是两条虚线总是在 a + b 的终点汇合。先走 a 再走 b，和先走 b 再走 a，到达的是同一个地方，也就是 a + b = b + a。四条线段围成一个平行四边形，a + b 就是它的对角线。

二是试着把 b 拖到和 a 方向相反的位置，比如 b = (−3, −1)。这时 a + b 变成 (0, 0)，两个向量正好抵消。

## 把向量放大、缩小、反过来

第二种运算是**数乘**：用一个普通的数 k 去乘向量，规则是**每个分量都乘以 k**。

<div class="ai-formula"><i>k</i> · (<i>v</i><sub>1</sub>, <i>v</i><sub>2</sub>) = (<i>k v</i><sub>1</sub>, <i>k v</i><sub>2</sub>)</div>

比如 0.5 × (7, 4) = (3.5, 2)：甜度和酸度都减半，可以想象成把苹果汁兑了一倍的水，味道变淡了，但「甜里带一点酸」的比例没变。

这正是数乘在几何上的意思：**方向不变，长度变成原来的 |k| 倍**。k 是负数时，箭头会翻转到相反的方向。在下面的演示里拖动 a，再拉动 k 的滑块：

<VectorPlane mode="scale" caption="图 1-3　数乘。绿色是 a，琥珀色是 k·a。拉动滑块，注意 k 为负数、为 0、在 0 和 1 之间时分别发生了什么。" />

把 k 从 2 慢慢拉到 −2，你会看到：k > 1 时箭头拉长；0 < k < 1 时缩短；k = 0 时整个箭头缩成原点上的一个点，这个所有分量都是 0 的向量叫**零向量**；k 变成负数后，箭头掉头指向反方向。不管 k 是多少，k·a 始终在 a 所在的那条直线上。

<Note kind="column" title="专栏　为什么只讲这两种运算">
加法和数乘看起来太简单了，为什么要专门拿出来讲？因为大模型里大量的计算，拆开看都是这两种运算的组合：先把几个向量各自乘上一个数，再加起来，即 *k*<sub>1</sub>**a** + *k*<sub>2</sub>**b** + …，这叫**线性组合**。

举两个后面会遇到的例子。第 26 讲的注意力机制，输出就是把若干个向量按「注意力权重」做线性组合；第 29 讲的残差连接，是把一层的输入和输出直接相加。等你读到那里，会发现它们用到的就是这一节的两张图。
</Note>

## 从 2 维到 4096 维

只用甜度和酸度描述水果显然太粗糙了。苹果和梨可能甜度、酸度都差不多，但一个脆、一个软，香气也不一样。想描述得更准确，就得加特征：脆度、香气、水分……每多一个特征，向量就多一个分量，维度就加 1。

3 维向量还能在空间里画出来，4 维以上就画不出来了。但这一点也不影响计算：**加法还是对应分量相加，数乘还是每个分量乘 k，长度还是平方和开根号**。规则一个字都不用改，只是分量变多了。这正是把东西变成向量的另一个好处——维度再高，算法都一样。

大模型处理文字，也是这个思路：**给词表里的每个词分配一个向量**。我们全站使用的玩具模型 TinyLM 只有 6 个词，每个词用一个 4 维向量表示。把这 6 个向量一行一行排起来，就是下面这张表：

「我」就是 (0.7, −0.6, −0.9, 0.3)，「爱」就是 (−0.3, −0.1, −0.8, −0.2)。和水果不同，这 4 个分量没有「甜度」「酸度」这样的名字。这些数字现在是随机生成的，还没有任何含义；模型经过训练以后，它们会被调整到「意思相近的词，向量也相近」的位置上。这个过程第 22 讲再讲。

一句话「我 爱 学 AI」有 4 个词，于是就变成了 4 个 4 维向量。把它们一行一行叠起来，就得到一张 4×4 的数字表——这就是第 3 讲要讲的矩阵。

真实的大模型里，每个词的向量要长得多。以大纲里用作例子的 Llama-3-8B 为例，每个词是一个 **4096 维**的向量（这个数字写正文时请对照官方配置核实）。4096 个分量，每一个都没有人能读懂的名字，但加法、数乘的规则和我们刚才拖来拖去的 2 维向量完全一样。

## 一个向量要占多少显存

到这里，我们可以换一个 Infra 的角度看向量：**它要占多少内存？**

向量的每个分量是一个浮点数。存一个浮点数要几个字节，取决于用什么格式：常见的 FP32 要 4 字节，大模型推理时常用的 BF16 只要 2 字节（为什么可以这样省、省了会不会出问题，第 10 讲专门讲）。

于是一个 4096 维、BF16 格式的向量要占 4096 × 2 = **8192 字节，也就是 8 KiB**。单看一个，好像很小。但大模型从来不只处理一个向量：

- 一段 1000 个词的输入，就是 1000 个这样的向量，合计 1000 × 8192 字节 ≈ **7.8 MiB**。而且模型有几十层，每一层都要处理这样一批向量。
- 词表里的每个词都要准备一个向量。Llama-3-8B 的词表大约有 12.8 万个词（128256 个，同样需要核实），光是这一张词向量表就要 128256 × 4096 × 2 字节 ≈ **0.98 GiB**。

<Note kind="point">向量的维度 d 是整个课程里最基本的一个数。显存要多少、计算量有多大，几乎都要从「每个向量有 d 个数」开始算。</Note>

## 用代码试一试

上面所有的数字，都可以用几行 NumPy 验证。先在 `tinylm/` 目录里运行一次 `python tinylm.py` 生成 `tinylm.json`，再在同一目录运行：

```python
import json
import numpy as np

apple = np.array([7, 4])         # 苹果：甜度 7，酸度 4
sugar = np.array([2, 0])         # 一勺糖：只加甜度
print(apple + sugar)             # 加法：对应分量相加
print(0.5 * apple)               # 数乘：每个分量乘 0.5
print(np.linalg.norm(apple))     # 长度：√(7² + 4²)

tiny = json.load(open("tinylm.json", encoding="utf-8"))
vocab = tiny["config"]["vocab"]
E = np.array(tiny["weights"]["embedding"])   # 6 个词，每个 4 维
print(E.shape)
print(E[vocab.index("我")])                  # 「我」的向量
print(E[vocab.index("我")] + E[vocab.index("爱")])

d = 4096                                     # Llama-3-8B 的隐藏维度（待核实）
print(d * 2, "字节")                          # 一个 BF16 向量
print(1000 * d * 2 / 2**20, "MiB")            # 1000 个 token 的向量
print(128256 * d * 2 / 2**30, "GiB")          # 词表里每个词一个向量
```

输出：

```text
[9 4]
[3.5 2. ]
8.06225774829855
(6, 4)
[ 0.7 -0.6 -0.9  0.3]
[ 0.4 -0.7 -1.7  0.1]
8192 字节
7.8125 MiB
0.978515625 GiB
```

逐行对一下：加糖苹果 (9, 4)，兑水苹果 (3.5, 2)，苹果的长度 √65 ≈ 8.06，和正文一致。`E.shape` 是 (6, 4)，即 6 个词、每个 4 维。倒数第四行把「我」和「爱」两个 4 维向量相加，规则和 2 维时一模一样：0.7 + (−0.3) = 0.4，−0.6 + (−0.1) = −0.7，依此类推。

## 容易混淆的地方

1. **「4096 维向量」在 NumPy 里是「1 维数组」**。这里的两个「维」不是一回事。向量的维度说的是它有几个分量；数组的维数（`ndim`）说的是它有几个轴。一个 4096 维的向量是一个形状为 `(4096,)` 的一维数组；而上面的词向量表 `E` 是二维数组，形状 `(6, 4)`。这个区别第 5 讲还会专门讲。
2. **不是每个分量都有人能看懂的含义**。水果的例子里，每个分量都有名字。但大模型学出来的向量，单独看某一个分量通常说明不了什么，有意义的是整个向量和其他向量之间的关系。
3. **点和箭头是同一个向量**。画成点还是画成箭头，只是为了看问题方便，数学上没有区别。

## 回顾

这一讲从水果店出发，看到了把东西变成数字的完整过程：先约定好每个位置代表什么特征，再给每个东西打分，得到一串有顺序的数，也就是向量。向量可以画成点或箭头；它有长度；可以相加，也可以乘以一个数，而这两种运算在任何维度下规则都一样。大模型做的第一件事，就是给每个词准备一个这样的向量；在真实模型里它有几千维，光是一张词向量表就要占将近 1 GiB 显存。

还有一个问题留着没细讲。在水果的演示里，我们用「距离」判断新水果像哪种水果。可是大模型里，判断两个向量像不像，更常用的是另一种量法：把两个向量的对应分量相乘再相加。为什么要这么量？它和两个箭头之间的夹角有什么关系？这就是下一讲的内容：**点积与余弦相似度**。
