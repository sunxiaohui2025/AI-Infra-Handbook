SFT 教会了模型像助手一样说话（第 47 讲），但它只能模仿示范数据。同一个问题，可以有很多种都“说得通”的回答：有的更准确，有的更啰嗦，有的语气生硬，有的带着不该说的内容。要把“什么是好回答”全部写成示范，几乎不可能。

但让人**比较**两个回答，判断哪一个更好，却容易得多。这一讲介绍怎么利用这种“二选一”的偏好数据来训练模型，也就是常说的**对齐**（alignment）：经典的 **RLHF**（基于人类反馈的强化学习），以及更简单、今天很常用的 **DPO**（直接偏好优化）。

## 偏好数据

偏好数据的每一条是一个三元组：一个提示，两个回答，以及人的判断“哪个更好”。比如：

- 提示：“我晚上睡不着，怎么办？”
- 回答 A：给出几条具体可行的建议，并提醒长期失眠应就医。
- 回答 B：“多睡就好了。”
- 判断：A 更好。

回答通常由 SFT 之后的模型自己生成（对同一个提示采样两次），再交给标注者比较。比较比打分更可靠：人很难稳定地说出“这个回答值 7.3 分”，却很容易说出“这个比那个好”。

## RLHF：先学一个打分员

RLHF 分两步。

**第一步，训练一个奖励模型**（reward model）。它通常是一个和语言模型结构相同、但输出层换成单个数字的模型：输入提示和回答，输出一个分数 r。怎么用“二选一”的数据训练它？用 **Bradley–Terry 模型**：假设人觉得 A 比 B 好的概率是

$$
P(A \succ B) = \sigma(r_A - r_B)
$$

σ 是第 14 讲的 Sigmoid。两个分数相等时概率是 0.5；A 的分高出 1，概率是 0.731；高出 3，是 0.953。训练的损失就是对人选中的那个回答取交叉熵（第 16 讲）：−ln σ(r<sub>好</sub> − r<sub>差</sub>)。两个分相等时损失是 ln 2 ≈ 0.693，分差越大损失越小。训练完，奖励模型就成了一个“自动的打分员”，能给任何回答打分。

**第二步，用强化学习优化语言模型。**让语言模型对提示生成回答，奖励模型给回答打分，然后调整语言模型的参数，让高分回答的概率变大。常用的算法叫 PPO。这里有一个重要的约束：不能让模型为了讨好奖励模型而“走火入魔”，比如发现某种奇怪的说法能骗到高分，就一直这样说。所以优化目标里还要减去一项，惩罚模型偏离原来的 SFT 模型太远（用第 16 讲的交叉熵思想衡量的一种“距离”，叫 KL 散度）：

<div class="ai-formula">最大化：奖励 − β × (和参考模型的差距)</div>

RLHF 是 ChatGPT 成功的关键技术之一，但它很复杂：要同时维护语言模型、参考模型、奖励模型，PPO 还需要一个价值模型，四个大模型同时在显存里，训练还很不稳定。

## DPO：跳过奖励模型

2023 年提出的 **DPO**（Direct Preference Optimization）发现，上面那个“奖励减去偏离惩罚”的优化问题，可以通过数学推导，变成一个直接作用在语言模型上的损失函数，**不需要单独训练奖励模型，也不需要强化学习**。

记 π 是正在训练的模型，π<sub>ref</sub> 是参考模型（SFT 之后的模型，固定不动），y<sub>w</sub> 是好回答，y<sub>l</sub> 是差回答。定义每个回答的“隐式奖励”为：模型给它的对数概率，比参考模型高出多少，再乘以 β：

<div class="ai-formula">隐式奖励(<i>y</i>) = β · (ln π(<i>y</i>) − ln π<sub>ref</sub>(<i>y</i>))</div>

然后套用 Bradley–Terry 的损失：

<div class="ai-formula">DPO 损失 = −ln σ(隐式奖励(<i>y</i><sub>w</sub>) − 隐式奖励(<i>y</i><sub>l</sub>))</div>

直观上，它要求模型“提高好回答的概率、降低差回答的概率”，而且是**相对于参考模型**的提高和降低。这个“相对”起到了 RLHF 里偏离惩罚的作用：模型不会无节制地偏离原来的样子。它的梯度还有一个很好的性质：前面乘着一个权重 σ(−差值)，好回答和差回答还没被区分开时，权重接近 0.5，推得用力；已经分得很开时，权重接近 0，几乎不推了。

下面的演示左边是奖励模型的偏好概率，右边是 DPO 的损失。拖动滑块，看分差、损失和“推的力度”怎么变。

<Note kind="point">偏好学习用“二选一”的数据训练模型。RLHF 先训练奖励模型（P(A ≻ B) = σ(r_A − r_B)），再用强化学习让模型获得高分、同时不偏离参考模型太远；DPO 把这两步合成一个直接的损失：相对参考模型，提高好回答、降低差回答的概率。</Note>

## 在 ToyLM 上做一次 DPO

ToyLM 看到“我 吃”时，“苹果”和“香蕉”几乎各占一半（0.501 和 0.499），因为语料里两者一样多。假设人更喜欢“苹果 。”。我们用 DPO 训练它（β = 0.5，只训练输出层），参考模型就是训练前的 ToyLM。

一开始，模型和参考模型完全一样，两个隐式奖励都是 0，损失是 ln 2 = 0.693。训练 10 步后，“苹果”的概率涨到 0.884，损失降到 0.309；30 步后 0.981，损失 0.129。随着两个回答被分开，每一步推的力度越来越小，损失的下降也越来越慢。

## 用代码复现

下面的代码先算了几组 Bradley–Terry 的概率和损失；然后在 ToyLM 上实现 DPO：计算两个回答在策略模型和参考模型下的对数概率，求 DPO 损失，按梯度更新输出层。

```python
import json
import numpy as np

ex = json.load(open("tinylm.json", encoding="utf-8"))["examples"]["22"]
V = ex["vocab"]
E, W1, b1, W2, b2 = (np.array(ex[k]) for k in ["E", "W1", "b1", "W2", "b2"])
sig = lambda z: 1 / (1 + np.exp(-z))

def hidden(a, b):
    return np.maximum(0, np.concatenate([E[V.index(a)], E[V.index(b)]]) @ W1 + b1)

def logp_seq(prompt, answer, W2, b2):
    """一个回答在给定提示下的对数概率：逐个 token 的 ln P 相加；同时返回对输出层的梯度。"""
    seq = ["。", "。"] + prompt + answer
    lp, gW, gb = 0.0, np.zeros_like(W2), np.zeros_like(b2)
    for i in range(2 + len(prompt), len(seq)):
        h = hidden(seq[i - 2], seq[i - 1])
        z = h @ W2 + b2
        p = np.exp(z - z.max()); p /= p.sum()
        y = V.index(seq[i])
        lp += np.log(p[y])
        g = -p; g[y] += 1                           # ln P(y) 对 logit 的梯度：onehot − p
        gW += np.outer(h, g); gb += g
    return lp, gW, gb

# 1. 奖励模型的偏好概率（Bradley–Terry）：P(A 比 B 好) = σ(r_A − r_B)
for rA, rB in [(1.0, 1.0), (2.0, 1.0), (3.0, 0.0)]:
    print(f"r_A = {rA}，r_B = {rB}：P(A 更好) = {sig(rA - rB):.3f}，损失 −ln σ = {-np.log(sig(rA - rB)):.3f}")

# 2. DPO：提示“我 吃”，人更喜欢“苹果 。”（chosen），不喜欢“香蕉 。”（rejected）
prompt, yw, yl, beta = ["我", "吃"], ["苹果", "。"], ["香蕉", "。"], 0.5
ref_w, _, _ = logp_seq(prompt, yw, W2, b2)           # 参考模型 = 微调前的模型，固定不动
ref_l, _, _ = logp_seq(prompt, yl, W2, b2)
W, b = W2.copy(), b2.copy()
for step in range(31):
    lw, gWw, gbw = logp_seq(prompt, yw, W, b)
    ll, gWl, gbl = logp_seq(prompt, yl, W, b)
    margin = beta * ((lw - ref_w) - (ll - ref_l))   # 隐式奖励之差
    loss = -np.log(sig(margin))
    if step in (0, 10, 30):
        print(f"第 {step:2d} 步：P(苹果) = {np.exp(lw):.3f}，P(香蕉) = {np.exp(ll):.3f}，DPO 损失 {loss:.3f}")
    coef = beta * (1 - sig(margin))                 # 损失对 margin 的梯度（取负），越“没学会”越大
    W += 0.01 * coef * (gWw - gWl)
    b += 0.01 * coef * (gbw - gbl)

z = hidden("我", "吃") @ W + b; p = np.exp(z - z.max()); p /= p.sum()
print("“我 吃”之后的分布：", {V[i]: round(float(p[i]), 3) for i in np.argsort(-p)[:3]})
```

输出：

```text
r_A = 1.0，r_B = 1.0：P(A 更好) = 0.500，损失 −ln σ = 0.693
r_A = 2.0，r_B = 1.0：P(A 更好) = 0.731，损失 −ln σ = 0.313
r_A = 3.0，r_B = 0.0：P(A 更好) = 0.953，损失 −ln σ = 0.049
第  0 步：P(苹果) = 0.501，P(香蕉) = 0.499，DPO 损失 0.693
第 10 步：P(苹果) = 0.884，P(香蕉) = 0.116，DPO 损失 0.309
第 30 步：P(苹果) = 0.981，P(香蕉) = 0.018，DPO 损失 0.129
“我 吃”之后的分布： {'苹果': 0.983, '香蕉': 0.017, '骨头': 0.0}
```

前三行：分差 0、1、3 时，偏好概率 0.5、0.731、0.953，损失 0.693、0.313、0.049。接下来三行是 DPO 训练的过程。最后一行：训练后“我 吃”之后，“苹果”的概率是 0.983。

## 到了大模型里

**显存是主要麻烦。**RLHF 的 PPO 要同时用到策略模型、参考模型、奖励模型和价值模型，大模型规模下要几倍于 SFT 的显存。DPO 只需要策略模型和参考模型，而且参考模型只用来算对数概率（只做前向），可以事先算好存起来，简单得多。这是 DPO 流行的主要原因。

**RL 训练里大量时间花在推理上。**PPO 这类方法每一步都要让模型生成大量回答，这部分是纯粹的推理（自回归解码），常常占了训练时间的大头。所以现代的 RL 训练框架会直接调用 vLLM 等推理引擎来生成，推理的效率直接决定了 RL 训练的速度。第 49 讲的推理模型训练，这一点更加突出。

**奖励模型也是一种模型服务。**RLHF 训练时，奖励模型要给大量回答打分；在线上，有的系统也会用奖励模型对多个候选回答排序，选出最好的那个返回。

## 容易混淆的地方

1. **“对齐”不只是“安全”。**偏好数据既包括“不要说有害的话”，也包括“更有帮助、更准确、格式更好”。很多时候它主要在提升回答的整体质量。
2. **奖励模型会被“钻空子”。**奖励模型只是人类偏好的一个近似，模型可能学会利用它的漏洞（比如回答越长分越高，就越写越长），这叫奖励投机（reward hacking）。偏离惩罚和 DPO 的“相对参考模型”都是为了限制这种情况。
3. **DPO 不是强化学习，但目标相同。**DPO 的损失是从 RLHF 的目标推导出来的，两者优化的是同一件事，只是 DPO 用“离线”的偏好数据直接训练，不需要在训练中生成新回答。

## 回顾

SFT 只能模仿示范，偏好学习让模型从“二选一”的比较中学到什么是更好的回答。RLHF 先用 Bradley–Terry 模型训练一个奖励模型，P(A ≻ B) = σ(r<sub>A</sub> − r<sub>B</sub>)，再用 PPO 等强化学习方法提高模型的得分，同时惩罚它偏离参考模型太远。DPO 把这两步合成一个直接的损失：相对参考模型，提高好回答的概率、降低差回答的概率，不需要奖励模型和强化学习。在 ToyLM 上，30 步 DPO 就把“苹果”的概率从 0.501 推到了 0.981。

偏好学习教模型说得“更好”。可还有一类问题，好坏不需要人来判断：数学题有标准答案，代码可以跑测试。如果直接用“答对没有”作为奖励来训练，模型会学会什么？下一讲：**推理模型与强化学习**。
