上一讲的量化方法，说到底就是“除以 scale、四舍五入”，叫 **RTN**（round-to-nearest）。8 比特时它几乎不损失精度；可降到 4 比特、3 比特，很多模型的效果会明显下降。

这一讲的两种方法，GPTQ 和 AWQ，都还是把权重存成 4 比特整数加 scale，格式和 RTN 一样，区别只在于**怎么决定每个权重取整成哪个整数**。它们的出发点是同一个观察：我们真正在乎的不是权重本身变了多少，而是**这一层的输出**变了多少。

## 该盯住的是输出

一个线性层 y = x · W（第 13 讲）。量化以后权重变成 Ŵ，输出变成 x · Ŵ。输出的误差是

<div class="ai-formula">x · W − x · Ŵ = Σⱼ xⱼ · (Wⱼ − Ŵⱼ)　（Wⱼ 是 W 的第 j 行，对应第 j 个输入通道）</div>

第 j 行权重的误差，被第 j 个输入通道的激活 xⱼ 乘了一下，再加到输出上。如果某个输入通道的激活特别大，这一行权重的一点点误差，在输出里就会被放大很多倍。

大模型恰恰有这样的通道：在 Transformer 的激活里，少数几个通道的数值长期比其他通道大几十倍（第 82 讲还会细看）。RTN 对每一行一视同仁，这几行的误差和别的行一样大，却被放大得最多，成了输出误差的主要来源。

所以，**量化需要知道激活长什么样**。GPTQ 和 AWQ 都要先拿一小批**校准数据**（几百条普通文本）跑一遍模型，记录每一层的输入 X，再根据 X 来量化这一层的权重。

我们用一个人造的层来比较：64 个输入通道、64 个输出，256 个 token 的校准数据，其中 4 个输入通道是离群通道，激活大 20 倍。4 比特、每个输出通道一个 scale 的 RTN，输出的相对误差是 **10.56%**。

## AWQ：给重要的行“放大”再量化

**AWQ**（Activation-aware Weight Quantization，2023 年）先问：哪些权重最重要？答案是激活大的输入通道对应的那些行。论文发现，只要把大约 1% 最重要的权重保持 FP16 不量化，效果就能恢复很多。可是一个矩阵里混着两种精度，对 GPU kernel 很不友好。

AWQ 用了一个等价变换来达到类似的效果。对第 j 个输入通道，取一个放大系数 sⱼ > 1：

<div class="ai-formula">x · W = (x / s) · (s · W)，　也就是 xⱼ 除以 sⱼ，第 j 行权重乘以 sⱼ</div>

数学上完全相等。现在量化的是放大后的 s · W。为什么这样误差会变小？同一个输出通道（同一列）的 scale 由这一列绝对值最大的数决定，把第 j 行放大一点，通常不会改变这个最大值，所以 scale 基本不变，取整误差的绝对大小也基本不变；可是反量化后要除以 sⱼ，这一行的误差就缩小成了原来的 1/sⱼ。重要的行误差变小了，代价是：放大得太多会抬高 scale，其他行的误差变大。

sⱼ 怎么定？AWQ 让它和激活的大小挂钩：sⱼ = (平均|xⱼ|)^α，在 0 到 1 之间搜索 α，选让输出误差最小的那个。我们的例子里，最好的 α 是 0.2，输出误差从 10.56% 降到 **6.34%**。离群通道那 4 行的权重误差从 0.0046 降到 0.0024，其余行从 0.0046 升到 0.0056：用一点不重要的误差，换来重要的误差减半。

x 要除以 s，这个除法不用真的做：它可以合并进前一个运算里，比如前面 RMSNorm 的权重（第 36 讲）直接除以 s。所以 AWQ 量化后的模型，推理时没有任何额外开销。

## GPTQ：取整之后，让别的权重来补偿

**GPTQ**（2022 年）换了一个角度。一个权重四舍五入以后产生了误差，能不能**调整还没量化的其他权重**，把这个误差抵消掉一部分？

回到输出误差 Σⱼ xⱼ · (Wⱼ − Ŵⱼ)。如果第 1 个输入通道和第 2 个输入通道的激活是相关的（比如 x₂ 常常约等于 x₁ 的一半），那么第 1 行取整多出来的误差，可以通过把第 2 行往反方向调一点来抵消。真实的激活各通道之间确实有很强的相关性，这种补偿就有了用武之地。

GPTQ 的做法是：**一行一行地量化**。量化第 i 行时，先四舍五入得到它的误差，再按一个由校准数据算出的矩阵，把这个误差分摊到后面还没量化的行上，然后再量化下一行。这个矩阵来自 H = XᵀX（输入的二阶统计量）的逆，它告诉我们“第 i 个通道的误差，用第 k 个通道来补偿，最划算的量是多少”。数学推导来自更早的 OBS（Optimal Brain Surgeon）方法，GPTQ 的贡献是把它做得足够快：利用 H⁻¹ 的 Cholesky 分解，所有输出通道一起处理，一个 1750 亿参数的模型几个 GPU 小时就能量化完。

实践中还有一个技巧：**先量化最重要的行**（H 的对角线最大的，也就是激活最大的通道），这样它们的误差有最多的行来补偿，自己却不会被别人的补偿再改动。

我们的例子里，GPTQ 的输出误差是 **5.30%**，比 AWQ 还小。有意思的是，它的**权重**平均误差反而最大（0.016，RTN 只有 0.0046）：为了补偿，很多权重被有意地调离了原来的值。这正好说明，权重误差不是该优化的目标。

<Note kind="point">权重量化该最小化的是输出误差，而输出误差取决于激活：激活大的通道，它那一行权重的误差被放大得最多。AWQ 用等价缩放把这些重要的行放大后再量化，让它们的相对误差变小；GPTQ 逐行量化，把每一行的取整误差按 H = XᵀX 的逆摊给还没量化的行去补偿。两者都只需要一小批校准数据，存储格式和 RTN 一样。</Note>

## 位宽越低，差别越大

代码也比较了 3 比特和 8 比特：

- **8 比特**：RTN 0.58%，AWQ 0.36%，GPTQ 0.30%。都很小，RTN 就够用。
- **4 比特**：RTN 10.56%，AWQ 6.34%，GPTQ 5.30%。
- **3 比特**：RTN 23.99%，AWQ 14.71%，GPTQ 13.07%。

格点越粗，“取整取到哪里”的选择越重要，聪明的方法优势越大。这也是为什么 8 比特量化很少需要 GPTQ、AWQ，而 4 比特及以下几乎离不开它们。

## 到了大模型里

**INT4 权重量化是部署的常见选择。**Hugging Face 上大量模型都有 GPTQ、AWQ 的 4 比特版本，通常每组 128 个权重一个 scale（第 80 讲）。vLLM、SGLang 可以直接加载它们，用专门的 W4A16 kernel（比如 Marlin）在读进片上之后反量化、再做 BF16 的矩阵乘法。小批量 decode 时速度能提高两三倍。

**效果损失因模型而异。**参数量大的模型通常更“耐”量化，4 比特几乎看不出差别；小模型、训练数据特别多的模型（每个参数“记”的东西更多）损失更明显。量化后一定要在自己关心的任务上评测（第 51 讲），不能只看困惑度。

**更低的位宽。**3 比特、2 比特需要更复杂的方法，比如把几个权重一起用一个码本向量表示（向量量化），或者先对权重做随机旋转让分布更均匀再量化。它们能把模型压得更小，但推理 kernel 也更复杂。

**校准数据的影响。**校准数据最好和实际的使用场景相近。用纯英文的数据校准，再拿去处理中文或代码，效果可能会差一些。

## 用代码复现

下面的代码构造了上面那个 64 × 64 的层（激活各通道之间有相关性，4 个离群通道），分别实现 RTN、AWQ（搜索 α）、GPTQ（先量化激活大的行，逐行补偿），比较权重误差和输出误差，以及离群通道那几行的误差，最后对比 3 比特和 8 比特。

```python
import numpy as np
rng = np.random.default_rng(0)

# 一个线性层 y = x · W，W 的形状 [输入 64, 输出 64]。校准数据 X：256 个 token，其中 4 个输入通道是“离群通道”，数值大 20 倍
d = 64
W = rng.standard_normal((d, d)) * 0.05
X = rng.standard_normal((256, d)) @ (np.eye(d) + 0.3 * rng.standard_normal((d, d)))   # 各通道之间有相关性，像真实的激活
X[:, [3, 17, 40, 58]] *= 20

def rtn(W, bits=4):
    """直接四舍五入（RTN），每个输出通道（W 的每一列）一个 scale"""
    qmax = 2 ** (bits - 1) - 1
    s = np.abs(W).max(0, keepdims=True) / qmax
    return np.clip(np.round(W / s), -qmax, qmax) * s

def err(Wq):                                             # 我们真正关心的：输出变了多少（相对误差）
    return np.linalg.norm(X @ W - X @ Wq) / np.linalg.norm(X @ W)

def awq(W, bits=4):
    """AWQ：输入通道 j 的权重先乘 s_j 再量化，计算时激活除以 s_j（结果不变）。s_j = (平均|x_j|)^α，搜索最好的 α"""
    best = None
    for a in np.linspace(0, 1, 11):
        s = np.abs(X).mean(0) ** a
        Wq = rtn(W * s[:, None], bits) / s[:, None]          # 等价于 (X / s) · Q(W · s)
        if best is None or err(Wq) < best[0]: best = (err(Wq), a, Wq)
    return best

def gptq(W, bits=4, damp=0.01):
    """GPTQ：一行一行（一个输入通道一个输入通道）地量化，把这一行的误差按 H⁻¹ 摊到还没量化的行上"""
    qmax = 2 ** (bits - 1) - 1
    s = np.abs(W).max(0) / qmax                              # 和 RTN 一样的 scale
    H = X.T @ X; H += damp * np.mean(np.diag(H)) * np.eye(d)
    p = np.argsort(-np.diag(H))                              # 先量化最重要的行（激活大的通道），让后面的行来补偿
    H, W = H[p][:, p], W[p].copy()
    U = np.linalg.cholesky(np.linalg.inv(H)).T               # H⁻¹ 的 Cholesky 分解（上三角）
    Q = np.zeros_like(W)
    for i in range(d):
        Q[i] = np.clip(np.round(W[i] / s), -qmax, qmax) * s
        e = (W[i] - Q[i]) / U[i, i]
        W[i + 1:] -= np.outer(U[i, i + 1:], e)              # 后面的行替它“补偿”误差
    return Q[np.argsort(p)]                                  # 换回原来的行顺序

w_err = lambda Wq: np.abs(W - Wq).mean()
print(f"RTN  4 bit：权重平均误差 {w_err(rtn(W)):.5f}，输出相对误差 {err(rtn(W)):.2%}")
e, a, Wa = awq(W)
print(f"AWQ  4 bit：最好的 α = {a:.1f}，权重平均误差 {w_err(Wa):.5f}，输出相对误差 {e:.2%}")
Wg = gptq(W)
print(f"GPTQ 4 bit：权重平均误差 {w_err(Wg):.5f}，输出相对误差 {err(Wg):.2%}")
out = [3, 17, 40, 58]; norm = [j for j in range(d) if j not in out]
for name, Wq in [("RTN", rtn(W)), ("AWQ", Wa), ("GPTQ", Wg)]:
    print(f"  {name:4s}：离群通道那 4 行的权重平均误差 {np.abs(W - Wq)[out].mean():.5f}，其余行 {np.abs(W - Wq)[norm].mean():.5f}")
for bits in [3, 8]:
    print(f"{bits} bit：RTN {err(rtn(W, bits)):.2%}，AWQ {awq(W, bits)[0]:.2%}，GPTQ {err(gptq(W, bits)):.2%}")
```

输出：

```text
RTN  4 bit：权重平均误差 0.00455，输出相对误差 10.56%
AWQ  4 bit：最好的 α = 0.2，权重平均误差 0.00540，输出相对误差 6.34%
GPTQ 4 bit：权重平均误差 0.01604，输出相对误差 5.30%
  RTN ：离群通道那 4 行的权重平均误差 0.00460，其余行 0.00455
  AWQ ：离群通道那 4 行的权重平均误差 0.00244，其余行 0.00559
  GPTQ：离群通道那 4 行的权重平均误差 0.00465，其余行 0.01680
3 bit：RTN 23.99%，AWQ 14.71%，GPTQ 13.07%
8 bit：RTN 0.58%，AWQ 0.36%，GPTQ 0.30%
```

前三行是 4 比特时三种方法的结果：输出误差 10.56%、6.34%、5.30%，GPTQ 的权重误差反而最大。中间三行把权重误差拆成离群通道那 4 行和其余的行：AWQ 把离群行的误差压到了 0.0024；GPTQ 离群行的误差和 RTN 差不多（它们最先量化，没有被补偿），但其余的行被大幅调整，替它们抵消了误差。最后两行是 3 比特和 8 比特。

## 容易混淆的地方

1. **GPTQ、AWQ 不是新的数据格式。**量化完的模型还是 INT4 加 scale，推理时的计算和 RTN 量化的模型一样；它们只是更聪明地选了每个整数。
2. **“需要校准数据”不等于“需要训练”。**它们只做前向，记录激活，不做反向传播，几分钟到几小时就能完成。
3. **权重量化不加速计算受限的部分。**W4A16 省的是读权重的带宽，decode 小批量时收益最大；prefill 和大批量 decode 是计算受限的，几乎不会变快。要让计算本身变快，需要激活也量化，这是下一讲的话题。

## 回顾

直接四舍五入的 RTN 在 4 比特以下损失明显。GPTQ 和 AWQ 都盯住输出误差而不是权重误差，用一小批校准数据记录每层的输入。AWQ 发现激活大的通道对应的权重最重要，用 x · W = (x/s) · (s·W) 的等价缩放把这些行放大后再量化，让它们的相对误差缩小，s 可以合并进前一层，没有额外开销。GPTQ 逐行量化，把每一行的取整误差按 H = XᵀX 的逆摊给还没量化的行去补偿。人造的例子里，4 比特时输出误差从 RTN 的 10.56% 降到 AWQ 的 6.34%、GPTQ 的 5.30%，位宽越低差别越大。

权重可以在部署前慢慢量化，激活却是每次推理时才产生的。要让矩阵乘法用 INT8 来算，激活也必须量化，可激活里的离群通道比权重里的还要极端。怎么办？下一讲：**激活量化与 SmoothQuant**。
