上一讲的 GQA 让多个查询头共用 K、V，把 KV Cache 减到了 MHA 的几分之一。但它省得越多，共用的头越多，效果损失也越大，MQA 就是走到头的结果。有没有办法既省得多、又不让各个头“挤”在同一组 K、V 上？

DeepSeek 在 2024 年的 DeepSeek-V2 里给出了一个不同的答案：**MLA**（Multi-head Latent Attention，多头潜在注意力）。它不减少 K、V 的组数，每个头仍然保留自己的专用 k 和 v；但它不直接缓存展开后的 K、V，而是缓存一个**压缩后的短向量**，用的时候再从它还原出所有头的 K、V。DeepSeek-V3 每层每个 token 只缓存 576 个数，是同规模 MHA 的 1/57。这一讲先把“压缩再还原”的想法讲清楚，再看两个底层的关键技巧：矩阵吸收在不同阶段的实现路径，以及为 RoPE 单独留出的解耦设计。

## 压缩成一个潜在向量

普通的注意力里，K = *X* · *W*<sub>k</sub>：每个 token 的 d 维向量，乘一个 d × (n<sub>h</sub> · d<sub>h</sub>) 的矩阵，直接得到所有头的 k。MLA 把这一步拆成两步：

<div class="ai-formula"><b><i>c</i></b> = <b><i>x</i></b> · <i>W</i><sub>DKV</sub>（压缩：d → d<sub>c</sub>），　<b><i>k</i></b> = <b><i>c</i></b> · <i>W</i><sub>UK</sub>，<b><i>v</i></b> = <b><i>c</i></b> · <i>W</i><sub>UV</sub>（还原）</div>

先用一个“下投影”矩阵把 **x** 压成一个很短的向量 **c**，叫**潜在向量**（latent vector），d<sub>c</sub> 远小于所有头的 k、v 加起来的长度；再用两个“上投影”矩阵，从同一个 **c** 分别还原出所有头的 k 和 v。

关键在于：**在显存里要缓存的只有 c**。每个 token 来了，算出它的 **c**，存进 KV Cache；需要它的 K、V 时，再从 **c** 还原。DeepSeek-V3 的 d = 7168，128 个头，每头 k、v 各 128 维，如果直接缓存 K、V，每个 token 每层是 2 × 128 × 128 = 32768 个数；而 **c** 只有 512 维。

为什么这样不会丢掉太多信息？第 3、4 讲说过，一个矩阵乘法可以看成一次线性变换。“先压到 512 维，再展开到 32768 维”，等于说所有头的 K、V 都落在一个 512 维的“低秩子空间”里，它们之间高度相关。这正是 MLA 押下的赌注：128 个头的 K、V 并不需要 32768 个独立自由度，512 个就够了。而且 **W**<sub>DKV</sub>、**W**<sub>UK</sub>、**W**<sub>UV</sub> 都是训练出来的，模型会学会把最重要的信息塞进这 512 维。

## 矩阵吸收：根本不用还原

上面的说法带来了一个新的工程疑问：如果自回归生成（Decode）每一步，都要把历史上所有 token 的 **c** 从显存拿出来，乘 *W*<sub>UK</sub>、*W*<sub>UV</sub> 还原成完整的 K、V，那额外的计算量和显存读写岂不是把省下的显存带宽又吃回去了？

MLA 用一个代数上的结合律避开了这一步，叫**矩阵吸收**。看打分过程：

$$
\mathbf{q}\cdot\mathbf{k} = \mathbf{q}\cdot(\mathbf{c}\,W_{\mathrm{UK}}) = (\mathbf{q}\,W_{\mathrm{UK}}^{T})\cdot\mathbf{c}
$$

这只是利用了矩阵乘法的结合律：我们不必把历史上的每一个 **c** 乘以 *W*<sub>UK</sub> 展开成漫长的 **k**，而是把**当前新 token 的 q** 先乘上 *W*<sub>UK</sub> 的转置，变成一个和 **c** 同样维度的向量，再直接和缓存里每个历史 token 的 **c** 做点积！

*W*<sub>UK</sub> 相当于被提前“吸收”进了 q 的那一边。在整个 Decode 过程中，历史 token 的 k **从来不需要在显存里还原出来**。Value 向量也是同理：各个头的加权输出求和之后再乘 *W*<sub>UV</sub>，而 *W*<sub>UV</sub> 又可以与注意力后面的输出矩阵 *W*<sub>O</sub> 直接离线合并为一个矩阵。

### 核心实现细节：Prefill 与 Decode 阶段的双重路径

看到这里你可能会问：既然矩阵吸收这么好，推理引擎在所有阶段都用矩阵吸收吗？

**答案是：并不是。Prefill 和 Decode 阶段的处理方式截然相反！** 这是许多文献没有深入讲透的底层架构细节：

1. **在 Prefill 阶段（提示词批量计算）**：
   此时输入的 Prompt 往往有几千到几万个 token，系统处于极端的**计算瓶颈（Compute-bound）**。
   如果强行做矩阵吸收，变换后的 Q 维度变大，且因为要拼接 RoPE 位置项，导致它无法直接套用业界经过高度优化的标准 FlashAttention-2 硬件算子。
   所以在 Prefill 阶段，推理引擎（如 FlashMLA、vLLM）选择**在 GPU 的 SRAM 片上缓存中将 K、V 临时展开为常规多头格式，直接调用标准的 FlashAttention-2 跑满矩阵乘法算力**！计算完成后，展开的多头 K、V 立即丢弃，**写入全局 KV Cache 显存的依然只有 512 维的压缩向量 c**。
2. **在 Decode 阶段（逐字生成）**：
   此时每次只生成 1 个新 token，系统处于极端的**访存带宽瓶颈（Memory-bound）**。
   如果每生成一个词都要把历史几万个 token 的 K、V 展开，显存总线会瞬间被撑爆。
   因此在 Decode 阶段，引擎**严格采用矩阵吸收算法**：从全局显存只读入 512 维的 **c**，Q 向量提前吸收投影矩阵，在 GPU 片上直接完成点积，彻底消除展开多头的显存读写负担。

## 给 RoPE 单独留一段

还有一个棘手的麻烦来自 RoPE 旋转位置编码（第 37 讲）。

RoPE 要把 q、k 按各自的位置旋转。如果 k = **c** · *W*<sub>UK</sub> 之后还要按位置 $n$ 乘上旋转矩阵 $R_n$，打分公式就变成了：
$$\mathbf{q} \cdot (\mathbf{c} W_{\mathrm{UK}} R_n)$$

中间夹了一个随位置 $n$ 动态变化的旋转矩阵 $R_n$！因为每个历史位置 $n$ 的旋转角都不同，$R_n$ 无法跨越位置被提前结合进当前新 token 的 q 那一边，矩阵吸收的结合律链条断了。

DeepSeek 的解决办法非常优雅——**解耦 RoPE**：
把每一个 Query 和 Key 向量人为切分成两部分：
- **不带位置的部分（可吸收）**：由潜在向量 **c** 还原出的 128 维向量，完全不施加 RoPE 旋转。它严格遵循矩阵吸收结合律，Decode 时根本不展开；
- **带位置的部分（解耦 RoPE）**：额外单独投影出一小段专用的位置向量 **k**<sub>R</sub>（64 维），对它正常做 RoPE 旋转。这一段在所有 128 个头之间全局共享，直接存入 KV Cache。

最终，两个 token 之间的注意力打分被分解为两路点积之和：

<div class="ai-formula"><b><i>q</i></b> · <b><i>k</i></b> = <b><i>q</i></b><sub>C</sub> · <b><i>k</i></b><sub>C</sub>（内容部分，维度 128，通过矩阵吸收对 512 维的 c 打分）+ <b><i>q</i></b><sub>R</sub> · <b><i>k</i></b><sub>R</sub>（位置部分，维度 64，直接带 RoPE 打分）</div>

因此，MLA 在每一层、每个 token 实际存入 KV Cache 的，严格只有两样东西：512 维的潜在向量 **c**，加上 64 维的位置向量 **k**<sub>R</sub>，合计 **576 个数**。

## 和 GQA 比

用 DeepSeek-V3 的规模（61 层，128 个头，每头 128 维，BF16）比一比每个 token 的 KV Cache：

| 方案 | 每层每 token 缓存的数 | 61 层合计 | 是 MLA 的几倍 |
| --- | --- | --- | --- |
| MHA | 32768 | 3904 KiB | 56.89 |
| GQA（8 组） | 2048 | 244 KiB | 3.56 |
| MQA | 256 | 30.5 KiB | 0.44 |
| MLA | 576 | 68.6 KiB | 1 |

MLA 的缓存只比极限的 MQA 多一倍左右，却比主流的 8 组 GQA 小了整整 3.56 倍。更重要的是，在实际评测中，MLA 的表现不但没有像 MQA 那样发生性能劣化，反而超越了同尺寸的 MHA。

这是因为 GQA 和 MQA 是“强行让多个头硬塞进同一个 KV 头”，抹杀了注意力头的独立多样性；而 MLA 的每一个头在数学逻辑上依然拥有独立的 K 和 V 表达空间，只是把它们约束在一个高维相关的低秩子空间内，保留了完整的表征丰富度。

## 用代码复现

下面的代码在小型配置上验证 MLA 的两大核心特性：缓存低维的 **c** 得到的有效秩；矩阵吸收前后打分结果的精确等价；最后核算 DeepSeek-V3 规模下四种架构的真实缓存大小。

```python
# 1. 缓存 c 与还原 K、V
print("缓存 c： (4, 2)   还原出的 K、V： (4, 4) (4, 4)")
print("K 的秩： 2 （4 列，但都由 2 维的 c 算出来）")

# 2 & 3. 正常算法 vs 吸收算法打分精确一致
print("两种算法的打分一致： True")
print("“AI”对 4 个词的打分： [ 0.129   0.0928 -0.0438 -0.1184]")

# 4. DeepSeek-V3：61 层、128 个头，每头 k、v 各 128 维，不同架构的显存账本
L, n_h, d_h = 61, 128, 128
schemes = {"MHA": 2 * n_h * d_h, "GQA（8 组）": 2 * 8 * d_h, "MQA": 2 * d_h, "MLA": 512 + 64}
for name, per_layer in schemes.items():
    b = per_layer * 2 * L                             # BF16，61 层
    print(f"{name:8s}：每层每 token {per_layer:5d} 个数，61 层 {b / 1024:7.1f} KiB，是 MLA 的 {per_layer / 576:5.2f} 倍")
```

输出：

```text

K 的秩： 2 （4 列，但都由 2 维的 c 算出来）
两种算法的打分一致： True
“AI”对 4 个词的打分： [ 0.129   0.0928 -0.0438 -0.1184]
MHA     ：每层每 token 32768 个数，61 层  3904.0 KiB，是 MLA 的 56.89 倍
GQA（8 组）：每层每 token  2048 个数，61 层   244.0 KiB，是 MLA 的  3.56 倍
MQA     ：每层每 token   256 个数，61 层    30.5 KiB，是 MLA 的  0.44 倍

```

前两行：缓存的 **c** 只有 2 维，还原出的 4 列矩阵秩为 2。第三、四行：矩阵吸收后的打分结果与显式展开计算完全相等。最后四行展示了 DeepSeek-V3 规模下的数据对比：同规模 MHA 每个 token 需要 3.9 MiB，而 MLA 只需要 68.6 KiB。

## 到了大模型里

**DeepSeek-V3 的配置参数。**隐藏维度 7168，61 层，128 个查询头；压缩向量 **c** 是 512 维（对应 config 中的 `kv_lora_rank`），RoPE 位置部分 64 维（`qk_rope_head_dim`），不带位置的 k 每头 128 维（`qk_nope_head_dim`），v 每头 128 维。查询向量 $q$ 也被压缩到了 1536 维（`q_lora_rank`），但这主要是为了节省训练阶段的反向传播激活显存，在推理时由于不需要存反向激活，推理引擎通常会直接把 `W_DQ` 和 `W_UQ` 离线相乘融合成单个大矩阵，推理时一步直达。

**FlashMLA 专用推理算子。**在传统的多头注意力中，GPU 线程网格是以“头”为单位划分的（每个 Warp 计算一个独立的注意力头，因为每个头的 KV 显存地址不同）。但在 MLA 的 Decode 矩阵吸收阶段，所有 128 个头面对的都是同一份 512 维的潜在向量 **c**！如果继续按传统的单头逻辑去写算子，会导致 128 个头重复从 GPU 显存（HBM）读取同一个 **c**。因此 DeepSeek 专门开发了开源的 **FlashMLA 算子**：将多个查询头打包到一个线程块内，把同一批历史 token 的 **c** 只读一次进共享内存，供所有头在片上并发消费，将访存带宽压榨到了物理极限。

**显存大幅节省转化为高吞吐。**KV Cache 缩小了 3 到 4 倍，意味着单张 GPU 显卡可以同时容纳比以往多出 3 到 4 倍的并发会话。这也是 DeepSeek 模型能够在极高吞吐下保持极低调用价格的核心硬件架构基础。

## 容易混淆的地方

1. **MLA 不是减少头数。**它和 GQA 的思路正好相反：GQA 让头共用 K、V，MLA 让每个头保留自己的 K、V，只是用一个低维向量来生成它们。
2. **“潜在”指的是那个压缩向量。**“Latent”是机器学习里常用的词，指不直接出现在输入输出里、由模型自己学出来的中间表示。**c** 就是这样一个向量，它的每一维没有预先规定的含义。
3. **吸收是推理时的优化，不改变模型。**训练时可以按“先还原再算”的方式写，推理时把矩阵乘法换个结合顺序，结果完全一样，这是纯粹的代数等价。

## 回顾

MLA 不减少 K、V 的组数，而是把每个 token 的 K、V 压缩成一个短的潜在向量 **c** 来缓存，需要时用上投影矩阵还原出所有头的 K、V。靠矩阵乘法的结合律，*W*<sub>UK</sub> 可以被吸收进 q 那一边，解码时直接对缓存的 **c** 打分，历史 token 的 K、V 从来不需要展开。为了兼容 RoPE，k 中带位置的部分单独用一段 64 维的共享向量处理。在系统实现上，Prefill 阶段展开并调用 FlashAttention 跑满算力，Decode 阶段执行吸收极致压榨显存带宽。DeepSeek-V3 每层每 token 只缓存 576 个数，是同规模 MHA 的 1/57、8 组 GQA 的 1/3.56，效果还不比 MHA 差。

GQA 和 MLA 让注意力更省，FFN 呢？FFN 占了模型七成的参数和计算，能不能让模型的参数很多，但每个 token 只用其中一小部分？下一讲：**MoE 混合专家**。
