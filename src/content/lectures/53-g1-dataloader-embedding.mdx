上一讲结束时，50 万字的讲义变成了一串编号：训练集 302,475 个，验证集 33,048 个。模型一次最多看 256 个 token，而它要学的是第 23 讲说的那件事：看到前面，猜下一个。

这一讲回答两个问题。第一，这一长串编号怎么切成一个个训练样本，每个样本的“题目”和“答案”是什么？第二，编号是整数，模型要做矩阵乘法，编号怎么变成向量？前一个问题由数据加载器（data loader）解决，写在 `data.py` 里；后一个是模型的第一层，嵌入（embedding）。

## 一个样本里有 T 道题

语言模型的训练数据不需要人工标注。一段文字本身就是题目和答案：“计算机 其实 只 会 做”，题目是“计算机”，答案是“其实”；题目是“计算机 其实”，答案是“只”；依此类推。

所以，从长序列里取出连续的 T + 1 个 token，前 T 个叫 x，后 T 个叫 y。y 就是 x 整体往后错一位：

- 位置 0：看到 x[0]，答案是 y[0] = x[1]
- 位置 1：看到 x[0..1]，答案是 y[1] = x[2]
- ……
- 位置 T − 1：看到 x[0..T−1]，答案是 y[T−1]

一个长 T 的样本里，有 T 道“预测下一个”的题。模型做一次前向，就同时给出这 T 道题的答案（第 34 讲的前向传播，每个位置都输出一行打分），因果掩码保证位置 t 只看得到 x[0..t]，不会偷看答案（第 27 讲）。这是语言模型训练效率高的根本原因：**一次前向，T 个训练信号**。

## 窗口怎么挪

样本是在长序列上开的一个个窗口。窗口每次往后挪多远，叫步长（stride）。下面的演示用训练集开头的 40 个真实 token：浅绿色是当前样本的 x，下面带琥珀色底线的是 y，虚线框是上一个样本的 x。

<SlideWindow caption="图 53-2　在训练集开头的 40 个 token 上开窗口。步长等于 T 时窗口首尾相接；步长小于 T 时相邻样本重叠；步长大于 T 时中间有 token 没用上。下方给出整个训练集能切出多少个样本。" />

试着调几组参数：

- **stride = T**：窗口首尾相接，每个 token 恰好出现在一个样本的 x 里。T = 256 时，训练集切出 1181 个样本。
- **stride < T**：相邻样本重叠。stride = 1 时样本数最多，但相邻两个样本几乎一模一样，模型一轮训练里把同一段话看了 T 遍，很容易背下来。
- **stride > T**：有一部分 token 永远不进任何样本，浪费数据。

我们训练时用 stride = T/2 = 128：样本数是不重叠时的两倍，同一段话在两个样本里出现，但位置不同（一次在窗口前半，一次在后半），模型能从同一段话里多学一点“前文更长时该怎么猜”。验证集用 stride = T，不重叠，每个 token 只算一次 loss。

## 编号怎么变成向量

模型的第一层是两张表。

**token 嵌入**是一张 V × d 的表，第 i 行是编号 i 的向量（第 22 讲）。编号 3949（“计算机”）进来，就取第 3949 行。它在训练开始时是随机数，训练中和其他参数一样被梯度更新，慢慢地，意思相近的 token 的向量会靠近。

**位置嵌入**是一张 T_max × d 的表，第 t 行是“位置 t”的向量。第 25 讲说过，注意力本身不知道词序，必须把位置信息加进去。第 25 讲讲的是用正弦、余弦公式算出来的位置编码；GPT-2 换了一种更简单的做法：位置向量也是参数，和 token 嵌入一样从随机数开始学。我们照 GPT-2 来。代价是模型只能处理不超过 T_max 个 token 的序列，第 T_max + 1 个位置在表里没有对应的行。

两者相加，就是送进第一层 Transformer Block 的输入：

$$
h_{b,t} = E_{\text{tok}}[\,x_{b,t}\,] + E_{\text{pos}}[\,t\,]
$$

b 是 batch 里的第几个样本，t 是位置。x 的形状是 [B, T]，查表后是 [B, T, d]；位置嵌入查出来是 [T, d]，对 batch 里每个样本都一样，PyTorch 的广播会把它加到每个样本上。

**步长和样本数**：stride = 8、4、1 时，样本数是 37,809、75,617、302,467，和 (302,475 − 8) ÷ stride 向上取整一致。

**T = 256、B = 16**：stride = T 时一轮 73 个 batch（1181 个样本 ÷ 16，丢掉最后不满的 13 个）。训练时 stride = 128，一轮 147 个 batch。一个 batch 的 x、y 都是 [16, 256]，一步训练就是 16 × 256 = 4096 道题。

**嵌入**：[16, 256] 的编号查表得到 [16, 256, 256]，位置嵌入 [256, 256] 广播相加，形状不变。两张表一共 1,114,112 个参数，其中 token 嵌入占了 94%。“的”在样本 0 的位置 34 和 41 各出现一次：查出的 token 向量完全相同，加上位置向量后就不同了。这就是位置嵌入的作用：同一个字，出现在不同位置，进入模型时已经带上了“我在哪”的信息。

<Note kind="point">语言模型的样本是长序列上的一个窗口：x 是前 T 个 token，y 是往后错一位的 T 个，一个样本里有 T 道题。编号经过 token 嵌入和位置嵌入两次查表、相加，变成 [B, T, d] 的向量。</Note>

## 容易写错的地方

- **x 和 y 错位的方向。**y 是 x 往后错一位（y[t] = x[t+1]），不是往前。写反了，模型学的是“看到后面猜前面”，加上因果掩码，它什么也看不到，loss 降不下去。
- **最后一个窗口越界。**窗口要 T + 1 个 token，起点上限是 len − T；写成 len − T + 1，最后一个样本的 y 会少一个 token，组 batch 时形状对不上。
- **验证集也打乱、也重叠。**不影响对错，但验证 loss 会因为每次抽到的样本不同而抖动，也会重复计算同一段话。

## 回顾

g1 加了 43 行的 `data.py`：`GPTDataset` 在长序列上按步长开窗口，取 T + 1 个 token，前 T 个是 x、后 T 个是 y；`load_corpus` 先按字符切出最后 10% 的验证集再分词；`make_loader` 用固定种子打乱、组 batch。训练集 302,475 个 token，T = 256、stride = 128 时一轮 147 个 batch。编号经过 token 嵌入（4096 × 256）和位置嵌入（256 × 256）相加，变成 [B, T, d]。

现在每个位置都有了一个 256 维的向量，但这些向量彼此独立：位置 5 的向量只知道自己是“的”、在第 5 个位置，不知道前面写了什么。要猜下一个 token，每个位置得能看到它前面的所有位置。下一讲：**g2 · 因果多头注意力**。
