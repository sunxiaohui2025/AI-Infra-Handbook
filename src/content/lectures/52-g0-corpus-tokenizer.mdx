第 2–5 篇把 GPT 拆成了零件：分词、嵌入、注意力、掩码、LayerNorm、残差、FFN、输出层，第 6 篇又讲了预训练和微调在做什么。每个零件我们都手算过、拖动过，但还没有把它们装在一起，真正训练出一个会写字的模型。

这一篇就做这件事：**从一个空目录开始，写出一个 GPT，在这门课自己的讲义上把它训练出来**。这个仓库叫 minigpt，一共 8 版，每讲一版，每一版都能跑。到最后一版，它能读懂“用一句话说明‘KV Cache’解决什么问题”这样的指令，并按格式作答。

这一讲是 g0：先准备语料，再写一个分词器，把 50 万字的讲义变成一串编号。

<Note kind="column" title="参考了哪本书">这一篇的路线参考了 Sebastian Raschka 的《Build a Large Language Model (From Scratch)》（中文译本见 <a href="https://skindhu.github.io/Build-A-Large-Language-Model-CN/">skindhu.github.io/Build-A-Large-Language-Model-CN</a>）：同样从数据加载器写起，经过注意力、GPT 模型、预训练，最后装进 GPT-2 的权重、做指令微调。不同的地方有三处：语料换成了这门课的中文讲义，分词器我们自己写、自己训练，代码按版本分目录，读者用 <code>diff -r g2 g3</code> 就能看出一讲改了什么。</Note>

## 为什么不直接用 GPT-2 的分词器

GPT-2 的分词器是现成的，词表 50,257 个 token。直接用它有两个问题。

第一，它是在英文网页上训练的，很多中文常用字没有被合并成一个 token，要用两三个字节 token 表示，序列变长，模型看到的上下文就短了。

第二，词表太大，对我们这个小模型不划算。嵌入表的参数是 V × d，V = 50,257、d = 256 时是 1287 万个，输出层再来一份，光这两张表就是 2500 多万个参数，是 4 层 Transformer 本身（约 316 万）的 8 倍。词表里绝大多数 token 在我们的语料里一次都不出现，这些参数白白占着。

所以我们自己训练一个分词器，词表定为 4096。

## 设计：从字符出发，生僻字退回字节

第 21 讲讲过 BPE：从最小的单位出发，一遍遍地把最常相邻出现的两个单位合并成一个新单位。“最小的单位”有两种选法。

GPT-2 从**字节**出发：任何文字都是一串 UTF-8 字节，初始词表就是 256 个字节，永远不会遇到不认识的字。代价是一个常用汉字占 3 个字节，要先花两次合并把它拼出来。

我们从**字符**出发：语料里出现过 3 次以上的字符，各占一个初始编号。这样一个汉字一开始就是一个 token，合并直接用在“模型”“请求”这样的词上。出现不到 3 次的生僻字，以及训练时根本没见过的字，**退回到字节**：拆成 3 个 UTF-8 字节，每个字节有自己的编号。这就是 Llama、Qwen 的分词器里常见的 byte fallback，它让“任何文字都能编码”这条保证依然成立。

于是词表的编号这样排：0–255 是 256 个字节，256 是分隔符 `<|endoftext|>`，257 起是字符（越常见编号越小），再往后是合并出来的 token，按学到的先后排。

还有一个细节：**合并只在一个“块”之内发生**。编码之前先把文字切成块：一串连续的英文字母、单个数字、一串连续的汉字、单个空白、单个其他符号。这样，“token”可以合成一个，但“token，”不会把逗号也粘进去；数字一位一位地切，模型看到的 2048 永远是 2、0、4、8 四个 token，不会因为“2048”恰好常见就单独成词。GPT-2 用的也是这种先切块、再合并的办法，只是它的规则针对英文。

## 训练分词器

`scripts/train_tokenizer.py` 用语料的前 90% 训练（最后 10% 留作验证集，后面训练模型时也这样切），存成 `data/tokenizer.json`，再拿几个例子看看效果：

<RunOutput cmd=".venv/bin/python scripts/train_tokenizer.py" file="minigpt/outputs/train_tokenizer.txt" caption="图 52-2　在讲义上训练出的分词器：1356 个字符加 2483 次合并，凑满 4096 个 token。最先学到的合并是“一个”、英文的 token，以及“模型”“请求”。" />

一行一行地看。

**词表的构成。**256 个字节 + 1 个分隔符 + 1356 个字符 + 2483 次合并 = 4096。训练集里有 1631 种不同的字符，其中出现 3 次以上的 1356 个，剩下的 275 个生僻字和符号走字节回退。

**最先学到的合并**是“一个”，然后是英文的 en、to、tok、token，然后是“模型”“请求”“每个”。“token”分了三步才合成：先合成 “to”，再 “tok”，最后 “token”，每一步都是当时次数最多的一对。这门课讲推理，“token”“模型”“请求”出现得多，自然先被合并。换成小说当语料，最先学到的会是完全不同的一批。

**最长的 token** 是 FlashAttention、PagedAttention、Transformer、HuggingFace、InfiniBand 这些专有名词。英文单词在一个块里，可以一路合并到整个单词；汉字一串也是一个块，但中文的“词”很少像英文专有名词那样一字不差地重复几十次，所以中文 token 大多是两三个字。

**例句**是 41 个字符，切成了 23 个 token。“每一层”“存下来”“下一个”“不用”“重算”都是一个 token。注意空格：讲义的写作规范要求中英文之间空一格，所以“KV”“Cache”之间、“把”之前都有一个单独的空格 token（编号 257，是出现最多的字符）。GPT-2 的做法是把空格粘在后一个单词的开头（“ Cache”是一个 token），可以省下这些空格 token；我们的切块规则把空白单独成块，换来规则简单，代价是序列长了一些。

**生僻字**“饕餮”不在词表里，退回成 6 个字节编号（每个字 3 个），解码回来一字不差。

**压缩率**：验证集 49,922 个字符编码成 33,048 个 token，平均每个 token 1.51 个字符。这个数决定了模型一次能“看”多远：上下文 256 个 token，约等于 390 个字符，差不多是讲义里的两三段。

<Note kind="point">分词器决定了模型看到的世界。词表越大，序列越短、一次看得越远，但嵌入表和输出层越大；从字符出发配合字节回退，中文的常用字一开始就是一个 token，任何字符又都能编码。</Note>

## 检查

每一版写完都跑 `tests/check.py`。g0 只检查两件事：验证集（分词器训练时没见过）编码再解码，和原文一字不差；没见过的字和表情符号也能还原。

<RunOutput cmd=".venv/bin/python tests/check.py g0" file="minigpt/outputs/check_g0.txt" caption="图 52-3　g0 的检查：分词器是可逆的。" />

“可逆”看起来理所当然，其实很容易写错。比如解码时一个一个 token 分别解码，生僻字就会变成乱码；比如编码时忘了分隔符要单独处理，`<|endoftext|>` 就会被拆成普通字符。后面训练出的模型生成的每一个编号，都要靠这个分词器变回文字，所以先把它验证死。

## 容易写错的地方

- **编码时的合并顺序。**必须按“学到的先后”合并，而不是按“这一块里哪一对次数最多”。训练时的次数是对整个语料统计的，编码一个新句子时，句子里的次数没有意义。
- **训练集和验证集要在分词之前切开。**分词器如果见过验证集，它的合并规则就带上了验证集的信息，后面验证集上的 loss 会偏乐观。我们只用前 90% 训练分词器。
- **词表大小要和模型对上。**模型的嵌入表是 V × d，V 必须等于分词器的词表大小。换一个分词器，模型就得从头训练。

## 回顾

g0 做了两件事：`data/prepare.py` 把 121 讲的 MDX 清理成 499,220 个字符的纯文本，讲与讲之间用 `<|endoftext|>` 隔开；`tokenizer.py` 用 133 行实现了一个从字符出发、生僻字退回字节的 BPE 分词器，在语料上训练出 4096 个 token，平均每个 token 1.51 个字符，编码再解码一字不差。

现在语料是一串 30 万个编号。可模型一次只能看 256 个，而且要学的是“看到前面，猜下一个”。这一长串编号怎么切成一个个训练样本？编号又怎么变成模型能计算的向量？下一讲：**g1 · 数据加载器与嵌入**。
